# MIT 模式 —— 控制逻辑与上位机指令集

**固件** `Code=107400` · **协议** 非标准 MAVLink v2 · **串口** 921600 8N1
**日期** 2026-11-22

---

## 0. 一句话概括

MIT 模式 = **给刚度 kp、阻尼 kd，让位置误差自己变成力矩**：

```
τ = kp·(p_des − p) + kd·(v_des − v) + τ_ff      →      iq = τ / Kt
```

它**没有位置环、没有速度环、没有积分项**。位置精度靠 kp 换，稳态有差是设计的一部分，
不是缺陷。这一点与位置模式（梯形规划 + 纯 P + 背算抗饱和）本质不同。

| 模式 | `30056 mode` | 给定 | 位置/速度闭环 | 位置语义 |
|---|---|---|---|---|
| 位置 | 1 | 目标角 | 有 | 进模式时 0~2π 归一化 |
| 速度 | 3 | 目标转速 | 有 | — |
| 力矩 | 4 | iq（A） | 无 | — |
| **MIT 阻抗** | **12** | **p/v/τ + kp/kd** | **无（PD 直接出力）** | **多圈、不折叠** |

> MIT 的位置是**电机轴多圈角** `theta_multi`，不折算减速比、不做 0~2π 归一化。
> 谐波关节要在输出端定位，请自行除以减速比。
>
> 2026-11-22 起，`p_des` 会先经过一级**限速/限加速整形**（15 rad/s、180 rad/s²），
> 大阶跃不再等于满力矩，见 1.2.1。

## 1. 控制律的真实实现

代码位置：`servo_isr.c:2600-2685`（20 kHz 电流环内，每拍执行）。

### 1.1 误差与坐标

```c
const float ds = (float)s_dir_sign;                       /* 模型方向 */
ep = ds * ((s_mit_p + s_mit_v*dt) - theta_multi);          /* 一阶外推后的位置误差 */
vdes = ds * s_mit_v;
om_d = ds * v_est;                                         /* 2 拍差分测速 */
tau  = s_mit_kp*epc + s_mit_kd*(vdes - om_d) + s_mit_tau;
```

- `p_des`、`v_des` 一律用**传感器坐标系**（即 30040 `enc_sum` 的正方向）表达。
  `dir_sign` 只在内部换算，上位机不需要关心电机接线方向。
- 位置误差先限幅 **±1.0 rad**（`SERVO_MIT_EP_MAX`，`servo_isr.c:553`）：
  kp 可能给到上千，`p_des` 打错一位就是满力矩冲出去。
- **不加齿槽前馈**（`servo_isr.c:2620` 附近的注释）：实测 A/B 反而更差 ——
  kp=10/kd=0.1 扫 0.8 rad 保持，齿槽关：峰峰 7.2 mrad；齿槽开：**14.2 mrad**。
  原因是 MIT 是纯 PD，前馈直接进力矩，表的误差没人兜，等于注入位置相关扰动。
  **MIT 的保持精度只能靠 kp 换。**

### 1.2 给定外推（默认开启）

MIT 帧约 1 kHz，控制在 20 kHz 跑。帧之间 `p_des` 是常数，等于目标每 1 ms 跳一步 ——
轨迹跟踪时这就是纯滞后（实测 2 Hz / 峰值 10 rad/s，误差 54 mrad 中 50 mrad = 5 ms × 10 rad/s）。

固件用帧里已有的 `v_des` 做一阶保持：

```
p_des(t) = p_frame + v_des·(t − t_frame)     外推上限 100 ms
```

帧龄从 20 kHz 计数取（`s_mit_tick`），不用 ms 计数 —— 1 kHz 帧用 1 ms 分辨率太粗。
超时时把已外推的位移**固化**进 `p_des` 再清 `v_des`，否则目标会回弹、力矩反向冲击。

### 1.2.1 目标整形：把阶跃变成斜坡（2026-11-22 新增）

MIT 没有轨迹规划器，**`p_des` 一帧跳多少，`kp` 就出多少力矩**。位置模式同一个目标
会走梯形规划，MIT 不会 —— 这是语义差异，不是参数问题。

实测：保持 `p=3.1867`，给 `p_des=6.2800`，误差 3.09 rad → 限幅到 1 rad → 满力矩 →
3.6 ms 撞 `0x0020`。

所以控制律不再直接用帧里的 `p_des`，而是用一个**限速 + 限加速**的整形值：

```
p_des(帧) ──► ① 位置差 × 12 /s → 期望速度 v_s（限 ±15 rad/s）
              ② v_shape 以 amax=180 rad/s² 逼近 v_s
              ③ p_shape += v_shape × 50 µs
              ④ 差 < 0.5 mrad 且 |v| < 0.02 → 吸附到位
```

| 参数 | 值 | 说明 |
|---|---|---|
| `SERVO_MIT_SHAPE_VMAX` | **15 rad/s**（143 rpm） | `v_des` 更大时自动放宽到 `1.2·|v_des|` |
| `SERVO_MIT_SHAPE_A_RATIO` | 12 | `amax = 12 × VMAX ≈ 180 rad/s²` |
| `SERVO_MIT_SHAPE_KP` | 12 /s | 位置差→期望速度，83 ms 时间常数 |
| `SERVO_MIT_SHAPE_EN` | 1 | 置 0 可关闭，回到直接执行 `p_des` |

两个必须处理的边界：

- **`kp=0` 阶段（盲起环）整形器直接跟随实际位置，绝不预跑**。否则起环帧 `p=0`
  会让整形值一路跑向 0，上刚度那一拍就变成"从 0 追到实际角"的满力矩阶跃 ——
  这正是 10:37 那次事故的另一种形态。
- **`v_des` 大时放宽限速**。正常轨迹每帧 `p` 连续变化，远低于 15 rad/s，完全不受影响；
  用户明确要高速时不能把轨迹拖慢。

效果（3.09 rad 阶跃，kp=30/kd=0.05，200 Hz）：

| 指标 | 只限速度 | **限速 + 限加速** |
|---|---|---|
| `\|iq\|` 峰 | 4.47 A（近满限幅） | **1.18 A** |
| `\|rpm\|` 峰 | 149.9 | 149.3 |
| 故障 | 无 | 无 |
| 到位残差 | -0.8 mrad | **-0.7 mrad** |
| 用时 | ~0.3 s | ~0.5 s |

代价是到位慢约 0.2 s，换来力矩冲击降 74%。

### 1.3 测速：专用 2 拍差分

D 项**不能用**控制环那个 `om`（8 拍累计 + 95 Hz 低通，群延迟 1.9 ms，
244 Hz 处相移 167°，阻尼项直接变负阻尼 —— 实测纯阻尼 kd=0.5 就起 5 A 极限环）。
也不能用单拍差分（被编码器 SPI 异步更新放大成隔拍跳动，极限环 742 Hz / 4 A）。

2 拍差分窗口 100 µs、群延迟 50 µs，254 Hz 处仅 9°。

### 1.4 τ → iq

```
iq = τ / (Kt_base × kt_comp)        Kt_base = 0.0910 N·m/A   (servo_isr.c:378)
```

`kt_comp` 是 Kt 温度补偿（默认开启，`servo_isr.c:771-804`），基准温度取 ψ 辨识那一刻的
电机温度，变化率限 ±0.2%/ms。50 °C 时同样的 τ 若不做补偿只出 96.4% 力矩。

**力矩上限的真相**：

| 环节 | 限值 | 是否生效 |
|---|---|---|
| 内部 τ 限幅 | ±1.5 N·m | ❌ 基本不生效 |
| iq 限幅 `cur_iqmax` | 默认 5.0 A（可调 0.05~5.0） | ✅ **真正的上限** |
| 温度降额 `derate` | 0~1，按 NTC | ✅ 再乘一次 |
| 位置误差限幅 | ±1.0 rad | ✅ 限制 kp 项 |

所以**有效力矩上限 = iq_max × Kt ≈ 5.0 × 0.091 = 0.455 N·m**（kt_comp=1、无降额）。
1.5 N·m 那个限幅要 iq_max > 16.5 A 才碰得到，而 `Servo_SetCurIqMax` 上限就是 5 A
（`servo_isr.c` 的 `SERVO_CUR_IQ_MAX`）。**别按 1.5 N·m 做机构设计。**

## 3. 30065 MitCtlInput —— 32 字节

布局 `"<qqffff"`（`mavlink_layouts.json` 30065 条目、`mavlink_common.c:25`）：

| 偏移 | 类型 | 字段 | 单位 | 固件是否解析 | 说明 |
|---|---|---|---|---|---|
| 0 | int64 | `pos_tar_p` | **编码器计数** | ✅ | 目标多圈角，2^21 counts/圈 |
| 8 | int64 | `pos_now_p` | counts | ❌ 回读位 | 下行填 0 即可 |
| 16 | float | `tq_set_NM` | N·m | ✅ | 前馈力矩 τ_ff，限 ±1.5 |
| 20 | float | `iq_max_A` | A | ❌ **不解析** | 别指望它限流，用 30082 |
| 24 | float | `speed_tar_p_s` | **counts/s** | ✅ | 目标速度 v_des |
| 28 | float | `speed_now_rad_s` | rad/s | ❌ 回读位 | 下行填 0 |

**换算**（`mavlink_host.c:34-35`）：

```python
ENC = 2097152.0            # 2^21 counts/rev
TWO_PI = 6.283185307179586

pos_counts = round(rad * ENC / TWO_PI)      # 1 count = 3.0 µrad
speed_counts = rad_s * ENC / TWO_PI         # 1 rad/s = 333772.6 counts/s
```

`pos_tar_p` 是**绝对多圈目标**，不是增量。跨圈不需要特殊处理（int64 不会 2π 突跳），
这和位置模式进模式归一化到 0~2π 的行为完全不同。

### 3.1 应答（9 字节，**LEN=9 不是 32**）

`mavlink_host.c:1144-1158`：

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | u8 | `status` | 0 成功 / 2 超范围 / 3 状态错误 / 4 无权限 |
| 1 | float | `p_des` 回读 | rad，**帧内目标**（正常运行不含外推；20 ms 超时后固化为外推终点） |
| 5 | float | `p_now` | rad，**当前 `theta_multi`**，与 MIT 同一口径 |

`p_now` 是上位机"贴当前角起步"最直接可靠的来源 —— 30040 的 `enc_sum` 是相对上电点的计数，
缺上电那一拍的基准角，自己换算会对不上（差整数圈）。

⚠ 应答的 `LEN` 是 9，与登记长度 32 不同。上位机解析必须按帧头 `LEN` 取长度，
不能按 layouts 的 32 硬读，否则会把后面的帧头当载荷。

### 3.2 四个角度口径别混

| 来源 | 口径 | 是否折叠 | 用途 |
|---|---|---|---|
| 30065 应答 `p_now` | `theta_multi` = 上电首拍角 + 累积计数 | 否，多圈 | **MIT 的 p_des 就用它** |
| 30040 `enc_sum` | 相对上电点的 counts | 否，多圈 | 画曲线、算速度；**不能直接当 p_des** |
| 30090 `pos@16` | `theta_m` 单圈（含编码器零点） | 是，[0,2π) | 人看的角度；与 `theta_multi` 差整数圈 |
| 30100 `p_now@0` | 位置环坐标（进模式时归一到 0~2π） | 是 | 位置模式专用，**MIT 下无效** |

⚠ `theta_multi` 的基准是**上电首拍**的角，不是每拍从 `theta_m` 推出来的。
重新做 Z（改 `s_enc_zero`）后两者会差一个常数，**不要用 `theta_m ± 2πn` 去反推 `theta_multi`**。
需要绝对值就读 30065 应答的 `p_now`。

MIT 不参与 30019 的 0~2π 归一化 —— 它是多圈绝对目标。

### 3.3 要"回本圈 0 点"怎么办

MIT 直接发 `p_des=0` 会真的走到**上电基准的 0**，可能倒转好几圈。要复现位置模式那种
"本圈 0~2π 语义"，由上位机做一次折算：

```python
def nearest_turn(p_now, target_0_2pi):
    """把单圈目标折到离当前位置最近的那一圈"""
    frac = p_now % TWO_PI          # Python 的 % 对负数也返回 [0, 2π)
    return p_now - frac + (target_0_2pi % TWO_PI)

p_des = nearest_turn(p_now, 0.0)   # 回本圈 0 点，不会绕圈
```

固件**不做**这个折算（这是 MIT 与位置模式的语义差别，不是缺陷）：MIT 的调用方
通常自己规划轨迹，跨圈连续运动是常态。

## 5. 进入 MIT 的两条路径

### 5.1 路径 A：给一帧 30065 直接起环（推荐）

第一帧 `30065` 自己完成全部装配（`servo_cmd.c:1039-1086`）：

```
Servo_SetEnable(0)          关模型三环
Servo_SetMode(POSITION)     仅标签
Servo_SetCurrentMode(1, 0)  起电流环（清积分）
Servo_SetMitCmd(p,v,kp,kd,τ) 先给给定
Servo_SetMitEn(1)           src → MIT
BspServo_PwmEnable(1)       开 MOE，并回读确认
```

若之前在别的模式且已使能，`ServoCmd_CtrlMit` 会先 `do_disable("mav mode switch")`
自动封锁再装配（`servo_cmd.c:1204-1208`）。

### 5.2 路径 B：控制字先使能，只留刚度

`30056(12)` → `30054 cw=1`。`arm_with_mode()` 会用**当前角** + `v=0` + `τ=0` 起环
（`app_param.c:120-126`），即"锁在当前位置"，此时还没有目标。之后再发 30065 才算运动。

好处：不会因为第一帧 `p_des` 写错而冲出去。

### 5.3 起环联锁（任一条不满足 → status=3，环不起）

| 检查 | 条件 | `s_mit_why` |
|---|---|---|
| 故障位 | `BspServo_GetFault() == 0` | 1 |
| 电流标定 | `IsCurrentCalibrated()` | 2 |
| 电角度零点 | `IsEncoderZeroed()`（Z 已做） | 3 |
| 辨识空闲 | `Act_IsBusy() \|\| OpenLoop \|\| VoltInject` 全否 | 4 |
| MOE 真的开了 | `IsPwmEnabled()` 回读 | 6 |

⚠ `s_mit_why` / `s_mit_bad` **目前没有 MAVLink 出口**（`Servo_GetMitState` 无调用点）。
status=3 时只能逐项排查：读 30090 的 `flags`（bit0=CAL、bit1=ZERO）与 `fault`，
读 30091 的 `p_lp[1]`（5=开环辨识中）。

## 6. 运行期保护

| 机制 | 门限 | 行为 | 代码 |
|---|---|---|---|
| **命令超时** | 20 ms 无新帧 | `v_des=0`、`τ_ff=0`，`p_des` **冻结在外推点** → 纯位置保持 | `servo_isr.c:639-654` |
| **deadman** | 2 s 无任何命令 | `do_disable` 封锁，MOE 关 | `servo_cmd.c:86` |
| 位置误差 | ±1.0 rad | 限幅（不是故障） | `servo_isr.c:553` |
| 力矩 | ±1.5 N·m → 再被 iq_max 夹 | 限幅 | `servo_isr.c:2678-2680` |
| 超速 | `1.5·abs(v_des) + 30` rad/s | `0x0020` 故障、封锁 | `servo_isr.c:2544-2553` |
| 跟随误差 | — | **MIT 下不会触发** `0x0100`（没有位置环） | `servo_isr.c:2703-2708` |
| 温度降额 | NTC | 乘在 `cur_iqmax` 上 | `servo_isr.c:2741-2758` |

### 6.1 停发 20 ms 到底会发生什么

这是最容易误解的一点：**不是松手，是把最后给的目标走完**。

- 0~20 ms：正常，`p_des` 按 `v_des` 外推。
- 20 ms 后：`v_des=0`、`τ_ff=0`，`p_des` 保留（已把外推位移固化）→
  `τ = kp·(p_des − p) + kd·(0 − v)`；**目标整形器继续以 ≤15 rad/s 把 `p_des` 走到位**
  （2026-11-22 加了整形器之后的行为）。
- 2 s 后：deadman 封锁，才是真正松手。

所以要"停在当前位置"，正确做法是发 `p_des = 当前角、v_des = 0`，或直接 `30054 cw=0`。
只是停发帧，电机会先走完最后那个目标。

### 6.2 超速门限为什么是 30 rad/s 起

MIT 的力矩是 `kp·e`，位置阶跃时 e 一下就是几十毫弧度，即使 kp=3 也能让 J=5.47e-5 的
转子在 0.1 s 内撞上 10 rad/s。实测：保持时改目标 0.083 rad、kp=25，0.1 s 内就报 `0x0020`，
看上去像"MIT 一改目标就跳闸"。改成 `1.5|v_des|+30`（≈286 rpm 基数）后正常运动不再误报，
真失控（编码器断线、dir 判错）仍会撞线。

### 6.3 上刚度瞬间撞 0x0020：一条真实事故的完整链路

2026-11-22 10:37 实测（上位机日志）：

```
07.513  MIT 起环   kp=0 起环 → p_now 3062.8801 rad → 上刚度 kp 30 / kd 0.050，给定流 200 Hz
07.550  30065 被拒 status=3（状态错误）
07.557  故障 0x0020 超速
```

**链路**：起环帧 `p=0`（盲起环 —— 此时还没读到 `p_now`，只能用 0 占位，靠 `kp=0` 不出力）
→ 紧接着 `30066` 上刚度 → 旧固件在这里用**缓存的 `s_mit_p=0`** 重发了一次给定
→ 实际角 3062.88 rad，误差 −3062.88 被 `EP_MAX` 限到 −1 rad
→ `τ = 30 × (−1) = −30 N·m` → iq 顶 −5 A 满反转
→ 空载加速度 `5 A × 0.091 / 5.47e-5 = 8317 rad/s²`，**3.6 ms 就到 30 rad/s**
→ `0x0020`，`ServoCmd_Poll` 随即 `do_disable`，之后所有 30065 都是 status=3。

**为什么 37 ms 而不是 3.6 ms**：帧传输 + 30066 分发 + 100 Hz 遥测的显示延迟。
故障实际发生在 30065 被拒之前，所以"被拒 status=3"是**结果**，不是原因。

**修复（2026-11-22，`app_param.c:279-305`）**：删掉 30066 的"立即刷新给定"分支。
配置帧只改缓存，下一帧 30065 才把新 kp/kd 带进 `Servo_SetMitCmd`。
删掉后上刚度最多晚 5 ms（200 Hz）生效，但不会再用一个过期的目标当指令。

**上位机必须遵守的顺序**（少一步就复现）：

1. `30066 {kp=0}` → `30065 {p=0}` 起环（拿 ack 的 `p_now`）
2. `30065 {p=p_now}` **先把目标贴到当前角**
3. 再 `30066 {kp=30}` 上刚度
4. 最后才开始轨迹流

第 2 步不能省。固件不再替上位机兜这个底 —— 它没有义务猜"这个 p=0 是想去 0 还是占位"。

**修复后的实测（2026-11-22 10:45，Code=107400，烧录后 CAL/ZERO 均在）**：

| 场景 | 结果 |
|---|---|
| **A**：起环 `p=0/kp=0` → 直接 `30066 kp=30`（跳过贴角，旧固件必炸） | `fault=0x0000`、`mode=12`、`iq=0.123 A`、`rpm=0` → **未超速** |
| **B**：`30065 p=p_now(0.0892)` 后再跑 0.02 rad / 0.5 Hz 正弦 @200 Hz | 300 帧、`\|iq\|`峰 **0.575 A**、`\|rpm\|`峰 1.2、故障=无 |
| 收尾 `30054 halt=1` | `fault=0`、`mode=0`、`iq=0` |

A 段那 0.123 A 是 kd 项对微速的响应（`v_des=0` 时 `kd·(−v)`），不是残余力矩，属正常。

脚本：`Agnet/mit_fix_verify.py`（含 A/B 两段与状态自检，可直接复跑）。

> A 段通过只证明"30066 不再用过期目标"，**不代表起环可以随便给 p**。
> 起环后第一帧 30065 如果 p 与当前角差几十毫弧度，kp=30 一样会在 3.6 ms 内顶满 iq。

### 6.4 为什么 kp=30 这么容易超速

`J=5.47e-5` 下，`kp × e / J` 就是加速度：

| 误差 e | kp=30 的 τ | 是否顶 iq 限 | 到 30 rad/s |
|---|---|---|---|
| 1 mrad | 0.03 N·m | 否 | 不超速 |
| 7 mrad | 0.21 N·m | 否 | 约 8 ms |
| **15 mrad** | 0.45 N·m | **刚好顶满** | **3.6 ms** |
| 1 rad（限幅） | 30 N·m → 实际 0.455 | 是 | 3.6 ms |

所以 MIT 的"安全起环"要求 **p_des 与当前角差 < 10 mrad**。
`mit_run.py` 当年能跑正弦不出事，是因为它起环后 offset 从 0 开始，误差天然为 0。
一旦上位机用"绝对角"而不是"相对偏移"起轨迹，就必须先对齐 `p_now`。

### 6.5 大阶跃直接撞 0x0020：MIT 没有轨迹规划（2026-11-22 10:59）

修好 6.3 之后又炸了一次，现象一样、原因不同：

```
10:58:19  MIT 起环      p_now 3.2354 rad，kp=30
10:58:31  MIT 正常跟踪  中心 3.2354，A=0.05 rad，0.5 Hz
10:58:54  MIT 正常停止  保持 p 3.1867 rad
10:59:18  MIT 目标      p_des 6.2800 rad（e 3092.5 mrad）  ← 3.09 rad 阶跃
10:59:18  30065 被拒    status=3
10:59:18  故障 0x0020
```

`e=3092.5 mrad` 就是全部答案：`kp=30 × 3.09 rad` → 被 `EP_MAX` 限到 1 rad
→ 30 N·m → iq 顶 5 A → 3.6 ms 到 30 rad/s。

**这不是固件 bug，是 MIT 的语义**：它是"阻抗给定"，不是"点到点定位"。
位置模式给 6.28 会走梯形规划（`motion_profile.c`），MIT 只会立刻用 `kp·Δp` 出力。

**处理（2026-11-22，`servo_isr.c:596-607`、`2667-2712`）**：加了一级目标整形，
把 `p_des` 的阶跃变成"限速 15 rad/s + 限加速 180 rad/s²"的准梯形曲线，见 1.2.1。

同一场景复测：

| 指标 | 整形前 | 整形后 |
|---|---|---|
| `\|iq\|` 峰 | 4.47 A（限幅 5 A） | **1.18 A** |
| `\|rpm\|` 峰 | 149.9 | 149.3 |
| 故障 | **0x0020** | **无** |
| 到位残差 | —（跳闸） | -0.7 mrad |

**所以现在 MIT 下给大目标不会再跳闸**，但要知道：

- 到位时间 ≈ `Δp / 15 rad/s` + 0.2 s，3.09 rad 约 0.5 s；
- 真要"点到点精确定位"，位置模式仍然更合适（有规划、有到位判定、有 `0x0100` 保护）；
- 整形器只作用于 MIT，不影响位置/速度/力矩三个模式。

## 7. 参数整定

### 7.1 物理判据（比试凑快）

阻尼环的穿越频率是 `kd/J`，必须**远低于电流环带宽**：

```
kd / (2π·J) ≪ f_current      J ≈ 5.47e-5 kg·m²（本机电机侧）, f_current ≈ 1 kHz
→ kd < 0.1
```

kd 超限的后果不是"阻尼更大"，而是 D 项变**负阻尼**，起 244 Hz 极限环、iq 顶限幅。

kp 的判据是"静摩擦除以允许误差"：

```
稳态误差 e_ss ≈ τ_friction / kp
本机静摩擦 ≈ 0.05 N·m → kp=30 时 e_ss ≈ 1.7 mrad（实测 6 mrad，含齿槽与测量噪声）
```

### 7.2 实测（`MIT优化_参数扫描与定值_20261118.md`）

| 组 | kp | kd | iq 峰 | 状态 |
|---|---|---|---|---|
| 优化前 | 10 | 0.5 | **5.6 A（顶限）** | 244 Hz 极限环 |
| **默认** | **30** | **0.05** | **<1.1 A** | 干净 |
| kp 扫描 | 10~120 | 0.05 | <1.1 A | kp>20 后精度见底（误差 15~19 mrad） |
| kd 扫描 | 30 | 0.2 / 0.5 | 顶限 | 复现振荡 |
| kd 扫描 | 30 | ≤0.08 | 干净 | — |

固件默认 `kp=30 / kd=0.05`（`app_param.c:29-30`），与 `mit_run.py` 一致。
**kd 的默认值曾经是 0.5~3.0，高了 5~60 倍，这是历史坑。**

### 7.3 起步建议

1. `kp=0, kd=0` 起环，确认 `p_now` 稳定、iq≈0。
2. `kp=10, kd=0`，给 0.05 rad 阶跃，看是否过冲/振荡。
3. kp 加到"再大也不更准"（本机 30），kd 从 0 加到"iq 噪声明显变大前"（本机 0.05）。
4. 做正弦跟踪，按 7.1 复核 kd 是否越界。
5. 大目标（几 rad）可以直接给：整形器按 15 rad/s、180 rad/s² 走过去，
   3.09 rad 约 0.5 s。要更快就调 `SERVO_MIT_SHAPE_VMAX` 重烧。

## 8. 上位机参考实现

### 8.1 打包 / 解包

```python
import struct

ENC    = 2097152.0
TWO_PI = 6.283185307179586
K_RAD2CNT = ENC / TWO_PI          # 333772.6

def pack_mit(p_rad, v_rad_s, tau_nm, pos_now_cnt=0, iq_max=0.0, spd_now=0.0):
    """30065 必须发满 32 B"""
    return struct.pack('<qqffff',
                       int(round(p_rad * K_RAD2CNT)),
                       int(pos_now_cnt),
                       float(tau_nm),
                       float(iq_max),
                       float(v_rad_s * K_RAD2CNT),
                       float(spd_now))

def unpack_mit_ack(payload):        # LEN 应为 9
    st    = payload[0]
    p_des = struct.unpack_from('<f', payload, 1)[0]
    p_now = struct.unpack_from('<f', payload, 5)[0]
    return st, p_des, p_now

def pack_mit_cfg(kp, kd, kt=0.091):
    """30066 必须发满 16 B；enc_line_inv_p_n 填 0"""
    return struct.pack('<ffff', float(kp), float(kd), 0.0, float(kt))

def unpack_mit_cfg_ack(payload):    # LEN 应为 9
    st = payload[0]
    return st, struct.unpack_from('<f', payload, 1)[0], struct.unpack_from('<f', payload, 5)[0]
```

### 8.2 最小可用序列

```
① 30068  {comm_auth=0, internal=0}          申请控制权（只需一次）
② 30056  {mode=12}                          选 MIT（只登记，不动作环）
③ 30090  读 flags：bit0(CAL)=1 且 bit1(ZERO)=1，fault=0
④ 30066  {kp=0, kd=0.05, kt=0.091}          先零刚度，绝对安全
⑤ 30065  {p=0, v=0, τ=0}                    起环；ack 里拿 p_now
⑥ 30065  {p=p_now, v=0, τ=0}                贴住当前位置 —— 必须确认 status=0
⑦ 30066  {kp=30, kd=0.05}                   上刚度（只在 ⑥ 成功后做）
⑧ 循环 30065 {p=p_now+偏置(t), v=偏置'(t), τ=ff}   @500 Hz
⑨ 30054  {cw=0} 或 {halt=1}                 退出（或等 deadman）
```

第 ⑤ 步用 `kp=0` 起环是关键：此时 `τ=kd·(0−v)=0`（静止），`p_des` 写错也不出力。
拿到 ack 的 `p_now` 后再上刚度，就不会有 `kp·e` 的起环冲击。
起环前请确认电机**静止**：有 ~10 rad/s 余速时 kd 项会出力（kd=0.05 → 0.5 N·m 已超 iq 限）。

⚠ ⑦ 之前必须完成 ⑥ 且 status=0。跳过 ⑥ 直接上刚度就是 6.3 那次 0x0020 的复现路径。

### 8.3 帧率与带宽

| 项 | 数值 |
|---|---|
| 30065 请求帧 | 44 B（10+32+2） |
| 30065 应答帧 | 21 B（10+9+2） |
| 500 Hz 双向 | 32.5 KB/s ≈ 325 kbps |
| 遥测（30027/30040/30090/30091/30100 各 100 Hz） | 24 KB/s ≈ 240 kbps |
| 合计 @500 Hz | ≈ 565 kbps（921600 余量约 39%） |
| @1 kHz | ≈ 890 kbps（**96% 占用，不推荐**） |

固件侧还有 `s_pending` 单槽：上一帧未 dispatch 时新帧直接丢弃（`mavlink_host.c:181-187`），
主循环 1 ms 处理一帧 → **实际吞吐上限约 1 kHz**。建议 500 Hz 起步。

## 9. 故障排查

### 9.1 status 码

| status | 含义 | 典型原因 | 处置 |
|---|---|---|---|
| 0 | 成功 | 已起环 / 给定已更新 | — |
| 2 | 超范围 | p/v 为 NaN、kp>5000、kd>100、p 非 finite | 检查打包 |
| 3 | 状态错误 | 故障位非 0 / C 未标定 / Z 未做 / 辨识忙 / MOE 拒开 | 见 9.2 |
| 4 | 无权限 | `comm_auth != 0` | 先发 30068 置 0 |

### 9.2 常见现象

| 现象 | 根因 | 验证 |
|---|---|---|
| **ACK 返回 0，但电机完全不动** | `30056` 没发或 mode≠12 → `AppParam_SetMitCmd` 只缓存不装配（`app_param.c:273`） | 读 30090 `p_st[2]`，应为 12 |
| **上刚度瞬间猛冲 → 0x0020** | ⑥ 没做/没成功就发 30066（旧固件还会用过期 `p=0` 刷新给定） | 查 ⑥ 的 status；固件 2026-11-22 已删刷新分支，但顺序仍不能省 |
| **给新目标就报 0x0020** | 大阶跃：MIT 无轨迹规划，`kp·Δp` 直接满力矩（3.09 rad 必炸） | 2026-11-22 起整形器已兜住；若仍报，确认 `SERVO_MIT_SHAPE_EN=1` |
| 起环瞬间猛冲一下 | 第一帧 `p_des` 与 `theta_multi` 差太多（常见差整数圈） | 先 `kp=0` 起环，ack 取 `p_now` |
| 一改目标就报 `0x0020` | `abs(v_des)` 大或 kp 大导致加速峰值超 `1.5·abs(v_des)+30` | 降低 kp、给合理 `v_des` |
| 保持时 iq 嗡嗡振、顶限幅 | kd 过大（>0.2）起 244 Hz 极限环 | 30066 把 kd 降到 0.05 |
| 位置一直差 1~2 mrad 回不到 0 | MIT 无积分，静摩擦除以 kp 就是稳态差 | 加大 kp（≤2000）或加 τ_ff |
| 停发后电机慢慢走 | 20 ms 后 `p_des` 冻结但 kp 仍在，属正常"保持"；2 s 才封锁 | 见 6.1 |
| 出力只有预期一半 | `cur_iqmax` 被改小（默认 5.0 A；历史遗留的 3 A 是 `spd_iqmax`，两者别混） | 读 30082 float[12]（cur_iqmax）与 float[6]（spd_iqmax） |
| 30065 完全无应答 | 帧长不是 32 B，被当坏帧丢（`mavlink_host.c:168`） | 抓包看 LEN |
| 应答解析错位 | 按 32 B 解析 9 B 应答 | 按帧头 LEN 取 |

| 30090 `p_st[3]` bit2 | 1 | armed |

## 11. 已知局限（如实列出）

1. **没有 MIT 专用遥测**。`Servo_GetMitState()`（tau/ep/kp/kd/p_now）与 `Servo_GetMitDt()`
   已实现但**无 MAVLink 出口**。目前只能靠 30065 应答的 `p_now`、30090 的 iq、30091 的 src
   间接判断。要诊断"kp·e 出了多少力"需要新开一条消息（建议在 30091 的空闲槽或新 msgid）。
2. **`s_mit_why` 无出口**。status=3 时无法区分"故障位/C 未标定/Z 未做/辨识忙"，
   只能逐项读 30090 flags 排除。
3. **kp/kd 回读未 clamp**（见 4 节）。上位机看到的可能是内部会再夹一次的值。
4. **有效力矩上限 0.455 N·m**，不是代码里写的 1.5 N·m。机构设计要按 0.455 算
   （更准确：`cur_iqmax × Kt × kt_comp × derate`）。
5. **30065 应答 LEN=9 ≠ 登记长度 32**，解析要按帧头 LEN。
6. MIT 下 `0x0100` 跟随误差永不触发 —— 如果上位机用它判断"堵转"，在 MIT 下会永远看不到。
7. 力矩前馈 `τ_ff` 不经过 `s_cur_iq_tau` 斜坡（MIT 分支在斜坡之后覆盖 `iq_ref`），
   阶跃给 τ 会直接冲击电流环。
8. **目标整形的三个参数是编译期常量**（`SERVO_MIT_SHAPE_VMAX` 15 rad/s、
   `A_RATIO` 12、`KP` 12），没有做成 30082 可调项 —— 要改需重烧。
   30082 的 16 个 float 槽已全部占用，若要做成运行时参数需新开一条消息。
9. 整形器会改变"停发 20 ms"的行为：不再是停在最后一帧，而是把目标走完（见 6.1）。
   依赖旧行为的脚本需要用 `30054 halt=1` 或发 `p_des=当前角` 来停。
