# 齿槽转矩前馈：实现与实测

> 目标：压掉低速段由齿槽引起的速度波动
> 代码：`Board/cog_ff.c` / `.h`，`param_store.c` 的齿槽表页
> 命令：`;` 开关、`:` 查询
> 实测：2026-11-17 06:05

---

## 1. 为什么速度环治不了齿槽

实测齿槽峰峰 **1.169 A**（双向平均），而 30 rpm 空载运行电流只有 0.13 A——**扰动是信号的 9 倍**。

但调 Kp/Ki 完全无效，原因是物理层面的：

| | 齿槽 | 摩擦 |
|---|---|---|
| 性质 | **位置**相关，周期 = 机械一圈的 24/28 阶 | 速度相关 |
| 速度环能不能看见 | **看不见** | 看得见 |

速度环的输入是速度误差。齿槽造成的**位移**不产生持续速度——转子被齿槽拉到下一个平衡点后速度又回到 0，环认为"没有误差"。所以无论增益怎么调，这部分误差都压不掉。

实测证据：上一轮做的增益调度在 3–500 rpm **完全测不出差异**，因为那 0.2–1.2 rpm 的误差本来就来自齿槽而不是增益不合适。

**唯一有效的办法是按角度查表直接抵消。**

## 2. 表从哪来

`}` 命令测：10 rpm 正向 1 圈 + 反向 1 圈，两向逐箱平均成 128 点表。

**两向平均是关键**：摩擦的常值偏置在正转时是 `+Tc`、反转时 `−Tc`，单向测量会把它当成齿槽的直流分量留在表里。两向平均后 `Tc` 抵消（实测 `dc` 从 0.103 降到 0.011）。

表存的是**"维持匀速所需的 iq"**，单位 A，缩放 1000 存 int16。所以直接叠到 iq 给定上就是正确的前馈量——负号已经在测量里了。

---

## 3. 三个必须做对的细节

### 3.1 表的 0 点不是编码器零点

齿槽表按 `rel = θ_multi − s_cog_th0` 分箱，**bin 0 对应测量起点 `s_cog_th0`**，不是编码器零点。

所以表必须带 `phase`（`s_cog_th0 mod 2π`），查表时用：

```
ph = (θ_multi − phase) mod 2π
```

漏了这一步，前馈会整体偏移最多半个齿槽周期——**那时候它不是补偿，而是加倍扰动**。

### 3.2 必须校验零点，否则重做 Z 后会静默失效

`θ_multi` 的零点由 Z 决定。**重做 Z 之后 `phase` 就失效了**，继续用会把扰动放大一倍，而且没有任何报错——只是"开了前馈反而更抖"。

所以表里同时存 `zero_ref`（测量时的编码器零点），加载/启用时比对：

```c
dz = |wrap_pi(zero_now − zero_ref)|
s_valid = (dz <= 1°)      /* COG_FF_ZERO_TOL */
```

不一致就 `valid=0`，前馈自动停用，`:` 命令能看到 `v=0`。

**两个角度缺一不可**：只存 `phase` 检不出失效；只存 `zero_ref` 又没法查表。`CogBlob` 里给它们各留一个 float 槽位，总大小仍是 280 B。

### 3.3 高速必须关掉

齿槽频率 = 24 阶 × 转速：

| 转速 | 齿槽基频 | 判断 |
|---|---|---|
| 30 rpm | 12 Hz | 全量补 |
| 100 rpm | 40 Hz | 全量补 |
| 500 rpm | 200 Hz | 开始衰减 |
| 1500 rpm | 600 Hz | **关闭**（电流环 1.4 kHz，跟不上） |

而且高速时转子惯性已经把齿槽滤掉了，本来就不需要补。所以按 `|w_ramp|` 门控：

```c
< 20 rad/s（191 rpm）  全量
20 ~ 52 rad/s          线性衰减
> 52 rad/s（496 rpm）  0
```

## 4. 叠加位置

```c
s_spd_iq = (kp·err) + i_term + ff_acc + ff_fric + cog_ff;
// 然后限幅
```

**不进积分**（积分是独立变量 `s_spd_i_term`），所以 PI 不会把前馈"学掉"——否则前馈会被积分反向抵消，等于白做。

---

## 5. Flash 存储：单独一页

| 页 | 地址 | 内容 |
|---|---|---|
| 倒数第二页 | `0x0807E000` | 齿槽表（24 B 头 + 256 B 数据 = 280 B） |
| 最后一页 | `0x0807F000` | ParamBlob（64 B） |

**为什么不塞进 ParamBlob**：128 点 int16 = 256 B，会让 ParamBlob 从 64 B 涨到 320 B，每次保存要写 40 个 doubleword、memcmp 也要比 320 B。而齿槽表是"标定一次用很久"的数据，没必要跟零漂/增益一起每 500 ms 比对。单独一页也让 `PS_VERSION` 不用再升一级（避免现有参数全部作废）。

表头：`magic('X72C') + version + n_bins + zero_ref + phase + pp + crc32`，`crc32` 覆盖它之前的全部字节。

## 6. 实测

### 6.1 前馈效果

条件：齿槽表 `pp=1.049 A`、`phase=98.37°`、`zd=0.00°`，每点采 4 s。

| rpm | 前馈 OFF σ | 前馈 ON σ | 改善 |
|---|---|---|---|
| 3 | 0.470 | 0.490 | **+4.0%（略差）** |
| 30 | 3.630 | **2.854** | **−21.4%** |
| 100 | 7.347 | **5.077** | **−30.9%** |

**30 rpm 降 21%、100 rpm 降 31%**，方向与幅度都符合预期（齿槽占扰动的比例随速度上升而上升，直到惯性开始接管）。

**3 rpm 没有改善，反而略差 4%**（在测量噪声内）。原因：3 rpm 时齿槽基频只有 1.2 Hz，速度环的积分器**跟得上**这个频率，已经把齿槽部分吸收了——前馈的边际收益本来就小。这也解释了为什么这个点的误差一直只能靠摩擦前馈改善。

### 6.2 跨复位验证

```
复位前 : cog n=128 en=0 v=1 pp=1.05A ph=98.37deg zd=0.00deg
软复位 !
复位后 : cog n=128 en=0 v=1 pp=1.05A ph=98.37deg zd=0.00deg
开前馈 ;: cogff ON valid=1
再查   : cog n=128 en=1 v=1 pp=1.05A ph=98.37deg zd=0.00deg
```

表、相位、零点全部从 Flash 正确恢复，`zd=0.00°` 说明零点一致。

## 7. 命令

| 键 | 作用 |
|---|---|
| `}` | 测齿槽（正反各一圈，14 s），**测完自动装进前馈缓存**，回显 `->cog ok` 或 `->cog REJECT` |
| `;` | 前馈开关（初始关闭，回显带 `send A to save`；开关随 `A` 落盘，冷启动自动恢复） |
| `:` | 状态：`n` 点数、`en` 开关、`v` 有效、`pp` 峰峰、`ph` 相位、`zd` 零点偏差、`now` 当前前馈量 |
| `A` | 保存参数（含齿槽表**和开关 en**，回显 `+cog`） |

**默认关闭是有意的**：相位错的前馈比不补更糟，必须显式开。而且 `;` 开启时会**再校验一次零点**——从 Init 到你现在按 `;` 之间可能做过 Z。

## 8. 局限

1. **烧录擦 Flash**，每次烧固件要重测齿槽（14 s）并重新 `A`。这是"Erase Full Chip"的固有代价。
2. **重做 Z 会让表失效**——`v` 会变 0，前馈停用。必须重测。这是设计上的保守选择：宁可不用，也不能用错相位。
3. **只测单向齿槽的残留**：双向平均消掉了摩擦常值项，但如果齿槽本身有正反不对称（机械间隙），平均会把一部分真实信号也平均掉。实测 `fwd=1.138 / rev=1.140` 几乎相同，说明这台机器的齿槽是对称的，影响可忽略。
4. **高速段没做**（>496 rpm 关闭）。理论上可以用电流环逆模型做高频前馈，但收益低、风险高（模型不准会引入振荡）。
5. **表的温度/位置依赖性未验证**：齿槽来自磁钢与齿槽几何，理论上温度影响很小，但没做过冷热对比。

---

## 9. 与增益调度的关系

两者是互补的，不是替代：

| | 增益调度 | 齿槽前馈 |
|---|---|---|
| 对付什么 | 不同工作点的**稳定性**（相位裕度） | **位置相关**的周期扰动 |
| 30 rpm 纹波 | 3.63 → 3.22（不可靠） | 3.63 → **2.85** |
| 100 rpm 纹波 | 7.35 → 7.33（不可靠） | 7.35 → **5.08** |

**增益调度解决"能不能稳"，齿槽前馈解决"稳了还剩多少误差"。** 后者才是低速精度的主要来源。

> ⚠ **本节表格是单次测量，已被第 10 节推翻**：交错重复 3 轮后，100 rpm 的
> `7.35 → 5.08` 复现不出来（实测 −5.9% / +0.1% / +7.3%，均值 +0.5%）。
> 30 rpm 有收益但幅度是 +15~18% 而不是 −21%，且要用**谱分量**才看得清。
> 保留本节是为了留下"用总 σ 评价窄带补偿会得出什么错误结论"的记录。

## 10. v2 修订（2026-11-17）：低速衰减、开关持久化、以及一次结论修正

### 10.1 为什么要改

三件事凑到一起：

1. **开关不落盘**。表在、零点对，但 `en` 只在 RAM 里，`CogFf_Init` 硬编码 `s_en=0`。
   每次上电都退回关闭 —— 现场等于"标定过却从来不生效"，必须人工发 `;` 才行。
2. **极低速补反了**。旧门控 `|w| <= 20 rad/s（191 rpm）` 一律全量，所以 3 rpm 也是 100%。
   实测 3 rpm 开全量，纹波 σ 从 0.397 涨到 0.449（**恶化 13%**）：3 rpm 时转子在
   黏滑（stick-slip）爬行区，1.05 A 峰峰的力矩前馈在静摩擦拐点反复激发，
   补偿直接变成抖动。低速段的问题不是"补得不够"而是"补得不对"。
3. **旧实测数字站不住**。第 9 节表格里的 `7.35 → 5.08（100 rpm）` 是单次测量，
   交错重复 3 轮后复现不出来（见 10.4）。必须改。

### 10.2 改动

| 位置 | 改动 |
|---|---|
| `cog_ff.h` | 新增 `COG_FF_W_LOW = 1.0472 rad/s`（10 rpm） |
| `cog_ff.c` `CogFf_Get` | 门控改三段：`<10 rpm` 按 `ω/ω_low` 线性起量；`10~191 rpm` 全量；`191~496 rpm` 线性退出；`>496` 关闭 |
| `cog_ff.c` `CogFf_Get` | 新增零点校验分频（256 拍 ≈ 128 ms）—— 见 10.3 的坑 |
| `cog_ff.c` `LoadFromFlash` | 恢复 `en`，**不再用 `s_valid` 压制**（原因见 10.3） |
| `param_store.c` | `CogBlob` 280 B → **288 B**，`COG_VERSION` 1 → 2，加 `en` 字段，**CRC 覆盖整张表** |
| `servo_cmd.c` | `;` 回显加 `send A to save` |

`CogBlob` 新布局（288 B = 36 个 doubleword，必须整除，否则末尾字节写不进去）：

```
magic(4) version(2) n_bins(2) en(2) rsv[3](6) | zero_ref(4) pp(4) phase(4)
| cog[128](256) | crc32(4) = 288
```

顺手修掉一个旧缺陷：v1 把 `crc32` 排在 `cog[]` **之前**，于是 CRC 只盖住 20 B 头，
齿槽表本身一位都没保护 —— 表里错一个点不会报警，只会让补偿静默反相。
v2 把 `crc32` 挪到最后，覆盖头部 + 整张 128 点表。

### 10.3 两个踩过的坑（都会伪装成"功能没生效"）

**坑 1：初始化顺序让 en 永远恢复不了。**
`CogFf_Init()` 在 `servo_isr.c` 第 1707 行，而 `BspServo_Init()` 在 1723 行 ——
加载表的那一刻编码器零点还是 0，`cog_install` 里的零点比对必然失败（`s_valid=0`）。
第一版在加载时写 `s_en = (en && s_valid)`，结果复位后稳定复现 `v=1` 但 `en=0`。
正确做法：加载时只恢复"用户意图"，安全门交给 `CogFf_Get` 里的 `s_valid`。
但 `s_valid` 又必须能在运行时更新（否则上电后一直配着失效表），所以 `Get` 里加了
256 拍分频的 `cog_check_zero()`。

**坑 2：诊断量被 9/10 的拍清零。**
为了不让 `:` 的 `now=` 在停机后一直显示旧值，一开始把 `s_spd_cog = 0` 放在 20 kHz
电流环的循环开头。但 `s_spd_cog` 只在 2 kHz 速度环的**第 10 拍**更新 ——
于是诊断读到的值有 90% 是 0，看着像前馈根本没工作（实测 41 个样本只有 5 个非零）。
清零必须放在 `s_spd_en == 0` 的 else 分支里。

### 10.4 重新实测：把"总 σ"换成"谱分量"

**测量方法的问题**：`σ` 里混着测速噪声、摩擦黏滑、母线波动，而齿槽前馈只针对
「24 阶机械」这一根线。用总 σ 判断，等于用总噪声去评价一个窄带补偿 ——
单次 4 s 的 σ 估计本身就有 ±10% 波动，前馈的收益正好被这个波动淹没。

**交错重复**（`cog_ab2.py`，OFF/ON 交替 3 轮，让温漂平摊到两侧）：

| 转速 | OFF σ | ON σ | 配对改善（各轮） |
|---|---|---|---|
| 3 rpm | 0.493 ± 0.072 | 0.570 ± 0.061 | **−17.0%**（−11.2 / −38.8 / −1.1） |
| 100 rpm | 6.937 ± 0.277 | 6.913 ± 0.709 | **+0.5%**（−5.9 / +0.1 / +7.3） |

结论：**总 σ 上，3 rpm 和 100 rpm 都没有可测收益**（3 rpm 甚至偏负）。
这直接推翻了第 9 节"100 rpm 7.35 → 5.08"的记录 —— 那是单次采样的运气。

**谱分析**（`cog_spec.py`，30 rpm，24 阶 = 12 Hz，Hann 窗 + 单点 DFT 扫峰，2 轮）：

| 量 | OFF | ON | 改善 |
|---|---|---|---|
| 速度谱 @12 Hz | 0.2113 rpm | 0.1783 rpm | **+15.6%**（各轮 +7.0 / +22.7） |
| 电流谱 @12 Hz | 0.0141 A | 0.0204 A | −44.6% |
| 总 σ | 3.474 | 2.832 | **+18.5%** |

30 rpm 是唯一能稳定看到收益的工作点：+15.6%（谱）/+18.5%（σ），两轮同向。

电流谱 12 Hz 反而变大是对的 —— 前馈本身就是往 iq 里注入 12 Hz 分量。
注意它的绝对量只有 0.02 A，远小于前馈的 0.5 A 峰峰：说明遥测的 iq 是**滤波后**的
（低通把 12 Hz 衰减了约 20 倍），所以 iq 谱不能用来判断前馈幅值，只能看方向。

**前馈输出的直接证据**（`cog_probe.py`，连续读 `:` 的 `now=`）：

| 转速 | `now` 峰峰 | 表 pp | 门控系数 |
|---|---|---|---|
| 3 rpm | **0.295 A** | 1.03 A | 0.287（= 0.314/1.047）✓ |
| 100 rpm | **0.952 A** | 1.03 A | 1.00 ✓ |

3 rpm 的样本序列 `+0.04 +0.08 +0.08 +0.07 +0.04 −0.00 −0.03 −0.05 −0.06 …`
周期约 1 s，正是 1.2 Hz（3 rpm × 24 阶）—— 门控和查表都对。

### 10.5 修正后的结论

| 工作点 | 齿槽前馈 | 原因 |
|---|---|---|
| < 10 rpm | **无收益，主动衰减到 0** | 齿槽基频 1.2 Hz 远低于速度环带宽，PI 已经完整抑制；主导误差是黏滑而非齿槽。全量补反而激发抖动 |
| 30 rpm | **+15~18%** | 齿槽 12 Hz 已接近速度环带宽边缘，PI 跟不上，前馈补上 |
| 100 rpm | 无显著差异 | 齿槽 40 Hz 超出速度环带宽，但转子惯性同时也把它滤掉了；σ 由其他成分主导 |
| > 496 rpm | 关闭 | 前馈跟不上 + 惯性已滤掉 |

一句话：**齿槽前馈不是"低速万能补偿"，它只在速度环带宽边缘那一段（10~50 rpm）有效。**
低于那一段，速度环自己就能压住；高于那一段，惯性替它压住了。

### 10.7 构建脚本的坑

直接 `UV4 -r` 且 `TMP=/tmp`（Git Bash 路径）时，UV4 会刷一屏
`*** Error: Failed to create temporary file name'`、最后写 `Target not created`，
**却仍然返回 RC=0**。看着像成功，实际一个文件都没编译。
`build_x72.py` 把 `TMP/TEMP` 指到工程内 `.build_tmp`，并强制校验
`0 Error(s), 0 Warning(s)`、`compiling <file>.c` 是否出现在日志里（防旧 `.o` 混过去）。

### 10.8 仍然存在的局限

1. `now=` 在 `D`（MOE=0）之后会保留停机前的最后一个值 —— 那时电流环整段不跑，
   else 分支的清零也执行不到。只影响诊断，不影响控制。
2. 开关持久化的前提是表也有效：重做 `Z` 后零点变了 → `v=0` → 前馈自动停用
   （`en` 仍为 1，恢复零点后自己会回来）。
3. 谱分析用 100 Hz 遥测（实测 115 Hz 帧率），看 40 Hz（100 rpm）时每周期不到 3 点，
   幅值不可信，所以 100 rpm 只给了 σ 结论、没给谱结论。

## 11. 作用域收窄 + 一次把持久化 bug 挖到底（2026-11-18）

### 11.1 齿槽前馈限定到纯速度模式

原来 `CogFf_Get` 在 `Servo_SpeedLoopStep` 里无条件调用，而位置环也走这个函数 ——
位置环模式（`s_pos_en`）同样会补齿槽。

改成只有 `s_pos_en == 0` 才补：

```c
if (s_pos_en == 0U) {
    s_spd_cog = CogFf_Get(BspServo_GetThetaMulti(), s_spd_ref_ramp);
} else {
    s_spd_cog = 0.0f;
}
```

判据用 `s_pos_en` 而不是 `s_spd_en`：`Servo_SpeedLoopStep` 只被
`(s_spd_en || s_pos_en)` 调用，所以 `s_pos_en==0` 就等于"纯速度闭环"。

理由（实测支撑，见 MIT 文档 9.3）：位置环的外环是位置 P 环，齿槽在这里补一次、
位置环又把残余偏差当误差纠一次 = 双重补偿；而且前馈注入的扰动没有积分器兜住
（速度环的积分围绕"速度误差"，不是位置）。力矩模式更连速度反馈都没有。

**验证**：位置环保持时 `:` 的 `now=` 恒为 `0.000A`；切到速度 100 rpm 后
`now=` 在 ±0.35 A 之间随角度变化。✓

### 11.2 优化程度（持久化后的新表：pp=1.13 A，ph=145.05°）

交错 A/B，每档 3 轮（OFF/ON 交替，温漂平摊）：

| 转速 | OFF σ (rpm) | ON σ (rpm) | 改善（配对均值） | 各轮 |
|---:|---:|---:|---:|---|
| 3 | 0.396 ± 0.026 | 0.385 ± 0.066 | **+2.5%** | −12.8 / −0.6 / +21.0 |
| 30 | 2.893 ± 0.088 | 2.276 ± 0.087 | **+21.2%** | +16.7 / +26.4 / +20.6 |
| 100 | 6.080 ± 0.030 | 3.620 ± 0.108 | **+40.5%** | +40.6 / +38.9 / +41.9 |

**30 rpm 与 100 rpm 三轮全部同向，100 rpm 的 σ 从 6.08 降到 3.62。**
3 rpm 落在噪声内（黏滑段主导，与前一轮结论一致）。

对比**旧表**（pp=1.03 A，ph=82.71°）在同一台机器上的结果：

| 转速 | 旧表 | 新表 |
|---:|---:|---:|
| 3 | +8.3% | +2.5% |
| 30 | **−21.4%** | **+21.2%** |
| 100 | **−20.0%** | **+40.5%** |

**同一份固件、同一套门控，换一张表就从 −20% 变成 +40%。** 相位错了不只是"没效果"，
而是把扰动放大一倍 —— 这解释了为什么齿槽前馈在不同人手里评价差异巨大：
表的质量决定一切，代码只是执行者。

### 11.3 挖出的 bug：齿槽表持久化**从实现起就没工作过**

现象：`}` 标定完，`:` 显示新表；`A` 回显 `PS saved (...+cog)`；`!` 复位后
`: ` 又回到旧表（1.03 A / 82.71°）。

一度怀疑页地址、DBANK、写保护、CRC，都不是。根因在 `ParamStore_SaveCog`：

```c
/* 旧实现：用 LoadCog 做"内容没变就不写"的比较 */
if ((ParamStore_LoadCog(cur.cog, &cur_n, &cz, &cp, &cpp, &cur_en) != 0U) && ...
```

而 `ParamStore_LoadCog` 内部第一件事是：

```c
memcpy(&s_cbuf, src, sizeof(s_cbuf));   /* ← 把待写数据 s_cbuf 覆盖成 Flash 旧数据 */
```

`s_cbuf` 既是"待写入的暂存区"又是"读取用的对齐缓冲"。于是：

1. 先往 `s_cbuf` 填好新表；
2. 调 `LoadCog` 比较 → **`s_cbuf` 被换成 Flash 里的旧表**；
3. `memcmp(cur.cog, s_cbuf.cog)` 比的是"旧表 vs 旧表" → 永远相等；
4. `return 1`（回显成功），**一个字节都没写**。

`ParamStore_HasCog()` 的 CRC 校验也通过（Flash 里确实是合法的旧表），所以整条链路
看起来全部正常，只有"复位后表变了"这一个症状。**这个别名 bug 让齿槽表持久化从
实现起就没真正工作过**，之前几次"跨复位表还在"的验证，读到的都是那张旧表。

修法：直接读 Flash 指针比较，不再经过 `s_cbuf`：

```c
const CogBlob *fw = (const CogBlob *)COG_FLASH_ADDR;
if ((fw->magic == COG_MAGIC) && (fw->version == COG_VERSION) &&
    (cog_crc(fw) == fw->crc32) &&
    (fw->n_bins == n_bins) && (fw->en == s_cbuf.en) &&
    (fw->zero_ref == s_cbuf.zero_ref) &&
    (fw->phase == s_cbuf.phase) && (fw->pp == s_cbuf.pp) &&
    (memcmp(fw->cog, tab, n_bins * 2) == 0)) {
    return 1U;
}
```

顺手补上 `zero_ref / phase / pp` 三个字段的比较（原来只比 `n_bins / en / cog[]`）——
相位变了必须重写，否则就是"表更新了但相位还是旧的"，等于把扰动放大一倍。

**验证**：`A` 回显带 Flash 回读 `fb=1.13A/145.05deg`，与内存一致；`!` 复位后
`: ` 仍是 `1.13A/145.05deg`。✓

### 11.4 另外两个小 bug（都是这一轮引入或发现的）

| 现象 | 原因 | 处理 |
|---|---|---|
| `A` 完全无回显（板子还活着） | 回读诊断用 `int16_t tb[4]` 接 `LoadCog`，而它会拷 `n_bins×2 = 256` 字节 → **栈溢出** | 传 `NULL`（`LoadCog` 内部有 `if (tab)` 判断） |
| `P` 回显 `tgt=nan p_ref=nan` | 新增的 `put_f6()`（6 位小数）恒输出 `nan`，缺陷未定位 | **删除** `put_f6`，回退 `put_f4`（0.1 mrad）。位置精度测试的基准因此有 ±50 µrad 不确定度，重复性（30 µrad）不受影响 |
| `fb=` 的相位标 `deg` 但值是弧度 | 打印时没换算 | 乘 57.29578 |

### 11.5 当前状态与使用建议

- 齿槽表：`pp=1.13 A，ph=145.05°，n=128，en=1，v=1`，**已持久化**
- 作用域：只在纯速度模式（`s_spd_en` 独占）生效，位置环 / MIT / 力矩模式自动为 0
- 有效区间：10–191 rpm 全量（`COG_FF_W_FULL`），191–496 线性退出，>496 关闭
- **3 rpm 以下不要开**：黏滑段全量补反而恶化（实测 −21% 那轮就是相位错时的 3 rpm）
- 换减速器、拆装编码器、重做 `Z` 之后必须**重新标定**（`}` 约 15 s），
  否则相位错位会把扰动放大而不是抵消

## 12. 作用域定稿：不按模式判断，只按速度门控（2026-11-18）

第 11.1 节曾把齿槽前馈收窄成"只有 `s_pos_en == 0`（纯速度模式）才补"。
**这是一次过度收窄，已回退。** 正确的边界不在"模式"，在"速度"。

### 12.1 位置环的两种工况，需求相反

`CogFf_Get(theta, w_ramp)` 内部的门控是 `|w_ramp|` 的函数：
`w=0 → g=0`；10–191 rpm 全量；两端线性退出。而 `w_ramp` 就是速度环的斜坡后给定。

| 工况 | `w_ramp` | `g` | 该不该补 | 原因 |
|---|---:|---:|---|---|
| 位置环静止保持 | 0 | 0 | **不该** | 齿槽在该角度是**常值**力矩，速度环 PI 的积分会吃掉它 |
| 位置环定位运动 | 峰值 17 rad/s ≈162 rpm | 1.0 | **该** | 齿槽变成**周期扰动**，积分跟不上 |

静止"不该补"有硬数据：位置保持误差实测峰峰 **222 µrad**；而齿槽峰峰 1.13 A × Kt 0.091
= 0.103 N·m，若积分不兜，kp=25 下位置误差应是 `0.103/25 = 4.1 mrad`。
实测比它小 18 倍 → **积分确实在兜**。此时强补反而有害（MIT 那轮的 7.2 → 14.2 mrad，
就是因为绕过门控强传 `COG_FF_W_FULL`，让零速也补）。

### 12.2 为什么运动段不需要单独验证

位置环的 `v_cmd` 直接喂 `Servo_SpeedLoopStep` —— 与纯速度模式**同一个函数、
同一个门控、同一张表**。外环从"速度给定"换成"位置 P 环"，不改变内环的
扰动抑制能力。所以第 11.2 节测到的 30 rpm +21.2% / 100 rpm +40.5%
对位置环的运动段**直接适用**。

### 12.3 最终形态

```c
/* 不按模式判断：静止时 w=0 → g=0 自动不补，运动时按速度门控补 */
s_spd_cog = CogFf_Get(BspServo_GetThetaMulti(), s_spd_ref_ramp);
```

**实测确认**（位置环从 3.52 rad 定位到 9.52 rad，快速采样 `now=`）：

```
静止保持   now = 0.001 A
运动中     now = +0.026 / +0.330 / -0.185 A   ← 随角度变化
到位后     now = 0.000 A
```

模式层面的结论（用户要求"其他模式关闭"仍然满足）：

| 模式 | 走 `Servo_SpeedLoopStep`？ | 齿槽 |
|---|---|---|
| 纯速度（`=`/`Y`/`O`） | 是 | 按速度门控补 |
| 位置环（`P`） | 是 | 按速度门控补（静止自动 0） |
| MIT | 否（跳过速度环） | **不补**（9.3 节实测加了自己更差） |
| 力矩（`>`/`M`/`N`） | 否 | **不补**（无速度反馈，补了是开环注入） |
