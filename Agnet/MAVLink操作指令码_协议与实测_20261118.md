# MAVLink 操作指令码：协议实现与实测（2026-11-18）

## 一、结论先行

**工程首次打通 MAVLink 操作指令闭环**：上位机发 MAVLink v2 帧 → 固件流式收帧 + X25 CRC 校验 → database 门卫（权限/状态/范围）→ set_app_* 操作 → 回读真实值 → 同 msgid 应答回发。

- 首期实现 **5 条操作消息**（30000/30054/30056/30068/30069），其余 86 条按"未实现静默丢弃"。
- 联调 6 项全部通过，CRC **0 错误**，非法模式被正确拒写，使能走完整联锁。
- 编译 **0 Error / 0 Warning**，烧录 **Verify OK**，实测结束 `moe=0 f=0x00`（安全封锁）。
- 这是从原 NO-GO 状态迈出的第一步：MAVLink 通道**操作类**消息可用，遥测仍由 `telemetry_tx.c` 发（未迁到 communication/ 层）。

## 二、与既有体系的关系

| 项 | 说明 |
|---|---|
| 物理通道 | USART1 @921600，与 ASCII 命令、100 Hz 遥测**共用**。0xFD 帧头区分 MAVLink，0x02/0x04 是 MIT/位置补偿帧，其余是 ASCII 单字符 |
| 协议口径 | MAVLink v2；CRC X25 覆盖 `buf[1..9+len-1]`（含 SEQ，**不含 0xFD 魔数**）+ crc_extra，与 `host/mavlink_proto.py`、`telemetry_tx.c` 完全一致 |
| 分层 | 严格遵循《固件协议层_职责与编写指南》：协议层不直改应用变量，一律经 `app_param`（database）+ `servo_cmd` 受控入口（复用 E/D/X 联锁） |
| 未做的 | 91 条全量字段、CANopen/EtherCAT、FlashDB（参数仍用现有 `param_store`）、独立 communication/ 与 database/ 目录（本轮放在 Board/ 扁平工程，避免大改工程结构） |

## 三、指令码表（首期 5 条）

帧格式：`0xFD | LEN | INCOMPAT | COMPAT | SEQ | SYSID | COMPID | MSGID[3,LE] | PAYLOAD | CRC16[2,LE]`

| msgid | 名称 | 方向 | Payload | 功能 | 应答 |
|---|---|---|---|---|---|
| **30000** | READ_PARAM | 主机→设备 | uint32 struct_id | 读结构体 | 用 struct_id 作 msgid 回发 |
| **30054** | AppControlWord | 双向 | uint16 Controlword + uint8 Halt | bit0=使能/封锁；Halt=立即封锁 | 回显同 msgid：[状态, cw回读低字节] |
| **30056** | AppOpMode | 双向 | int8 Modes | 1=位置 / 3=速度 / 4=力矩 | [状态, 回读mode] |
| **30068** | AppPermissionConfig | 双向 | uint8 comm_auth + uint8 internal_auth | 权限总闸（comm=0=上位机接管） | [状态, comm, internal] |
| **30069** | SystemCmd | 主机→设备 | uint8 Sys_cmd | 0=空 /1=存参数 /2=软复位 /3=清故障 | [状态, cmd] |

**状态字节**（应答 payload[0]）：0=SUCCESS / 1=READ_ONLY / 2=OUT_OF_RANGE / 3=WRITE_STATE_ERROR / 4=NO_AUTHORITY。

**关键约定**：
- **无独立 ACK**：写操作回显同 msgid 作为应答（对齐 `mavlink_proto.py` 的 write_mechanism）。
- **回读真实值**：应答里的模式/控制字/权限是 `get_app_*` 从固件状态读回的，写入被拒时不会误报成功。
- **命令层回显仍在**：MAVLink 使能会同时触发 ASCII 行 `[CMD] ON ...`，属预期（两条路径共用联锁）。
- **30000 首期只支持** struct_id = 30055（AppStatusInfo，46B，填了 statusword/error_word/vbus/mode）、30054/30056/30068；其余 struct_id 不回帧并计 unknown。

## 四、门卫规则（database 层）

| 规则 | 实现位置 | 行为 |
|---|---|---|
| 权限总闸 | `app_param.c` `has_host_auth()` | comm_auth≠0 时所有 set 返回 NO_AUTHORITY |
| 使能联锁 | `app_param.c`→`ServoCmd_Arm()` | 复用 E 命令：故障/电流未标定/零点未对齐均拒，返回 WRITE_STATE_ERROR |
| 模式范围 | `AppParam_SetOpMode()` | 仅 1/3/4 合法，其余 OUT_OF_RANGE |
| 系统命令状态 | `AppParam_ExecSysCmd()` | 存参数要求先封锁；清故障要求先 D；复位在应答发出后延迟执行 |
| 存参数首期限制 | 同上 | `ParamStore_Save` 需完整 ParamBlob（由 C/Z/@/$/+ 逐步填充），首期实现为"Flash 已有有效 blob 则幂等成功"，不真正写 Flash，避免写半套参数 |

## 五、代码结构（新增 4 个文件 + 改 5 个文件）

**新增（Board/ 扁平工程，已加入 MDK 的 Application/User/Servo 组）**：

| 文件 | 职责 |
|---|---|
| `mavlink_common.c/.h` | X25 CRC + 组帧 + 首期 9 条消息元数据表（len/crc_extra），收发共用一份口径 |
| `app_param.c/.h` | database 门卫：权限/状态/范围检查 + set/get_app_*，上位机改状态的唯一通道 |
| `mavlink_host.c/.h` | 帧流式接收（0xFD）+ CRC 校验 + 5 条指令分发 + 应答队列 + 失败重同步 |

**修改**：
- `servo_cmd.c/.h`：`ServoCmd_Poll` 字节循环加 MAVLink 帧消费（返回 1 的字节从 ASCII/MIT/POSF 分派中排除）；暴露 `ServoCmd_Arm/Disarm/ClearFault` 受控入口
- `uart_link.c/.h`：新增 `UartLink_TrySendBinary()`（含 0x00 的二进制帧发送，复用遥测暂停/防抢线）
- `servo_isr.c`：`Servo_Init` 调 `AppParam_Init()` + `MavHost_Init()`
- `Core/Src/main.c`：主循环 `ServoCmd_Poll()` 后调 `MavHost_Task()`
- `MDK-ARM/X72_FOC.uvprojx`：Servo 组新增 3 个 .c

**数据流**：
```
USART1 RXNE → ServoCmd_Feed 队列 → ServoCmd_Poll 字节循环
  ├─ 0xFD/收帧中 → MavHost_FeedByte → 完整帧 pending
  ├─ 0x02 MIT / 0x04 POSF → 各自帧状态机
  └─ 其余 → handle() ASCII 命令
主循环 → MavHost_Task → dispatch → app_param(set/get) → ServoCmd_Arm/Disarm
  → ack_prepare → UartLink_TrySendBinary（暂停遥测 DMA，逐字节 TDR）
```

## 七、明确局限与下一步

1. **只做了操作类 5 条**，遥测反馈类（30055/30061）仅支持 30000 读到 30055 的简版字段，30061 AppMotionInfo 未填全。
2. **存参数（Sys_cmd=1）首期为幂等确认**，未真正打包写 Flash——需补 "从当前 Servo 状态生成 ParamBlob" 的打包函数。
3. **模式值仅记录未装配**：30056 设 3/4 后，实际运行模式仍需 ASCII 命令（W/M）或后续 Phase 在使能时按 mode 自动装配 `Servo_SetSpeedMode/CurrentMode`。
4. **文件放 Board/ 而非 communication//database/ 目录**：本轮为最小改动，遵循扁平工程惯例；若按指南第 5 节建正式目录，需大改 uvprojx，可后续重构。
5. **软复位（Sys_cmd=2）** 在应答发出后经 `NVIC_SystemReset()` 执行，本轮未实测（避免打断会话）。
6. `MavHost_Task` 中 UART 忙时 `s_tx_drop` 计数语义是"延迟重试次数"而非丢帧，命名可后续优化。

下一步建议按优先级：① 补模式装配（使能时按 op_mode 选环）→ ② 补 30061 全字段回读 → ③ 补 ParamBlob 打包实现真正的存参数 → ④ 视需要迁到正式 communication/database 目录。
