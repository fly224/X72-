# MIT 模式（阻抗控制）：实现与实测

> 2026-11-17 22:41–23:05。固件 `Code=98684`（+2500 B），已烧 22:48。

---

## 1. 为什么单独做一个模式

MIT 模式（Mini Cheetah 那一套）的语义是：**上位机给刚度 kp、阻尼 kd，
让外部负载决定位置**。控制器只做

```
τ = kp·(p_des − p) + kd·(v_des − v) + τ_ff
```

然后 `iq = τ / Kt` 交给电流环。被推走是**正常现象**，不是故障。

这跟现有的层级控制有本质区别：位置环会把"被推走"当成误差去积分、拼命顶回来，
结果外部一碰就对抗。所以它不能拼在位置/速度环上，必须是独立模式。

## 2. 实现

### 2.1 控制侧（`servo_isr.c`）

放在 `s_cur_en` 分支里、**速度环之前**（两者互斥，MIT 优先）：

```c
const float ds   = (float)s_dir_sign;
const float ep   = ds * (s_mit_p - theta_multi);      // 多圈角，跨圈不突跳
const float epc  = clamp(ep, ±SERVO_MIT_EP_MAX);      // ±1.0 rad
const float vdes = ds * s_mit_v;
float tau = s_mit_kp*epc + s_mit_kd*(vdes - om) + s_mit_tau;
tau = clamp(tau, ±SERVO_MIT_TAU_MAX);                 // ±1.5 N·m

iq_ref = tau / SERVO_KT_NM_PER_A;                     // Kt = 0.0910
iq_ref = clamp(iq_ref, ±s_cur_iq_max);                // ±5 A
```

四层限幅是刻意的，每一层挡不同的东西：

| 层 | 值 | 挡什么 |
|---|---|---|
| 位置误差 | ±1.0 rad | kp 可能给到上千，p_des 打错一位就是满力矩冲出去 |
| 力矩 | ±1.5 N·m | 上层给的 τ_ff 不合理时 |
| iq | ±5 A | 1.5 N·m 相当于 16 A，硬件只允许 5 A |
| 超速 | 1.5·\|v_des\| + 10 rad/s | MIT 要按给定速度跑，不能用固定的 300 rpm 门限 |

另外：`Servo_SetCurrentMode(0)` 会连带清 MIT 标志 —— 否则下次使能会带着
上一帧的 p_des/kp 直接冲一下。

### 2.2 传输：为什么用二进制帧

两个硬约束把 ASCII 路堵死了：

1. **可打印字符全部用尽**（27 个字母 + 全部标点都被占了，见 `serve_cmd.c` 的命令表）；
2. 现有数值解析器一次只吃**一个**数，而 MIT 每帧要 5 个量，拆成 5 条命令会
   引入相位不一致（p_des 和 kp 不再属于同一时刻）。

所以走二进制帧，格式**照抄 MIT Mini Cheetah**：

```
帧 = 0x02 | 8 字节数据 | 1 字节校验和(数据字节算术和)

[0..1] 位置 16bit  [-12.5, 12.5] rad
[2..3] 速度 12bit  [-65, 65] rad/s      ([3] 高 4 位 = 速度低 4 位)
[3..4] kp   12bit  [0, 5000] N·m/rad    ([3] 低 4 位 = kp 高 4 位)
[5..6] kd   12bit  [0, 100] N·m·s/rad
[6..7] 力矩 12bit  [-18, 18] N·m
```

照抄位序的理由：**将来接 CAN 时，解包函数可以原样复用**，只是载体从串口
换成 FDCAN 的 8 字节 payload。

### 2.3 使能与失效

- 第一帧负责起环路：`SetCurrentMode(1)` → 写给定 → `SetMitEn(1)` → `PwmEnable(1)`，
  顺序是"**先给给定再使能**"，否则使能那一拍会用 0 或上一帧的值。
- 联锁：故障 / 未做 C / 未做 Z / 辨识中 → 拒绝，并记 `mb` 原因码。
- **每帧续 deadman**：上位机停发 2 s 自动封锁 —— 这正是 MIT 该有的失效行为。
- 坏帧（校验错）只记数，不改给定。

## 3. 实测

测试脚本 `mit_test.py`，200 Hz 发帧，`S` 行 20 Hz 采样：

| 项目 | 结果 |
|---|---|
| 使能（kp=0） | `p0 = 4.319 rad`，`T = 0.010 N·m` —— 不起力 ✓ |
| 位置保持（kp=8, kd=0.3, 1 s） | 漂移 **0.0050 rad** ✓ |
| 位置阶跃 +0.2 rad | 终点误差 **−0.006 rad**（−0.3°），**无振荡** ✓ |
| 力矩限幅 | 峰值 **0.460 N·m** = 5 A × 0.091 ✓（不是 8×0.2=1.6） |
| 坏校验帧 ×20 | 位置变化 **−0.001 rad**，全部拒绝 ✓ |
| 退出（D） | `moe=0 en=0`，MIT 标志清除 ✓ |

阶跃轨迹（20 Hz 采样，50 ms 一点）：

```
4.317 → 4.519 → 4.523 → 4.527 → 4.524 → 4.524 → 4.523 → 4.522 → 4.525 → 4.526
```

一步到位、轻微过冲 8 mrad 后收敛。因为 J 只有 5.47e-5 kg·m²，0.455 N·m
就是 8300 rad/s²，0.2 rad 只需几毫秒 —— 20 Hz 采样根本分辨不出上升沿。

稳态 0.006 rad 的偏差来自静摩擦：`0.05 N·m / kp 8 = 6 mrad`，与实测吻合。
**这正是 MIT 的固有特性**（靠刚度换位置精度），要更准就加大 kp。

## 4. 过程中踩到的三个坑

### 坑 1：静态变量声明在使用点之后（编译期）

`do_status`（约 725 行）要读 `s_mit_bad`，而我把 MIT 的静态量写在文件末尾
（2500 行附近）—— C 语言必须先声明后使用，直接 9 个 error。

### 坑 2：帧超时 10 ms 太短

最初设 10 ms。逐字节慢发（3 ms/字节 × 10 = 27 ms）会被判超时，半帧被丢弃，
**剩下的字节流进单字符解析器** —— 症状很怪：`g=1.00/1.50`，因为帧里的
`0x48` 恰好是字符 `'H'`（Ki 档位循环键）。改成 50 ms。

### 坑 3：USART1 中断优先级 8，突发帧整段溢出（最关键）

现象：整帧一次性 write 出去，固件只收到半帧；逐字节慢发就正常。`ue`
（ORE 计数）随每次突发增长。

根因：`usart.c` 里 `HAL_NVIC_SetPriority(USART1_IRQn, 8, 0)` —— 最低优先级。
而 ADC 注入完成中断是 **0**、1 ms 任务是 1~5。控制中断一次执行几十微秒，
这期间到达的字节全部溢出（USART 只有 1 字节接收寄存器）。

修法：

| 文件 | 改动 |
|---|---|
| `usart.c` | USART1 优先级 **8 → 0** |
| `adc.c` | ADC1_2 优先级 **0 → 1**（同级不能互相抢占，必须让串口更高） |

代价：串口中断会抢占 20 kHz 控制环。但接收中断只做"读 RDR + 入队"，
约 0.2 µs（0.4% 周期），可以接受。

改完突发 5 帧全部接收，完整测试跑通。

## 5. 已知限制

1. **偶发丢帧约 1.5%**（`mb` 计数）。帧长固定 + 校验和能挡住坏帧，但丢字节后
   要等到下一个 0x02 才重新同步。彻底解决要上 **USART RX DMA 环形缓冲**，
   把接收从"每字节中断"变成"主循环读指针"。
2. **帧率上限**：当前靠 ASCII 通道（921600），10 字节 = 0.11 ms，理论上限
   很高，但实测每帧之间至少要留 ~100 µs 才稳定 → 约 **1 kHz 封顶**。
   真正的 MIT 用法（500 Hz~1 kHz）刚好够，但余量不大。
3. **没有位置/速度的线性插值**：MIT 典型实现会按收到两帧之间的时间插值，
   本实现是零阶保持（用最近一帧）。20 kHz 控制拍下，1 kHz 帧率意味着
   每 20 拍更新一次给定，阶跃型指令会有 1 ms 的台阶。
4. **kp/kd 没有抗饱和积分**：MIT 本身无积分项，稳态误差是设计的一部分，
   靠 kp 换精度。

## 8. 跑电机：从"能动"到"能动得对"（23:10–23:45）

第一次用 `--kp 10 --kd 0.5` 跑 ±1 rad / 0.5 Hz 的正弦：行程对了，但 `|iq|` 峰值
**5.5 A**（顶着限幅），收尾 `T=-0.46` 卡在限幅，保持时电机在"嗡嗡"。

顺着查下去，发现两个真问题。

### 8.1 保持时的极限环：D 项把相位滞后变成了负阻尼

用 20 kHz 片内录制看保持时的 iq 频谱：

| 配置 | iq sd | 主峰 |
|---|---:|---|
| kp=0, kd=0 | 0.12 A | 859 Hz（已知外部扰动） |
| kp=10, kd=0 | 0.11 A | 850 Hz |
| **kp=0, kd=0.5**（纯阻尼） | **4.37 A** | **244 Hz / 5.0 A** |
| kp=10, kd=0.5 | 4.32 A | 254 Hz / 4.2 A |

**纯阻尼、没有弹簧，照样振荡** —— 说明问题在 D 项本身，不在 P。

先怀疑测速：控制环用的 `om` 是"8 拍累计 + 95 Hz 低通"，群延迟约 1.9 ms，
在 244 Hz 处是 167° 相移，阻尼直接变负。换成单拍速度（`GetOmegaFast`）后
频率升到 742 Hz，仍然 4 A —— 因为编码器 SPI 是异步更新，单拍差分被 0/2v
的隔拍跳动污染。再换成 2 拍差分（跨过一个完整的隔拍周期，窗口 100 µs），
还是 ~700 Hz。

**继续算才发现根子在别处**：阻尼环的穿越频率是 `kd/J`。
`kd=0.5 / J=5.47e-5 = 9141 rad/s = 1455 Hz` —— **远高于电流环 1 kHz 带宽**。
D 环在电流环已经跟不上的频率上要求力矩，相位一超 90° 就变成负阻尼，
振荡频率落在 700 Hz 附近（相位到 180° 的点）。

**扫一遍小 kd 验证**（kp=10，保持不动）：

| kd | iq sd | 主峰幅值 | D 环穿越 |
|---:|---:|---:|---:|
| 0.005 | 0.113 A | 0.055 A | 15 Hz |
| 0.02 | 0.091 A | 0.063 A | 58 Hz |
| **0.05** | **0.084 A** | 0.033 A | 145 Hz |
| 0.10 | 0.102 A | 0.058 A | 291 Hz |
| 0.20 | 0.116 A | 0.037 A | 582 Hz |
| 0.50 | **4.32 A** | 4.2 A | 1455 Hz ← 极限环 |

**结论：kd ≤ 0.2 稳定，0.5 起必振。** 判据是 `kd/(2πJ) ≪ 电流环带宽`，
按这台机器（J=5.47e-5、电流环 1 kHz）就是 `kd/(2π·5.47e-5) < 300 Hz` → kd < 0.1 左右。
之前文档里 kd=0.5~3.0 的默认值**高了 5~60 倍**，已把 `mit_test.py` 默认值改成 0.05。

### 8.2 上位机停发时，最后一帧的 v_des 会继续推电机

收尾只发一帧保持帧时，`S` 读到 `T=-0.46`（顶着限幅）。原因是那帧丢了或还没到，
`v_des` 停在 3.14 rad/s，kd 项一直执行。deadman 是 2 s，对这种模式太慢。

固件里加了 **20 ms 命令超时**（`Servo_MitTask1ms`）：超时就冻结 `v_des` 与 `τ_ff`，
只保留位置刚度 —— 等效于"松手后停在原地"，这正是 MIT 该有的行为。
加完之后收尾 `T=0.00`。

### 8.3 测量上的修正：误差要按位置帧自己的时间戳算

第一版用"当前时刻的 p_des"减"5 ms 前采到的位置"，凭空多出 16 mrad 假误差
（峰值速度 3.14 rad/s × 5 ms）。改成记录每个位置帧的到达时刻、按该时刻
解析地算 p_des，误差从 32 mrad 降到 25 mrad —— 这 7 mrad 就是测量假象。

### 8.4 修正后的实测（±1 rad 正弦，500 Hz 发帧）

| 频率 | 幅值 | RMS 误差 | 中位误差 | 行程 | \|iq\|峰值 |
|---|---:|---:|---:|---:|---:|
| 0.5 Hz | 1.0 rad | **0.016 rad（0.9°）** | 0.012 | 2.006 rad | **1.00 A** |
| 1.0 Hz | 0.8 rad | 0.030 rad | 0.023 | 1.598 rad | 1.32 A |
| 2.0 Hz | 0.8 rad | 0.054 rad | 0.043 | 1.599 rad | 3.00 A |

对比修正前（kp=10 / kd=0.5）：误差 25 mrad、**峰值 5.5 A**、保持时 4 A 嗡振。
现在误差 16 mrad、**峰值 1.0 A**、保持时 iq sd 0.084 A —— 抖动消失，
同样轨迹用的电流降到 1/5。

**误差随频率上升的部分主要是命令传输延迟**，不是控制带宽：2 Hz 时峰值速度
10 rad/s，5 ms 的端到端延迟（500 Hz 帧 + 串口 + 遥测时间戳）就对应 50 mrad，
与实测 54 mrad 吻合。换成 CAN @1 kHz 后这部分会降到 ~10 mrad 量级。

### 8.5 实测到的稳定边界（供现场参考）

| 量 | 实测稳定范围 | 依据 |
|---|---|---|
| kp | 0–120 都稳（误差在 0.015–0.019 rad 见底，被摩擦占住） | kp=120 时 `|iq|` 峰值 1.45 A |
| kd | **≤0.2**，0.5 起极限环 | 见 8.1 表 |
| 位置误差限幅 | 1.0 rad | 满误差时 iq 顶 5 A |
| 命令超时 | 20 ms | 超过即冻结 v_des |

## 9. 优化（2026-11-18）：给定外推、超速门限、以及一项被实测否掉的改动

### 9.1 给定外推（一阶保持）—— 跟踪误差 −41%

**问题**：MIT 帧率约 1 kHz，而控制在 20 kHz 跑。帧之间 `p_des` 是常数
（零阶保持），等于目标"每 1 ms 跳一步"。轨迹跟踪时这个台阶就是**纯滞后**。

先量化：2 Hz、±1.0 rad 的轨迹，峰值速度 10 rad/s。实测 RMS 误差 60–74 mrad，
而 5 ms（帧间隔 + 串口 + 遥测时间戳）乘 10 rad/s = **50 mrad** —— 误差的主体就是延迟。

**做法**：帧里本来就有 `v_des`，直接在帧间隔内线性外推

```
p_des(t) = p_frame + v_des·(t − t_frame)
```

不需要额外传感器，也不放大噪声（`v_des` 是上位机给的期望速度，不是差分出来的）。

帧龄从 **20 kHz 计数**取，不用 ms 计数 —— 1 kHz 帧间隔本身就是 1 ms，1 ms 分辨率
根本分辨不出帧龄：

```c
const uint32_t age = s_mit_tick - s_mit_stamp;   /* uint32 无符号减法，回绕安全 */
float dt = (float)age * BSP_TS_CURRENT;
if (dt > 0.1f) dt = 0.1f;
ep = ds * ((s_mit_p + s_mit_v * dt) - theta_multi);
```

**超时边界必须处理**：`Servo_MitTask1ms` 里超时清 `v_des` 时，先把已经外推出去的
位移**固化**进 `s_mit_p`：

```c
if (s_mit_v != 0.0f) { s_mit_p += s_mit_v * 20ms; s_mit_v = 0.0f; }
```

不固化的话，目标会从"外推到的地方"退回"帧里的位置"，1 kHz 下约 0.2 rad 的倒退，
对 kp=25 就是 5 N·m 的反向指令，直接顶到限幅 —— 每次停发都反向敲一下。

**A/B 实测**（同一轨迹 2 Hz/±1.0 rad，kp=30 kd=0.1，各 2 次）：

| | RMS 误差 | 中位误差 |
|---|---:|---:|
| 零阶保持（外推关） | 0.0605 / 0.0744 | 0.0497 / 0.0674 |
| **一阶外推（开）** | **0.0377 / 0.0412** | **0.0239 / 0.0263** |
| 改善 | **−41%** | **−57%** |

编译期开关 `SERVO_MIT_EXTRAP_EN`（默认 1），置 0 重烧即可复现 A/B ——
可打印字符已全部占满，不为了一个对比开关去污染运行时接口。

诊断：`S` 行在 MIT 生效时追加 `dt=<ms>`，正常 1 kHz 帧率下应稳定在 0.1–1.0 ms，
接近 20 ms 表示帧掉了或正在超时冻结。

### 9.2 超速门限：MIT 阶跃会被误判成失控

原门限 `1.5·|v_des| + 10 rad/s`。保持时 `v_des=0`，门限只有 10 rad/s。

但 MIT 的力矩是 `kp·e`：位置阶跃 0.083 rad、kp=25 → τ 顶到限幅 1.5 N·m →
对 J=5.47e-5 是 27400 rad/s²，**0.1 s 内就超过 10 rad/s**，`f=0x20` 封锁。

现象极具误导性：改一次目标就跳闸，看着像"MIT 不能用于定位"。

改成 MIT 独立门限 **30 rad/s（≈286 rpm）**：

```c
((s_mit_en != 0U) ? (1.5f * fabsf(s_mit_v) + SERVO_MIT_WMAX) : SERVO_CUR_WMAX)
```

关节类应用 30 rad/s 是合理上限：正常 MIT 运动够用，真失控（编码器断线、dir 判错）
仍会撞线。

### 9.3 齿槽前馈：加了，实测更差，撤回

理由本来很顺：齿槽是**位置的函数**，零速保持时同样存在，表现就是"停不准"。
而且 `CogFf_Get` 的门控给零速 0（为速度环的 3 rpm 黏滑段设计的），所以强制传
`COG_FF_W_FULL` 拿全量。

**A/B 实测（kp=10/kd=0.1，扫 0.8 rad 保持，17 点）：**

| | 峰峰 | σ |
|---|---:|---:|
| 齿槽 OFF | **7.2 mrad** | 2.1 mrad |
| 齿槽 ON | **14.2 mrad** | 4.2 mrad |

**差一倍，反而更差。**

原因：速度环里齿槽前馈加在 PI 输出上，误差由积分吸收；MIT 是纯 PD，
前馈直接进力矩，表的误差（空载标的、128 点插值、1.03 A 峰峰）没人兜，
等于往环路里注入一个位置相关的扰动，与 kp 的位置刚度对着干。

**结论：MIT 不加齿槽前馈。** 代码里已删，注释保留原因。

### 9.4 保持精度：由 kp 决定，这是物理约束

扫 0.8 rad、17 个保持点，看"相对误差"的峰峰（齿槽周期 0.2618 rad，跨度约 3 个周期）：

| kp | kd | 相对误差峰峰 |
|---:|---:|---:|
| 3 | 0.05 | **32 mrad（1.84°）** |
| 10 | 0.1 | **7.2 – 10.9 mrad（0.41–0.62°）** |

kp=3 时 `kp·e = 0.096 N·m` 正好是摩擦/齿槽量级，所以误差卡在 30 mrad。

这就是 MIT 的固有特性：**刚度换精度**。想更准只能加 kp，而 kp 又受两个上限约束：

1. **kd 上限 0.34**（`kd/J < 2π·1 kHz` 电流环带宽）。kp 单独加大会让 ζ 降低，
   欠阻尼振荡。
2. **超速门限 30 rad/s**：kp 越大阶跃越快，越容易撞门限。

要突破这两条只有提高电流环带宽，那是硬件/参数层面的事（L 已确定，采样率 20 kHz）。
