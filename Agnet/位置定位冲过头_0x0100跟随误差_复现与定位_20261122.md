`telemetry_tx.c:398` 把 `Servo_GetSpeedRampRef()` 乘 60/2π 输出。
所以实测 `wref=92` 是 **92 rpm = 9.6 rad/s**，远低于 v_max=25。
（我一度误判为 92 rad/s，已纠正。）

## 3. 定位到的机制

`Servo_SetPosMode` 起环时：

```c
const float old_base = pos_coord_align();      // base = theta_multi − theta_single
const float dbase    = s_pos_base - old_base;
p_target_rad -= dbase;                          // 旧坐标 → 新坐标
PosLoop_Enable(ds * pos_coord_now());
```

其中 `p_pos = theta_multi − base`，而 `base = theta_multi − theta_single`
→ **`p_pos` 应当恒等于单圈角（0~2π）**。

**但实测 `p_now` 出现过 25.6753（超过 4 圈）**——这说明 `pos_coord_align()` 在那一次**没有让 p_pos 落回 0~2π**，即 `base` 算得不对（`m − s ≈ 0`）。

若 `m − s ≈ 0`，则 `base ≈ 0` → `p_pos ≈ theta_multi`（累积多圈），正是 25.675 的来源。

**待查（下一步）**：`bsp_servo.c` 里 `s_theta`（`GetThetaCached` 的返回）与 `s_theta_multi` 是否**同拍、同源**更新。若 `s_theta` 在某条路径上返回的是累积值而非折叠值，`m − s` 就会退化为 0。

---

## 4. 试过但**已回退**的改法（重要，别重犯）

我曾删除 `p_target_rad -= dbase`，理由是"p_pos 恒等于单圈角，新旧坐标相同、不需要平移"。

**结果更糟**：

```
转 12 圈后进位置模式: p_now=25.6753  p_tgt=100.0960
→ 目标与当前位置差 74.4 rad
→ 因为行程长、v_max 限幅使 e 不超 6，**不报故障**，电机会无声地自己走 74 rad
```

**"无声走 74 rad"比"报故障"危险得多**，所以已回退。

> 结论：`dbase` 平移**是必要的**；bug 在 `dbase` 的取值（`m − s` 不可靠），
> 不在"要不要平移"。

## 5. 当前可用状态与规避

回退后实测（Code=106732）：

```
转 10+ 圈 → 切位置模式: p_now=0.3012  st=DONE  err=+0.00134
+0.3 定位: 误差 −0.42 mrad
```

**工作正常——前提是 `p_now` 落在 0~2π。**

### 上位机必须遵守

1. **位置定位用"当前 p_now + 增量"**，不要填绝对 0.0000
   - 0.0000 的含义是"单圈角 0 点"，不是机械零点
2. **切换位置模式后先读一次 30100 的 `p_now`**
   - 若 `p_now` 明显 > 2π（如 25.6），说明本次对齐失效
   - **此时不要下发绝对目标**，改用相对增量（相对增量在同一坐标系内仍然自洽）
