当前工程状态：`.uvprojx` 只含 38 个 CubeMX 源文件，未包含 `three_loop_deploy.c`，IncludePath 也没有 `simulink_code_gen`；`main.c` 的 USER CODE 区为空，`while(1)` 空循环。

## 3. 必须裁定的衔接点

| 级别 | 问题 | 证据 | 处置 |
|---|---|---|---|
| **Critical** | **双电阻采样相序错配** | 网表：OPA1(PA2/ADC1_IN3) ← R4 → `U_GND`（**U 相**）；OPA2(PA6/ADC2_IN3) ← R3 → `W_GND`（**W 相**）；OPA3(PB1/ADC3_IN1) 无外部网络。模板按 A/B/C 三相读取，并注释「两路时 `ic = -ia - ib`」——该改法假定能采 U、V 两相，与硬件不符 | 生成代码只用 `ia`、`ib`。应填 `U.ia = Iu`；`U.ib = -(Iu + Iw)`（重构 V 相）；`U.ic` 可填 `Iw` 但代码不用。**禁止**把 OPA2(W 相)直接赋给 `U.ib`，否则 120° 相位错误、FOC 失效；同时 ISR 不要读 ADC3 |
| **Major** | ISR 归属 | `.ioc`：`NVIC.ADC1_2_IRQn=0`（最高）、`TIM1_UP_TIM16_IRQn=5`；ADC1/2/3 注入由 `TIM1_TRGO(OC4REF, Pulse=1)` 触发。模板建议在 TIM1 更新 ISR 调 `step()` | 注入转换完成前读 ADC 会取到旧值；中心对齐下 UIF 上溢/下溢各一次可能 40 kHz；TIM1_UP 与 TIM16 共享向量。应把 `step()` 放进 `ADC1_2_IRQHandler` / `HAL_ADCEx_InjectedConvCpltCallback`，TIM1_UP 不跑控制律 |
| **Major** | `PWM_ARR = 4249` 与工程不符 | `.ioc` `TIM1.PeriodNoDither=4250`；`tim.c` `htim1.Init.Period = 4250`、`sConfigOC.Pulse = 2125` | 模板改用 `main.h` 的 `TIM_1_8_PERIOD_CLOCKS`（4250）。中心对齐频率 = 170 MHz / (2×4250) = 20 kHz |
| **Major** | `double` 实时性 | `real_T = double`；3 处 `sin/cos/sqrt` 双精度走软件库；Cortex-M4F FPU 仅单精度 | 50 µs @170 MHz ≈ 8500 周期（半周期 4250 周期）。接好后必须用 `DWT->CYCCNT` 实测 `step()`，留 50% 余量；超限则模型全改 `single` 后重新 codegen（`sinf/cosf`） |
| **Major** | `VBUS_DIV = 1.0` 是错误值 | 网表：VM → R64(100 kΩ) → R63(100 kΩ) → 节点 `$1N185` → R65(1 kΩ) → GND，D12 钳位 3V3，R66(330 Ω) → `VBUS_ADC` → C2 | 分压比 = 1 k / (100 k + 100 k + 1 k) = **1/201 ≈ 4.975e-3**；48 V → 0.2388 V。模板置 1.0 会把 48 V 读成 0.239 V，SVPWM 电压前馈与限幅失效 |
| **Major** | 与 `AGENTS.md` 体系冲突 | AGENTS 规定 MATLAB **R2023a**、模型导出函数 `xxx_input/_config/_step/_output`、`kAxis` 结构体、参数必须走 database `set_app_*/get_app_*`；本套为 **R2023b** + ERT `ExtU/ExtY/step`，`pos_ref` 直接来自 `BSP_GetPosRefRad()` | 属「独立控制律内核」。直接接入可跑，但不符合量产四层架构；`pos_ref`/增益需经 database 路由，否则上位机与总线改参数失效 |
| **Minor** | 编码器在 ISR 内阻塞 SPI | 网表 MT6835(U2) 仅接 SPI_CS/MISO/MOSI/SCK 与 CAL_EN，ABZ/UVW 未引出；`.ioc` 已配 SPI1 DMA1_Ch1/Ch2 | 20 kHz ISR 内用 `HAL_SPI_TransmitReceive` 轮询违反 ISR 最小化。改为 DMA 异步预读 + 缓存，ISR 只读上次角度；另需编码器零点偏置标定、单圈跨圈计数、故障时拉低 `U.en` |

参数已内联固化在 C 中（极对数 14、电流限幅 9 A、速度限幅 120 rad/s、位置环 Kp 50.265、速度环 Ki 10.1907 / Kp 0.0729 等），**改参数必须改模型重新 codegen，禁止手改生成文件**（AGENTS.md 禁止事项 1）。但 README 指向的 `three_loop_params.m` 不在工作区，参数源头需先补齐。

## 4. 下一步操作序列

1. **确定路线**（唯一需要你拍板的决策）
   - **路线甲（建议先做）**：把 ERT 控制律直接接到当前纯净 CubeMX 工程，不引入四层架构，目标是先在实机上验证 20 kHz 电流环、DWT 周期数与双电阻采样相序。
   - **路线乙**：按 `AGENTS.md` / 参考工程规范，把三环拆成导出函数模块并接入 `kAxis` + database + CiA402/MAVLink，工作量大但符合量产架构。
   两条路线的差别只在「适配层」，控制律本身不变；建议先走甲拿实测证据，再决定是否转乙。

2. **加入 Keil 工程**：把 6 个生成文件（仅 `three_loop_deploy.c` 参与编译）加入 `X72_FOC.uvprojx`，IncludePath 增 `../../../simulink_code_gen`；排除 `sil_test.c`、`ert_main.c`，`integration_example.c` 只作模板。可用 `Agnet/prepare_mdk_project.py --verify` 的思路做幂等校验。

3. **把模板改造成 `servo_isr.c`**（放在 `USER CODE` 区或 `Board/`）：修 5 处硬编码 —— `PWM_ARR`→4250、`VBUS_DIV`→1/201、双电阻相序映射、去掉第三相 ADC 读取、编码器改 DMA 缓存 + 零点偏置。所有 `BSP_*` 占位函数按现有 HAL 实现。

4. **中断接线**：`stm32g4xx_it.c` 的 `ADC1_2_IRQHandler` → `HAL_ADC_IRQHandler` → `HAL_ADCEx_InjectedConvCpltCallback` 内调 `Servo_20kHz_ISR()`；`main.c` 的 `USER CODE BEGIN 2` 调 `Servo_Init()`；失能/过流/编码器异常时 `U.en=0` 并清 TIM1 BDTR 的 MOE 封锁 PWM。

5. **性能与时序实测**：开 `DWT->CYCCNT` 测 `step()` 周期数与 ISR 总时长；在线读 `Y.ticks[0:1:2]` 应为 20:2:1；确认 ADC 注入触发点（OC4REF = 1）避开开关噪声。超预算则改 `single` 重新 codegen。

6. **空载联调**：低压限流、不接电机，先 `en=0` 确认 `duty=0.5`；再依次开环 → 电流闭环 → 三环。`iq_ref` 在 SIL 中已达 9 A 限幅，实机需确认限流与实际电机额定一致。

7. **补齐参数与文档**：把 `three_loop_params.m`（或等价参数源头）放入工作区、核对 R2023a 与 R2023b 的生成规则差异、补 VBUS 分压与编码器零点标定记录；确认 `Kt=225.5 mN·m/A`、`p=14` 与 X72 实际电机一致。
