# 速度闭环 1–1000 rpm 全程实测

测量时间：2026-11-17 06:41
固件：`Code=91724 RO=6828 RW=148 ZI=15388`（0 Error / 0 Warning）
配置：增益调度 **ON**、齿槽前馈 **ON**（`en=1`，表 128 点，pp=1.03 A）、摩擦/加速度前馈 ON
母线：30.70–30.76 V（空载，带减速器）
数据：`sweep_1_1000.csv`（UTF-8 BOM）

---

## 1. 测量方法

| 项 | 做法 | 为什么 |
|---|---|---|
| 调速方式 | `=` 数值命令（逐字符发） | `Y`/`O` 只有 3/30/100/500/1500/3000 六个档位，做不出连续曲线 |
| 引导符时序 | `\r` → 等 50 ms → `=` → 等 60 ms → 逐字符 12 ms → `\r` | 引导符与数字同批到达时解析器偶发丢字节（历史 `_1` 命令就是这么坏的） |
| 回显校验 | 拿不到 `[CMD]` 回显就整条重发一次 | ASCII 回显是单槽（`s_out_pending`），碰上遥测 DMA 在飞会整行丢掉，不能把"没回显"当"已执行" |
| 每点时序 | 设定 → 稳定 **3 s** → 采集 **3 s** | 1.5 s 不够：从上一档切过来时低速黏滑要几秒才稳，早期 σ 会系统性偏高 |
| 统计窗口 | 取采集段后 50% 的帧 | 丢掉切换瞬态 |
| 遥测 | 30025 帧，实测帧率 115 Hz | 速度、iq 给定、母线、斜坡给定 |

**一个必须说明的限制**：帧率 115 Hz → Nyquist 58 Hz。24 阶齿槽在 150 rpm 就已经 60 Hz，
**中高速的齿槽分量全部混叠**，所以本报告不给齿槽相关的谱结论（谱分析只在 30 rpm 做过）。

## 3. 分析

### 3.1 稳态误差：全速段优秀，低速的百分比是假象

|误差| ≤ 0.21%（2 rpm 除外），1000 rpm 为 −0.02%…+0.14%（重复测量的两轮分别是 −0.02 与 +0.14）。
最大百分比出现在 **2 rpm：+4.03%**，但**绝对值只有 0.081 rpm**；1 rpm 的 +0.80% 绝对值是 0.008 rpm。
低速的百分比大完全是因为分母小，不代表控制差。积分 + 摩擦前馈已把静差压到编码器分辨率之下。

### 3.2 纹波 σ：三段，中间最差

| 段 | σ 绝对 | σ% | 主因 |
|---|---|---|---|
| 1–30 rpm | 0.41–4.54 | 11–41% | 黏滑（stick-slip）爬行 + 编码器量化。1 rpm 时一圈要 60 s，齿槽/摩擦拐点全暴露 |
| 50–400 rpm | 4.0–21.0 | 1.7–15% | **弱点区**。绝对值最大出现在 200–300 rpm（16–21 rpm） |
| 500–1000 rpm | 1.5–5.0 | 0.2–1.0% | 惯性把周期扰动滤掉了，速度环工作点也最好 |

**注意中速段的重复性问题**：同一 300 rpm 点
- 热切换（在环内直接改给定、**保留积分**）+ 稳定 3 s → σ = 16.0
- 冷启动（`D` 后重进环、**清积分**）+ 长驻留 → σ = 7.2（连续 6 个 3 s 窗口 7.19–7.53，非常稳）

同一转速差 2.2 倍，说明 100–300 rpm 段存在**与积分初值相关的非线性行为**（摩擦极限环）。
所以该段只能给"区间"（σ% ≈ 5–15%），不能拿单次值当定论。
高速段（≥500 rpm）两次一致（σ% 0.2–1.0），可信。

### 3.3 iq–转速关系：黏滞前馈小了一个数量级

线性拟合（20 点）：**iq = 0.1145 + 3.621e-4 · rpm** [A]
换算成角速度：**iq = 0.1145 + 3.46e-3 · ω** [A, ω in rad/s]

对照当前前馈配置：

| 项 | 配置值 | 实测需求 | 倍差 |
|---|---|---|---|
| 摩擦常数 `s_ff_fric` | 0.150 A | 0.1145 A（截距） | 1.3×（合理，`$` 标定值） |
| 黏滞 `s_ff_visc` | 2.14e-4 A/(rad/s) | 3.46e-3 A/(rad/s) | **小 16 倍** |

后果：1000 rpm 时前馈只给 0.022 A，实际需要 0.398 A，缺的 0.376 A 全靠积分补。
稳态看不出问题（积分收敛了，误差仍 ≤0.2%），但**动态会滞后**：加速时积分要重新爬，
这就是为什么 σ 在中速段偏大、且对积分初值敏感。

`$` 两点标定（3 rpm / 100 rpm）只给了两点，无法分离摩擦常数与黏滞——
3 rpm 时 iq≈0.086、100 rpm 时 iq≈0.173，斜率算出来是 (0.173-0.086)/(10.47-0.314) = 8.6e-3 A/(rad/s)，
都比 2.14e-4 大一个量级。当前值可能是早期手调的遗留。

**建议**：把 `s_ff_visc` 改到 3.4e-3 A/(rad/s)（即 `]` 命令输入 34），再复测中速段 σ。
但要先确认：前馈加了以后 iq 给定变小，速度环的等效增益会变，可能需要重调 Kp。

### 3.4 母线：全程无压力

30.70–30.76 V，1000 rpm 时 30.74 V。1000 rpm 的反电动势 ≈ 6.4 V 峰值（线电压 11 V），
远未触及 30.7 V 母线。按此前实测的 36.5 V/3000 rpm 折算，1000 rpm 只需约 12 V，
余量充足——**1–1000 rpm 全程不受电压限制**。

### 3.5 200–270 rpm 有一段高纹波带

单次扫描时 245–270 rpm 的 σ 冲到 16.7–27.3（6.8–10.5%），280 rpm 回落到 8.8，300 rpm 到 4.6。
长驻留复测 260 rpm 稳定在 16.9（6.5%），确认**不是瞬时现象**。
增益在 100–500 rpm 是同一组（kp=0.583 / kits=0.0408，插值为常数段），
所以不是调度切换引起的。具体机制未定位（需要 20 kHz 采样 + 更高的时间分辨率谱分析，
当前 115 Hz 遥测看不到 100 Hz 以上的成分）。

## 4. 本轮顺手修掉的问题

### 4.1 `!` 软复位会永久卡死主循环（已修）

```c
do_disable("reset");
while (s_out_pending != 0U) { ascii_pump(); }   /* 旧代码：无超时 */
```

`UartLink_TrySendAscii` 在 `huart1.gState != HAL_UART_STATE_READY`（遥测 DMA 在飞）时
直接返回 0，只让调用方下一轮再试。若一直碰上遥测占线，这个 while 就把主循环钉死。

**现象**：遥测照常在 TIM6 中断里发，但所有 ASCII 命令都没反应，连 `!` 也救不回来，
只能烧录复位。实测踩到过一次（06:32）。

**修复**：加 `guard < 200000` 上限。

### 4.2 ASCII 回显是单槽，丢了不报错

`s_out_pending` 只有一个槽。上一行没发完时新的 `emit` 会顶掉旧的，且没有任何提示。
表现是"命令偶发没回显"。测试脚本已改成"没回显就重发"，但固件侧值得加一个丢弃计数，
通过 `S` 输出，否则现场排查这类问题只能靠猜。

python sweep_1_1000.py COM27                        # 全程 20 点，约 2.5 min

长驻留看稳定性：
```bash
python -c "
import math
from cog_ff_test import Rig
from sweep_1_1000 import collect_rich, set_rpm
rig=Rig('COM27'); rig.cmd('D',0.3); print(set_rpm(rig,300)); rig.keep(2)
for k in range(6):
    fr=collect_rich(rig,3.0); v=[x[1] for x in fr]; m=sum(v)/len(v)
    print(k, round(m,2), round(math.sqrt(sum((x-m)**2 for x in v)/len(v)),3))
rig.cmd('D',0.3); rig.close()"
```
