## 1. 补的是什么，为什么

原来的速度控制只有一个 PI 环，**给定是阶跃的**。这导致两个结构性问题，都不是调参能解决的：

| 现象（实测） | 根因 | 调参能修吗 |
|---|---|---|
| 30 rpm 超调 31% | 进环那一拍 `kp·err` 就顶到 3 A 限幅，环实际工作在 bang-bang 区 | 不能。降增益只会让稳态纹波变大（1x 时 22.5 rpm） |
| 3000 rpm 指令下 iq 长时间压限幅 | 同上，且加速过程全靠饱和电流 | 不能 |
| 3 rpm 超调 68.8% | 库仑摩擦起跳（静摩擦约 0.028 N·m = 0.30 A） | 不能，需要摩擦补偿 |

所以补的是**给定侧**：把阶跃限速成斜坡，让 PI 工作在线性区。

```
用户给定 (rpm)
   ↓  =<rpm> 连续 / O 档位 / W·Q 正反转
[斜坡] 每 2 kHz 一拍，|Δw| ≤ accel·Ts      ← 本次新增
   ↓  w_ramp
[速度环 PI 2 kHz]  Kp·err + ∫Ki·err·Ts，iq 限幅可配   ← 限幅本次改为运行时可变
   ↓  iq_ref
[电流环 20 kHz]  解耦 + BEMF 前馈 + 圆限幅
```

## 2. 固件改动

### 2.1 给定斜坡（`servo_isr.c`）

```c
if (s_spd_ramp_init == 0U) { s_spd_ref_ramp = w_meas; s_spd_ramp_init = 1U; }
const float step = s_spd_acc * SERVO_SPD_TS;      // accel × 500us
const float dw   = w_ref - s_spd_ref_ramp;
if      (dw >  step) { s_spd_ref_ramp += step; }
else if (dw < -step) { s_spd_ref_ramp -= step; }
else                 { s_spd_ref_ramp  = w_ref; }
```

三个容易写错的点：

1. **首次进入必须从实测速度起步**，不是从 0。否则"加斜坡"只是把阶跃推迟一拍，等于没加。
2. **斜坡在模型坐标系里推进**（`dir` 已乘），换向时方向自动正确；对外 `Servo_GetSpeedRampRef()` 再乘一次 `dir` 还原到用户坐标系 —— 否则 `dir=-1` 时上位机会看到"给定 +30、斜坡 −30"，误判成振荡。
3. **`accel ≥ 20000` 视为不限制**，用于对比纯 PI 的阶跃响应。

### 2.2 新增 API

| 函数 | 说明 |
|---|---|
| `Servo_SetSpeedAccel(rad/s²)` | 默认 400（≈3820 rpm/s）；下限 5，上限 20000 |
| `Servo_GetSpeedAccel()` | |
| `Servo_SetSpeedIqMax(A)` | 默认 3 A；范围 0.1–9 A（9 A = 模型设计值，仍远低于 12 A 硬件跳闸） |
| `Servo_GetSpeedIqMax()` | |
| `Servo_GetSpeedRampRef()` | 斜坡后给定，**用户坐标系** |
| `Servo_GetSpeedState(..., float *w_ramp)` | 加了一个输出参数 |

下限不为 0 的理由：全 0 会让给定永远不动（accel 全 0）或连静摩擦都克服不了（iqmax 全 0），现象都是"进环了但电机不动也不报错"，与"参数没生效"完全无法区分。

### 2.3 遥测 30025 扩展（`telemetry_tx.c`）

`LEN_IN` 57 → **61**，`+57` 新增 `spd_ref_rpm`（f32，斜坡后给定）。

上位机按 `payload.length >= 61` 判断，**旧帧仍能解析**（`motor_temp` 的 `>=57` 判据不变）。`FRAME_IN` 由 69 B 变 73 B。

### 2.4 带参数的数值命令（`servo_cmd.c`）

原来命令层是逐字符即时的（不需要回车），所以引入了小状态机：

| 引导符 | 参数 | 示例 |
|---|---|---|
| `=` | 速度给定 rpm | `=300⏎`、`=-30.5⏎`、`=⏎`（查询） |
| `~` | 加速度 rad/s² | `~400⏎` |
| `\|` | iq 限幅 A | `\|3⏎` |

实现要点：
- 累积 `[-+0-9.]`，遇 `CR`/`LF` 应用，遇其他字符**立即放弃并回显**（静默丢弃会让人以为命令生效了）
- **300 ms 超时**：半截数字挂着会吞掉后续所有单字符命令，现象是"命令全都不响应了"，很难联想到是没敲回车
- `=` 复用 `do_speed()`，所以联锁（C/Z/故障）、坐标系换算、"已在环内只改给定"这些分支全部继承
- 空数值（引导符后直接回车）= 查询当前值
- 没有引入 `strtof`，自己写了 12 行定点+小数解析，避免把 newlib 的浮点扫描器拉进固件

**为什么不用更多档位代替**：档位每加一档要改固件+上位机两边，成本比解析器高；而且带载后工作点会变，档位覆盖不全。档位保留用于快速切换常用点。

## 3. 离线验证：斜坡到底值不值

`python Agnet/verify_speed_ramp.py`

模型参数与实测对齐：`Kt=0.0936 N·m/A`（psi 由 2496 rpm 电压饱和点反算）、`J=2.3e-4 kg·m²`（由"8x 增益最优"反推）、库仑摩擦 `0.028 N·m`（=30 rpm 稳态 iq 0.35 A × Kt）、电流环 `τ=114 µs`。

### 低速段：收益有限

| 给定 | accel | 斜坡时间 | 上升时间 | 超调 | 峰值 iq |
|---|---|---|---|---|---|
| 30 rpm | 不限（阶跃） | 0 ms | 5 ms | 17.9% | 1.93 A |
| 30 rpm | 400 | 7.9 ms | 6 ms | 18.9% | **1.45 A** |
| 30 rpm | 200 | 15.7 ms | 10 ms | 16.6% | 0.98 A |
| 30 rpm | 100 | 31.4 ms | 19 ms | **9.1%** | 0.67 A |

30 rpm 下斜坡把峰值电流从 1.93 A 降到 1.45 A，但超调基本不变（甚至略升 1 个点）—— 因为 7.9 ms 相对整个响应占比太小，而超调主要来自摩擦起跳。

### 高速段：斜坡的价值在这里

| 给定 | accel | 斜坡时间 | 到 90% | 峰值 iq | iq 饱和时长 |
|---|---|---|---|---|---|
| 500 rpm | 不限（阶跃） | 0 | 39 ms | 3.00 A | **44 ms** |
| 500 rpm | 400 | 131 ms | 103 ms | **1.59 A** | **0 ms** |
| 1500 rpm | 不限（阶跃） | 0 | 115 ms | 3.00 A | **140 ms** |
| 1500 rpm | 400 | 393 ms | 314 ms | **1.59 A** | **0 ms** |
| 3000 rpm | 不限（阶跃） | 0 | 232 ms | 3.00 A | **285 ms** |
| 3000 rpm | 400 | 785 ms | 628 ms | **1.59 A** | **0 ms** |

**结论：默认 400 合适** —— 高速段彻底消除 iq 饱和（3.00 → 1.59 A），低速段几乎无损失。要更平滑的低速响应可以调 100–200，代价是上升时间从 5 ms 变到 19 ms。

> 仿真的 30 rpm 超调 17.9% 与实测 31% 有差距，说明摩擦模型比实际温和。所以**只能看趋势，不能当绝对预测**。

## 6. 这次没做的（按收益排序）

1. **摩擦补偿**：3 rpm 的 68.8% 超调只能靠这个。做法是 `iq_ff = Tc/Kt·sign(w_ref)` 加上速度相关的黏滞项，需要先标定 `Tc`。风险是零速附近抖动，要配一个死区。
2. **加速度前馈**：`iq_ff = J·accel/Kt`。J 已经有反推值（2.3e-4），但误差可能 50%，前馈量打折扣（0.6–0.8）更安全。
3. **抗饱和改进**：现在是条件积分（冻结），可以换 back-calculation（`i_term += (u_sat - u)·Kb·Ts`），退饱和更快。
4. **位置模式的速度前馈**：位置环输出 `hold_w` 时把一阶差分当速度前馈，能显著减小跟随误差。但这要先解决位置环跨圈的问题。

前三项都需要实机标定，建议先把斜坡这版跑通再逐个加。
