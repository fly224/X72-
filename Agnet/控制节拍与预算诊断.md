## 0. 结论先行

| 问题 | 实测结论 |
|---|---|
| 控制节拍跑多快 | **10.0 kHz**，不是设计的 20 kHz（`dt_avg=17000cyc`，两个 PWM 周期） |
| 为什么是 10 kHz | 单拍耗时 **8847 cyc = 52.1 µs > 50 µs**，ISR 排不进 20 kHz 时间槽，ADC2 每两次触发只完成一次，节拍被"半速自锁" |
| 谁吃掉 8847 cyc | 模型 `three_loop_deploy_step()` **7410 cyc（83.8%）**，其中 **≈5170 cyc 是两次双精度 `sin`/`cos`**；编码器 DMA 753；占空比 248；角度 218；电流 193 |
| 能不能上 20 kHz | 能，而且余量很大。**配置⑤（单精度 + CMSIS-DSP）= 1813 cyc / 21.3%**，实测 `rate=20.0kHz`、`adc1=adc2=60010`、`model=593 cyc` |
| 只把 `real_T` 改 float 够不够 | 不够。只改类型仍 8751 cyc；加字面量 `f` 到 6983 cyc；**再做掉 double `sin/cos/sqrt` 才到 1813 cyc**——三步收益分别是 -9%、-20%、-74% |
| 当前上电是否安全 | 是。`MOE=0`、`fault=0x00`、`en=0`，只发不收 |

一句话：**这块板现在跑的是"模型按 20 kHz 离散化、控制器实际 10 kHz"的状态，闭环前必须把两者对齐**——要么模型改单精度（保持 20 kHz），要么模型步长改 1e-4（正式降到 10 kHz）。

```
[DIAG] rate=10.0kHz dt_avg=17000cyc dt_min=16991cyc
```

| 字段 | 含义 | 怎么用 |

| `adc1/adc2` | 两路注入完成的**真实**次数 | 两者不等 = 有一路在丢触发 |
| `ticks` | 控制节拍累计数 | 与 `adc2` 相等 = 每对采样都跑了一拍 |

## 2. 根因链（每一步都有实测证据）

### 2.1 发现：节拍只有 10 kHz

`ticks=30009` 出现在开机 3 s 处 → 10003 Hz。同时 `dt_avg=17000cyc`，正好是两个 PWM 周期（8500×2）。

### 2.2 关键证据：两路 ADC 完成次数 2:1

```
ticks=30009   adc1=60018   adc2=30009
```

- TIM1 中心对齐 `ARR=4250` → TRGO(OC4REF) = **20 kHz**，ADC1 确实拿到 20 kHz
- ADC2 只有 10 kHz，而 `ticks` 与 `adc2` 严格相等 → **节拍是被 ADC2 拖慢的**

### 2.3 硬件配置排查：ADC2 是对的

启动时打印寄存器快照：

```
[REG] adc1:CFGR CR SQR1 adc2:CFGR CR SQR1 CCR: 80002003 1000000D 0E2D0043 80002002 10000009 00005441 00830000
```

| 寄存器 | ADC1 | ADC2 | 判读 |
|---|---|---|---|
| `CFGR` | `80002003` | `80002002` | 都是 `CONT=1`、`JQDIS=1`；仅 DMAEN 模式位不同 |
| `CR` | `1000000D` | `10000009` | `ADEN=1`、`JADSTART=1` 两边都有；差别只是 ADC1 多了 `ADSTART=1`（常规组在跑） |
| `SQR1` | `0E2D0043` | `00005441` | L=3（4 通道）/ L=1（2 通道），符合工程配置 |
| `CCR` | `00830000` | 同左（公共） | `CKMODE=11`=HCLK/4=42.5 MHz，`TSEN=1` |

结论：**ADC2 的注入触发配置与 ADC1 完全一致，硬件没配错。**

### 2.4 对照实验：把控制律短路

临时在 `Servo_ControlTick()` 开头加 `s_tick_count++; return;`（ISR 降到约 1 µs），其余不动：

```
[DIAG] rate=20.0kHz dt_avg=8499cyc dt_min=8342cyc
[DIAG] step max=0cyc
[DIAG] ticks=60010 adc1=60010 adc2=60010
```

**两路立刻变成 60010 : 60010，20.0 kHz。** 到这里可以排除"ADC2 配置错"，锁定为：**单拍耗时超过触发周期时，ADC2 会丢一半触发，节拍被锁在半速**。这个失败模式很阴——不报错、不置故障位，只是静静地跑一半。

> 机制细节（`JQDIS=1`，注入队列关闭）：上一拍的注入序列尚未被软件收尾时到来的新触发会被丢弃，因此 ISR 超时的代价正好是"丢一个触发"。

### 2.5 短路代码已删除

`TEMP PROBE` 三行已移除，`grep` 确认 `s_tick_count++` 只剩函数末尾那一处。

## 3. 8847 cyc 花在哪：四组对照

`hot` 分段由 DWT 直接测量（每段 2 次读寄存器，成本可忽略）。

| 配置 | model | 总计 | 实测节拍 | 判断 |
|---|---:|---:|---|---|
| ① double + double 字面量 + `SetDuty(double)` | 7408 | **9646** | 10 kHz | 超 20 kHz 预算 13.5% |
| ② ①+ `SetDuty(float)`（本轮修复） | 7410 | **8847** | 10 kHz | 仍超 4.1% |
| ③ `real_T=float`，字面量仍 double | ~6500 | **8751** | 10 kHz | 只省 9%，**字面量把表达式拉回 double** |
| ④ `real_T=float` + 字面量加 `f`（101 处） | 5764 | **6983** | **20.0 kHz** | 占 82.1% 预算，可行 |
| ⑤ ④ + `sin/cos/sqrt` 换 CMSIS-DSP `arm_*_f32` | **593** | **1813** | **20.0 kHz** | 占 **21.3%**，余量充足 |

配置 ④ 的实物输出：

```
[DIAG] rate=20.0kHz dt_avg=8500cyc dt_min=8495cyc
[DIAG] step max=6983cyc  82.1% of measured period
[DIAG] hot theta=211 readinj=188 model=5764 duty=132 enc=652 cyc
[DIAG] ticks=60024 adc1=60024 adc2=60024
```

### 3.1 为什么"只改 real_T"几乎没用

`rtwtypes.h` 里 `typedef double real_T`，改成 `float` 后，模型里的常量仍然是**无后缀 double 字面量**：

```c
three_loop_deploy_DW.vd_int += (0.0 - id) * 2378.18563877 * 5.0E-5;
```

C 的 usual arithmetic conversions 会把 `float * double` 提成 double，于是每拍仍然调用 `__aeabi_dmul / __aeabi_ddiv`。链接映射里可以数出来：

```
69 __aeabi_dmul   62 __aeabi_dadd   45 __aeabi_ddiv   29 __aeabi_dsub
12 __aeabi_d2f     5 __aeabi_f2d   10 __aeabi_dcmpgt  6 __aeabi_dcmplt
```

`__aeabi_fadd / __aeabi_fmul` 一个都没有 → **float 确实走硬件 FPU**（`system_stm32g4xx.c:185` 已置 CPACR），问题只在于这段代码根本不是 float 运算。

### 3.2 已经落地的修复：`BspServo_SetDuty` 改 float

```c
// 改前：三个 double 形参 → 3×__aeabi_dmul + 3×__aeabi_d2iz(软浮点)
void BspServo_SetDuty(double d1, double d2, double d3);

// 改后：全程 float → VMUL.F32 / VCVT
void BspServo_SetDuty(float d1, float d2, float d3);
```

实测 **1025 → 248 cyc（-757）**，是这轮唯一进主干的性能改动。同时把 `servo_isr.c` 里 7 处 `(double)` 强转改成 `(real_T)`，这样模型将来切单精度时不需要再动应用层。

### 3.3 `enc=753 cyc` 的构成

`BspServo_StartEncoderDma()` 里调用 `HAL_SPI_TransmitReceive_DMA()`，HAL 会做 lock 检查、状态机判断、DMA 通道重配。理论上可以直接写 `SPI1->CR2 / DMA1_Channel3->CNDTR` 把它压到 ~150 cyc，但这属于"为了省 10% 去动 HAL"，暂时不做，先记录。

### 关键发现：配置④ 的 5764 cyc 里 ≈5170 全是两次双精度 sin/cos

| `three_loop_deploy_step` 的三角调用 | `sin.o(i.__hardfp_sin)`、`cos.o(i.__hardfp_cos)` | `fastmathfunctions.o(.text.arm_sin_f32)`、`arm_cos_f32` |

## 5. 必须做的选择（二选一，不能都不做）

### 方案 A：保持 20 kHz，模型改单精度 + 三角走 CMSIS-DSP（已实测，推荐）

在 Simulink 侧：
1. 所有信号、参数、状态的数据类型设为 `single`
2. 让生成代码里的常量带 `f` 后缀（Config → Math and Data Types 相关选项，或代码生成后校验）
3. **`sin`/`cos`/`sqrt` 换成 `arm_sin_f32`/`arm_cos_f32`/`arm_sqrt_f32`**——这一步不是优化，是必需项：只做 1+2 仍是 6983 cyc（82%），因为 `sin(float)` 会被提升成 double
4. 重新跑 SIL 对比（`sil_expected.csv` 会变，容差按单精度重新定）

**实测结果（配置⑤）**：`model` 7410 → **593 cyc**，单拍 8847 → **1813 cyc（21.3%）**，节拍 20.0 kHz，两路 ADC 计数相等。

落地后的验收三件套（缺一不可）：

```bash

grep -cE "[0-9]\.[0-9]+f" three_loop_deploy.c        # 应 ≈99
# 2) 双精度软浮点是否清零（看 map 的映像符号表，不是全文）
sed -n '/Image Symbol Table/,/Memory Map of the image/p' X72_FOC.map | grep -c __aeabi_d
# 3) 实物节拍
python Agnet/serial_link_check.py -p COM27 -t 8     # 另抓 [DIAG] 看 rate=20.0kHz
```

### 方案 B：正式降到 10 kHz

模型步长改 `1e-4`，`cnt_i>=20` 改成 `>=10`（保持位置环 1 kHz），重新生成。当前硬件不用动。
好处是 52% 占用很稳；代价是电流环带宽减半。

### 不能接受的状态：现在这个

模型按 `Ts=5e-5` 离散化，实际按 `1e-4` 执行：
- 电流环积分增益等效减半（`vd_int += ... * 5.0E-5` 每 100 µs 才加一次）
- `cnt_i>=20` 的位置环变成 500 Hz，不是 1 kHz
- 电流在 20 kHz PWM 上以 10 kHz 采样，采样点相对 PWM 的位置在漂

**闭环使能前必须先对齐。**

## 6. 局限与未验证项

1. 所有结论来自**单板单次上电**，未做温度/批次方差统计
2. `dt_min=16991` 说明抖动很小，但只用 DWT 观察了 3 s 窗口
3. 配置 ④/⑤ 的周期数是**手工改生成代码**得到的（代码内 99 处字面量加 `f`，另 2 处"1.1 / 23.2"在文件头注释里不计），不可持续；Simulink 重新生成后应以生成结果为准
4. `max_step` 是峰值，受中断抢占影响（`vbus`/`theta` 段很稳定，`model` 段 ±10 cyc）
5. 未验证 20 kHz 下其他中断（SPI DMA、TIM6、UART）叠加后是否仍有余量——配置 ④ 只跑了 18 s 空载，`tx=299 drop=0 rec=0` 说明丢帧为 0，但没有更长时间的浸泡
6. **配置⑤ 的 1813 cyc 是 `en=0` 路径**：`three_loop_deploy.c:137` 的 `if (en < 0.5)` 外，Clark/Park 与三角是每拍都跑的，但电流环 PI、SVPWM 扇区判断、占空比限制都在这条 `else` 里，**闭环后 `model` 还会涨**。基线 8847 同样是 `en=0` 路径，所以横向对比仍成立，但闭环预算要另外补测
7. ⑤ 的改法是**手工补丁生成代码**，Simulink 重新生成即失效；正式落地必须改模型（见 §5 方案 A）。精度上单精度 vs 双精度会改变数值细节，需重跑 SIL 并重新定容差
8. CMSIS-DSP 用的是 Keil pack `ARM.CMSIS-DSP@1.16.2`，不是工程目录里的 `Drivers/CMSIS/DSP` 副本；改本地副本不会生效

### 顺带修掉的 flash 浪费

`UL_NOINLINE` 之前，AC6 `-O3` 把 `put_u32` 的十进制循环在**每个调用点完全展开**，`UartLink_ReportDiag` 一个函数 5676 B。四组格式化函数加 `noinline` 后：

| 函数 | 改前 | 改后 |
|---|---:|---:|
| `UartLink_ReportDiag` | 5676 B | 436 B |
| `UartLink_ReportStatus` | 2128 B | 444 B |
| `UartLink_FaultDump` | 4212 B | 820 B |
| `UartLink_Init` | 1068 B | 352 B |

整体 Code 从 59224 B 降到 **49216 B（-10 KB）**，之后加诊断行只回到 49864 B。
