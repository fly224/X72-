## 1. 硬件依据（网表逐条核对）

`Hardware/Netlist/net_report.md`：

```
$1N216 = R55(1k) pin1 + R53(50k NTC) pin2 + R56(50k) pin1
$1N211 = R54(1k) pin1 + R57(50k) pin1 + U14(2P 连接器) pin1
NTC_GAN   = U4 pin12(PA4) + C32(100nF) + R55 pin2
NTC_MOTOR = U4 pin16(PC4) + C33(100nF) + R54 pin2
3V3       = ... + R56 pin2 + R57 pin2
GND       = ... + R53 pin1 + U14 pin2
```

两路拓扑相同，**被测 NTC 都在下臂**：

```
3V3 ── R56/R57 (50kΩ 0.1%) ──┬── R54/R55 (1kΩ) ── PA4/PC4 (ADC, 高阻)
                             │
                       被测 NTC
                             │
                            GND
```

- ADC 输入电流是 nA 级，1kΩ 上压降可忽略 → `V(ADC) = V(节点)`
- 25 °C 时若 NTC = 50 kΩ → 分压中点 **1.65 V** → 码值 **≈2048**（自检基准）
- 1kΩ + 100nF 构成 τ=100 µs 低通，只滤高频，不影响直流

| 通道 | 上拉 | 被测件 | 参数 |
|---|---|---|---|
| NTC_GAN | R56 = 50 kΩ | 板上 **R53 `RL0603N503F4150FTF`** | **50 kΩ, B(25/85)=4150 K, 1%**（型号确定） |
| NTC_MOTOR | R57 = 50 kΩ | U14 外接 2P 探头 | **10 kΩ, B=3950**（实测反推，见 §4） |

## 2. 固件改动

### 2.1 ADC2 常规组的启动约束（最关键）

ADC2 同时承担 **20 kHz 注入采样**（W 相电流，TIM1_TRGO 触发），所以常规组不能按 CubeMX 默认方式启动：

```c
hadc2.Init.ContinuousConvMode    = DISABLE;   /* CubeMX 默认 ENABLE */
hadc2.Init.DMAContinuousRequests = DISABLE;   /* CubeMX 默认 ENABLE */
CLEAR_BIT(ADC2->CFGR, ADC_CFGR_CONT | ADC_CFGR_DMACFG);
hadc2.DMA_Handle->Init.Mode = DMA_NORMAL;     /* CubeMX 默认 CIRCULAR */
HAL_DMA_Init(hadc2.DMA_Handle);
```

为什么：

1. **默认配置会让 ADC2 满速扫 NTC**：2 通道约 1.7 µs 一轮、DMA 请求约 570 kHz，既挤总线又长期占用 ADC2。
2. **必须 NORMAL**：CIRCULAR 下 HAL 的完成回调不会把 ADC 状态机归位，第二次 `HAL_ADC_Start_DMA` 会一直返回 `HAL_BUSY`。
3. **绝不能 `HAL_ADC_Init` 重配**（会复位注入配置），**绝不能 `HAL_ADC_Stop_DMA`**（它清 `ADEN`，20 kHz 注入链会一起失效）。

改动后占空比：每 100 ms 换 2 个通道（约 1.7 µs），即 **< 0.01%**，对注入链路无影响。

### 2.2 踩到的坑：NVIC 与 ISR 都不存在

CubeMX 只给 `DMA1_Channel4` 配了参数（`adc.c:458` 只有 `Instance` 赋值），**既没使能 NVIC，`stm32g4xx_it.c` 里也没有 `DMA1_Channel4_IRQHandler`**。

后果：DMA 硬件照样把数据搬完，但 HAL 的完成回调永不触发 → 状态机卡在"转换中" → 50 ms 超时后重试 → 永远失败 → **温度恒为 NaN**。

第一次实机抓包就是这个现象（1560 帧，`driver_temp`/`motor_temp` 全 `None`）。补两处：

```c
/* bsp_servo.c —— 优先级取最低 15（ADC 注入=0、SPI1=1、USART1=8） */
HAL_NVIC_SetPriority(DMA1_Channel4_IRQn, 15, 0);
HAL_NVIC_EnableIRQ(DMA1_Channel4_IRQn);

/* stm32g4xx_it.c USER CODE 区 */
void DMA1_Channel4_IRQHandler(void)
{
  extern DMA_HandleTypeDef hdma_adc2;
  HAL_DMA_IRQHandler(&hdma_adc2);
}
```

### 2.3 第二个坑：`-O3` 下不能用 `NAN` 宏

```text
warning: use of NaN via a macro is undefined behavior due to the currently
         enabled floating-point options [-Wnan-infinity-disabled]
```

当前优化选项下编译器认为 NaN/Inf 不存在，`NAN` 宏会被折叠成不可预期值。恢复原 `telemetry_tx.c` 的位拷贝做法：

```c
static float Ntc_NaN(void)
{
    uint32_t bits = 0x7FC00000u;      /* 静默 NaN */
    float f;
    memcpy(&f, &bits, sizeof(f));
    return f;
}
```

判空也用取反写法避开 NaN 比较：`if (!(inv_t > 0.0f)) return Ntc_NaN();`

### 2.4 换算与采样节拍

```c
/* 10 Hz，1 ms 任务里软启动一次；DMA 完成中断只置状态，logf 换算留到任务里 */
if (s_ntc_state == 2U) {          /* 数据就绪 */
    s_temp_gan   = Ntc_CodeToCelsius(s_ntc_raw[0], NTC_GAN_R25, NTC_GAN_BETA);
    s_temp_motor = Ntc_CodeToCelsius(s_ntc_raw[1], NTC_MOT_R25, NTC_MOT_BETA);
} else if (s_ntc_state == 0U) {   /* 每 100 ms 启动一次 */
    if (++s_ntc_div >= NTC_PERIOD_MS) HAL_ADC_Start_DMA(&hadc2, (uint32_t *)s_ntc_raw, 2U);
} else {                          /* 转换中，超时 50 ms 判失败重来 */
    if (++s_ntc_div >= NTC_TIMEOUT_MS) { s_ntc_state = 0U; s_ntc_fail++; }
}
```

换算公式：

```
V = code/4095 × 3.3
R = Rpull × V / (3.3 − V)                     （NTC 在下臂）
T = 1 / (1/T25 + ln(R/R25) / B) − 273.15
```

边界：`code == 0`（开路）或 `code >= 4095`（短路）→ **NaN**，上位机显示 `--`。宁可显示没有，也不编一个温度出来。

## 4. 实测与「69 °C 疑云」

### 4.1 第一次实测：驱动器 31.6 °C，电机 68.99 °C

板子刚上电、电机未运行，69 °C 明显不合理。用公式反推：

```
T=69 °C（按 50k/B4150 算） → R ≈ 8.36 kΩ → V ≈ 0.47 V → code ≈ 588
```

再假设探头是 **10 kΩ/B3950**：`8.36 kΩ` 对应

```
T = 1/(1/298.15 + ln(8.36/10)/3950) − 273.15 ≈ 29.1 °C
```

与板温 31.6 °C 自洽。**说明 U14 上插的是 10k/B3950 探头，不是板上那种 50k。**

### 4.2 把两路参数拆开后复测

## 5. 标定（换探头或要求更高精度时）

1. **确认探头规格**：查电机厂家给的 R25 与 B 值，改 `NTC_MOT_R25` / `NTC_MOT_BETA` 两个宏，重编译。
2. **两点法复核**：
   - 探头放冰水混合物（0 °C），记录页面读数；
   - 放沸水（100 °C，按当地气压修正），记录读数；
   - 两点偏差若同向且接近，说明 B 值偏差；若一大一小，说明 R25 偏差。
3. **看原始码值**：`BspServo_GetNtcRaw(&gan, &motor)` 可直接读到 `s_ntc_raw[]`，调试时用它对照万用表测 PC4/PA4 电压。
4. **自检点**：室温 25 °C、探头 50 kΩ 时，PA4/PC4 应为 **1.65 V ± 30 mV**（码值 2048±40）。

## 6. 局限

1. **NTC_MOTOR 参数是按实测反推的，不是厂家标称**：目前按 10k/B3950 换算得 29.07 °C，与板温自洽，但没做冰水/沸水两点标定。误差可能在 ±2–3 °C。
2. **单点温度、无开路检测的独立上报**：开路（code=0）与短路（code=4095）都归为 NaN，上位机只能看到 `--`，分不清是"没接"还是"短路"。要区分需再占 1 bit 或 1 字节。
3. **10 Hz 采样**：热时间常数秒级，够用；但若要做过温保护的快速响应，需要提高频率（届时注意 ADC2 与注入的占空比）。
4. **host 侧 `mavlink_layouts.json` 未同步**：`PG_X72_CAN/host` 里 30025 仍记 LEN=53、无 `motor_temp` 字段。`verify_fw_frame.py` 里对 `motor_temp` 是按固定偏移直接解的；跑 `gen_msg_layouts.py` 重新生成前，需先在 `mavlink_msg_*.h` 补字段，否则会被覆盖回去。
5. **温度尚未参与任何保护逻辑**：没有过温降额/停机。`Servo_SlowTask1ms` 里只做显示，故障判定未接。
