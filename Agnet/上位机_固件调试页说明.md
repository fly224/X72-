## 1. 为什么单独开一页，而不是塞进现有「电机调试」

现有 `电机调试` 页里那张「编码器校准」卡是**早期演示动画**——进度条和偏移量都在浏览器本地生成，既不下发也不回读固件（原文注释写着"本页在仿真下演示收敛过程"）。把真实命令混进去，两种行为会互相冒充。

所以新增独立的 `固件调试` 模块（导航「调试」组第一项），并在旧卡片标题上加标注 `演示动画 · 真实校准请用「固件调试」页的 ^ 命令`，正文点明两条真实路径（`Z` 电角度对齐 / `^` 编码器非线性校准）。

## 2. 页面结构（5 张卡）

### 卡 1：链路与状态 —— `S`

10 个实时 tile：`en / moe / cal / z / f / fl / deadman / 转速 / Iq / 母线`。

判读要点：
- `f` 非 `0x00` 时变红（故障位）
- `fl=1` 表示 Flash 里有通过 CRC 的参数，上电自动应用
- `deadman` 是剩余毫秒，**掉到 0 就封锁输出**，能直观看出保活是否在工作

### 卡 2：标定与辨识 —— `C` `Z` `@` `#` `^` `A` `!`

| 按钮 | 命令 | 耗时 | 前置条件 |
|---|---|---|---|
| 电流零点标定 | `C` | 200 ms | MOE=0、电机静止 |
| 极对数/方向/零点 | `Z` | ≈9 s | 已 `C` |
| R/L 在线辨识 | `@` | ≈0.4 s | 已 `C`+`Z`、MOE=0 |
| 注入幅值（循环） | `#` | — | 下次 `@` 生效，0.6/1.0/1.5/2.5 V |
| 编码器自校准 | `^` | ≈7 s | 已 `C`+`Z`、MOE=0 |
| 写 Flash | `A` | <50 ms | MOE=0、已标定 |
| 软复位 | `!` | ≈2 s | 有二次确认弹窗 |

结果 tile：`R (mΩ) / L (µH) / |Z| (Ω) / 注入电流幅值 (A) / 自校准圈数 / chip 码`。

`chip=3` 是 MT6835 寄存器 `0x113[7:6]=11` 的自报成功，**不是固件推测**。

⚠ `^` 成功后必须**人工断电 ≥6 s**，EEPROM 里的新参数才被加载——固化在页面上的红色提示框，固件做不到这一步。

### 卡 3：速度闭环 —— `W` `Q` `O` `L` `Y` `K`

- 转速档 chips：`3 / 30 / 100 / 500 / 1500 / 3000 rpm`（对应固件 `O` 键的 6 档）
- 增益档 chips：`0.125x … 32x`，其中 **1x 标「基准」**= 实测最优（`kp=0.5834`、`kiTs=40.76e-3`）
- `档位归位 Y`：把两个档位同时复位到默认，并让浏览器索引与固件重新对齐
- `正转 W` / `反转 Q` / `详情 K` / `状态 S`

7 个 tile：`w_ref / w_meas / iqc / iterm / nex / Kp / Ki·Ts`。`nex` 落在 `2000±200` 才显示绿色（实测 2016 Hz）。

### 卡 4：谐波抑制与波形记录 —— `%` `&`

- `%` 开关，按钮文字实时显示 `ON/OFF`（跟 `S` 回显的 `h=` 同步），旁边显示 5/7 次 d/q 残余
- `&` 采集 1024 点 iq（20 kHz，51.2 ms），收到 `[CMD] REC end n=1024` 后自动算频谱
- 上半张：iq 时域波形（自动缩放，标注 min…max 与时长）
- 下半张：频谱 0–5 kHz，虚线标出**基波**（`rpm/60×14` Hz）与**6 次**（`1.4×rpm` Hz）
- 6 个 tile：`5 次 d/q / 7 次 d/q / 主峰频率 / 主峰幅值 / 基波分量 / 6 次分量`

### 卡 5：命令回显

`[CMD]` / `[REC]` 行原样显示，最新在最上，按内容着色（成功绿、失败红、发送蓝、接收灰）。最多留 240 行。

## 3. 三个必须知道的固件侧约束（页面已处理，但用的人要知道）

### ① deadman 2 s

固件里任何命令都重置 deadman，2 s 内无命令自动封锁。

页面的处理：`tickFw()` 里每 1.5 s 发一次 `S`（同时兼作状态回读）。**但 `tick` 只在本模块激活时被调用**——离开本页就不再保活，2 s 后固件自行封锁。这是有意的：定时器绝不能挂在模块外面，否则切走后电机还在转。切走时会弹 toast 明确告知。

### ② 档位是循环键

`O` 只做 `(idx+1)%6`、`L` 只做 `(idx+1)%9`，固件**没有**"设为第 N 档"的接口。页面维护一份浏览器侧索引，点目标档时按差值发 N 次；每次 `O`/`L` 的回显会反向校准索引。

索引失配的典型症状：点了 100 rpm 却跑 30 rpm。此时点「档位归位 Y」。

### ③ 回显单缓冲

固件 `s_out` 只有一个缓冲，连续猛点会互相顶掉。所以所有命令走 60 ms 间隔的队列，队列 >24 条时直接拒绝并提示。

## 4. 典型操作流程

```
刷新页面（Ctrl+Shift+R）→ 点「连接串口」
  ↓
固件调试页会自动发 S + K 拉一次状态
  ↓
首次上电：C → 等 1 s → Z → 等 10 s（或确认 S 里 cal=1 z=1）
  ↓
可选：@ 测 R/L、^ 编码器校准（后者需断电）
  ↓
A 写 Flash（此后上电自动恢复，不用再 C/Z）
  ↓
速度闭环：档位归位 Y → 选转速档 → 正转 W
  ↓
看 K 的 w_meas / iqc，或切到仪表盘看波形
  ↓
封锁 D
```

> 刷新页面会断开 Web Serial，需重新点「连接串口」；固件侧 deadman 2 s 会自行封锁，不会失控。

FFT 精度：合成 700 Hz / 0.25 A 正弦，实测峰值 703.1 Hz、0.2457 A（幅度误差 1.7%，Hann 窗 + 非整 bin 的固有泄漏）。

解析器里抓到并修正的两个真 bug：
1. **`kp=583.38e-3` 被重复乘 `1e-3`** → 界面显示 0.00058，看着像增益掉了三个数量级。
2. **`spd rpm ->` 被 `/^spd\s/` 抢先匹配** → 档位索引永不更新，表现为"高亮不跟着走"。

这两个都是纯离线测试才暴露的，真机上只会表现为"数值不对 / 点了没反应"，极难反查。

## 6. 局限

1. **`&` 采集期间遥测会被暂停约 70 ms**（43 行 ASCII，固件直写 TDR 时遥测让路）。示波器会缺一小段，不影响判读。
2. **没有做电流阶跃（M/N/T/U/V）的控件**——那几个命令属于电流环整定，已有结论（现有参数即最优），暂不缺。
3. **位置模式（P）故意没放按钮**：固件里 `P` 只切 `Servo_SetMode`、不清 `s_spd_en`，速度环起来后按 P 不生效；且位置环跨圈移动的问题未解决（`pos_ref` 折叠只保证 ±π 内正确）。放个按下去没反应或行为诡异的按钮比不放更糟。
4. **`!` 软复位在 iframe 预览里可能被 `confirm()` 策略拦住**。若点了没反应，改用命令行或直接拔插。
5. 页面仍是"单文件 + 全局函数"结构，新增模块走同样的约定（`mountXxx` / `tickXxx` / `modules` 注册），没有引入构建步骤。
