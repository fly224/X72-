# 控制模式与参数辨识的切换逻辑：审查与修复

**日期** 2026-11-21 · **固件** Code=117876 · **协议** 非标准 MAVLink v2
**涉及代码** `servo_cmd.c`、`motor_ident.c`、`motor_rl_ident.c`、`encoder_cal.c`、`actuator.c`

---

## 0. 一句话

切换逻辑**只做了"辨识 → 控制"方向的检查，没做"控制 → 辨识"和"辨识中使能"**。已补，并统一了占用判断。

---

## 1. 三个问题

### 1.1 使能路径完全不检查辨识占用（高）

`do_enable()` 原有四道检查：已在使能、故障位、电流零点、电角度零点。**没有检查"是否有辨识在跑"**。

为什么其他检查拦不住：

```
辨识期间 MOE 是辨识模块自己 BspServo_PwmEnable(1) 打开的，
而 s_armed 仍是 0（辨识要求未使能才能启动）。
所以 "already ON" 那道判断不会命中。
```

**后果（连锁）**：

| 步骤 | 发生什么 |
|---|---|
| 辨识跑到一半 | MOE=1、s_armed=0、`src=SPEED`/`OPENLOOP` |
| 上位机发 30054 使能 | `do_enable` 通过 → `Servo_SetPosMode(1, …)` 起环 + `PwmEnable(1)` |
| ISR 下一拍 | 分支优先级 `s_pos_en` > `s_ol_en` → **辨识的给定被整段忽略** |
| 辨识模块 | 以为在跑，实际电机被位置环控制 → 数据全错 → 超时或算出荒谬 L |
| 辨识收尾 | `BspServo_PwmEnable(0)` 关掉 MOE，但 `s_armed=1` |
| 上位机看到的 | "已使能"却不动（`s_armed=1` / `MOE=0` 不一致） |

### 1.2 `Servo_IsOpenLoop()` 覆盖不全（中）

各控制模式入口（CUR/SPD/POS/STEP/MIT）都在用 `Servo_IsOpenLoop()` 做"辨识中"判断，但这个量**只反映 `s_src == SERVO_SRC_OPENLOOP`**：

| 辨识 | 运行时的标志 | `Servo_IsOpenLoop()` |
|---|---|---|
| C / Z / ^ 主体 | `SetOpenLoop(1)` | 1 ✓ |
| **@ 的 L 段** | `SetOpenLoop(0)` 后 `SetVoltInject(1)`（`motor_rl_ident.c:307-309`） | **0** ✗ |
| **$ ( ) < }** | 全程用速度环/电流环 | **0** ✗ |

所以"辨识中发 30019"这条路，上述两类**拦不住**：帧被接受、`src_enter` 抢走分支，辨识被静默破坏。

### 1.3 三个 Start 不检查 MOE（低，加固）

| 模块 | 检查 `IsPwmEnabled()` |
|---|---|
| `FricCal_Start` / `MechIdent_Start` / `FluxIdent_Start` | ✅ 有 |
| `MotorIdent_Start` / `RlIdent_Start` / `EncCal_Start` | ❌ **没有** |

后三者只靠 `do_align()` / `do_rl()` / `do_enc_cal()` 里的 `s_armed` 兜底。当前没有别的调用路径，属加固项。

## 2. 修复

### 2.1 统一的占用判断

```c
/* servo_cmd.c */
static uint8_t ident_busy(void)
{
    if (Act_IsBusy() != 0U)         { return 1U; }   /* 覆盖全部：所有辨识都 Act_Acquire */
    if (Servo_IsOpenLoop() != 0U)   { return 1U; }   /* 开环拖动 */
    if (Servo_IsVoltInject() != 0U) { return 1U; }   /* @ 的 L 段 */
    return 0U;
}
```

三路缺一不可：

- `Act_IsBusy()` 是**主判据**。六个辨识模块启动时都 `Act_Acquire`，收尾或 `busy_fn` 归零后 1~2 ms 内自动释放（`actuator.c` `Act_Task1ms`）。
- `Servo_IsOpenLoop()` 补"已 Acquire 但还没进状态机"的那几拍。
- `Servo_IsVoltInject()` 专门补 `@` 的 L 段——它把 open loop 关了，只剩这个标志。

### 2.2 落点

| 位置 | 改动 |
|---|---|
| `do_enable()` | **新增** `ident_busy()` 检查，拒绝并提示 "wait, or send D to abort" |
| `do_current` / `do_speed` / `do_pos` / `do_step` / MIT 入口 | `Servo_IsOpenLoop()` → `ident_busy()` |
| `MotorIdent_Start` / `RlIdent_Start` / `EncCal_Start` | 补 `BspServo_IsPwmEnabled() != 0` → BUSY |

## 4. 上位机要注意的三件事

### 4.1 "命令被拒"不能靠返回值判断

`set_controlword()` / `set_pos_speed()` / `_send_fields()` 都是**只发不等应答**（`send()` 返回的 `ok=True` 只代表帧发出去了）。辨识期间发这些命令，返回值仍然是 `ok=True`。

要判断是否真的生效，看状态量：

| 目的 | 看哪里 |
|---|---|
| 使能是否成功 | 30090 `en`（`flags.bit2`） |
| 哪个环在跑 | 30091 `src`（0 NONE / 2 SPEED / 3 POS / 1 TORQUE / 5 OPENLOOP） |
| 是否在位置模式 | 30100 `pos_mode` |
| 辨识结果 | 30092 的 kind + ok |

> 只有 `action()`（30069）**会等应答并解析 status**，所以辨识的启停能看到明确拒绝。

### 4.2 `halt` 会中止所有辨识，不只是停控制

`do_disable()` 里依次调用：

```c
Servo_SetOpenLoop(0,0,0);
MotorIdent_Abort();
RlIdent_Abort();
EncCal_Abort();
Act_ForceRelease();
FricCal_Abort();
MechIdent_Abort();
FluxIdent_Abort();
```

所以辨识跑到一半发 `30054 halt=1`，辨识**被中止且不会推 30092**。上位机会一直等到超时。

### 4.3 辨识中改模式（30056）只登记，不会影响正在跑的辨识

它只写 `s_op_mode`，不动作环。但会影响**辨识结束后第一次使能**按哪个模式装配。

## 5. 未改的项（说明理由）

| 项 | 为什么不动 |
|---|---|
| 让 `set_controlword` 等应答 | 会引入 0.8 s 延迟，且保活线程每 200 ms 调一次，等待会互相阻塞。改用状态量判断更合适 |
| 辨识期间禁止 30056 | 已经无害（只登记），禁了反而多一条要记的规则 |
| `Act_IsBusy()` 释放延迟 | 释放靠 `busy_fn` 归零 + 1~2 ms 轮询，结束到可再次使能最多 2 ms，不值得改 |
