## 2. 上位机改动（`servo-web/index.html`）

1. **顶部读数条 `#liveStrip`**：三块数值 + 轴名 + 在线状态；刷新频率跟随 `requestAnimationFrame`，与模块无关。
2. **数据新鲜度**：`ax.rxT` 打时间戳，`isStale()` 超过 **1500 ms** 无帧即全量显示 `--`（不展示过期值）。
3. **解码器**：新增 `MSG_ID.CUR_IN = 30025`、`CUR_OUT = 30027`，保留旧 `TELEMETRY = 1` 兼容；旧帧扩展为可带 `vbus`（payload ≥ 32 B 时读 +28）。
4. **仪表盘**：指标卡由 6 张增至 7 张（新增母线电压），末张奇数卡横向铺满；真实帧下**扭矩/位置**无来源，显示 `--` 而不是假的 0。
5. **示波器**：`CFG.channels` 增加 `vbus`（量程 60 V），环形缓冲同步记录。
6. **去重采样**：30025/30027 成对到达（间隔 <2 ms），用 4 ms 最小间隔只入环形缓冲一次，避免采样率翻倍。
7. **窄屏**：`max-width:1480px` 时 header 允许换行，避免按钮被裁切。

## 3. 固件改动

| 文件 | 内容 |
|---|---|
| `Board/telemetry_tx.h/.c`（新） | 100 Hz 组帧 + CRC-16/X.25 + USART1 DMA 发送 |
| `Board/servo_isr.c` | 20 kHz ISR 里做 `iu/iv/iw/iq_used/duty` 快照；1 ms 任务调 `Telemetry_Task1ms()`；`Servo_Init()` 调 `Telemetry_Init()` |
| `Board/bsp_servo.h` | 新增 `Servo_GetSample()` 声明 |
| `MDK-ARM/X72_FOC.uvprojx` | 加入 `telemetry_tx.c`（源文件 41 → 42） |

帧结构：两条报文**拼成一次 DMA 传输**（65 + 44 = 109 B），避免半帧交错；`huart1.gState` 非 READY 时直接丢帧计数，不阻塞控制。

带宽核算：109 B / 10 ms = **10.9 kB/s**，占 921600 baud（92.16 kB/s）的 **11.8%**。

idq 用与 `three_loop_deploy.c` 完全相同的变换，保证上位机看到的 Iq/Id 就是控制律内部值：

```
theta_sum = 14·θm + π/2 + 0.00105·ωm
i_α = ia,  i_β = 0.57735·ia + 1.15470·ib
id = cos·i_α + sin·i_β,  iq = cos·i_β − sin·i_α
```

## 6. 局限（必读）

- **未做真实串口联调**：固件已烧录并发帧，但本轮未接 USB-485/未核 COM27 对端，验证止于「字节级一致」。
- **报文无轴号**：30025/30027 是单轴报文，遥测落到页面当前选中轴；多轴需加轴号或按 ID 区分。
- **温度不可用**：`NTC_GAN(PA4)/NTC_MOTOR(PC4)` 未配置 ADC，固件按 NaN 发送，界面显示 `--`（不伪造数值）。
- **扭矩/位置**不在 30025/30027 内，接真实帧时显示 `--`；需补 30055/30061 才能显示。
- 页面解析器**不校验 CRC**（沿用原有实现），CRC 正确性靠固件侧与 Python 侧验证。
- `Board/` 直发 UART 属**调试/联调临时通道**；量产应由 `communication/` 协议层统一收发。
- 固件仍**无使能路径**（`BDTR.MOE=0`、`Servo_SetEnable()` 无调用），电机不会因本次改动运转。
