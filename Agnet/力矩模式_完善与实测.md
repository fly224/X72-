# 力矩模式：根因修复与给定整形

测量时间：2026-11-17 06:47–06:56
固件：`Code=93524 RO=6428 RW=156 ZI=15404`（0 Error / 0 Warning）
状态：`cal=1 z=1 f=0x00`，齿槽前馈 `en=1`（对力矩模式无影响，`iq_ref` 通道独立）

---

## 1. 先说根因：力矩模式此前从未真正输出过

`servo_isr.c` 的电流环里，三路给定源是这么选的：

```c
float iq_ref = s_cur_iq_ref;
if (s_spd_en != 0U) {
    iq_ref = Servo_SpeedLoopStep(...);          /* 速度环 */
} else if (MechIdent_Refs(&iq_ref) != 0U) {     /* 机械辨识 */
    id_ref = 0.0f;
} else {
    (void)CurStep_Refs(&id_ref, &iq_ref);       /* 注释：非活动时原样返回 */
}
```

而 `CurStep_Refs` 的实现是：

```c
if (s_state == CS_IDLE) {
    *id_ref = 0.0f;
    *iq_ref = 0.0f;      /* ← 返回 0（"未接管"），但给定已经被抹掉 */
    return 0U;
}
```

**注释和行为是反的。** 纯力矩模式（`M`/`N` 或 `>iq`）走的正是第三个分支，
给定在进电流环前被清零。

现象具有极强的误导性：

| 观察点 | 看到的值 | 结论倾向 |
|---|---|---|
| `>` 查询 | `iq_tar=0.30 ramp=0.30` | 给定正常，环在跑 |
| 30025 遥测 +4（iq 给定） | `0.000` | 给定没到 |
| 30027 遥测 +16（iq 实测） | `0.02` | 没电流 |
| 30025 +28/32/36（ua/ub/uc） | 只有几十 mV 噪声 | 像功率级坏了 |
| `S` 状态 | `moe=1 cur=1` | 硬件在使能态 |

四个表里三个互相矛盾，很容易往硬件/采样/驱动方向查。

**修复**：`CS_IDLE` 时直接 `return 0U`，不动调用方的指针。
`CS_DONE` / `CS_PRE` 仍然写 0 并返回 1 —— 阶跃结束后强制回零是刻意的，
那时确实该接管。

顺带核对：`MechIdent_Refs` 在 `s_inj_en == 0` 时直接 `return 0U`、不动指针，
本来就是对的。只有 `CurStep_Refs` 这一处。

## 2. 新增的给定侧能力

### 2.1 `>` 数值命令：任意力矩给定

```
>0.35          → 进力矩模式并给 0.35 A（等价于 do_current(0.35)，联锁全部复用）
>              → 查询
```

返回：

```
[CMD] cur en=1 iq_tar=0.50 ramp=0.37 meas=0.33A T=0.034Nm lim=5.00 tau=500.00ms dead=0.00
```

四个电流值必须一起看：`iq_tar` 是命令层目标，`ramp` 是整形后进环的值，
`meas` 是实测。只看 `meas` 分不清"给定没跟上"还是"环路跟不上"。

`M`/`N`（±1.0 A 固定）保留，做快速点动用。

### 2.2 `"` 数值命令：给定斜坡时间常数

```
"20            → 20 ms 一阶低通（默认）
"0             → 直通，用于阶跃响应测试
```

**为什么需要**：1 A 阶跃对应的加速度是 Kt·Δi/J = 0.091/5.47e-5 ≈ 1660 rad/s²，
齿轮间隙和齿槽会被整个激起来。20 ms 把 d(iq)/dt 压到 50 A/s，
对应 8 Hz 带宽，仍在多数力控外环之上。

斜坡只在 20 kHz 电流环内做（不在命令层），实现是在 `iq_ref` 进 PI 之前插一阶低通。
`CurStep` 的阶跃测试会覆盖 `iq_ref`，所以斜坡不影响电流环整定。

**实测验证**（阶跃 0 → 0.5 A）：

| tau | 阶跃后 0.2 s | 0.4 s | 0.6 s | 理论值 |
|---|---|---|---|---|
| 0 ms | 0.50（瞬时） | — | — | 直通 |
| 500 ms | 0.20 | 0.30 | 0.37 | 0.197 / 0.275 / 0.350 |

实测电流 `meas` 与 `ramp` 贴得很紧（0.19 / 0.28 / 0.33），说明电流环跟随给定
没有额外滞后。

### 2.3 力矩估算与限幅

- `T = Kt · iq_meas`，**Kt = 0.0910 N·m/A**（= 1.5 × p × ψ，ψ 用实测 4.333 mWb）
- 与 `mech_ident.c` 的 `MI2_KT` 同源，避免"力矩输出"和"惯量辨识假设"两处自相矛盾
- `lim` 显示运行时限幅（默认 5 A，`Servo_SetCurIqMax` 可改，命令层暂未开放）

⚠ 注意 `SERVO_CUR_PSI = 7.59e-3` 是实测 ψ 的 1.75 倍，那个常量只用在 BEMF 前馈上。
**力矩换算不能用它**，否则力矩虚高 75%。这个不一致仍未处理（改它会动到速度环的
解耦前馈，需要单独回归）。

### 2.4 死区补偿接口（默认关闭）

死区 DTG=50 × tDTS(5.88 ns) = **294 ns**，占 20 kHz 周期的 0.59%，
折算电压 `0.0059 × 30.7 V ≈ 0.18 V`，除以 R=0.4 Ω 相当于 **0.45 A**。

`Servo_SetCurDeadGain(g)` 提供按电流方向（±30 mA 迟滞）的 vq 偏置补偿，
默认 0 = 关闭。**这次没有开**，原因见第 3 节的实测结论。

## 3. 实测：线性度

工况：空载（带减速器），每点 `>` 给定 → 稳定 0.7 s → 采 0.8 s，
iq 实测取 30027 帧尾段 60% 的均值。

| iq 给定 | iq 实测 | 偏差 | σ | rpm | 备注 |
|---:|---:|---:|---:|---:|---|
| 0.02 | 0.003 | −0.017 | 0.090 | 0.00 | 死区平台 |
| 0.05 | 0.042 | −0.008 | 0.094 | −0.01 | |
| 0.08 | 0.067 | −0.013 | 0.096 | −0.01 | |
| 0.12 | 0.093 | −0.027 | 0.086 | −0.01 | 最大偏差 |
| 0.20 | 0.205 | +0.005 | 0.105 | 0.01 | |
| 0.30 | 0.294 | −0.006 | 0.095 | 0.00 | |
| 0.45 | 0.445 | −0.005 | 0.118 | −0.01 | |
| 0.70 | 0.008 | −0.692 | — | 0.00 | **超速保护触发** |

**结论**：

1. **0.05–0.45 A 段偏差 ≤ 0.027 A**（最大 6% of 0.45 A，多数在 1% 内），
   稳态精度已经足够，不需要为它开死区补偿。
2. **0.02 A 以下有死区平台**（给定 0.02 只出 0.003）。这是死区的直接体现，
   但 20 mA 以下本来就在噪声/静摩擦量级，工程意义有限。
3. **0.70 A 不可用**：Kt·0.7 = 0.064 N·m 减去静摩擦后，空载电机几十毫秒就
   加速到 300 rpm 撞 `BSP_FAULT_OVERSPEED(0x20)`，MOE 封锁、故障锁存，
   必须 `X` 清除。这不是 bug —— 纯力矩模式本来就没有速度约束。

**因此死区补偿这次不开**：它改善的是过零畸变和小信号动态，
而稳态精度已由电流环积分兜住（偏差 ≤0.027 A）。要开的话必须先做一个
"给定扫描 + 实测电流"的标定，把 0.45 A 的理论值逐步收敛到实际值，
否则补 0.45 A 会把 20 mA 的给定直接推成过零振荡。

---

## 4. 力矩模式的固有约束（不是缺陷）

| 约束 | 值 | 原因 |
|---|---|---|
| 超速保护 | 300 rpm 固定 | 力矩模式没有速度环，空载必然一路加速 |
| iq 限幅 | 5.0 A（可设） | 硬件过流另有一套，这只是软件上限 |
| 位置漂移 | 无约束 | 纯力矩模式不保持位置，转子被外力拖动是正常行为 |
| 联锁 | C + Z + 无故障 | 电角度错时"正 iq"可能产生反向力矩 |

空载台架上力矩模式的可用给定区间是 **约 0–0.5 A**；再大就必须带载或堵转。

## 5. 复现

```bash
python torque_test.py COM27 --iqs 0.02,0.05,0.12,0.2,0.3,0.45   # 线性度
python torque_test.py COM27 --taus 0,5,20,50                     # 斜坡对比
python torque_test.py COM27 --step 0,0.5                         # 阶跃响应
```

测试脚本用 `collect_dual()` 同时解析 30025（给定/速度/母线）与 30027（id/iq 实测）。
**不能用 30025 的 +4 当实测** —— 那是 `s_iq_ref`（给定），拿它当实测会得出
"跟随完美"的错误结论。

每次超速保护后必须 `X` 清故障，否则后续 `>` 全部被拒。
