# 状态机加固（实现与验证 · 2026-11-20 23:15）

> 目标：在不改变对外语义的前提下，消除三处会导致"实际在跑的环与 src 不符"的隐患。
> 全部改动已编译烧录（`Code=116504`，0 Error 0 Warning）并通过实机不变式检查。

## 一、三条改动

| # | 位置 | 问题 | 改法 |
|---|---|---|---|
| 1 | `servo_isr.c:69` `src_enter()` | "读比较 → 写 → seq++"三步非原子；1 ms 任务（MIT 超时/deadman/故障）与主循环（命令）会并发改写，后写者覆盖前者，两次切换只留一个 seq | 用 `__get_PRIMASK/__disable_irq` 包住，只关十几个周期 |
| 2 | `servo_isr.c:153` `Servo_SetEnable()` | 只写 `s_enable`，`s_src` 交给各 `SetXxxMode(0)` 清；只要有一条路径只调了前者，就留下 `en=0 但 src=SPD` 的含糊态 | 封锁时同步 `src_enter(NONE)`；**不动 OPENLOOP**（辨识用开环跑，与 `s_enable` 无关，清掉会打断辨识） |
| 3 | `servo_cmd.c:2977` `mit_apply()` | ASCII 0x02 MIT 帧直接 `mit_engage()`，若正在位置/速度环里，位置环的 iq 会在一拍内换成 MIT 的 τ 输出，转子抽一下；MAVLink 30065 有 `prepare_switch` 先封锁 | 加同样的切环保护，只在"已使能且不在 MIT 环"时 `do_disable`，续帧不重复断输出 |

### 为什么第 1 条值得改

状态机是"单一真值"，一次丢失的切换意味着**实际在跑的环与 src 不符**。这类故障最难查：S 行显示 SPEED，实际电流环在跟位置环的给定。M4 的 32 位写本身原子，但 `if (s_src == v) return; s_src = v; s_src_seq++;` 这组不是。

编译与烧录：


实机不变式（`K` 行 `src=` 回读）：

| 步骤 | 结果 |
|---|---|
| 上电初始 | `src=NONE` |
| `>0` 力矩（缺 Z，被拒） | `[CMD] CUR refused: elec angle not aligned (send Z first)` |
| 拒绝后 | **`src=NONE`（未被污染）** |
| `=1000` 速度（缺 Z，被拒） | `[CMD] SPD refused: elec angle not aligned (send Z first)` |
| 拒绝后 | **`src=NONE`** |

"拒绝路径不改变状态机"是一条关键不变式：联锁拒绝时必须保持原状态，否则会出现"命令没生效但状态已经变了"。

## 三、状态机不变式（当前成立，改动时勿破坏）

1. `s_src` 是唯一真值，5 个使能标志全部由宏派生，任何地方不得单独置位
2. `POS ⊃ SPEED ⊃ TORQUE`，`MIT / OPENLOOP` 独立
3. 切换只能经 `src_enter()`，它保证原子且 seq 递增
4. 联锁拒绝时状态不变
5. 故障 / `en=0` / deadman → 必回 `NONE`
6. `OPENLOOP` 不受 `s_enable` 影响（辨识通道）
7. `ServoCmd_ActiveMode()` 用 `s_src` 直接判，不用派生量（否则 POS 会被报成 VEL）

## 四、故意没做的

| 项 | 原因 |
|---|---|
| `Servo_SetOpenLoop(1)` 抢占时清速度环积分 | 需要跨 700 行作用域（`s_spd_i_term` 定义在后面）。实际路径上都已清：辨识前要求 `armed=0`，而 `SetSpeedMode(0)` 会清零 |
| 把 ASCII 的 `=rpm` / `P` 也改成"自动先封锁再切" | ASCII 是调试通道，"必须先 D"是刻意的安全约束；MAVLink 才是给上位机用的、需要无感切环的那条路 |
| 给状态机加"故障态" | 故障一律回 NONE 并由 `f=` 区分原因，多一个状态会让派生矩阵复杂一倍而收益有限 |

## 五、局限

- 只验证了"拒绝路径不污染 src"；**正常切换路径无法实测**（`z=0`，所有闭环入口被拒）
- 临界区只防并发写，不防"读到旧值后决策"——调用方仍需保证"先查后写"在同一上下文
- MIT 切环保护只在 ASCII 帧路径加，`ServoCmd_CtrlMit` 本来就有，两条路现在一致
