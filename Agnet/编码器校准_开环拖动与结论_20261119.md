# 编码器校准：开环拖动通道建立与结论

- 日期：2026-11-19
- 对象：X72 FOC 伺服（STM32G474 + MT6835 21bit 磁编 + 谐波关节）
- 现象起点：执行 `^` 编码器自校准被中断后，电机无法产生有效转矩

---

## 一、结论先行

| 结论 | 判定依据 | 可信度 |
|---|---|---|
| 编码器 **SPI 通信、计数累计正常** | 30040 满 100 Hz；静止 2 s 内 `enc_sum` 变化 0；开环拖动时 `pos_sum` 累计 **22.6 圈** | 高 |
| **电机本体、功率级、电流环正常** | `N`（iq=−1 A）时 `idq` 精确跟踪 −1.00 A 持续 600 ms；开环拖动可把转子带到约 600 rpm | 高 |
| **电角度不可用**，且不是"固定零点偏置" | 12 个固定补偿角（−180°…+180°，步长 30°）扫遍整圈，响应 0/23/110/50/36/6.8/80/21/276/77/158/126 rpm —— 无规律、无单一峰值 | 高 |
| **MT6835 芯片级自校准在本机 FAIL** | `^` 开环拖到 600 rpm、转满 22.6 圈后芯片回报 `0x113[7:6]=2`（FAIL），并置 `f=0x02` | 高 |
| 单次极点对数辨识会把**错零点写进 Flash** | `ratio=14.79 (resid 0.21) < MI_RATIO_TOL=0.25` 被判可信 → `pn=15` → `finish_ok()` 用 15 当分母算 `zero` | 高 |

**一句话**：编码器在"数数"层面是好的，但**角度输出已经不可用**；固件侧的 `^` 自校准已经能真正把转子拖到 600 rpm，但**芯片自己判失败**——这一层已经超出固件能修的范围。

## 二、本次改动（都已编译 0 Error / 0 Warning 并烧录）

### 1. `^` 增加开环拖动通道（`encoder_cal.c`）

原来 `^` 只走速度闭环。闭环依赖编码器角度，一旦角度不可信就形成死锁：

```
修编码器 → 要 ^ 成功 → 要 400~800 rpm → 要速度闭环 → 要编码器角度 → 又回到起点
```

开环强制角（`Servo_SetOpenLoop`）**不读编码器**，正好打破循环。关键设计：

| 项 | 值 | 原因 |
|---|---|---|
| `EC_OL_IDREF` | 2.5 A | 1.5 A 时 0 圈（起动力矩不足） |
| `EC_OL_ACC` | 300 rad/s²（电） | **必须升频**：直接给 600 rpm（140 Hz）会全程失步，实测 `turns=0.00` |
| `EC_OL_RAMP_MS` | 4500 ms | 0→600 rpm 约需 2.9 s，留余量 |
| SETTLE 位置核对 | 3 s 内 ≥1 圈 | 转不动就报 `EC_ERR_SPEED`，不空等 30 s |

`s_ol_theta` 在 **20 kHz ISR** 里累加（`servo_isr.c` 的 `Servo_SetOLSpin`）。不能在 1 ms 任务里推进：600 rpm 对应 140 Hz 电频率，1 ms 更新一次等于每拍跳 50° 电角度，磁场是"跳"的不是"转"的。

### 2. 开环模式独立超速门限（`servo_isr.c`）

`SERVO_CUR_WMAX = 31.4 rad/s`（300 rpm）。开环要拖到 600 rpm，沿用这条会在起拖瞬间判超速。新增 `SERVO_OL_WLIM = 200 rad/s`（≈1900 rpm），只兜"完全失步/电流失控"。

### 3. 极对数硬校验（`motor_ident.c`）

```c
if ((ratio < ...) || (resid > MI_RATIO_TOL) || ...) fail;      /* 原有 */
if (s_res.ratio_int != (uint16_t)BSP_POLE_PAIRS) fail;        /* 新增 */
```

`MI_RATIO_TOL=0.25` 太松，`14.79` 会被接受成 15，接着用一个错分母算 `zero` 并写进 Flash，而 `S` 行仍显示 `z=1` —— **静默损坏**。本板极对数已知为 14，宁可让 Z 失败重试。

### 4. 新增 `-<deg>` 电角度补偿扫描命令（`servo_isr.c` / `servo_cmd.c`）

运行时改 `s_elec_off`（**不写 Flash**，掉电恢复 0），`K` 行回读 `eoff=`。用于现场判定"零点错"还是"编码器随位置失真"。

## 三、实测数据

### 3.1 电角度补偿扫描（2.5 A 力矩，每点 0.25 s）

| eoff(°) | 峰值 rpm | eoff(°) | 峰值 rpm |
|---|---|---|---|
| −180 | 0.0 | +30 | 79.5 |
| −150 | 0.0 | +60 | 21.2 |
| −120 | 23.0 | **+90** | **276.4** |
| −90 | 109.8 | +120 | 77.3 |
| −60 | 49.6 | +150 | 158.2 |
| −30 | 35.9 | +180 | 126.2 |
| 0 | 6.8 | | |

若只是零点偏置，应当只有一处出转矩、±90° 处为零。实测**几乎每个角度都有响应且大小无规律** → 误差随转子位置变化，固定补偿无效。

> 注：第一次用 1 A 扫描时 12 个点全为 0，那是**电流不足**（1 A≈0.091 N·m，接近起动力矩），不是角度问题。方法学上必须用足够电流，否则会得出错误结论。

### 3.2 `^` 开环拖动自校准

```
[CMD] EC start 600rpm 64turns ~7s (auto OL) DO NOT touch motor
     0.1s  转速 0.0 rpm
     2.1s  转速 0.0 rpm
     4.1s  转速 0.0 rpm
     6.2s  转速 0.0 rpm
[CMD] EC FAIL chip reported FAIL  chip=2  OL  turns=22.60
收尾 f=0x02
```

- `turns=22.60` 证明转子确实被拖动（`pos_sum` 累计，与编码器角度质量无关）
- `chip=2` 是**芯片自己**判定的失败（`0x113[7:6]=2`），不是固件判的
- 600 rpm 下 2 s 约 20 圈，与 22.6 圈吻合，说明拖动速度正确

### 3.3 现象对照

| 输入 | 结果 |
|---|---|
| `N`（iq=−1 A） | `f=0x00`，`idq` 跟踪 −1.00 A，**转速 0** |
| `M`（iq=+1 A） | 立即 `f=0x20`，`moe=0` |
| `W`（速度 30 rpm） | `moe=1` → 0.3 s 内 `f=0x20`，`iterm=−3.00` 顶限幅、`wmeas=0` |
| `Z` | `ratio` 在 13.97~14.79 之间跳动；`off` 在 −128.95°~+92.86° 之间跳 |

`Z` 是开环的（`Servo_SetOpenLoop`，1 ms 步进 120°），理论上与编码器角度无关；`ratio`/`off` 抖动说明 2 A 注入下转子**跟随不稳**（关节起动力矩大于 2 A 的 0.18 N·m）。

## 四、为什么判定为硬件层

1. 开环拖动能把转子稳定带到 600 rpm → 电机、驱动、母线都正常
2. 芯片在正确的转速区间、转够 22.6 圈后仍判 FAIL → 芯片内部自校准判据不通过
3. MT6835 自校准失败的典型原因：磁钢偏心/气隙异常/磁场强度超限/振动过大 —— 都是机械或芯片层面
4. `f=0x02` 来自 `STATUS[2:0] != 0`（`bsp_servo.c` 的编码器状态检查），即芯片自报磁场异常

**推论**：`^` 在这台机器上会反复失败，且每次失败都会把 EEPROM 里的补偿表留在坏状态 —— 这解释了"执行 `^` 之前一切正常、之后不再正常"的时间线。

---

## 五、局限（必须说明）

1. **没有拿到 MT6835 数据手册的 0x113 位定义与自校准判据细节**，`chip=2` 的具体失败原因（磁场弱/偏心/转速波动超限）无法区分
2. 未验证"闭环 600 rpm 下芯片是否能通过"——闭环需要可用角度，当前不可得
3. 未测磁钢的实际偏心/气隙，需要机械量具
4. `wmeas` 在开环拖动期间读 0，与 `pos_sum` 走 22.6 圈矛盾；已确认 `BspServo_GetThetaRad()` 每拍无条件执行，怀疑是 ASCII 占用 UART 期间遥测帧陈旧，**未最终证实**
5. Z 的 `ratio`/`off` 抖动可能同时包含"转子跟随不稳"与"编码器角度失真"两种因素，本次未能分离

## 六、建议

### 立即
1. **停止在这台机器上执行 `^`**：每次失败都会破坏 EEPROM 补偿表
2. 用 MT6835 官方上位机工具读取 `0x113` 全字节与校准状态，并尝试重写补偿表 / 恢复出厂
3. 若官方工具也判失败 → 换编码器小板；换后按 `C → Z → ^（完整跑完）→ 断电 >6 s → 上电 → Z` 走一遍，并确认 `Z` 输出 `ratio≈14.0 / pn=14`

### 恢复后
4. 用 `-<deg>` 命令做一次"电角度扫描"作为验收：应当在某一个角度附近出现明显峰值、且 ±90° 处接近 0。若仍然无规律 → 编码器仍不合格
5. `Z` 必须同时满足 `ratio∈[13.5,14.5] && pn==14`，否则不要继续（固件已硬卡）

### 保留的固件能力（与本次故障无关，可长期使用）
- `-<deg>` 电角度补偿扫描 + `K` 行 `eoff=` 回读（掉电失效，安全）
- `^` 的开环拖动通道：将来若速度闭环起不来，仍可把转子拖起来做诊断
- 极对数硬校验：防止错零点被写进 Flash

## 八、重要更正（2026-11-19 21:45，实测推翻前文结论）

前文第四节判定"电角度不可用、需换编码器"，**该结论是错的**。用 ASCII `=<rpm>` 数值给定（而非 `W` / `M` / MAVLink 30019）重测，速度闭环在**全转速段正常**：

| 目标 rpm | 实测均值 | σ | iq 均值 A | 故障 |
|---|---|---|---|---|
| 30 | 30.5 | 2.75 | 0.06 | 0x00 |
| 60 | 61.1 | 4.66 | 0.11 | 0x00 |
| 100 | 101.6 | 6.06 | 0.17 | 0x00 |
| 200 | 197.7 | 12.89 | 0.28 | 0x00 |
| 300 | 300.3 | 5.36 | 0.21 | 0x00 |
| 600 | 600.5 | 1.30 | 0.32 | 0x00 |
| 1000 | 999.7 | 6.30 | 0.51 | 0x00 |

1000 rpm 连续 60 s（0.35 s 保活）：均值 **999.97 rpm**，误差 **−0.03 rpm（−0.0027%）**，σ 5.54，iq 均值 0.446 A / 峰值 0.990 A，Tmot 24.94→26.19 °C，`f=0x00` 全程无故障。

### 为什么之前误判

1. **起步阶段的失败被当成了稳态失败**。`W` / `M` 的失败都发生在使能后 0.3 s 内；`=1000` 的失败则是 **2 s deadman 到期**（`K` 显示 `spd en=0`、`wref=0`），不是故障。没有保活就会误读成"跑不住"。
2. **电流不足以判断转矩**。1 A≈0.091 N·m，与谐波关节起动力矩同量级；静止时"给 1 A 不转"是正常的，不能推出角度错。
3. **固定偏置扫描不是受控实验**。每个 `eoff` 试点的转子起始位置都不同，得到的峰值本来就不可比，所以"无单峰"这个结论无效。
4. `Z` 的 `ratio_bad n=60/0` 是**开环 2 A 步进推不动转子**（不是角度失真）。但 `Z` 失败并不妨碍速度闭环运行——`s_enc_zero` 保持上次有效值即可。

### 正确的可用性判据

判"电角度是否可用"应该用**中高速闭环跟踪**，而不是静止/低速大电流：

- 发 `=600\r`，0.3 s 保活，观察 5 s：`|误差| < 1%` 且 `f=0x00` → 电角度可用
- 低速（≤100 rpm）出现偶发 `f=0x20` 时，先看是否**缺少保活**，再看 `1.5×|w_ref|+余量` 这条门限在低速下是否过窄

### 仍然成立的部分

- 编码器 SPI/计数正常、`^` 的开环拖动通道可用、`motor_ident` 的极对数硬校验有效（这三项与本次更正无关）
- 单次 R/ψ 辨识、Kt 温度补偿等历史结论不受影响
- **`^` 仍然不要随意执行**：芯片自校准在本机判 FAIL 这一点没变，且失败会破坏 EEPROM 补偿表
