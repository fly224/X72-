# 超速误判：高速切零速报 30019 状态错误

**日期** 2026-11-21 · **固件** Code=112468（修前 112356）· **验证** 复现→修复→回归全部实测

---

## 一、现象与真正的故障位

你看到的三个回执：

```
30019 ✗ 状态错误      ← status=3 WRITE_STATE_ERROR
30056 模式 3          ← 只是登记模式，不动作环
30054 未 armed（cw 0x00）
```

读板子得到的是 `fault=0x0020` —— **bit5 超速**，不是过压（`vbus=30.77 V` 正常，`cal=1 z=1`，`ps_diag=0`）。
（我上一条按能量估算判成过压，是错的；实测数据优先。）

---

## 二、根因：峰值保持用"给定"初始化，忽略了余速

`servo_isr.c` 里超速判据：

```c
wlim = 1.5 × max(|ref|, s_spd_wpeak) + 10 rad/s
```

而 `s_spd_wpeak` 在**进环那一拍**是这样种下去的（原代码 `servo_isr.c:1238`）：

```c
if ((enable != 0U) && (s_spd_prev == 0U)) {
    s_spd_wpeak = fabsf(r);      /* r = 本次给定 */
    ...
}
```

问题在 `s_spd_prev == 0U` 这个条件：`do_disable()` 会调 `Servo_SetSpeedMode(0, 0)`，所以**每次停止/故障封锁后 `s_spd_prev` 都归 0**。于是：

```
1000 rpm 稳态
→ 点停止（halt）→ do_disable → s_spd_prev=0，电机自由滑行
→ 0.25 s 后余速仍有 346 rpm（36.2 rad/s）
→ 给 0 rpm 重新进环 → s_spd_wpeak = |0| = 0
→ 门限 = 1.5×0 + 10 = 10 rad/s（95 rpm）< 36.2
→ 8 拍（0.4 ms）后置 BSP_FAULT_OVERSPEED
→ MOE 关 → 200 ms 后保活帧 30019 撞上 fault → status=3
```

同一处缺陷在 `Servo_SetPosMode()`（原 `:1289` `s_spd_wpeak = 0.0f`）也有：从速度模式带余速切位置保持，位置环 `v_cmd` 从 0 长起，门限同样只有 10 rad/s。

---

## 三、复现证据（修前固件）

`repro_entry_overspeed.py`，1000 rpm → halt → 0.25 s → 给 0：

```
[1] 已到速 996.7 rpm  en=1  fault=0x0000
[2] 余速 346.1 rpm（36.2 rad/s），en=0
[3] 30019 -> ok=True
    故障出现 t=0.027（27 ms）  fault=0x0020  rpm=261.9
      t=0.307  rpm=-6.21  iq=0.000  en=1  fault=0x0020
```

注意 `en=1` 但 `iq=0`：**这是第二个 bug**（见 §5）。

---

## 四、修复

`s_spd_wpeak` 的起点改成「给定」与「进环那一刻的实测余速」的较大者：

```c
// servo_isr.c:1248（速度模式）
{
    const float w_now = fabsf((float)s_dir_sign * BspServo_GetOmegaMech());
    const float w_cmd = fabsf(r);

    s_spd_wpeak = (w_now > w_cmd) ? w_now : w_cmd;
}

// servo_isr.c:1306（位置模式起环）
s_spd_wpeak = fabsf((float)s_dir_sign * BspServo_GetOmegaMech());
```

**为什么不会削弱失控保护**：

| 场景 | 修前门限 | 修后门限 |
|---|---|---|
| 静止起转给 1000 rpm | 1.5×104.7+10 = 167 | 同（余速≈0） |
| 静止起转给 0（编码器断线类失控） | 10 rad/s | 同（余速≈0） |
| 带 346 rpm 余速给 0 | **10 rad/s（误判）** | 1.5×36.2+10 = 64 rad/s |
| 停机后迟迟不停转 | 10 rad/s（3 s 后） | 峰值 0.5 s 时间常数衰减，3 s 后同样收回 10 rad/s |

最后一行是关键：余速只是把门限临时抬高，**衰减机制没动**，所以"停不下来"仍会在几秒内被抓。

## 五、第二个 bug：故障后 `armed` 不清

修前实测：`fault=0x0020` 已置位、MOE 已关、`iq=0`，但 `en=1 cw=0x01`。

原因：ISR 的故障分支只关 MOE，不动 `s_armed` / `s_src`；而 `ServoCmd_Poll()` 里没有"故障 → 封锁"的路径（grep 全工程，没有任何主循环调用）。

后果不只是显示错误：

1. 界面说"使能中"，30019 返回成功，电机却没输出；
2. 更糟的是清故障后再发控制字，`do_enable()` 会走 `already ON` 的幂等分支直接 `return`，**MOE 再也不会被重新放开** —— 只能先显式 disarm 一次才能恢复。

补在 `servo_cmd.c:3257`（和 deadman 同一层）：

```c
if ((s_armed != 0U) && (BspServo_GetFault() != 0U)) {
    do_disable("fault");
    return;
}
```

只在"已 armed 且有故障"时触发，正常路径零开销。

**这条未实测**：修好超速后没有可安全复现的故障源（过压要能量、欠压要断电、缺相要拔线）。只有代码审查 + 正常运动下不误触发（1000 rpm 稳态 `en=1` 保持）。要彻底验证需要一个故障注入接口，我没加（写故障位属于危险接口）。

## 七、顺带发现：上位机脚本的一个坑

`set_keepalive()` 要求 `setpoints_valid[mode]` 为真，所以**必须在第一次给定之后调用**。第一版复现脚本顺序写反了，保活静默失败（返回 `ok=False` 但没人检查），2 s 后 deadman 自动封锁——现象是"起转正常、两秒后自己停、`en=0`"，很容易误判成固件问题。已在脚本里改为先给定时再开保活，并把返回值打出来。
