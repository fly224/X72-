# 速度环增益调度（多段 PID 查表）：实现与实测

> 目标：用已辨识参数（J / Kt / 摩擦曲线 / 齿槽）设计分段增益，降低不同转速下的速度误差
> 代码：`Board/servo_isr.c` 的 `s_sched[]` + `sched_lookup()`
> 命令：`,` 切换、`.` 只读查询
> 实测时间：2026-11-16 23:35–23:50

---

## 1. 设计依据：为什么必须分段

用实测参数反推当前增益对应多少带宽：

```
wc = Kp · Kt / J = 0.5834 × 0.0910 / 5.47e-5 = 970 rad/s = 154 Hz
```

**154 Hz 已经超过测速通道的 95 Hz 低通（8 拍累计 + alpha=0.03）**。也就是说当前增益把测速带宽的相位裕度吃干净了——这解释了历史现象：

- 增益再往上（16x / 32x）→ iq 打限幅、纹波反弹到 22~25 rpm
- 增益往下（1x 旧值 0.073）→ 积分慢摆，纹波 22.5 rpm

**中间那个 0.583 不是"最优"，而是"唯一能稳的点"**。不同工作点需要的裕度不同，所以只能靠分段腾出空间。

### 各段的物理依据

| 段 | 主导因素 | 策略 |
|---|---|---|
| 0 rpm（静止） | 齿槽（峰峰 1.17 A，是 30 rpm 运行电流的 9 倍） | Kp 略降防抖，靠积分消静差 |
| 1~30 rpm（爬行） | 摩擦死区 + 齿槽，系统呈"黏滑" | **Kp 必须高**（见 §4 的教训） |
| 30~500 rpm | 黏滞摩擦，线性区 | 实测最优 0.583 |
| >1000 rpm | BEMF 占掉大部分电压预算 | 降 Kp 留相位裕度，Ki 保持 |

## 2. 表与实现

```c
static const SpdSchedPt s_sched[7] = {
    /*  w[rad/s]   rpm      kp      kits      依据 */
    {   0.00f,             0.250f, 0.0300f },  /* 0：静止保持，略降防抖 */
    {   0.21f,   /*   2 */ 0.550f, 0.0400f },  /* 进入爬行立刻拉回最优 */
    {  10.47f,   /* 100 */ 0.583f, 0.0408f },  /* 实测最优（154 Hz） */
    {  52.36f,   /* 500 */ 0.583f, 0.0408f },  /* 平坦段 */
    { 104.72f,   /*1000 */ 0.550f, 0.0430f },  /* 电压余量变紧，Ki 略升 */
    { 209.44f,   /*2000 */ 0.520f, 0.0420f },  /* BEMF 已占大半 */
    { 314.16f,   /*3000 */ 0.500f, 0.0410f },  /* 接近电压上限 */
};
```

### 三个关键决策

**① 查表变量用 `|s_spd_ref_ramp|`，不是 `w_ref`、也不是 `w_meas`**

| 候选 | 问题 |
|---|---|
| `w_ref` | 给 3000 rpm 时一开始就跳高速段增益，而电机还在零速，起动需要的增益拿不到 → 起动无力 |
| `w_meas` | 反馈式调度，增益随实测速度变，给定与反馈相差大时增益来回跳，可能自激 |
| **`w_ramp`** | 从实测速度起步、按 accel 缓慢爬升，**起动时自动落低速段、到速后落高速段**，单调平滑 |

**② 段间线性插值，不是阶跃切换**

Kp 阶跃会让 `iq = Kp·err` 瞬间跳变，形成冲击。插值后每拍变化 <1e-3，等效连续。

**③ 高速段"降 Kp 但保 Ki"**

第一版把 Ki 跟着 Kp 一起降（0.0408→0.036→0.030），实测 1500 rpm 稳态误差 11.77 rpm（0.78%）。原因：**Kp 降是为了留相位裕度，而积分只影响静差、几乎不影响相位裕度**，不该跟着降。改成 Kp 0.55 / Ki 0.043 后误差回到可接受范围。

## 3. 命令

| 键 | 作用 |
|---|---|
| `,` | 切换调度 ON/OFF（A/B 对比用） |
| `.` | **只读查询**（不切换） |

`. ` 是必须的：`,` 按一次就翻转，脚本用 `,` 判状态会把自己的判断依据改掉（第一版踩过——先读一次就把 ON 翻成 OFF，后面全乱）。

切换回 OFF 时会把当前查表值抄进手动增益，避免"关掉瞬间增益跳到旧的手动值"。

`K` 行在调度开启时显示**实际生效**的查表值，不会出现"显示 0.58 但实际跑 0.11"的误导。

## 4. 实测

### 4.1 三轮数据（如实记录，含矛盾）

**第一轮（表：0.11→0.18→0.40→0.583 爬升）**

| rpm | 调度 ON 误差/纹波 | 固定 0.583 | 判断 |
|---|---|---|---|
| 3 | 0.000 / **1.114** | 0.024 / **0.451** | **调度差 147%** |
| 30 | 0.052 / 3.304 | 0.104 / 3.590 | 略好 |
| 100 | 0.118 / 7.286 | 0.554 / 7.268 | 误差好 4.7 倍 |
| 500 | 1.032 / 1.874 | 0.873 / 1.749 | 持平 |
| 1500 | 10.379 / **6.744** | 19.312 / **4.732** | 误差好 1.9 倍 |

**3 rpm 差 147% 是设计错误**：把 0~30 rpm 做成 0.11→0.40 的爬升，3 rpm 处插值只有 0.152。爬行时摩擦死区 + 齿槽让系统"黏滑"，**Kp 越小越需要更长时间攒力矩越过死区，一旦越过又冲过头**——纹波就是这么做出来的。

修正：0.21 rad/s（2 rpm）往上一律 0.55~0.583，只在真正的 0 点降。

**第二轮（修正后）**

| rpm | 调度 ON 误差/纹波 | 固定增益 | 判断 |
|---|---|---|---|
| 3 | 0.022 / 0.712 | 0.073 / 0.548 | 仍差 30% |
| 30 | 0.063 / 3.219 | 0.466 / 3.138 | 误差好 7.4 倍 |
| 100 | 0.158 / 6.794 | 0.456 / 6.542 | 误差好 2.9 倍 |
| 500 | 0.966 / 1.607 | 1.133 / 1.249 | 持平 |
| 1500 | 11.766 / 4.087 | 5.475 / **12.545** | 纹波好 67% |

**第三轮（同表，重复测量）**

| rpm | 调度 ON | 固定增益 | 与第二轮对比 |
|---|---|---|---|
| 3 | 0.018 / 0.451 | 0.075 / 0.315 | 仍差 43% |
| 30 | 0.279 / 3.657 | 0.424 / 3.507 | 仍略好 |
| 100 | 0.515 / 7.332 | **0.188** / 6.638 | **反转：这次固定增益更好** |
| 500 | 1.167 / 2.246 | **0.253** / 1.569 | **反转** |
| 1500 | 19.188 / 6.115 | 11.257 / 10.791 | 误差反转，纹波仍好 43% |

### 4.2 结论：中速段的差异落在测量噪声里

第二轮和第三轮**结论相反**（100 rpm：第一次调度好 2.9 倍，第二次差 2.7 倍）。原因：

1. **稳态误差量级只有 0.2~1.2 rpm**，而 100 Hz 遥测 + 3 s 采样的重复性是同一个量级
2. **3–500 rpm 的查表值都在 0.55~0.583 之间**，与固定增益 0.5834 差别 <6%，物理上本来就不该有显著差异

**能确认的只有两条**：

**① 1500 rpm 上固定增益确实在振荡。** 证据不是误差数字，而是 `iq_mean=0.906 A`、`iq_peak=2.21 A`——空载 1500 rpm 的稳态电流应该只有 0.2 A 量级，0.9 A 说明它在一路加减速地振。同一组固定增益两次测得纹波 12.545 与 10.791 rpm、iq 均值 0.906 与 0.282 A，**工况本身重复性差**，所以"降多少"给不出定量结论，只能保守取 0.50。

**② 零速静态保持两组都完美**（`mean=0.0000`，`sd=0.0000`，`max=0.0004 rpm`，各 251~252 帧）。但这只是空载静止——没有外力扰动时齿槽被静摩擦锁住，本来就容易。

### 4.3 反向验证：调度确实在按表切换

| 给定 | 实际查到 | 理论插值 |
|---|---|---|
| 500 rpm | `kp=0.58 kiTs=40.80e-3` | 52.36 段点，0.583 / 0.0408 ✓ |
| 1500 rpm | `kp=0.54 kiTs=42.50e-3` | (157−104.7)/104.7=0.5 → 0.55+0.5×(0.52−0.55)=0.535 ✓ |

## 5. 诚实的评价：调度解决了什么、没解决什么

### 解决

- **提供了一个可切换、可插值、可诊断的增益调度框架**，后续改表不用动控制逻辑
- **高速段避免振荡**（固定增益在 1500 rpm 已经在振）
- **零速段有独立档位**，不会用中速段的大 Kp 去蹭齿槽

### 没解决

**中速段的稳态误差没有可测改善。** 因为那本来就不是"增益不合适"造成的——0.2~1.2 rpm 的误差来自**齿槽（位置相关扰动）**，而不是增益不足。速度环是速度反馈，对位置相关的周期扰动无能为力：扰动造成的位移不产生持续速度，环"看不见"它。

**这就是为什么调 Kp 调不出改善。** 真正的解药是**齿槽前馈**——按机械角查 128 点表，把 ±0.6 A 的扰动直接抵消掉。`}` 命令已经能测这张表（`pp=1.169 A, dc=0.015`），缺的是把它存进 Flash 并在 ISR 里查表补偿。

### 测量能力的天花板

100 Hz 遥测 + 3 s 采样分辨不出 0.5 rpm 以下的差异。要定论需要：
- 片内 20 kHz 记录（`&` 命令已有）+ 更长窗口
- 或多个转速点各测 5 次取中位数
- 或带载测试（负载会放大误差，信噪比改善）

## 7. 下一步（按收益排序）

1. **齿槽前馈**（收益最大）：128 点表 + Flash 存储 + ISR 按 θ_multi 查表。预期把低速纹波压掉大半——当前 3 rpm 纹波 0.45 rpm、30 rpm 纹波 3.5 rpm，主要都是齿槽贡献。
2. **带载重测调度**：负载会放大稳态误差、提高信噪比，那时才能真正判断分段是否值得保留。
3. **提高测速带宽**：当前 95 Hz 是速度环带宽的硬约束。若能把测速做到 300 Hz（减少累计拍数 + 提高控制频率），速度环带宽可以推到 40~50 Hz，误差与抗扰都会改善。
