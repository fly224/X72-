## 1. 先说那个阻断性 bug

### 现象（修复前）

固件上电约 **1.18 ms** 后整片 MCU 冻结：PWM 停在最后一拍占空比、20 kHz 电流环停摆、遥测永远只有第 1 帧。

### 根因

`HAL_UART_Transmit_DMA()` 在 NORMAL 模式下，DMA 搬运结束只是开始——它要清零 `CR3.DMAT` 再置位 `TC` 中断，由 `HAL_UART_IRQHandler()` → `UART_EndTransmit_IT()` 才把 `gState` 从 `BUSY_TX` 复位成 `READY`。

而 `Core/Src/stm32g4xx_it.c` 里**没有 `USART1_IRQHandler`**，`Core/Src/usart.c:147` 的 `HAL_UART_MspInit()` 却已经 `HAL_NVIC_EnableIRQ(USART1_IRQn)`。于是 TC 中断一挂起就落到 `startup_stm32g474xx.s` 的 `Default_Handler`（`b .` 死循环）。

### 两条硬证据（`MDK-ARM/X72_FOC/X72_FOC.map`，修复前）

```
USART1_IRQHandler   0x080002bf   Thumb Code   0   startup_stm32g474xx.o(.text)
Removing stm32g4xx_hal_uart.o(.text.HAL_UART_IRQHandler), (1614 bytes).
```

- 第一行：符号**大小 0 字节**，指向 Default_Handler；
- 第二行：`HAL_UART_IRQHandler` 没人引用，被链接器当死代码删掉。

### 修复（修复后同一文件）

```
USART1_IRQHandler   0x080082d1   Thumb Code   12   stm32g4xx_it.o(.text.USART1_IRQHandler)
HAL_UART_IRQHandler 0x080056f9   Thumb Code 1614   stm32g4xx_hal_uart.o(.text.HAL_UART_IRQHandler)
```

改动位置：`Core/Src/stm32g4xx_it.c:376`，写在 `/* USER CODE BEGIN 1 */` 区，CubeMX 重新生成会保留。

> **维护约束**：若将来在 CubeMX 里勾上 "USART1 global interrupt" 并重新生成，CubeMX 会在非 USER 区生成同名函数，必须删掉手写这个，否则报 `L6200E: Symbol USART1_IRQHandler multiply defined`。

## 2. 硬件链路（网表实证）

### 2.1 相关网络

来源：`Hardware/Netlist/pin_map.csv`、`net_report.md`

| 网络 | 连接点 |
|---|---|
| `UART_TX` | U4 pin44 **PB6**（USART1_TX）；CN8 pin5；U5 THVD1426 pin4 (D) |
| `UART_RX` | U4 pin45 **PB7**（USART1_RX）；CN8 pin6；U5 pin1 (R)；R41 10k 上拉 3V3 |
| `$1N325` | U5 pin2 (RE#) + pin3 (SHDN#) → R45 10k 上拉 **+5V** |
| `485_A` | U1 pin2；R43 10Ω ← U5 pin6 (A)；R46 120Ω；D10 TVS |
| `485_B` | U1 pin3；R42 10Ω ← U5 pin7 (B)；R46 120Ω；D10 TVS |

- **CN8 [HC-0.8-6PWT]** 是调试排线座：`1=GND 2=NRST 3=SWCLK 4=SWDIO 5=UART_TX 6=UART_RX 7/8=GND`
- **U1 [BX-GH1.25-3PWT]** 是 485 出线座：`1=GND 2=485_A 3=485_B`
- **U5 THVD1426DRLR**：3 V–5.5 V 供电（datasheet SLLSF87A），**AutoDirection**（方向由 D 引脚数据自动切换，MCU 不需要 DE/RTS）
- 板载 120 Ω 终端 R46 与 TVS D10 已常焊
- PB6/PB7 的 I/O 结构在 STM32G474 datasheet DS12288 Table 12 中是 **FT_c / FT_f**，即 5 V 容忍，THVD1426 的 5 V 域 RO 输出可直接接入

### 2.2 三条可选路径

| 路径 | 接法 | 结论 |
|---|---|---|
| **A. RS-485** | USB-RS485 → U1：`GND→pin1`、`A→pin2`、`B→pin3` | 完整双向，板子本来的设计意图；有终端、有 TVS、方向自动 |
| **B. TTL 单向（CN8）** | 只接 `GND` + `CN8 pin5(pin5=PB6)` | **可行，零冲突** —— 用于"只收不发"的联通验证，能跑完 A–E 全部判定 |
| **C. TTL 双向（CN8 pin5+pin6）** | 再接 `pin6(PB7)` | **有冲突**，原因见 2.3 |

### 2.3 为什么只接 pin5 可以、接 pin6 不行

关键在于两个脚的**驱动方向**：

| 脚 | MCU 侧 | 同时接到 | 谁在驱动这根线 |
|---|---|---|---|
| **pin5 / PB6** | USART1_TX（MCU **输出**） | THVD1426 pin4 = **D（输入脚）** | **只有 MCU**。THVD 的 D 是高阻输入，不反向驱动 |
| **pin6 / PB7** | USART1_RX（MCU **输入**） | THVD1426 pin1 = **RO（推挽输出）** | **THVD1426 在驱动**。SHDN# 经 R45 上拉到 +5V，芯片常使能，RO 一直推挽输出 5V 电平 |

所以：

- **只接 `GND` + `pin5`**：USB-TTL 的 RX 只是"旁听" MCU 的 TX，总线上只有 MCU 一个驱动器 → **完全安全**，横幅和 100 Hz 二进制流都能收到，`serial_link_check.py` 的 A–E 五项全部可判。
- **再接 `pin6`**：THVD1426 的 RO（5V 推挽）与 USB-TTL 的 TX（3.3V 推挽）对接，两个输出对打。空闲时都是高电平，靠 1.7V 压差灌电流；一旦 TTL 拉低，就是 5V 直灌 3.3V 输出。

> PB7 本身是 FT_f（5V 容忍，DS12288 Table 12），所以 THVD 的 5V RO 直连 MCU 没问题；问题不在 MCU 侧，而在"两个输出接在同一个节点上"。

**将来需要下行（发使能/位置指令）时，三选一**：

| 方案 | 操作 | 代价 |
|---|---|---|
| 走 485 | 用 USB-RS485 接 U1 | 需转换器，但零改板 |
| 关断 THVD | 拆 R45，把 `$1N325`（U5 pin2/pin3 焊盘）飞线到 GND | 芯片进 shutdown，RO 变高阻，TTL 可双向。需动板 |
| 拆收发器 | 热风取下 U5 | 最干净，但 485 功能一起没了 |

**不要在 CN8 上乱插通用 ST-Link 6P 排线**：标准 ST-Link 的 6P 是 `VDDC/SWCLK/GND/SWDIO/NRST/SWO`，与这块板的 `GND/NRST/SWCLK/SWDIO/TX/RX` 定义不同，插错会把 SWO 或 VDD 怼到 UART 脚上。

## 3. 三步操作

### 第 1 步：接线（二选一）

#### 方案 B —— TTL 单线，只收不发（最快，设备最少）

```
USB-TTL 模块                 目标板 CN8 (HC-0.8-6PWT, 0.8mm 间距)
  GND  ────────────────────  pin1  GND        ← 必须共地
  RX   ────────────────────  pin5  UART_TX (PB6)

  pin6 (UART_RX / PB7)  ───  悬空，绝对不要接
  模块的 TX             ───  悬空
  模块的 3V3 / 5V       ───  悬空，不要给板子供电
```

- 模块电平档拨到 **3.3 V**。PB6 输出 3.3 V，5 V 档的 RX 通常也能识别（阈值约 2.0 V），但 3.3 V 档最稳
- 参数：**921600 / 8 / N / 1 / 无流控**
- 这条线只能收，不能发。对"联通验证"完全够用——`serial_link_check.py` 本来就是只读的
- CN8 是 0.8 mm 间距贴片座，杜邦线插不进去，必须用配套线束把 pin5 和 pin1 引出来

#### 方案 A —— RS-485，双向（正式路径）

```
USB-RS485 转换器           目标板 U1 (GH1.25-3P)
  GND  ─────────────────  pin1  GND
  A(+) ─────────────────  pin2  485_A
  B(-) ─────────────────  pin3  485_B
```

- 转换器若自带 120 Ω 终端，与板上 R46 并联成 60 Ω，@921600 短距离一般仍通；若误码就换不带终端的型号
- A/B 极性反了通常一个字节都收不到，或收到全 0x00/0xFF

## 8. 局限与未验证项

1. **实物链路已通（2026-11-15 09:32 实测）**：经 ST-Link VCP `COM27` 收到 100 Hz 连续流，A–E 全 PASS，见 §9.3。仍未验证的是**下行**（RX 未启用）与**长线/RS-485 差分**场景（当前是 TTL 单线旁听）。
2. **PB7 的 5 V 电平**：datasheet DS12288 Table 12 标注 FT_f（5 V 容忍），但长期可靠性建议实测 RO 高电平与 PB7 电压。
3. **R46 120 Ω 常焊**：若外接转换器也带终端，总线负载 60 Ω。@921600 短距离通常无碍，长线需实测。
4. **ASCII 横幅与二进制流混发**：横幅全是 < 0x80 的 ASCII，不会与 0xFD 帧头冲突，解析器会把它计入"帧间丢弃字节"。若上位机把这部分当错误，属预期行为。
5. **`uart_link.c` 用阻塞发送**：仅用于启动阶段（< 3 ms），运行期不要调用，否则会与 100 Hz DMA 抢总线。
6. **RX 侧尚未启用**：本次只打通 TX。下行（使能、位置指令、参数读写）要等 `communication/` 协议层落地，届时才需要 RX DMA + 帧解析 + deadman。

## 9. 实测记录与联调中挖出的两个 bug（2026-11-15 09:32）

### 9.0 现场现象与定位方法

横幅只在复位后发一次，所以"连上去读 3 秒"永远是 0 字节。改用 **先开后台抓包、再烧录触发复位**（`serial_capture.py` + Keil `-f`），才把启动段完整录下来：

```
[T] sim:init begin → ok → bsp:init begin → dwt → opamp → adccal → adcdma → inj → enc → pwm ok, MOE=0 → init ok
[BOOT] bsp=OK tim6=OK fault=0x00 vbus=31.1V
[BOOT] telemetry on: 109 B/frame x 100 Hz = 10900 B/s
```

### 9.1 bug ②：横幅缓冲区越界 60 B → IBUSERR

| 项 | 内容 |
|---|---|
| 现象 | 横幅 380 B 打完，`[T]` 一条不出，`MAVLINK_FRAMES 0` |
| 首轮证据 | `CFSR=0x00000100`（IBUSERR）、`HFSR=0x40000000`（FORCED）、`MSP=0x20001AC0` |
| 排除项 | 栈没有溢出：`__initial_sp=0x20001B90`，fault 时仅用 208 B（栈共 2 KB） |
| 决定性证据 | 异常帧偏移 4 处：`R2=0x0000017C`（=380，横幅字节数）、`R12=0x3D3D3D3D`（`====`）、`PC=0x0A0D3D3C`（`\r\n===`）、`xPSR=0x01000000` |
| 根因 | `UartLink_Init()` 里 `char buf[320]` 装 380 B 文案，越界 60 B 覆盖返回地址，返回时跳进 ASCII 数据取指 |
| 修复 | 缓冲区改 512 B；**并给所有 `put_*` 加 `s_lim` 上界**（`LIM_SET(buf)` 预留 '\0' 位），杜绝以后改文案再犯 |
| 附带 | `it.c` 的 `HardFault_Handler` 现在会打印 CFSR/HFSR/MMFAR/BFAR/MSP/位名/栈窗口（纯寄存器轮询，不依赖 HAL 与 SysTick） |

> 这个 bug 是"加了诊断反而把系统搞崩"的典型：诊断代码本身的越界，被它自己的 fault dump 抓了出来。

### 9.2 bug ③：母线分压比写成 1/201，应为 1/21

网表 `pin_map.csv` 实测阻值（`0402WGF1003TCE` = 100 kΩ，`0402WGF1002TCE` = **10 kΩ**）：

```
VM ──R64(100k)── $1N184 ──R63(100k)── $1N185 ──R65(10k)── GND
                                        └──R66(330Ω)── VBUS_ADC ──C2(100nF)──GND
```

- 分压比 = 10k / (100k+100k+10k) = **1/21**
- 旧常量按"R65=1k"写成 1/201，母线读数放大 10 倍（判据里读出 294.64 V，实际 30.78 V）
- 修改：`Board/bsp_servo.h` 的 `BSP_VBUS_DIVIDER` → `1.0f/21.0f`

### 9.3 A–E 判定实测结果
