## 1. 位置环坐标不含编码器零点（实测 0.94 rad 固定偏移）

### 现象

上位机按“30090 单圈角 + 30040 计数”推算当前位置，再下发绝对目标，**每次都会差一个固定角度**：

| 测试 | 起始单圈角 | 指令 | 实测误差 |
|---|---|---|---|
| 1 | 2.8531 rad | +1.5 rad | **−931.7 mrad** |
| 2 | 3.1568 rad | +0.2 rad | **−940.5 mrad** |

两次软复位、两个不同位置，偏移恒定在 **0.936 ± 0.005 rad**——是常数，不是比例误差。

### 根因（代码）

多圈角的基准在上电时只播种一次：

```c
/* bsp_servo.c:978 */
if (s_tmulti_first != 0U) {
    s_tmulti_first = 0U;
    s_tm_base      = theta;          // theta = raw·k + s_enc_zero
    s_theta_multi  = theta;
} else {
    s_theta_multi = s_tm_base + pos_sum·(2π/2²¹);
}
```

而播种发生在 `BspServo_Init()`（`servo_isr.c:3297`，内部 `bsp_servo.c:415/417` 启动注入 ADC 中断）之后、`param_load_and_apply()`（`:3306`）之前。也就是说：

- ISR 第一次跑时 `s_enc_zero` 还是 **0**（参数页尚未加载）；
- `s_tm_base = raw_boot·k + 0`；
- 于是 `theta_multi = raw_now·k`，**与零点无关**；
- 而 30090 的 `pos` 是 `theta = raw·k + s_enc_zero`，**含零点**。

两者相差正好是 `s_enc_zero`（本机 ≈ 0.94 rad ≈ 53.8°）。

### 影响

- 上位机用 `p0 + counts×2π/2²¹` 算出的位置**不是**位置环坐标，绝对定位会稳定偏 `s_enc_zero`。
- 位置环自身是自洽的：目标与反馈都在同一坐标里，**所以“上一条目标 + 增量”的相对移动是正确的**（这也是历史 20 圈测试能通过的原因）。
- 由于基准是 raw，重做 Z **不会**改变位置目标坐标（与直觉相反）；改变的是 30090 的 `pos` 读数。
- 存在一个理论上的竞态：如果某次上电 ISR 尚未播种就先加载了参数，基准会含零点，帧原点会跳 0.94 rad。实测多次上电都稳定（ISR 总是先跑），但这是**未定义行为**，不能依赖。

### 建议修复（二选一）

**A. 改语义（推荐但影响面大）**：让 `BspServo_SetEncoderZero()` 同步平移 `s_tm_base += Δzero`，使 `theta_multi` 始终等于 `theta + 2πN`。
代价：齿槽表是以 `theta_multi` 为自变量的，帧一移，**已存的齿槽表相位全错**，必须重做 `}`；所有示教点也要重做。

**B. 加只读遥测（低风险，推荐先做）**：新增 **30100 AppPosStatus**，直接给出位置环坐标与状态：

```
theta_multi(f32) | pos_target(f32) | pos_ref(f32) | pos_err(f32)
v_ff(f32) | kp(f32) | vmax(f32) | errmax(f32)
state(u8) | comp_en(u8) | flags(u8) | rsv
```

上位机以后只用 30100，不再从 30090/30040 推算；顺带解决 §2。

## 2. 位置状态机与误差没有出口

`Servo_GetPosState()`（`servo_isr.c:1338`）只在 ASCII 回显里用（`servo_cmd.c:718/773/994/1221`），**没有进任何遥测帧**。

- 上位机无法知道 `IDLE/MOVE/HOLD/DONE/ERR`；
- 无法读 `p_ref / e / v_ff`；
- 到位只能靠 30040 计数稳定来猜（当前文档的做法）。

这不是“算错”，是接口缺项；30100 可一并解决。

## 3. 速度模式的加速度参数会限制位置环（跨模式耦合）

位置环输出的 `v_cmd` 不是直接进速度环 PI，而是先经过速度环的**斜坡**：

```c
/* servo_isr.c:2384-2403 */
if (s_pos_en) {
    s_pos_vcmd = PosLoop_Step(...);
    w_ref_model = s_pos_vcmd;          // 位置环输出
}
iq_ref = Servo_SpeedLoopStep(w_ref_model, om);
/* 内部：s_spd_ramp.a_max = s_spd_acc;  ramp_step(...) */
```

`s_spd_acc` 就是 30019 的 `acc_tar_p_ss`（速度模式的斜坡加速度）。于是：

> **在速度模式里把 acc 调小（比如 20 rad/s²），切到位置模式后，位置环的实际加速度也被压到 20 rad/s²**，而规划器仍按 200 rad/s² 前进 → 规划跑在前面 → 误差增长 → 超过 6 rad 触发 `BSP_FAULT_FOLLOW`。

估算：3 rad 行程、vmax=25、acc=20 时，误差在 ~0.3 s 就到 6 rad，必然跳故障。默认 acc=400 时不会显现，所以平时看不出来。

**建议**：位置模式下把斜坡的 `a_max` 取 `max(s_spd_acc, 400)`，或直接旁路斜坡（位置规划器已经限了 200 rad/s²，且 `profile_start(p_meas, v_meas)` 保证速度连续，不会产生阶跃）。

## 4. 目标补偿的标定依据已失效

`pos_loop.h:143`：

```c
#define POS_COMP_DFLT  (0.01998f)   /* 标定值 = 4121.3" 均值 */
```

但 `pos_loop.c` 的 P/I 段注释已经写明，那个 −4123" 恒定偏差的根因是 **Ki=0 时抗饱和回灌仍执行**，把 `i_term` 顶到 −2.0 rad/s，等效位置偏差 `2.0/Kp = 0.02 rad`。该 bug 已于 2026-11-18 修掉（`if (s_ki > 0) {...} else { s_i_term = 0; }`）。

修复后的 20 圈实测（`重复定位精度_20圈与90度摆动.md`，2026-11-18）：

```
正向 +20 圈  均值 +3.7"    反向 −20 圈  均值 +9.8"
```

**没有 0.02 rad 的恒定偏差了。**

所以现在 `comp_en=1` 不再是“补掉少走量”，而是**让每次定位多走 20 mrad（1.15°）**。默认 `comp_en=0` 所以没暴露，但接口还在，是个哑雷。

**建议**：把 `POS_COMP_DFLT` 改为 0，并在 30082 的 `comp_mrad` 写入时拒绝非 0 值（或保留但注释“已废弃”）。至少要把默认值清零。

## 5. Kp 允许 1，但低 Kp 必然触发跟随故障

纯 P 环的稳态跟踪误差 = `v/Kp`。`vmax=25`、`errmax=6` → **Kp < 4.2 时，只要跑到 vmax 就必然超差**；Kp=1 时误差 25 rad，一动就跳。

`PosLoop_SetKp()` 的下限是 1（`pos_loop.c:312`），没有和 `vmax/errmax` 联动。

**建议**：下限改为 `max(1, 2·vmax/errmax)`（当前参数下 ≈ 8.3，取 10 更稳），或写入时若 `vmax/Kp > 0.5·errmax` 直接拒绝并提示。

---

## 6. 进位置模式会覆盖手动速度增益

`do_pos()` 在装配时调用 `apply_spd_gains()`（`servo_cmd.c:754`），它无条件把 `CMD_SPD_BASE_KP × K档` 写进速度环。

如果用户此前用 `sched_en=0` + `spd_kp` 手调过速度环，**切一次位置模式就被覆盖回 0.583**。`do_speed()`/`do_enable()` 同样如此（`:632`、`:841`）。

**建议**：`apply_spd_gains()` 在 `sched_en==0` 时不要写（尊重手动值），或至少在进环回显里提示“已重套档位增益”。

## 9. 复现脚本要点

```python
# 1) 软复位，确保 counts≈0 时读 p0
lk.action(2); sleep(3); lk = connect()
p0 = lk.ctrl_status()["pos"]
K = 2*math.pi/2**21

# 2) 进位置模式并使能
lk.set_mode(1); lk.set_controlword(0x0F, 0)

# 3) 用 30090+30040 推算位置发绝对目标
P = p0 + 0.2
lk.set_pos_speed(pos_rad=P)
sleep(2)
now = p0 + lk.pos_counts()*K
print("误差", (now-P)*1000, "mrad")     # 实测 ≈ -940 mrad
```

### 10.2 第 7 条：到位判据永不置位（新发现）

30100 上线后第一次跑位置模式，`st` 一直在 MOVE。逐项量化：

```
|e|    : min 0.68  max 4.78  mean 3.14 mrad   （窗口 5 mrad，勉强）
|v_meas|: max 19.954 rad/s                    （窗口 0.5 rad/s，20 拍里 19 拍超）
```

**根因**：静止测速（编码器差分）的噪声尖峰能到 20 rad/s，用 `|v_meas| < 0.5` 做硬门限等于要求“噪声不能存在”，于是位置停稳了也判不成立。这个缺陷在 30100 之前**无法被发现**——没有 `settled` 出口，谁都不知道到位标志从未置位过。

**修法**：去掉速度判据。防“路过目标被误判到位”改用时间窗——穿越时 `|e|` 会在几毫秒内涨出 10 mrad，不可能连续维持 100 ms。

### 10.3 一个使用层面的坑（不是固件 bug）

`set_keepalive(True, mode, hz)` 的第二个参数是**模式**。位置模式必须传 1；传 3（速度）时保活发的是速度给定，位置环 deadman 2 s 到期被封锁，现象是“走到一半自己停、定位差 41 mrad、`st` 掉回 IDLE”。第一次测 30100 时踩了这个坑，误以为是位置环问题。
