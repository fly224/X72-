# 目标补偿标定：实现、接口与实测结论

日期：2026-11-18
对象：X72 关节模组（STM32G474 + MT6835 21 bit，母线 30.77 V，空载）
位置环：Kp=100，Vmax=25 rad/s，Amax=200 rad/s²，梯形规划

---

## 结论

1. **标定成功**：行程 ≥1 圈时，实际停止位置稳定地比指令少 **4125″（0.01998 rad）**，
   且与行程无关（1/2/4/8/20 圈都是 4125″±5″）。
2. **补偿实现 + 对外接口完成**：补偿量写入规划目标，`P` 回显可读，
   二进制帧 `0x04` 可读写三个参数。
3. **但实测发现补偿会破坏重复性**，所以**默认关闭**：

| 同段 20 圈行程（A=1.95, B=127.62），n=20 | mean | σ | range |
|---|---|---|---|
| 补偿关闭 | −4123.2″ | **28.5″** | 135.5″ |
| 补偿开启 | −66.5″ | **245.2″** | 826.6″ |

**均值被拉回 0，σ 恶化 8.6 倍。**

4. **根因**：停止点由"齿槽 + 摩擦"的微观地形决定，0.02 rad 的位移足以把落点
   从一个"稳定坑"挪到"不稳定斜坡"。**σ 本身是位置相关的**——同一段行程上
   A=0.124/B=125.79 处 σ 只有 5.3″，A=1.95/B=127.62 处是 28.5″。

   也就是说："少走 0.02 rad"和"停得稳"是同一件事的两面——落点稳定恰因为它
   卡在坑里，而坑就在目标前面 0.02 rad 处。硬把它推到目标，反而失去了坑。

## 一、标定方法与数据

### 1.1 方法

`pos_offset_scan.py`：固定起点 A，对每个行程 d 做"正向到达 + 反向到达"各 n 次，
每次到达后回 A（避免多圈累积）。到达后保活 6 s（每 1.35 s 重发同一目标），
末尾 0.32 s 用 30040 的 `enc_sum` 采样，取末 5 帧均值。

偏差定义：`dev = (enc_B − enc_A) − d`，即"实际行程 − 指令行程"。

### 1.2 数据（n=2，Kp=100）

| d [rad] | d [圈] | fwd 偏差 | rev 偏差 | \|偏差\| 均值 |
|---|---|---|---|---|
| 1.5708 | 0.25 | +132.7″ | −14.7″ | 74″ |
| 3.1416 | 0.50 | −577.7″ | −8.2″ | 293″ |
| **6.2832** | **1.00** | **−4141.2″** | **+4109.0″** | **4125″** |
| 12.566 | 2.00 | −4142.8″ | +4109.3″ | 4126″ |
| 25.133 | 4.00 | −4143.4″ | +4108.8″ | 4126″ |
| 50.265 | 8.00 | −4137.7″ | +4106.6″ | 4122″ |
| 125.664 | 20.00 | −4142.6″ | +4109.8″ | 4126″ |

### 1.3 两个判读

**① 是"少走"不是"过冲"**：fwd 为负、rev 为正，符号相反幅度相同，
说明两个方向都停在离起点更近的位置。

**② 是阈值特性，不是行程线性**：d ≥ 1 圈后偏差饱和在 4125″，
d < 0.5 圈时只有几十到几百角秒。阈值落在 0.5~1 圈之间（取 5.0 rad）。

**这决定了补偿模型**：不能用 `k·d` 的比例模型，只能用"行程阈值 + 常数"。

## 二、补偿实现

### 2.1 算法

补偿加在**规划器目标**上，不改用户指令值：

```c
// PosLoop_Step() 的 restart 分支
s_travel  = fabsf(s_p_tgt - p_meas);
s_p_tgt_c = s_p_tgt;
if (comp_en && comp > 0 && s_travel > comp_min) {
    s_p_tgt_c += (s_p_tgt > p_meas) ? comp : -comp;   // 朝运动方向多走
}
profile_start(&s_pf, (double)p_meas, v_meas);
profile_set_target(&s_pf, (double)s_p_tgt_c);
```

为什么用 `restart` 分支而不是 `PosLoop_SetTarget`：行程必须用**实测位置**算，
而 `SetTarget` 在命令上下文执行，拿不到当拍的实测位置。

为什么补偿不写回 `s_p_tgt`：对外回显与用户指令保持一致，
诊断量 `dev` 才会显示"补偿后的残余偏差"，便于评估补偿效果。

### 2.2 参数

| 参数 | 默认 | 含义 |
|---|---|---|
| `comp` | 0.01998 rad | 补偿量（标定值 4121.3″ 均值） |
| `comp_en` | **0（关闭）** | 见第三节的实测警告 |
| `comp_min` | 5.0 rad（0.8 圈） | 行程低于此值不补偿 |
| `POS_COMP_MAX` | 0.05 rad | 可设上限 |

### 2.3 修改的文件

| 文件 | 改动 |
|---|---|
| `pos_loop.h` | 新增 `POS_COMP_*` 宏 + 标定表与警告注释 |
| `pos_loop.c` | 新增 `s_p_tgt_c`/`s_travel`/`s_comp*`，restart 分支算补偿，getter/setter |
| `servo_cmd.c` | `P` 回显加 `cmp=`/`ce=`；新增 0x04 帧接收与应答 |

## 三、对外控制接口

### 3.1 位置指令（已有）

```
P<rad>\r        绝对定位（编码器坐标系，多圈），自动应用补偿
P\r             保持当前位置
```

应答含补偿状态：

```
[CMD] POS upd tgt=2.0000 ref=2.0000 e=0.0016 st=1 en=1 em=6.00 iv=0.000 cmp=19.98mr ce=0
                                                                        └─补偿量─┘ └使能
```

`st`：0=IDLE 1=MOVE 2=HOLD 3=DONE 4=ERR
`em`：跟随误差上限（rad）
`iv`：位置环积分项（rad/s，当前恒 0，积分默认关闭）

### 3.2 补偿参数帧 `0x04`（新增）

可打印字符已全部占满，补偿参数必须能被外部控制器以数值方式读写，
所以用与 MIT 帧同一套约定的二进制帧。**共 7 字节**：

| 偏移 | 内容 |
|---|---|
| 0 | `0x04` 帧头 |
| 1 | `cmd`：0=补偿量(rad) 1=使能(0/1) 2=行程阈值(rad) |
| 2..5 | `f32` 小端 |
| 6 | 校验和 = **byte[1] + byte[2] + … + byte[5]**（不含帧头，与 MIT 帧的"payload 字节和"一致） |

应答是一行 ASCII：

```
[CMD] PCMP comp -> 19.98mrad
[CMD] PCMP en -> 1
[CMD] PCMP min -> 5.00rad
[CMD] PCMP bad cmd 9          <- cmd 越界
```

**Python 示例**：

```python
import struct
def posf(ser, cmd, val):
    buf = bytearray([0x04, cmd]) + struct.pack('<f', val)
    buf.append(sum(buf[1:]) & 0xFF)      # 不含帧头
    ser.write(bytes(buf))
```

**已验证**：写入 → 回读一致、使能 0/1 切换、越界 cmd 报错、半帧 50 ms 超时自动丢弃、
`P` 回显 `cmp=`/`ce=` 与帧写入同步。

## 四、实测：补偿的副作用

### 4.1 同段行程 A/B

条件：A≈1.95 rad，B=A+20 圈，n=20，其余参数不变。

| 配置 | mean | σ | range |
|---|---|---|---|
| `ce=0`（关闭） | −4123.2″ | 28.5″ | 135.5″ |
| `ce=1`（开启） | −66.5″ | **245.2″** | 826.6″ |

**均值修正到位（−4123 → −66），但 σ 从 28.5″ 涨到 245″。**

### 4.2 三层对照

| 条件 | σ |
|---|---|
| A=0.124 / B=125.79，无补偿（前一轮测试） | **5.3″** |
| A=1.95 / B=127.62，无补偿 | **28.5″** |
| A=1.95 / B=127.64（补偿 +0.02） | **245.2″** |

**同一台机器、同一套参数，仅目标位置差 1.9 rad 或 0.02 rad，σ 就差 5~46 倍。**

这直接证明：**σ 是位置相关的**，不是一个可以独立优化的常数。

### 4.3 为什么补偿反而更差

停车过程是"减速 → 过冲 → 回退 → 被摩擦/齿槽锁住"。落点稳定，
是因为它恰好卡在某个齿槽-摩擦的"势阱"里（需要的挣脱力矩大）。
无补偿时，电机少走 0.02 rad 后停住——**那个位置就是阱底**。

补偿把目标推前 0.02 rad，电机多走一点，落点移到"阱壁"上：
挣脱力矩小，微小的电流噪声就能推动它，于是停点分散。

**这是"定位精度"与"重复定位精度"的固有权衡在这个系统上的具体表现**：
阱底的可重复性最好，但它不在指令位置上。

### 4.4 与齿槽前馈的关系

齿槽前馈在速度环里，靠 `w_ramp` 门控——**停止时 `w_ramp=0`，前馈为 0**，
所以停车瞬间没有齿槽补偿。若要让它在零速生效，需要把齿槽力矩折算成
等效位置偏置（`Δθ = τ_cog/(Kp_pos·Kp_spd·Kt)`）并叠加到 `p_ref`。

MIT 那轮试过"强制全量齿槽前馈"，保持误差从 7.2 翻到 14.2 mrad ——
零速下的齿槽补偿必须非常小心，这也是本轮没有采用的直接原因。

## 五、结论与建议

### 5.1 当前交付

- **标定数据**：`pos_offset_scan.py` + 本文档 1.2 节，可复现
- **补偿实现**：`pos_loop.c`，行程阈值 + 常数，参数可运行时改
- **对外接口**：`P` 指令 + `0x04` 参数帧，已逐项验证
- **默认配置**：`comp=0.01998 rad`、`comp_en=0`（关闭）、`comp_min=5.0 rad`

### 5.2 建议

| 需求 | 做法 |
|---|---|
| 要重复定位精度（±0.01°） | 保持 `ce=0`，用 Kp=100 的现配置（σ 5~28″，随位置） |
| 要绝对定位精度 | **外部闭环**：上位机读 30040 的 `enc_sum`，把残差累加进下一条 `P` 指令。比开环补偿可靠，因为闭环能适应落点的位置相关性 |
| 特殊工况确认落点稳定 | 可临时 `ce=1` + 调整 `comp`，但必须实测 σ 后再用 |

**不建议**：把 `comp` 当作"标定一次永久有效"的修正量。它的有效性与落点位置强耦合，
换行程、换起点、换温度都可能失效。

### 5.3 外部闭环的伪代码

```python
tgt = 10.0                      # 目标（rad，控制器坐标）
for _ in range(3):              # 2~3 次迭代足够
    send(f"P{tgt:.4f}")
    wait_settle()
    actual = read_enc_sum() / 2**21 * 2*pi + OFFSET
    tgt += (tgt_cmd - actual)   # 把残差补进下一条指令
```

残差收敛到 σ 量级（5~28″）后停止，不要追求 0——那会掉进 4.3 说的"阱壁"。
