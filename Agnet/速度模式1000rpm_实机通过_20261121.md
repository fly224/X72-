## 四、两个必须记住的事实

### 4.1 板上跑的是**旧固件**，不是昨晚那版

Z 的回显是：

```
[CMD] IDENT start id=2.00A: step120x60 then sweep2x, ~9s
[CMD] IDENT FAIL ratio_bad n=60/0 moe=0
```

- `~9s` 是**改动前**的文案（昨晚改成 `~22s`）
- FAIL 行没有 `ratio / res / mdeg` 字段（昨晚加的诊断）

结论：昨晚 23:32 烧进去的「150 ms 稳定时间 + 连续拖动法 + 诊断打印」**不在板上**，
板子当前是更早的版本（60 ms 阶跃法）。所以 `Z` 仍然 `ratio_bad`。

### 4.2 `z=1` 是 Flash 存档恢复的，不是这次标定出来的

`z` 是纯 RAM 变量，复位清零；能读到 1 是因为上电时从参数页读到 `PS_FLAG_ZERO`
（`servo_isr.c:2638`）。**这个零点是 V 相还正常时标定的，现在仍然有效**——
所以速度模式能跑。

**风险**：一旦闪存参数页被擦（`UV4 -f` 下载、`SAVE_PARAM` 异常、或手动清参），
`z` 就会永久为 0，而当前固件的 `Z` 又过不去 —— 届时速度模式会再次锁死。
昨晚就是这个状态。

## 五、建议的处理顺序

1. **先不要烧固件**。当前这套（V 相正常 + 旧固件 + Flash 里的零点）是能跑的，
   跑 1000 rpm 已验证
2. 如果要让 `Z` 自恢复能力回来，需要把昨晚那版（150 ms + 连续拖动）重新烧进去，
   但要接受"烧录会擦参数页 → 需要重做 C 和 Z"的代价。烧之前先确认这一点
3. 长期应把「下载不擦参数页」修掉（Keil Options → Utilities → Settings →
   Download Function 改成 `Erase Sectors` 而非 `Erase Full Chip`），
   否则每次升级固件都要重做整套标定
4. 若要复核速度环在全速段的表现，可用同一脚本扫几档：
   `python bringup_1000.py COM27 500 20` / `1000` / `1500`

## 六、局限

- 只跑了 20 s、单一转速（1000 rpm）空载；未做长时间温漂复测
- 转速取自固件 `K` 行的 `wmeas`（编码器 8 拍累计 + 95 Hz 低通），不是外部仪表
- `z=1` 的零点来自历史标定，其线性度未在本轮重新验证
- 板上固件版本未核实具体 commit/编译时间，仅从回显文案与缺失字段推断为改动前版本
- 未测量相电流波形与相电压波形，无法给出效率/谐波数据
