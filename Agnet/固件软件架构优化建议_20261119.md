# X72 电机固件软件架构优化建议

- 日期：2026-11-19
- 范围：`Firmware/FM_Servo_V3/embedded_project/STM32G474_App/Board`（21 个 .c / 20 个 .h / 14962 行）
- 立场：不重写、不换 RTOS、不先搬目录；按"正确性收益 / 风险"排序，分阶段小步改

---

## 一、结论先行

1. **最大的结构缺陷不是分层不清，而是"辨识链路没接到控制律上"**。`ParamBlob` 存了 `r_ohm / l_h / psi_wb`，控制律却用编译期常量，代码注释自己写着"控制律用的 `SERVO_CUR_PSI` 是编译期常量"。改参数必须重编译，`@`/`+` 测出来的值对行为零影响。
2. **第二缺陷是"执行器没有归属"**。6 个辨识/校准模块各自有状态机，都能直接开 MOE、改开路角、写编码器零点，没有互斥。今天 `^` 一中断就把 EEPROM 补偿表写坏、整机失效，是这一缺陷的直接后果。
3. **第三缺陷是"模式用一组布尔表示"**。9 个 `*_en` 交叉组合出大量非法状态，`en=1 / moe=0` 这种含糊态在代码注释里已被点名，并已实际产生过 bug（切环失败、MIT 误报 active）。

## 三、缺陷清单（含证据与后果）

### 缺陷 1：辨识参数不进控制律

```c
param_store.h:58-65   float r_ohm;  l_h;  psi_wb;   /* 已存 Flash */
servo_isr.c:280-282   #define SERVO_CUR_LD (85.0e-6f)
                      #define SERVO_CUR_LQ (85.0e-6f)
                      #define SERVO_CUR_PSI (4.333e-3f)
servo_isr.c:235       #define SERVO_KT_NM_PER_A (0.0910f)
servo_isr.c:2359      "只恢复到一个缓存里供回显；控制律用的 SERVO_CUR_PSI 是编译期常量"
```

连带后果：`SERVO_CUR_KI_TS` 按 **R=0.4 Ω** 设计，实测 R=0.28 Ω，**静态失配 43%**，但改不了——它在编译期。

**这不是"不够优雅"，是"补参数补不动"**：任何基于实测参数的整定都得改代码重烧。

### 缺陷 2：执行器无归属（今天事故的根因）

6 个模块都能独立 `BspServo_PwmEnable(1)`、`Servo_SetOpenLoop(...)`、`BspServo_SetEncoderZero(...)`。没有任何"当前谁在占用执行器"的记录。

今天的故障映射：

| 现象 | 架构根因 |
|---|---|
| `^` 中断 → EEPROM 补偿表损坏 → 后续全部失效 | 辨识模块可在任意时刻抢占执行器，且无"未完成即毒化"的保护 |
| `@` 后紧跟 `+` → `FI FAIL fault` | 模块间无前置/互斥契约 |
| `C` 后紧跟 `Z` → `pn=13 / ratio=12.84` | 同上，无"前置就绪"声明 |
| `Z` 用 `pn=15` 算零点写 Flash（`z=1` 却不出力） | 无单一"标定有效性"校验层（本次只做了局部补丁） |

### 缺陷 3：模式是一组布尔，不是状态机

```c
s_spd_en / s_pos_en / s_cur_en / s_mit_en / s_ol_en / s_olv_en / s_rec_en / s_harm_en / s_ff_en
```
9 个布尔 → 512 种组合，其中大部分非法。已产生的实际 bug：
- 力矩判定要写 `IsCurrentMode() && !IsMit && !IsSpeed && !IsPos`（排除法，漏一个就错）
- `en=1 / moe=0` 含糊态需要专门注释提醒
- MIT 装配失败仍返回 `active=12`（误报成功）

### 缺陷 4：命令层双路径

ASCII（57 个单字符）与 MAVLink（30054/30056/30019/30025/30065…）各自实现权限、联锁、模式装配。今天实测同一目标转速：
- `=30` → 正常
- MAVLink `mode=3 + 30019` → 一度 `f=0x20`

行为不一致说明**校验逻辑写了两遍**。

### 缺陷 5：诊断通道将到顶

`S` 行 187/200 字符。本次加 `ktc=` / `eoff=` / `tau=` 已经挤到边缘。下一次加字段就必须删旧字段。

### 缺陷 6：控制文件承担系统初始化

```c
servo_isr.c:2385   ServoCmd_Task1ms();
servo_isr.c:2502   ServoCmd_Init();
servo_isr.c:2505   AppParam_Init();
servo_isr.c:2506   MavHost_Init();
```
"ISR 文件"实际是系统集成点，没有独立的 `system_init` 层。

## 四、目标架构

```
接口层     ASCII parser ─┐
                         ├→ Cmd_Router（唯一门卫：权限/联锁/模式/应答）
           MAVLink parser┘
                ↓
服务层     Ident 服务 × 6 + 执行器占用仲裁（Act_Acquire / Act_Release）
                ↓
控制内核   foc_current / loop_speed / loop_pos / mode_mit
           纯函数：step(setpoint, feedback, params*) → duty
                ↓
参数快照   ParamSnapshot（ParamBlob → 只读双缓冲），控制律按快照取值
                ↓
BSP/HAL    PWM / ADC / SPI 编码器 / NTC（只访问硬件，不含策略）
```

关键约束：
- 控制内核**不包含任何 `#define` 调参常量**，全部来自 `ParamSnapshot`
- 控制内核**不引用** `ServoCmd_*` / `MavHost_*` / `AppParam_*`
- `ParamSnapshot` 双缓冲 + 序号，20 kHz 内只读指针，不加锁
- 服务层的每个模块必须 `Act_Acquire` 成功才能动执行器，异常路径统一 `Act_Release`

## 五、分阶段改造

### P0-1 参数快照（最高优先，正确性收益最大）

| 项 | 内容 |
|---|---|
| 新增 | `param_snapshot.c/h`：`struct { float ld, lq, psi, kt, r, spd_kp, spd_ki_ts; uint32_t seq; }` |
| 改动 | `servo_isr.c` 的 4 处常量改为读快照；`ParamStore_Load` 后填充快照 |
| 兼容策略 | **快照默认值 = 现有常量**，第一步保证行为逐位不变；再逐项切换并复测 |
| 验收 | 发 `+` 后 `K` 行 ψ 变化 → 力矩换算立刻跟着变；阶跃响应超调/上升时间与改前一致（±5%） |
| 风险 | 中等。动的是电流环增益来源，必须每切一项就复测带宽与超调 |

### P0-2 执行器占用仲裁（防破坏性故障）

| 项 | 内容 |
|---|---|
| 新增 | `actuator.c/h`：`Act_Acquire(owner_id)` / `Act_Release(owner_id)` / `Act_Owner()` |
| 改动 | 6 个辨识模块的 `Start()` 首行 acquire；所有 exit 路径 release；主循环 watchdog 超时强制 release |
| 验收 | 第二个模块启动时返回 `busy` 并回显占用者；故障/超时后自动释放；**不再出现"标定被中途打断导致参数损坏"** |

### P0-3 单一模式状态机

| 项 | 内容 |
|---|---|
| 新增 | `enum CtrlMode { IDLE, CAL, ALIGN, ENC_CAL, TORQUE, SPEED, POS, MIT, FAULT }` + `s_mode` |
| 改动 | 9 个 `*_en` 收敛为派生宏/只读查询；`Servo_SetMode` 成为唯一写入口 |
| 验收 | 静态检查：`en=1 && moe=0` 组合不可达；模式切换失败必须返回错误码而非静默 |

### P1-1 命令路由统一

`Cmd_Request{src, id, args, len}` → `Cmd_Router`（唯一门卫）→ 唯一应答。ASCII 与 MAVLink 只做 parser。
验收：同一指令两种来源结果一致；用今天 `30019 vs =` 的差异做回归用例。

### P1-2 结构化诊断替代 `S` 行

把低频项（`bias`/`ovc`/`raw`）拆到独立命令，`S` 行只留高频关键量；或直接改为索引化 TLV 帧。
验收：新增字段不再受 200 字符限制。

### P1-3 拆 `servo_isr.c`

`foc_isr.c`（仅 20 kHz，目标 ≤600 行、0 个调参 `#define`）+ `ctrl_mode.c` + `system_init.c`。

### P2-1 控制内核离线可测（根治误判）

控制核做成 `step(in, params) -> out` 纯函数，宿主侧编译 + 黄金轨迹回归（阶跃/扫频/极限环）。
**这一项能自动抓住今天这类"`Z` 报成功但不出力"**——因为离线用例直接断言"给定 iq 应产生转矩"。

### P2-2 目录按层重组

最后做。`App/ Ctrl/ Ident/ Proto/ Bsp/`。先做会制造大量 diff 但零行为收益。

## 六、明确不做

- 不重写控制律（现有环路已实测调好，重写等于把已验证的东西换成未验证的）

- 不把辨识算法换成"更先进"的（当前问题在集成，不在算法）
- 不为分层而分层（P2-2 放最后）

## 八、建议的落地顺序

1. **P0-2 执行器仲裁**（先把"会把机器搞坏"的路堵死，改动小、无控制风险）
2. **P0-1 参数快照**（正确性收益最大，但要逐项切换 + 复测）

4. P1-1 → P1-2 → P1-3
5. P2-1 离线回归（可与 P1 并行）
6. P2-2 目录重组（最后）

P0-2 与 P0-1 都是"不改控制律数值"的前提下可做的，风险可控；P1-3 拆文件属纯搬运 + 头文件整理，行为不变。

## 九、P0-2 执行器占用仲裁：已实施并验证（2026-11-19 23:00）

### 新增文件

`Board/actuator.c` / `Board/actuator.h`（已加入 `MDK-ARM/X72_FOC.uvprojx`）

```c
typedef enum { ACT_NONE=0, ACT_MOTOR_IDENT, ACT_RL_IDENT, ACT_FLUX_IDENT,
               ACT_MECH_IDENT, ACT_FRIC_CAL, ACT_ENC_CAL, ACT_NUM } ActOwner;

uint8_t     Act_Acquire(ActOwner o, uint8_t (*busy_fn)(void));  /* 1=占成功，0=被占用 */
void        Act_Release(ActOwner o);
void        Act_ForceRelease(void);
ActOwner    Act_Owner(void);
const char *Act_OwnerStr(void);
void        Act_Task1ms(void);        /* 模块自报空闲即自动释放 */
```

三条设计要点：

1. **不抢占、不排队**：`s_owner != ACT_NONE` 直接返回 0，调用方原样返回自己的 BUSY 码。
2. **释放不靠调用方记得写**：`Act_Task1ms()` 每 1 ms 调一次模块的 `busy_fn`，模块自报结束就自动释放。少写一处 Release 就少一个死锁。
3. **500 ms grace**：刚 Acquire 的窗口内不判自动释放，避免模块在 `Start()` 里还没置状态就被误判成"已结束"。

### 接入点（6 个模块，均插在全部前置检查之后、改状态之前）

| 模块 | 位置 | owner |
|---|---|---|
| `motor_ident.c` `MotorIdent_Start` | fault 检查之后 | `ACT_MOTOR_IDENT` |
| `motor_rl_ident.c` `RlIdent_Start` | fault 检查之后 | `ACT_RL_IDENT` |
| `motor_flux_ident.c` `FluxIdent_Start` | 模式检查之后 | `ACT_FLUX_IDENT` |
| `mech_ident.c` `MechIdent_Start` | mode 范围检查之后 | `ACT_MECH_IDENT` |
| `fric_cal.c` `FricCal_Start` | fault 检查之后 | `ACT_FRIC_CAL` |
| `encoder_cal.c` `EncCal_Start` | fault 检查之后 | `ACT_ENC_CAL` |

配套：`servo_cmd.c` 的 `do_disable()` 增加 `Act_ForceRelease()`（D 本来就会 abort 所有辨识）；`servo_isr.c` 的 1 ms 任务在 `EncCal_Task1ms()` 之后调用 `Act_Task1ms()`（放在所有辨识状态机之后，避免用到上一拍状态）；`Servo_Init` 增加 `Act_Init()`。

另外补了 `MechIdent_IsBusy()` / `FricCal_IsBusy()`（这两个模块原来只有 `GetState()`）。

### 实机验证

| 项 | 方法 | 结果 |
|---|---|---|
| 并发被拒 | `+` 运行期间每 1.5 s 发一次 `@` | **10/10 回显 `RL refused: busy`** |
| 令牌自动释放 | `+` 结束后再发 `@` | `RL ok R=457.67mohm` → 自动释放成功 |
| 控制无回归 | `=1000` 跑 5 s | 均值 **1000.2 rpm**，`f=0x00` |

编译 `Code=114864`（+296 B），0 Error / 0 Warning，烧录 Verify OK。

### 顺带发现的新缺陷（接口层，属 P1-1 范围）

**ASCII 回显是单缓冲，连续两条命令的回显会互相覆盖。**

证据：一次测试里同时发 `?`（帮助，约 200 字符）与 `+`，然后再发 `@`——`@` 的 `RL refused` 回显完全消失，且 `?` 的帮助行尾部被截断（`... M/N T/U/V .sc`）。而单发 `S` 连测 10 次，**10/10 正常**，说明 RX 队列（32 B，满则丢新）没问题，丢的是**发送侧的回显**。

根因：`emit()` 只写同一个 `s_out`，靠 `s_out_pending` 标志等 DMA 发完；上一条未发完时新一条直接覆盖。这与历史记录里"`S` 行被遥测帧插入截断"是同一机制。

修复方向（建议并入 P1-1 命令路由统一）：`emit()` 改为 2~3 行 ping-pong 队列，或 pending 时返回明确丢弃计数（让上位机知道漏了一条，而不是静默丢失）。

## 十、P0-1 辨识参数接管控制律：已实施并验证（2026-11-19 23:05）

### 改动本质

把 4 个编译期常量改成运行时变量，**默认值仍等于原常量**，所以上电行为与改动前一致；只有辨识成功后才改变。

| 常量 | 原值 | 现用途 | 数据来源 |
|---|---|---|---|
| `SERVO_CUR_PSI` | 4.333e-3 Wb | BEMF 前馈 `dec_vq` 的主导项（约占 vq 的 98%） | `+` FluxIdent |
| `SERVO_KT_NM_PER_A` | 0.0910 N·m/A | MIT τ→iq、τ 回读、力矩估算 | 由 ψ 派生：`Kt = 1.5·p·ψ` |
| `SERVO_CUR_LD` / `LQ` | 85e-6 H | dq 交叉耦合解耦 | `@` RlIdent |
| （R） | 无 | 仅记录，**不**自动改电流环 Ki（见下） | `@` RlIdent |

新增接口（`bsp_servo.h`）：

```c
void    Servo_SetIdentPsi(float psi_wb);              /* ψ -> Kt + BEMF 前馈 */
void    Servo_SetIdentRl(float r_ohm, float l_h);     /* L -> dq 解耦，R 记录 */
void    Servo_GetIdentParams(float *r,*ld,*psi,*kt);
uint8_t Servo_IdentApplied(void);
```

野值保护：ψ ∈ [2, 8] mWb、L ∈ [10, 300] µH、R ∈ [0.05, 2] Ω，NaN 一律拒绝。越界只"不采用"，绝不写坏环路。

### 接入点

- `flux_task1ms()`：`FI_DONE` 时调 `Servo_SetIdentPsi(r->psi_wb)`
- `rl_ident_task1ms()`：`RL_IDENT_OK` 时调 `Servo_SetIdentRl(r->r_ohm, r->l_h)`
- `Servo_RestoreFromFlash()`：`PS_FLAG_PSI` / `PS_FLAG_RL` 时同样调用 → **上电即用上次辨识值**，不必每次重测
- `K` 行新增 `psi=<mWb> kt=<mN·m/A> ld=<µH>`，回显控制律**正在用**的值（不是缓存）

### 实机验证

```
boot      psi=3.91 mWb  kt=82.03 mN·m/A  ld=75.96 uH      ← Flash 值已接管
after +   psi=3.93 mWb  kt=82.57 mN·m/A                    ← 21×3.932 = 82.57，误差 0.04
after @   psi=3.93 mWb  kt=82.57 mN·m/A  ld=78.96 uH       ← 等于 RL ok L=78.96uH，ψ 未变
speed     1000 rpm 5 s -> 均值 1002.2 rpm，f=0x00           ← 基线 1000.2，无回归
```

`Code=115264`（+400 B），`RW=228`（+16 B = 4 个新增 float），0 Error / 0 Warning。

### 必须说明的三点

1. **力矩标度整体变了 −9.3%**。旧常量 Kt=91.00 mN·m/A，现在跟随实测 ψ（3.91~3.93）→ 82.0~82.6。含义：
   - MIT 给同样的 τ，iq 会**多给约 10%**（因此实际出力更接近设定值）
   - `Servo_GetTorqueEst()` 对同一 iq 的读数**低约 9%**
   - 如果之前按旧 Kt 调过 MIT 的 kp/kd，手感的绝对刚度会跟着变，需复验

2. **R 没有自动改电流环 Ki，这是刻意的**。按零极点对消 `Ki·Ts = (R/L)·Kp·Ts`：
   - 用 `@` 的 R=0.458 / L=78.96µ → Ki·Ts ≈ 0.156（现值 0.126，温和）
   - 用 `+` 的 R=0.382 / L=25.35µ → Ki·Ts ≈ 0.433（**3.4 倍**，会显著改变超调）
   两个通道的 L 相差 3 倍（78.96 vs 25.35 µH），在它们收敛之前自动改 Ki 等于拿一个验证过的环去换没验证的环。**前置条件：`@` 与 `+` 的 L 差 < 20% 才允许启用。**

3. **ψ 的绝对值有会话/工况偏置**。今天三个来源：专用温漂曲线外推 4.39、`+` 早段 4.11、当前 3.93，跨度约 11%。控制律现在跟随最后一次 `+` 的结果，所以：
   - 想要"工作温度下的 Kt"，就在热稳态跑一次 `+`
   - 温度本身影响很小（α_ψ=−0.12 %/K，10 K 才 1.2%），这 11% 主要是测量偏置，不是温度

### `K` 行长度已到 183/200

再加字段会撞上限。这就是 P1-2（结构化诊断）需要尽快做的直接原因。

## 十一、P0-3 控制状态机：已实施并验证（2026-11-19 23:20）

### 关键发现：那 5 个布尔是"分层"的，不是"平铺互斥"

原来 `s_cur_en / s_spd_en / s_pos_en / s_mit_en / s_ol_en`，如果直接压成一个平铺枚举会**破坏 MIT 和位置环**，因为：

```
位置环 -> 速度环 -> 电流环      （下层必须开）
MIT    -> 电流环的子模式
```

`Servo_SetSpeedMode(1)` 内部要调 `Servo_SetCurrentMode(1)`；`Servo_SetCurrentMode(0)` 要连带关 MIT 和位置环。用布尔表达时，"该开哪几个"全靠 setter 里的调用顺序维持，这就是含糊态的根源。

### 做法：给定源做单一真值，5 个标志全部派生

```c
typedef enum { SERVO_SRC_NONE=0, SERVO_SRC_TORQUE, SERVO_SRC_SPEED,
               SERVO_SRC_POS, SERVO_SRC_MIT, SERVO_SRC_OPENLOOP,
               SERVO_SRC_NUM } ServoSrc;      /* 定义在 bsp_servo.h，对外可查 */
static volatile ServoSrc s_src = SERVO_SRC_NONE;

#define s_ol_en   (s_src == SERVO_SRC_OPENLOOP)
#define s_cur_en  ((s_src == SERVO_SRC_TORQUE) || (s_src == SERVO_SRC_SPEED) || \
                   (s_src == SERVO_SRC_POS)    || (s_src == SERVO_SRC_MIT))
#define s_spd_en  ((s_src == SERVO_SRC_SPEED) || (s_src == SERVO_SRC_POS))
#define s_pos_en  (s_src == SERVO_SRC_POS)
#define s_mit_en  (s_src == SERVO_SRC_MIT)
```

三层好处：
1. **层级关系变成恒等式**，不再依赖调用顺序；`POS` 一定带 `SPD` 和 `CUR`
2. **两个给定源不可能同时生效**，从结构上消灭"位置环使能了但完全不生效"
3. 20 kHz ISR 里的 38 处读取**一行都没改**（宏展开），控制路径零改动

setter 里原来的副作用没有丢，提取成两个函数复用：

```c
cur_reset_exec()   /* 清 vd/vq 积分、iq 斜坡、死区符号 —— 原 SetCurrentMode(0->1) */
cur_stop_all()     /* 清电流状态 + PosLoop_Disable + CurStep_Abort —— 原 SetCurrentMode(0) */
```

另外修掉一个隐患：`Servo_SetCurrentMode(1, iq)` 现在**只在 `src==NONE` 时**才切到 TORQUE，已在 SPEED/POS/MIT 时不会把状态降级（原来的布尔版本会把 `cur_en` 置 1，形成两个源同时为真的含糊态）。

### 新增接口

```c
typedef enum { SERVO_SRC_NONE=0, ... } ServoSrc;   /* bsp_servo.h */
ServoSrc    Servo_GetSrc(void);
uint8_t     Servo_GetSrcSeq(void);     /* 每次切换 +1 */
const char *Servo_SrcStr(void);        /* "TORQ"/"SPD"/"POS"/"MIT"/"OL"/"NONE" */
```

`K` 行末尾追加 `src=`，**当前给定源一眼可见**。

### 一个测试方法学的坑（记下来）

第一轮回归里 `Z 结束后 src=OL` 看着像 bug，其实是**我的测试时序错了**：我只等了 3 s 就去读 `K`，而 Z 要跑约 9 s，读到的是"辨识进行中"。力矩模式那次也一样——故障太快，读到时已被故障分支清回 NONE。**判据类测试必须等到状态机真正结束再读，否则会把正常当故障。**
