# 电角度校准（Z）：上位机指令集

**日期** 2026-11-21 · **固件** Code=117644 · **协议** 非标准 MAVLink v2 · **串口** 921600 8N1
**适用代码** `Board/motor_ident.c/h`、`servo_cmd.c`、`servo_isr.c`、`mavlink_host.c`；上位机 `host/mavlink_link.py`、`Agnet/ident_lib.py`

## 0. 一页速查

| 要做的事 | 指令码 | 字段 | 应答 |
|---|---|---|---|
| 设注入电流 | **30082** | float 槽 **0** `align_id` | 2 B：`status` + `n_ok` |
| **触发电角度校准** | **30069** | **`action = 5`**（=`Z`） | 2 B：`status` + `action` |
| 看是否成功 | **30090** | `flags` bit1 = `z` | 100 Hz 主动上报 |
| 看写入了什么 | **30092** | **`kind = 8`** | 事件帧，连发 5 帧 ≈50 ms |
| 看电角度补偿 | **30091** | `eoff_deg@32` | 100 Hz 主动上报 |
| 存盘 | **30069** | `action = 1` | 2 B |

```
C（action=4，电流零点）→ MOE=0 → 30082(align_id) → 30069(5) → 等 30092 kind=8 → 查 30090.z
```

**一句话**：`30069 action=5` 启动，`30092 kind=8` 是结果；`status=0` 只代表**入队**，成败必须看 30092。

## 1. 前置联锁

Z 会在 20 kHz 里开环注入 d 轴电流拖动转子，所以有六条硬约束：

| # | 条件 | 怎么确认 | 不满足的现象 |
|---|---|---|---|
| 1 | **MOE=0**（未使能） | 30090 `en == 0`；必要时 `30054 cw=0x06, halt=1` | 静默，等 50 s 超时 |
| 2 | **电流零点已标定**（C 做完） | 30090 `cal == 1` | 静默，等超时 |
| 3 | **无故障位** | 30090 `fault == 0` | 静默，等超时 |
| 4 | **没有别的辨识在跑** | — | 静默，等超时 |
| 5 | **执行器未被占用** | 别发 30019/30054/30056 | 静默，等超时 |
| 6 | **轴能自由转**（无抱闸/夹持） | — | 30092 `ok=0, err=6`（STUCK） |

### 1.1 ★ 最容易踩的坑：`status=0` 不代表启动成功

`do_align()` 里两条拒绝路径**只发 ASCII、不推 30092**（`servo_cmd.c`）：

```c
if (s_armed != 0U) { emit("[CMD] Z refused: still ON"); return; }   // 不推 30092
if (e != MOTOR_IDENT_OK) { emit("[CMD] Z refused: ..."); return; }  // 不推 30092
```

而 `SC_ACT_ALIGN_ZERO` 分支**无条件**返回 `SC_EXEC_ACCEPT`（`servo_cmd.c:3553`）：

```c
case SC_ACT_ALIGN_ZERO:
    do_align();
    return SC_EXEC_ACCEPT;      // 不管 do_align 成没成
```

后果：**前置不满足时，`action(5)` 照样回 `status=0`，然后你一条 30092 都收不到**，只能等到超时。ASCII 通道已默认关闭（`X72_ASCII_DEBUG=0`），那两行 `refused` 文本在板上根本不会发出来。

**所以上位机必须自己查前置**（第 1~4 条），不能靠 `status` 判断。这是当前固件的缺口，见 §8 第 1 条。

### 1.2 两个电流范围不是一回事

| 位置 | 范围 | 作用 |
|---|---|---|
| `Servo_SetAlignId`（30082 槽 0） | **0.2 ~ 4.0 A** | 写入门槛，超范围**整帧被拒**，值不变 |
| `MotorIdent_Start` 内部 | 0.5 ~ 5.0 A | 再夹一次（`MI_ID_MIN/MAX`） |

**有效区间是 [0.5, 4.0]**。默认 **2.0 A**（`servo_isr.c:212`）。

`align_id` **不落盘**，上电回 2.0。

## 2. 指令集

### 2.1 30069 SystemCmd（触发）

| 字段 | 类型 | 值 |
|---|---|---|
| `action` | u8 | **5** = 电角度校准（内部代号 `Z`） |

请求 1 B，应答 2 B：`[status, action]`。

`status` 映射：`0` 接受、`1` 非法动作、`2` 互斥未释放、`3` 状态不允许、`4` 无权限。**Z 的分支永远回 0**，见 §1.1。

### 2.2 30082 AppDebugParam（参数）

| 槽 | 名称 | 单位 | 范围 | 默认 | 说明 |
|---|---|---|---|---|---|
| float **0** | `align_id` | A | 0.2~4.0（有效 0.5~4.0） | **2.0** | 注入的 d 轴电流 |

```python
lk.dbg_write(floats={"align_id": 2.5})
```

选择依据（实测）：

| 工况 | 建议值 | 理由 |
|---|---|---|
| 空载、低摩擦（本台架） | **2.0** | 默认，60 步全部有效 |
| 带谐波减速器 | 2.5~3.5 | 起动力矩大，电流小了会 STUCK |
| 小扭矩电机 / 怕过流 | 1.0~1.5 | 但低于约 0.8 容易在某个位置卡住 |

### 2.3 30090 AppCtrlStatus（状态位）

| 偏移 | 字段 | Z 相关 |
|---|---|---|
| 3 | `flags` | **bit1 = `z`**（1 = 已做过且成功） |
| 36 | `fault` | 非 0 时 Z 不会启动 |
| 2 | `mode` | 完成后回 0 |

`flags` 位定义：

| bit | 含义 |
|---|---|
| 0 | `cal`（C 电流零点） |
| **1** | **`z`（Z 电角度）** |
| 2 | `en`（MOE） |
| 3 | `cog`（齿槽表有效） |
| 4 | `sched`（增益调度） |

### 2.4 30092 AppIdentResult（结果，kind=8）

40 B，事件帧，**连发 5 帧（约 50 ms）**，内容完全相同。不是请求-应答：**不要**往 30092 发东西。

| 偏移 | 类型 | 字段 |
|---|---|---|
| 0 | u8 | `kind` = **8** |
| 1 | u8 | `ok`：1 成功 / 0 失败 |
| 2 | u16 | `n`（= `n_step`） |
| 4 | f32×8 | `v[0..7]`，见 §3 |
| 36 | f32 | `resid`（重复一份 `v[7]`） |

## 3. 字段语义（kind=8）

### 3.1 成功（`ok=1`）

| 字段 | 类型 | 单位 | 含义 | 判读 |
|---|---|---|---|---|
| `v[0]` | f32 | — | `ratio` 极对数（**实数**） | 与整数偏差 <0.02 可信；>0.25 会被判 RATIO 失败 |
| `v[1]` | f32 | — | `dir` | **+1 / −1**，已写入 `s_dir_sign` |
| `v[2]` | f32 | **deg** | `offset_rad` 电角度零点 φ | ∈ [−180, 180] |
| `v[3]` | f32 | **deg** | `zero_mech` **已写入的编码器零点** | 与改前对比能看出挪了多少 |
| `v[4]` | f32 | — | `n_step` 有效步进样本数 | 正常 60 |
| `v[5]` | f32 | — | `n_sweep` 扫描样本数 | 正常数百 |
| `v[6]` | f32 | — | `n_fail` 被判无效丢弃的样本 | 0~2 正常，>5 说明有打滑 |
| `v[7]` | f32 | — | `resid` = \|ratio − round(ratio)\| | <0.02 好，>0.1 勉强 |

`ratio` 取整就是极对数 `pn`：`pn = round(v[0])`。

### 3.2 失败（`ok=0`）

失败帧**换了含义**，`v[0]` 是错误码而不是 `ratio`：

| 字段 | 类型 | 单位 | 含义 |
|---|---|---|---|
| `v[0]` | f32 | — | **错误码**（见表 §5），取值 1~8 |
| `v[1]` | f32 | mdeg | `dmech_avg` 每 120° 步进的平均机械角 |
| `v[2]` | f32 | mdeg | `dmech_min` |
| `v[3]` | f32 | mdeg | `dmech_max` |
| `v[4]` | f32 | — | `ratio`（可能是 0 或不合理值） |
| `v[5]` | f32 | — | `n_step` |
| `v[6]` | f32 | — | `n_fail` |
| `v[7]` | f32 | — | `resid` |

**`dmech` 是最有用的诊断量**：正常 120° 电角步进对应机械角

```
dmech = (2π/3) / pn = 2.0944 / 14 = 0.1496 rad = 8.571° = 8571 mdeg
```

| `dmech_avg` | 含义 |
|---|---|
| **≈8571 mdeg**（三位数到四位数） | 正常（本机 pn=14） |
| 几十 mdeg | 基本没动 → 电流不足或卡死 |
| ≈4000 mdeg | 只走到一半 → 极对数算错或严重打滑 |
| `min` 与 `max` 相差数倍 | 打滑 / 丢步 |

## 4. 完整下发序列

```python
import sys, time, struct
sys.path.insert(0, r"G:\FOC\驱动开发\PG_X72_CAN\host")
from mavlink_link import SerialLink

lk = SerialLink(); lk.connect("COM27", 921600)
time.sleep(1.5); lk.set_permission(0, 0)

# ---- 1) 前置（必须自己查，见 §1.1）----
st = lk.ctrl_status()
if st["cal"] != 1:
    raise SystemExit("先做 C 电流零点（action=4）")
if st["fault"] != 0:
    lk.action(3); time.sleep(0.6)
lk.set_controlword(0x06, halt=1); time.sleep(0.4)
assert lk.ctrl_status()["en"] == 0, "MOE 未封锁"

lk.dbg_write(floats={"align_id": 2.0})          # 30082 槽 0
time.sleep(0.2)

# ---- 2) 触发 ----
lk.last_msg.pop(30092, None)                    # 清残留（它是连发 5 帧的事件帧）
t0 = time.time()
r = lk.action(5)                                # 30069 action=5
assert r.get("status") == 0, r

# ---- 3) 等 kind=8，取第一帧 ----
pay = None
while time.time() - t0 < 50:                    # 实测 ~22 s，留 50 s
    m = lk.last_msg.get(30092)
    if m and m["ts"] >= t0:
        raw = lk._payload_of(m)
        if raw and len(raw) >= 40 and raw[0] == 8:
            pay = raw
            break
    time.sleep(0.05)

if pay is None:
    raise SystemExit("50 s 内没有 30092 kind=8 —— 大概率是前置不满足（§1.1）")

# ---- 4) 解析 ----
ok = pay[1]
v = struct.unpack_from("<8f", pay, 4)
if ok:
    ratio, dirn, off_deg, zero_deg, n_step, n_sweep, n_fail, resid = v
    print("pn=%d ratio=%.3f dir=%+d off=%.3f° zero=%.3f°"
          % (round(ratio), ratio, dirn, off_deg, zero_deg))
    print("n_step=%.0f n_sweep=%.0f n_fail=%.0f resid=%.4f"
          % (n_step, n_sweep, n_fail, resid))
else:
    print("FAIL err=%.0f  dmech(mdeg) avg=%.0f min=%.0f max=%.0f ratio=%.1f"
          % (v[0], v[1], v[2], v[3], v[4]))

# ---- 5) 存盘 ----
lk.action(1)                                    # 参数页会自动存，这条只是立刻写一次
print("z 位 =", lk.ctrl_status()["z"])
```

### 4.1 已封装好的写法

`Agnet/ident_lib.py` 的兼容层已经处理了「清残留 → 等 kind → 去重 → 还原文本」：

```python
from ident_lib import Link
lk = Link("COM27")
txt, el, refused = lk.run("Z", ["[CMD] IDENT"], timeout=0.0)
print(txt, "%.1f s" % el)
```

`_KIND_OF["Z"] = 8`、`_ACTION_OF["Z"] = 5`、`_TMO_OF["Z"] = 50`（`ident_lib.py:74-77`）。

### 4.2 等待的三条规则

1. **`ts >= t0` 过滤**：30092 是连发 5 帧，紧邻的两次同类辨识之间会互相污染。发之前 `pop` 一次，收的时候再按时间戳过滤。
2. **同 kind 只取第一帧**：5 帧内容相同，重复计数没有意义。
3. **不要轮询发送**：30092 不是应答消息，问它没有用（会被当未知方向丢弃）。

## 5. 错误码

`MotorIdentErr`（`motor_ident.h:42-52`）：

| 码 | 名称 | 含义 | 怎么办 |
|---|---|---|---|
| 0 | OK | 成功 | — |
| 1 | BUSY | 已有辨识在跑 / 执行器被占 | 等 30 s 或发 `action=14` 中止 |
| 2 | CAL | 电流零点未标定 | 先 `action=4`（C） |
| 3 | FAULT | 启动前已有故障 | 先 `action=3` 清故障 |
| 4 | PWM | MOE 打开失败 | 查母线电压 / 驱动故障 |
| 5 | TIMEOUT | 总时长超 45 s | 多半是卡死，查机械 |
| 6 | **STUCK** | 转子几乎没动 | **加大 `align_id`**、查抱闸 |
| 7 | RATIO | 极对数不合理（非整数或超 1~64） | 检查磁极数、加大电流重试 |
| 8 | FAULT_RUN | 运行中触发故障（多为过流） | 降低 `align_id`，查相序 |

对照表：

| 现象 | 码 | 真正原因 |
|---|---|---|
| `dmech_avg` 几十 mdeg、`n_fail` 大 | **6** | 起动力矩不够 → 电流小了 |
| `dmech_avg` ≈4000 mdeg | **7** | 只走一半，极对数算成 28 |
| `ratio` = 0 或 >64 | **7** | 编码器方向反了 / 丢步严重 |
| `n_fail` 很小但 `ratio` = 13.5 | **7** | 磁极数与编码器分辨率不匹配 |
| 直接码 8 | 8 | 电流太大，某一步过流 |

## 6. Z 改了什么、没改什么（影响面）

这段很重要：Z 写 `s_enc_zero`，而不同功能用的是**两套角度**。

```c
/* bsp_servo.c:938 */
float theta = raw * k + s_enc_zero;      // theta_now，含零点
```

| 功能 | 用的角 | 含 `s_enc_zero`？ | Z 之后 |
|---|---|---|---|
| **电角度 / Park** | `theta_now`（单圈） | **是** | **改变**（这正是目的） |
| **软件 LUT（30098）** | `dir × theta_now` | **是** | **相位平移 14×Δzero**，需重标 |
| 30090 `pos` | `theta_now` | 是 | 改变 |
| **位置环 / 30100 `p_now`** | `theta_multi` | **否**（base 播种时零点未加载） | **不变** |
| **齿槽表（30093）** | `theta_multi` | **否** | **不变**，不用重做 `}` |
| 位置环目标 / 示教点 | `theta_multi` | 否 | 不变 |

结论：

- **Z 之后不必重做齿槽表**（`CogFf_Get(BspServo_GetThetaMulti(), ...)`，`servo_isr.c:1964`）。
- **Z 之后必须重标软件 LUT**（如果启用了它）——LUT 的自变量含零点，零点一挪相位全偏。
- 位置环坐标与示教点**不受影响**，但 30090/30040 口径的读数会变。

## 7. 落盘与回读

| 项 | 存哪 | 是否自动 | 怎么回读 |
|---|---|---|---|
| `dir` / `zero_rad` | 参数页（`PS_FLAG_Z`） | **自动**（500 ms，`MOE=0 & cal=1 & z=1`） | 30090 `flags.bit1`（只能看"做过"） |
| `align_id` | — | **不落盘**，上电回 2.0 | 30082 float 0 |
| 极对数 `pn` | 参数页有字段，但**控制不用** | 自动 | 30092 当次结果 |
| `eoff_deg` | — | **不落盘** | 30091 `eoff_deg@32` |

`action=1` 只是"立刻写一次"，不是必须的（参数页本来就每 500 ms 自动存）。但 Z 刚跑完时建议发一次，确保 `dir/zero` 立刻进 Flash。

**回读不到的量**：`zero_rad` 的数值本身（30090/30091 都没有这个字段）。想知道挪了多少，只能在 Z 前后对比 30090 `pos`，或者看当次 30092 的 `v[3]`。

## 8. 已知缺口

| # | 缺口 | 影响 | 规避 |
|---|---|---|---|
| 1 | **前置不满足时静默**：`status=0` 但无 30092 | 上位机只能等 50 s 超时 | 自己查 §1 的 6 条前置 |
| 2 | **极对数不参与控制** | Park 用编译常量 `SERVO_CUR_POLE = BSP_POLE_PAIRS = 14`；Z 只是"测出来"并用于算零点 | 换电机必须先改常量再 Z，否则电角度仍错 |
| 3 | **`zero_rad` 无回读字段** | 无法核对"这次 Z 和上次差多少" | 用 `v[3]`（度）对比 |
| 4 | **`align_id` 不落盘** | 每次上电重设 | 上位机初始化流程里写一次 |
| 5 | **没有进度反馈** | 22 s 内只有心跳，不知道进行到哪一步 | 只能等；30092 是唯一结果 |
| 6 | **`action=14` 中止后不推 30092** | 中止与失败无法从协议上区分 | 记时间戳，超时算中止 |

第 2 条补充：`finish_ok()` 用 `ratio_int` 算零点补偿 `delta`，所以 Z 的极对数是**参与了"算零点"**的；只是 Park 变换没用它。换电机时如果真实极对数不是 14，会出现"Z 按真值算零点、控制按 14 跑"的错位。
