| 项 | 结果 |

## 一、齿槽表 128 → 512 箱

### 1.1 为什么加密有用

128 箱在 14 对极下，每个齿槽周期只有 **9 个点**，线性插值把峰顶削掉一大截：
同一个转子，128 箱测出峰峰 **1.071 A**，512 箱测出 **1.228 A**（+15%）。
少了这 15%，前馈只能补掉一部分扰动，剩下的直接变成速度纹波。

### 1.2 实测（100 rpm，稳态 5~6 s，同一台机同一工况）

| 配置 | 均值 | std | CV |
|---|---|---|---|
| 128 箱 + 前馈开 | 100.07 | **3.96 rpm** | 3.96% |
| 128 箱 + 前馈关 | 100.12 | 6.18 rpm | 6.17% |
| **512 箱 + 前馈开** | 100.18 | **1.02 rpm** | **1.02%** |
| 512 箱 + 前馈关 | 100.04 | 6.08 rpm | 6.07% |

前馈消扰率：128 箱时 (6.18−3.96)/6.18 = **36%**；512 箱时 (6.08−1.02)/6.08 = **83%**。
均值不受影响（−0.0x%），说明不是把误差"摊"掉了，是真的把扰动补掉了。

### 1.3 改动清单（类型与容量的连锁反应）

256 已经放不进 `uint8_t`，所以沿线全部改成 16 位 —— 这是这次改动最容易漏的地方：

| 位置 | 改动 |
|---|---|
| `mech_ident.h` | `MI2_COG_BINS_MAX 512` / `MI2_COG_BINS_DFLT 512`；`cog_n` → `uint16_t`；`cog[]` 按 MAX 分配 |
| `mech_ident.c` | 新增运行时 `s_cog_bins` + `MechIdent_SetCogBins()`；累加/清零循环计数器 `uint8_t` → **`uint16_t`** |
| `cog_ff.h/.c` | `s_n`、`CogFfInfo.n_bins`、`CogFf_CopyTableMv(from)` → 16 位 |
| `param_store.h/.c` | `COG_BINS_MAX 512`；`CogBlob` 288 → **1056 B**；`COG_VERSION 2 → 3`（旧表自动作废）；`SaveCog/LoadCog` 的 `n_bins` → `uint16_t` |
| `mavlink_host.c` | 30093 的 `p93[2]` 从"箱数"改成**块数**（n_bins = n_blk×8），`p93[3]` 加 bit1=本次是否做过相位对齐 |
| `host/mavlink_link.py` | `cog_read()` 按头部 n_blk 自适应（不再硬编码 16 块） |

**踩到的死循环**：`MechIdent_Start` 里清零累加器的循环用 `uint8_t i` 配
`i < s_cog_bins` —— 512 时条件恒成立，主循环直接卡死（现象：30069 无 ACK、
遥测照发）。和命令队列那次是同一类错误，这次是第二次踩。

## 二、相位对齐：平移基准，不搬数据

原来零点偏差 >1° 就判表失效（`s_valid=0`），重做一次 Z 就白丢 30 s 辨识。

**为什么不用旋转表**：查表索引是 `(θ_multi − phase)`。零点平移 δ 之后，同一
机械位置的 `θ_multi` 大 δ；只要 `phase` 也加 δ，索引自动回到原处 ——
纯标量运算、零量化损失（旋转整表会丢 0.7° 的分辨率）、不需要 1 KB 临时缓冲。

```c
dz = cog_dwrap(zero_now - zero_ref);
if (fabsf(dz) <= 1°)      { valid = 1; return; }        /* 正常 */
if (fabsf(dz) <= π)       { phase += dz; zero_ref = zero_now; valid = 1; }  /* 对齐 */
else                      { valid = 0; }                /* 不是零点平移，作废 */
```

对齐是**幂等**的（对齐后残差为 0），所以每次上电对齐一遍也不会漂。
诊断：`CogFfInfo.aligned` / `align_deg`，30093 的 `p93[3]` bit1。

**尚未验证的部分**：需要真重跑一次 Z 才能让 δ 超过 1°，本轮没做（会动转子 ±1 圈）。
下次重做 Z 之后，看 30093 的 `p93[3]` bit1 是否为 1、`zero_dev_deg` 是否回到 ≈0。

## 三、速度环陷波（30096）

### 3.1 实现

- 加在**反馈**上（不动给定响应），在 2 kHz 的环内节拍运行；
- 二阶 RBJ 陷波 + **深度混合**：`y = (1−k)·x + k·H(z)·x`，极点不变、零点变浅，
  k 由 `depth_db` 换算（0 dB = 直通，40 dB ≈ 完整陷波），避免大 Q 在 f0 附近相位突变；
- 系数只在参数变化时算一次（2 kHz 里不做 sin/cos），运行时每拍 5 乘 4 加；
- 参数只存 RAM（落盘要动 ParamBlob 版本 → 作废现有 C/Z 标定，留给"双页乒乓"一起做）。

### 3.2 接口

```
30096 AppAdvCfg (24 B)：en(1) + pad3 + f0_hz(f32) + depth_db(f32) + q(f32) + rsv(f32)
应答 24 B：回填**实际生效**的值（内部会夹到 f0≤900 Hz、Q 0.3~10、深度 0~40 dB）
pl[0]=0xFF 表示"只读回"（上位机 send() 会把载荷补齐到 24 B，发不出短帧）
```

`mavlink_link.notch(en,f0,depth,q)` / `notch_read()`。

### 3.3 实测：这台机器的陷波只能用在 300 Hz 以上

| 配置（100 rpm） | 均值 | std | 结论 |
|---|---|---|---|
| 陷波关 | 100.03 | 1.16 rpm | 基准 |
| **23 Hz 20 dB Q3** | — | — | **直接触发超速故障（0x0020）** |
| 150 Hz 20 dB Q3 | 68.2 | 25.6 rpm | 严重拖慢 + 振荡 |
| 300 Hz 20 dB Q3 | 96.4 | 1.37 rpm | 基本透明（略有下垂） |

原因可算：转矩→转速的传递是 `1/(Js)`，刚性交叉频率
`Kp·Kt/J = 0.583×0.0918/7.3e-5 ≈ 733 rad/s ≈ 117 Hz`。
陷波放在交叉频率附近会吃掉相位裕度 —— 23 Hz 直接失稳，150 Hz 只剩很薄的裕度。
**所以 f0 至少取 2.5 倍交叉频率（≥300 Hz）**，这也是机械谐振的典型位置；
低频纹波（电频率 23 Hz、齿槽 47 Hz）属于**扰动**而不是谐振，正确工具是前馈（已在用）。

`notch()` 已加保护提示：`en=1 且 f0 < 60 Hz` 时返回 warning，写明实测会触发超速。

## 四、仍未闭环

1. **齿槽表跨烧录的持久化**：本轮量完 `A` 存盘后，重新烧录再读 `cog_read` 得到
   `n_bins=0`（表没装上）。参数页 `ps_diag` 正常，所以怀疑烧录把最后 8 KB
   （0x0807E000 齿槽页 + 0x0807F000 参数页）一起擦掉 —— 与 09:43 那次
   `ps:empty magic / ver=0xFFFF` 是同一个现象。**建议尽快做双页乒乓 + 让烧录不擦末页**。
2. 相位对齐没被真实 Z 变更触发过（见二）。
3. 一次未复现的超速（0x0020）：在"表未装上、前馈未生效"的那一轮出现，
   之后相同工况连续 5 次都没再出现，暂记为待观察。
