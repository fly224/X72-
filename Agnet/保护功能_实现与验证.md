> 四项都在 `bsp_servo.c/h` + `servo_isr.c` + `main.c` 里，一次烧录全部生效。
> 固件 `Code=96184 RO=6812 RW=180 ZI=17460`，0 Error / 0 Warning。

## 0. 为什么先做保护

这四项的共同点是：**不做也不会立刻出问题，出事时来不及**。

而且其中一项有真实案例：2026-11-17 早些时候，`!` 软复位命令里有个无超时的
`while (s_out_pending != 0U) { ascii_pump(); }`，一旦碰上遥测 DMA 一直占线，
主循环被永久钉死。现象极具迷惑性 —— **遥测在 TIM6 中断里照常发，但所有 ASCII
命令都没反应，连 `!` 也救不回来，只能重新烧录**。如果那次发生在 MOE=1 的运行中，
PWM 会保持最后占空比，电机就是飞车。

那次只能靠人拔电。所以看门狗是第一优先级。

## 1. 看门狗（IWDG，250 ms）

### 1.1 实现

不走 HAL：`HAL_IWDG_MODULE_ENABLED` 在 `stm32g4xx_hal_conf.h` 里是注释掉的，
打开它要连带把 `stm32g4xx_hal_iwdg.c` 加进 Keil 工程 —— 这个工程有"重新生成后
源文件丢失、旧 `.o` 让链接悄悄成功"的前科，能不动工程文件就不动。
IWDG 的全部配置只有 4 个寄存器，直接写反而更可控：

```c
IWDG->KR  = 0xCCCCu;    /* 启动（LSI 同时起振） */
IWDG->KR  = 0x5555u;    /* 解锁 PR/RLR */
IWDG->PR  = 4u;         /* /64 */
IWDG->RLR = 125u;       /* 125 × 64 / 32000 = 250 ms */
while ((IWDG->SR & 0x3u) != 0u) { }   /* 等 PVU/RVU 落 */
IWDG->KR  = 0xAAAAu;    /* 重装 */
```

LSI 26–34 kHz 对应实际超时 **235–308 ms**。

### 1.2 为什么喂狗必须在主循环

这是本次实现最关键的一条设计决策。1 ms 定时器中断（TIM6）里也在跑状态机
（`FrcCal_Task1ms`、`MechIdent_Task1ms`、`ServoCmd_Task1ms` …）。如果在那儿喂狗，
"中断还活着、主循环死了"这种故障**永远不会被复位** —— 而这正是上面那个真实案例
的形态。

所以 `BspServo_WdgKick()` 放在 `main.c` 的 `while (1)` 里，紧跟 `ServoCmd_Poll()`。

### 1.3 启动时机

放在 `Servo_Init()` **之后**：那里有 Flash 参数恢复和编码器首帧，耗时不确定，
先让它们跑完再上狗，避免启动阶段被复位。

### 1.4 调试注意

停在断点会被复位。需要单步时把 `bsp_servo.c` 里的 `BSP_WDG_ENABLE` 改 0 重编。

### 1.5 验证：真的会复位

不能只验证"加了不报错"，必须验证"该复位时会复位"。做法：临时注释掉
`BspServo_WdgKick()`，重编烧录，数启动打点（`[T] bsp:init begin`）：

| 配置 | 3 s 内 boot 次数 | 等效复位周期 |
|---|---:|---:|
| 去掉喂狗 | **10** | **300 ms**（250 ms 超时 + 启动 ~50 ms） |
| 恢复喂狗 | 0 | 不复位 ✓ |

这同时证明了三件事：IWDG 真的启动了、超时值就是 250 ms 量级、喂狗路径有效。

## 2. 母线过压 / 欠压

### 2.1 阈值依据（不是拍脑袋）

| 项 | 值 | 依据 |
|---|---:|---|
| 功率管 | **JMSH1004BGQ** | 网表实测，100 V 耐压 N-MOS |
| 母线电容 | 63 V 档（48 V 系统常规） | — |
| **OV 跳闸** | **58 V** | 低于 63 V 电容留 5 V，高于 48 V 标称留 10 V 给制动回馈 |
| **UV 跳闸** | **18 V** | 低于此值 FD6288Q 的 UVLO 本来也要关断，固件先一步封锁；32 V 台架 / 48 V 系统都不用改阈值 |

### 2.2 判据细节

- **20 ms 消抖**（1 kHz 任务里连续 20 次超限）：母线在每个开关沿都有几十微秒的
  跌落与振铃，单拍判据必然误跳。
- **上电 300 ms 屏蔽**：分压/ADC 还没稳，否则每次上电都先报一次欠压。
- **过压任何状态都判**：错接电源或制动泵升，即使没使能也要报。
- **欠压只在输出使能时判**：只插 USB、母线断电是正常工况，那种情况下判欠压
  会让板子永远带着故障位。

### 2.3 验证

把 OV 临时改到 25 V（低于 30.8 V 的实际母线）重编烧录：

```
[CMD] st en=0 moe=0 cal=1 z=1 ... f=0x40 ... v=30.77
[CMD] EN refused: fault=0x40 (send X to clear)
```

`f=0x40` = `BSP_FAULT_OVERVOLT`（bit6），MOE 已被 `FaultSet` 清掉，`E` 被拒。
恢复 58 V 后 `dr`/`f` 均正常。UV 未单独验证（同一段代码，只差比较方向与使能条件）。

### 2.4 一个需要留意的偏差

实测母线读数 **30.77 V**，而台架电源标称 32 V —— 偏低 3.8%。若电源确实是 32.0 V，
说明分压比 1/21 有约 4% 偏差（1% 电阻不该有这么大，更可能是电源本身带载跌落或
万用表口径不同）。**建议用万用表实测母线后用 `v=` 对一下**：若确有 4% 偏差，
OV 58 V 实际会在 60.3 V 才跳，仍在 63 V 电容之下，但余量变小。

## 3. 温度降额

### 3.1 阈值

| 通道 | T0（开始降） | T1（降到 0） | 依据 |
|---|---:|---:|---|
| GaN / 驱动 | **85 °C** | **105 °C** | NTC 贴在驱动/散热器上，结温远高于读数，保守取值 |
| 电机绕组 | **110 °C** | **140 °C** | F 级绝缘 155 °C，留 15 °C 余量 |

降额系数 = 两路中更保守的一路，线性插值；**NTC 开路/短路时驱动层返回 NaN，
此时不降额**（宁可少一层保护，也不要因为测温故障把电机锁死）。

### 3.2 收口位置：所有给定来源汇合后的唯一一点

```c
/* servo_isr.c，模式选择之后、进电流 PI 之前 */
if (s_derate < 1.0f) {
    const float lim = s_derate * ((s_spd_en != 0U) ? s_spd_iqmax : s_cur_iq_max);
    if (iq_ref >  lim) { iq_ref =  lim; }
    if (iq_ref < -lim) { iq_ref = -lim; }
}
```

放在这里的理由：**力矩 / 速度 / 位置 / 机械辨识 / ψ-R-L 辨识的给定都汇合到这一行**，
一处就全覆盖。用各模式自己的限幅乘系数，而不是统一用 `s_cur_iq_max` ——
速度环的 3 A 限幅比力矩模式的 5 A 小，统一用 5 A 会让速度模式在降额前就不受约束。

温度降额**不改用户的基准限幅** `s_cur_iq_max`：它是乘在上面的临时系数，温度回落
自动恢复，不应该把用户参数改掉。

### 3.3 验证

把阈值临时压到 20→25 °C（实际 NTC 28.2 / 26.9 °C，必然降额到 0）：

```
S: ... f=0x00 ... v=30.77 dr=0.00
set: [CMD] SPD on: w_ref=100.00rpm kp=0.58 kiTs=40.76e-3 iqmax=3A moe=1
实测: 转速 0.00 rpm (max 0.31)   iq 均值 0.0000
```

速度环接受了 100 rpm 给定、MOE=1，但 **iq 恒为 0、电机完全不动** —— 降额链路
（NTC → 1 ms 任务 → `s_derate` → 20 kHz 限幅）整条打通。

恢复 85/105/110/140 后 `dr` 字段不再出现（正常温度下系数 1.00）。

### 3.4 副作用

辨识（扫频/惯量/ψ-R-L）也会被这个限幅截断。过热时宁可测不完整，也不让电机继续
升温 —— 这是有意的取舍，辨识前应确认 `dr=1.00`。

## 4. 编码器运行期校验

### 4.1 先纠正一处：运行期校验本来就有

我上一轮说"`0x113` 和 SPI CRC 只在自校准里读、`BSP_FAULT_ENCODER` 没人为它置位"，
**这是错的**。`bsp_servo.c:644` 的 SPI DMA 完成回调里已经有：

```c
if (status != 0U || angle >= BSP_ENC_COUNTS) {
    if (++s_enc_err_cnt >= BSP_ENC_ERR_MAX) FaultSet(BSP_FAULT_ENCODER);
    return;                       /* 保留上一帧有效角度 */
}
s_enc_err_cnt = 0;
```

即：MT6835 的 3 个 status 位 + 21 位角度越界 + 连续 5 次异常 → 置故障。这条路径
是有效的。

### 4.2 真正缺的是"位翻转但数值仍合法"

上面的判据抓不到这种情况：status 全 0、角度落在 [0, 2^21) 内，但某个高位被干扰
翻了 —— 数值完全合法，电角度却跳了。控制环会把它当成真实位移去追（位置环尤其
危险）。所以补一条**角度连续性**：

```c
int32_t d = (int32_t)angle - (int32_t)s_enc_raw;   /* 按模 2^21 取最短差值 */
if (d >  half) { d -= (int32_t)BSP_ENC_COUNTS; }
if (d < -half) { d += (int32_t)BSP_ENC_COUNTS; }
if (abs(d) > BSP_ENC_JUMP_MAX) {                   /* 65536 count = 1/32 圈 */
    if (++s_enc_jump_cnt >= 3) FaultSet(BSP_FAULT_ENCODER);
    return;                                        /* 丢帧，继续用上一帧 */
}
```

阈值依据：20 kHz 下 4000 rpm 的合法变化只有 **约 7000 count**（0.021 rad），
取 1/32 圈 = 65536 count，余量 **9 倍**，正常运动不可能误触。
必须按模 2^21 算差值 —— 否则每圈过零都会算成 2^21 的跳变。

### 4.3 未验证

**没有在实机上注入过坏帧**（需要用调试器改 `s_enc_rx` 或干扰 SPI）。
目前只是代码级实现 + 参数推演。若后续要验证，最省事的办法是临时把
`BSP_ENC_JUMP_MAX` 改到远小于合法变化（例如 1000），跑 100 rpm，
应当立即报 `f=0x02`；验证完改回。

## 6. 局限与后续

1. **UV 未实机验证**，OV 验证后恢复的是 58 V，实际跳闸点未在真实高压下复测。
2. **母线读数与电源标称差 3.8%**，建议万用表校准后再定 OV 的最终余量。
3. **编码器连续性未注入验证**，且没有校验 SPI 帧的 CRC 字节（`rx[5]`）——
   MT6835 的 CRC 定义需查手册确认后才能加，贸然校验可能全是误报。
4. **温度降额没有回差**：85 °C 精确附近会在 1.00/0.99 之间微抖，但因为系数是
   连续乘在限幅上，不会引起振荡，故未加迟滞。
5. **没有过温故障位**：现在只降额不报故障。若需要"到 T1 直接锁存停机"，
   再加 `BSP_FAULT_OVERTEMP`（bit8）。
