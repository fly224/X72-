# 使能语义：使能 ≠ 跑到上次的目标

**日期** 2026-11-21 · **固件** Code=112420 · **验证** 8/8 + 17/17 + 26/26

---

## 一、问题

> 只要以前成功下发过 30019，"使能"就等于"立刻跑到那个目标"。

确实如此，而且是**两层**问题叠加。只改固件不够——我把两层都改了才真正修好。

---

## 二、第一层：固件 `arm_with_mode()` 直接装配缓存给定

`app_param.c:84` 原来：

```c
case APP_OP_MODE_VEL:
    ok = (s_w_valid != 0U) ? ServoCmd_CtrlSpeed(s_w_target) : ServoCmd_Arm();
    break;
case APP_OP_MODE_TORQUE:
    ok = (s_iq_valid != 0U) ? ServoCmd_CtrlTorque(s_iq_target) : ServoCmd_Arm();
    break;
```

`s_w_valid` / `s_iq_valid` 一旦被 30019/30025 置 1 就再不复位，于是：

- **速度**：disarm 后重使能、清故障后重使能、上位机重连点"启动" → 立刻朝上次转速冲
- **力矩**：更糟，一使能就按上次 iq 出力
- **位置**：一使能就朝上次目标位置走（可能是一段大行程）

### 改法（`app_param.c:93`）

一律以**安全初值**起环：

| 模式 | 起环动作 |
|---|---|
| 速度 | `ServoCmd_CtrlSpeed(0.0f)` — 零速保持 |
| 力矩 | `ServoCmd_CtrlTorque(0.0f)` — 零力矩 |
| 位置 | `ServoCmd_Arm()` — `do_enable` 把位置环锁在当前角 |
| MIT | `CtrlMit(当前角, 0, kp, kd, 0)` — 只留位置刚度，零速度/零前馈 |

`do_enable()` 本来就是"位置环锁当前角"，所以位置分支直接复用它。

**为什么不影响"先给给定、再使能"**：任何给定在 `armed=0` 时都会自己完成装配并起转（`do_speed` / `do_pos` / `do_current` / `mit_engage` 的完整分支），那条路径根本不经过这里；等 cw 到达时 `armed` 已经是 1，走 `arm_with_mode` 开头的幂等返回。

`s_*_valid` 保留，但从此只作"曾经收到过给定"的历史记录，不再参与使能决策。

## 三、第二层：上位机保活把旧目标重申回来

只改固件，实测仍然失败——`cw` 后末速 **1000.49 rpm**。原因是保活线程每 200 ms 重发 `setpoints` 里的值，而 `setpoints` 还存着 1000：

```
halt → do_disable（固件侧已清）→ cw 使能（固件 0 速保持）→ 200 ms 后保活发 30019=1000 → 拉到 1000
```

固件不能拒绝一帧合法的 30019，所以这一层只能在上位机解决（`mavlink_link.py:1020`）：

```python
if r.get("ok") and (halt != 0 or (cw & 0x0001) == 0):
    with self.lock:
        for k in self.setpoints_valid:
            self.setpoints_valid[k] = False
```

`_keepalive_loop` 里本来就有 `if valid:` 判断，作废后自动停发；下次 `set_speed_rpm()` 会重新置 `valid=True`，保活随之恢复。

**语义上这也更正确**：disarm 之后"没有有效给定"，而不是"一直重申上一帧"。

## 五、发现项（未修，需你定）

**力矩模式的超速门限没有纳入"进环余速"**

`SERVO_CUR_WMAX = 31.4 rad/s`（300 rpm）是个固定值，而力矩模式没有速度环，门限就是它。于是**带着 1000 rpm 余速切到力矩模式**（`set_torque` 会自己起电流环）会立刻置 `0x0020`：

```
速度 1000 rpm → halt → 立刻 set_mode(4) + set_torque(0.15)
→ src 切到 TORQUE，om 还有 104 rad/s > 31.4 → 0.4 ms 后 0x0020
```

这与上一轮修的"速度环峰值从余速起"是同一个根源，但力矩分支用的是常量门限，没有峰值保持。修法有两条：

1. 力矩模式也引入进环余速（`1.5×|om_entry| + SERVO_CUR_WMAX`，随 0.5 s 衰减）—— 与速度环一致；
2. 或者在 `do_current` 起环前拒绝"余速过大"（`|om| > 0.5×WMAX` 时要求先停），给出明确提示而不是跳故障。

我倾向第 1 条（语义一致），但它会放宽力矩模式的失控保护窗口，需要你确认可接受再改。
