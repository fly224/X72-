# 编码器自校准：方案调研与实现

> 2026-11-16 · X72 / STM32G474CEU6 + MT6835 · 命令 `^`

## 1. 结论

**走 MT6835 芯片内置的客户端自校准，实机已跑通。**

```
[CMD] EC ok turns=51.60 avg=599.90rpm [595.26..595.90] chip=3 -> !!! POWER CYCLE REQUIRED (>6s) !!!
```

`chip=3` 表示芯片寄存器 `0x113[7:6]=11`（自校准成功），是芯片自己的判据，不是固件推测的。转速稳定在 599.9 rpm，波动区间 595.26~595.90（±0.4 rpm），满足"匀速"前提。

**但这只是"校准完成"，不是"校准生效"** —— 厂商明确要求成功后等 >6 s 并**给芯片断电**，重新上电才加载 EEPROM 里的新参数。板上没有编码器电源开关，这一步必须人工做。

## 2. 两家参考工程的调研结果

| 工程 | 有什么 | 缺什么 |
|---|---|---|
| **VESC**（`bldc-master`） | `enc_corr[360]` 修正表的**应用**逻辑（`mcpwm_foc.c:3256`：按机械角 0~359° 查表，从电角度里减掉）+ 掉电存储（`conf_general.c:131`）+ Lisp 写入接口 | **没有生成这张表的算法**。表由 VESC Tool 或 Lisp 脚本从外部写入 |
| **FM_XC**（`FM_Servo_V3`） | `elec_angle_compensation` 一个**常数**偏置（`motor_ctl_loop.c:74`） | 没有偏心/非线性补偿 |

所以两家都不能直接抄。

VESC 的做法值得借鉴的是**接口形态**：360 点、按机械角索引、单位是度、运行时只做一次减法。这个结构的开销可以忽略（一次整数索引 + 一次浮点减法），比自己设计插值合理。

## 3. 为什么选芯片自校准而不是软件 LUT

MT6835 有三层校准：

| 层 | 怎么触发 | INL | 谁做 |
|---|---|---|---|
| ① 出厂 | 芯片 FT 测试 | ±0.5° | MagnTek |
| **② 客户端自校准** | **CAL_EN 引脚拉高 + 匀速 64 圈** | **±0.07°** | **芯片自己** |
| ③ NLC 对拖 | 与更高精度基准编码器对拖，写 256 点表 | ±0.02° | 需要第二套设备 |

第 ② 层是免费的：芯片内部有 DSP 和 EEPROM，自己算非线性、自己烧录，**不占 MCU 的 CPU、Flash、也不占控制节拍**。

相比之下软件 LUT（Infineon IMR、多数开源 FOC 的做法）要：
- 开环转一圈记录传感器读数（正反各一遍以抵消摩擦/齿槽）；
- 与理想线性曲线比较生成 128~1024 点表；
- 存 Flash、运行时插值；
- 而且**无法补偿芯片自身的谐波误差**，只能补安装偏心。

既然芯片能自己做到 ±0.07°，软件 LUT 只应作为"换用无自校准能力的编码器"时的退路。

## 4. 硬件前提（已确认）

`Hardware/Netlist/pin_map.csv`：

```
U4 [STM32G474CEU6],47,PB9,CAL_EN
U2 [MT6835GT-STD],4,CAL_EN,CAL_EN
```

**CAL_EN 已经接到 PB9**，且 `.ioc` 里 PB9 已配置为 `GPIO_Output`、默认 `PULLDOWN`、`Locked=true`（`X72_FOC.ioc:411-414`），`gpio.c:60` 上电即写 RESET。所以硬件完全就绪，不需要改板。

`bsp_servo.c` 里仍然加了一次 `BspServo_InitEncCalPin()` 做双重保险——CubeMX 重新生成时若改了 PB9 配置，这里会拉回输出低电平（上电瞬间进校准模式是危险的）。

## 5. 实现

### 5.1 SPI 寄存器访问

MT6835 的帧是 24 bit：`C3~C0 | A11~A0 | D7~D0`，读寄存器命令 `C3~C0 = 0b0011`：

```c
tx[0] = 0x30 | ((addr >> 8) & 0x0F);
tx[1] = addr & 0xFF;
tx[2] = 0x00;                    // 数据从这里回来
```

难点是 SPI1 被 20 kHz 角度 DMA 独占。`BspServo_ReadEncReg()` 的做法是：先等 `s_spi_busy` 清零（最多 5 ms），再阻塞发 3 字节（约 2.3 µs @10.6 MHz）。期间 ISR 的 `StartEncoderDma()` 会返回 BUSY，角度保持上一拍值 —— 丢 1 拍，600 rpm 下相当于 0.05% 的圈数误差，可接受。

### 5.2 状态机

```
SPINUP   启动速度闭环，加速到 600 rpm
SETTLE   连续 3 s 转速都在 400~800 rpm 区间内（AUTO_CAL_FREQ=0x03 的范围）
CAL      CAL_EN=1，记录起始位置；每 100 ms 读 0x113[7:6]
           = 2 -> 芯片判失败，立即中止
           = 3 -> 芯片判成功，收工
         同时统计圈数与转速极值，仅用于记录
DONE     拉低 CAL_EN，关速度环，封 MOE，打印结果并提示断电
```

### 5.3 为什么不用 deadman

校准要连续转 7 s，而 deadman 是 2 s。本模块与 `Z`（极对数辨识）用同样的做法：全程 `s_armed = 0`，deadman 不倒数，自己管 30 s 超时 + 每拍查故障位。对外只有"开始 / 查询 / 中止"三个动作，`D` 命令会调 `EncCal_Abort()`。

### 5.4 判据只认芯片，不认圈数

第一版写完时我用 "圈数 ≥ 64" 作为成功判据，这是错的：芯片要在转完最后一个周期后才把参数写进 EEPROM，只按圈数收工会拿到一张没写完的表。现在**圈数只用于打印进度**，结束条件只有两个 —— 芯片报 2（失败）或 3（成功），其余一律等超时。

实机也印证了这点：芯片在 **51.6 圈**时就已经报成功，并不是 64 圈。所以拿圈数当判据必然误判。

## 6. 实测数据

```
[CMD] EC start 600rpm 64turns ~7s  DO NOT touch motor
[CMD] EC ok turns=51.60 avg=599.90rpm [595.26..595.90] chip=3 -> !!! POWER CYCLE REQUIRED (>6s) !!!
```

| 项 | 值 |
|---|---|
| 目标转速 | 600 rpm（`AUTO_CAL_FREQ` 默认 0x03 = 400~800 区间） |
| 实际平均 | 599.90 rpm |
| 波动区间 | 595.26 ~ 595.90 rpm（±0.4 rpm，说明速度环在这个工况下很稳） |
| 芯片判完成时圈数 | 51.6 圈 |
| 芯片状态 | 3 = 成功 |
| 校准期间电流峰值 | 3.27 A（`ovc=-3.27/-3.26`） |
| 总耗时 | 约 7 s |

## 7. 必须做的收尾（固件做不到）

厂商手册 9.2 第 (5)(6) 步：

> 自校准成功完成后（等待 >6 秒钟），请务必给芯片断电；芯片重新上电后，才可以进行别的操作。

板上没有编码器电源开关，`!` 软复位也不断 3.3 V，所以**只能人工断电**。校准完不断电就继续跑，芯片可能还在校准模式里，角度输出不可信。

建议流程：

```
C → Z → ^  → 等 "POWER CYCLE"  → 断电等 6 s  → 上电
→ C → Z（重新标定，因为编码器非线性变了，零点可能有微小变化）
→ 验证
```

## 8. 怎么验证校准真的有效

校准前测得的主脉动是 **117 Hz、0.146 A**（500 rpm 时，正好是基波频率），来源判定为电角度周期性误差。校准后应该看到这个峰明显下降。

用已有的 `&` 命令采 20 kHz 波形 + FFT 对比：

```bash
python harm_fft.py COM27 500      # 断电重启前后各跑一次，比较 117 Hz 分量
```

判据：
- 117 Hz 分量下降 → 校准生效，偏心误差被压下去
- 没变化 → 要么校准参数没被加载（没断电），要么那 0.146 A 不是编码器引起的（可能是磁路不对称，芯片校准管不了）

## 10. 局限与后续

| 项 | 现状 |
|---|---|
| **必须人工断电** | 固件无法切断编码器电源。若将来做产线工装，可以考虑用 MOS 控制 3.3 V |
| 转速区间固定 400~800 rpm | 用的是出厂默认 `AUTO_CAL_FREQ=0x03`。若某台电机在这个区间机械共振，需要用 SPI 改寄存器（`写寄存器` 命令 `0b0110`）切到 100~200 或 800~1600 区间 |
| 只做了第 ② 层 | NLC 对拖（±0.02°）需要第二套高精度基准，本轮不做 |
| 温漂 | MT6835 内置温度补偿，但校准是在室温做的；高温下 INL 会退化（厂家给出 70 °C 时速度波动约 ±10 rpm @3000 rpm） |
| 未做软件 LUT 退路 | 若换用无自校准能力的编码器，需要补 128~1024 点 LUT + Flash 存储 + 插值，可参考 VESC 的 `enc_corr[360]` 接口形态 |
