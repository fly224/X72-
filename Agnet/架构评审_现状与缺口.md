# X72 伺服固件架构评审

> 2026-11-17 22:00–22:10。基于当前工程实测：`Board/` 17 个 .c 共 11526 行，
> `Core/` 3069 行，Simulink 生成代码 1331 行；固件 `Code=96184`（512 KB Flash 占 18.8%）、
> `ZI=17460`（128 KB RAM 占 13%）。版本号 `UART_LINK_FW_VER = "0.1.0-debug"`。

---

## 1. 分层现状

| 层 | 文件 | 行数 | 职责 | 问题 |
|---|---|---:|---|---|
| 生成代码 | `simulink_code_gen/three_loop_deploy.c` | 1331 | 位置环 + 速度环 + 电流环（MBD） | **只在一个分支里用到，参数已与手写路径脱节** |
| 控制律 | `servo_isr.c` | 1988 | 20 kHz 五条并行链 + 速度环 + 调度 + 前馈 + 记录 | 单文件承担过多职责；调制链重复 4 份 |
| 命令/编排 | `servo_cmd.c` | 2420 | ASCII 解析 + 模式切换 + deadman + 23 个 handler + 结果泵 | **god module**；81 个 `case` 标签 |
| 硬件抽象 | `bsp_servo.c` | 898 | PWM/ADC/编码器 SPI-DMA/NTC/母线/故障/看门狗/保护 | 职责混杂：硬件 + 保护 + 热管理 |
| 台架辨识 | `mech_ident` 等 7 个模块 | **2663** | 扫频/惯量/齿槽/极对数/ψ-R-L/阶跃/编码器校准 | **无条件编进量产固件**，无编译开关 |
| 通信 | `telemetry_tx.c` `uart_link.c` | 812 | 100 Hz 三帧 + ASCII 通道 | 回显单槽，丢弃无计数 |
| 存储 | `param_store.c` | 387 | 两页 Flash + CRC | **无 A/B 冗余** |

## 2. 最严重的结构性问题：两套控制栈，参数已漂移

模型路径（`E` 使能 / 位置保持）与手写路径（速度、力矩）**跑的是两套不同的电流环参数**，
而且没有人同步过：

| 参数 | 模型 `par_c/par_w`（`servo_isr.c:1883`） | 手写路径现值 | 偏差 |
|---|---:|---:|---:|
| `kp_i` | 0.71314153 | **0.5341** | 模型高 33% |
| `ki_i` | 2378.1856（= 0.1189/Ts） | **2513.2**（= 0.12566/Ts） | 模型低 5% |
| `Ld` / `Lq` | 113.5 µH | **85 µH** | 模型高 34% |
| `psi` | 7.59298 mWb | **4.333 mWb** | **模型高 75%** |
| `kp_w`（速度环） | 0.07292272 | **0.583** | 模型低 **8 倍** |
| `ki_w` | 10.190689（ki·Ts = 5.1e-3） | **0.0408** | 模型低 **8 倍** |

来源：`servo_isr.c:1883-1910` 的 `model_params_init()` 是 2026-11-15 之前的整定值；
2026-11-17 的 P1 参数校正（L 113.5→85 µH、ψ 7.59→4.33 mWb、Kp 0.713→0.534）
只改了 `servo_isr.c` 的宏，**没有同步 `par_c/par_w`**。

后果：
- 位置模式（`E`）的电流环带宽是 1335 Hz（手写路径是 1000 Hz），零点/极点对消失配；
- 位置模式在转速不为 0 时，BEMF 前馈按 7.59 mWb 给，实际只需 4.33 —— **过补 75%**，
  设计上相当于在 q 轴串了一个正反馈项；
- 位置模式的速度环只有手写路径的 1/8 增益，跟随性能天然差 8 倍。

这不是"两套参数各有取舍"，而是**同一台机器上跑两套没对齐的控制器**，
而且没有任何注释或测试说明哪一套是准的。

## 3. 一个 20 kHz ISR 里五条并行链，特性覆盖不一致

`servo_isr.c` 的顶层分支：

| # | 分支 | 触发条件 | 用途 | 死区补偿 | 5/7 次谐波 | 温度降额 | 齿槽前馈 |
|---|---|---|---|:--:|:--:|:--:|:--:|
| 1 | 故障 | `GetFault()!=0` | 封锁、占空比回中 | — | — | — | — |
| 2 | `s_ol_en` | `L`/`Z` 对齐 | 虚拟角 dq 电流闭环 | ✓ | ✗ | ✗ | ✗ |
| 3 | `s_olv_en` | `@` 的 L 段 | 虚拟角 d 轴电压注入 | **✗** | ✗ | ✗ | ✗ |
| 4 | `s_cur_en` | `>` / `=` | 力矩 + 速度闭环 | ✓ | ✓ | ✓ | ✓（仅速度环） |
| 5 | else（模型） | `E` / `P` | 位置保持 | ✓ | **✗** | **✗**（本轮已补） | ✗ |

每条链都自己写了一遍 Clarke/Park、PI、圆限幅、逆 Park、SVPWM 占空比，
**约 60 行 × 4 份 = 240 行重复数学**。改一处（比如限幅策略、抗饱和）必须记得改四处。

本轮实测到的直接后果：温度降额我一开始只加在 4 号分支，
`E` 位置保持（5 号分支）完全不受降额约束 —— **已补**（`par_c[10] = 9.0f * s_derate`，
模型唯一的限流入口）。这只是同类问题的一个实例，谐波抑制和齿槽前馈在模型路径同样缺失。

## 4. 状态管理：9 个标志，没有单一真相

| 标志 | 位置 | 含义 |
|---|---|---|
| `s_enable` | servo_isr:40 | 使能 |
| `s_mode` | servo_isr:65 | POSITION / VELOCITY / SPEED |
| `s_cur_en` | servo_isr:216 | 电流（力矩）模式 |
| `s_spd_en` | servo_isr:444 | 速度闭环 |
| `s_ol_en` | servo_isr:84 | 开环虚拟角 |
| `s_olv_en` | servo_isr:94 | 开环电压注入 |
| `three_loop_deploy_U.en` | 生成代码 | 模型使能 |
| `s_armed` | servo_cmd:89 | 已武装（deadman 计时中） |
| `s_kill` | servo_cmd:87 | 待封锁标志 |

这 9 个标志共同描述**一个**逻辑状态（等效于 CiA402 的
Disabled/Ready/SwitchedOn/OperationEnabled/QuickStop/Fault 六态），
但没有状态机、没有非法组合检查。例如 `s_spd_en=1` 且 `s_cur_en=1` 是可能的，
谁优先取决于 ISR 里 `if/else if` 的书写顺序 —— 这种"顺序即优先级"的隐式规则
在 1988 行的文件里很难维护。

## 5. 缺失清单（按层，含证据）

### 5.1 产品化必需，当前完全没有

| 缺失 | 证据 | 影响 |
|---|---|---|
| **固件升级通道** | 分散加载 `LR_IROM1 0x8000000`，无 bootloader 区 | 现场升级必须拆机接 SWD |
| **CAN 应用层** | `fdcan.c` 只有 `MX_FDCAN1_Init`，Board 层零引用 | 板子叫 X72_CAN 却只能用串口 |
| **位置给定/回零/软限位** | `P` 命令回显 `POS hold`；`Servo_SetPosRef` 只在初始化贴当前角；`motion_profile.c` 无调用者 | 做不了点到点运动 |
| **抱闸输出** | 全工程无 brake 相关代码 | 垂直轴断电会掉 |
| **故障历史** | 只有 `s_fault` 位，无时间戳、无历史 | 现场偶发故障无法追溯 |

### 5.2 可靠性

| 缺失 | 证据 | 影响 |
|---|---|---|
| **参数页无 A/B 冗余** | `ParamBlob` 固定 `0x0807F000`，`CogBlob` 固定 `0x0807E000` | 擦除中掉电 = 全部标定丢失（C+Z+cog+RL+ψ 要重做约 2 分钟 + 人工步骤） |
| **ASCII 回显丢弃无计数** | `s_out_pending` 单槽，新 `emit` 直接覆盖旧行，无 drop 计数 | 现场"命令没反应"只能靠猜 |
| **CPU 负载不可见** | `Servo_GetMaxStepCycles()` 定义了但**无人调用** | 20 kHz 预算 8500 cycles，实际占用未知；ISR 里有 11 处 `sinf/cosf` |
| **无栈用量分析 / 无 MPU** | 工程无相关配置 | 深调用（sinf + 生成代码）溢出不可检测 |

### 5.3 可维护性

| 问题 | 证据 |
|---|---|
| **god module** | `servo_cmd.c` 2420 行 / 23 个 handler / 81 个 case |
| **台架代码进量产** | 2663 行辨识模块无条件编译，量产固件里带着"扫频/惯量/齿槽/开环注入"这些会转电机的命令 |
| **死代码** | `motion_profile.c`（240 行，无调用者）、`Servo_GetMaxStepCycles`（无调用者） |
| **遗留文件** | `Board/servo_cmd.c.bak_v6ident`（15.5 KB，11-15） |
| **注释漂移** | `bsp_servo.c` "分压比 1/201"（实为 1/21）；`model_params_init` 头注释写"10 kHz → 100 us"而 `par_c[2]=5e-5`（20 kHz）；`mech_ident.h` 写 `ALPHA=0.03` 而实际 `0.21`；`servo_isr.c` 死区注释还写 670 ns/1.34%（实为 294 ns/0.588%） |

### 5.4 性能

| 项 | 现状 | 天花板 |
|---|---|---|
| 测速低通 | `BSP_SPEED_LPF_ALPHA=0.21` @2.5 kHz ≈ 95 Hz | 速度环带宽被压在 ~150 Hz 以下 |
| 电流采样 | 30 mV/A，额定 5 A 只占 4.5% 满量程 | 26.9 mA/LSB，噪声 1.8 LSB |
| ISR 计算 | 11 处 `sinf/cosf`，无实测负载 | 20 kHz 周期 8500 cycles |

## 6. 建议的优先级

### P0 两套参数对齐（改动最小、风险最明确）

三条路，需要选一条：

1. **同步 `par_c/par_w` 到实测值**（6 行改动）：`kp_i=0.5341`、`ki_i=2513.2`、
   `Ld/Lq=85e-6`、`psi=4.333e-3`、`kp_w=0.583`、`ki_w` 按 0.0408/Ts。
   → 位置模式行为会变（电流环变慢、BEMF 前馈减半），需重测位置保持与阶跃。
2. **废弃模型路径**：手写一个位置环（约 100 行 P + 前馈），删掉生成代码。
   → 彻底消除双栈，调制链合成一份，特性覆盖自然统一；代价是放弃 MBD 生成流程。
3. **保持现状但显式标注**：在 `model_params_init` 上写清"这是模型原始整定，
   故意不跟手写路径同步"，并禁止在位置模式做性能评估。→ 最省事，但技术债留着。

### P1 特性覆盖补齐

至少把**温度降额**（已补）和 **5/7 次谐波**补到模型路径，或者明确写"仅速度/力矩模式支持"。

### P2 状态机收敛

把 9 个标志收进一个 `servo_state_t`，加非法组合断言。这一步不动控制律，只动入口。

### P3 产品化功能

bootloader → CAN 应用层 → 位置给定/回零/软限位 → 抱闸。

### P4 工程化

参数 A/B 页、ASCII drop 计数、CPU 负载上报、台架代码编译开关、清理死代码与注释。

---

## 7. 一句话总结

**这套固件的控制算法部分已经相当完整（辨识、前馈、调度、补偿都有实测支撑），
真正缺的是"工程结构"：两套控制栈没有对齐、五条并行链各写一遍、
九个状态标志没有单一真相、以及产品化必需的升级/通信/位置功能全缺。**

最短的收益路径是先做 P0+P1（约一天，能消除"同一台机器两套控制器"这个最大隐患），
再做 P2（状态机），最后才是 P3 的产品化功能 —— 因为 P3 建立在前三者之上，
否则每加一个功能都要在五条链、两套参数里各改一遍。
