# 位置环精度与重复定位精度实测

> 2026-11-17 · X72 · 手写三环 · 固件 `Code=105xxx`

## 0. 结论

| 指标 | 实测 |
|---|---|
| 单向重复定位精度（1.0 rad，n=10） | **σ = 27 µrad（0.0015°），range = 85 µrad，±3σ = 82 µrad** |
| 双向重复定位精度（正/反交替，n=10×2） | **σ = 44 µrad，±3σ = 132 µrad** |
| 双向差（正向均值 − 反向均值） | **+48 µrad**（0.0028°） |
| 定位偏差（相对目标） | **+17 ~ −85 µrad 量级，随行程变化** |

换算成角秒：σ ≈ **5.6″**，双向差 ≈ **10″**。

---

## 1. 先做的一件事：三环默认改走手写代码

原来 `E` 使能走的是模型三环（`three_loop_deploy`），只有 `P` 命令走手写位置环。
现在 `E` 也切到手写：

```c
/* do_enable() */
Servo_SetEnable(0U);                    /* 模型三环保持关闭 */
Servo_SetMode(SERVO_MODE_POS_LOOP);
apply_spd_gains();
Servo_SetPosMode(1U, BspServo_GetThetaMulti());   /* 目标=当前实测，误差≈0 */
BspServo_PwmEnable(1U);
```

模型分支同时**旁路掉执行**：`s_enable == 0` 时不调 `three_loop_deploy_step()`，
直接输出三相中点。两个好处：

1. 省掉每拍模型内部的三角函数（生成代码 1331 行）；
2. 杜绝"某条路径意外置 `s_enable=1` 就让模型突然接管"。

> `s_enable` 现在没有任何入口会置 1。模型代码与 `par_c/par_w` 保留，
> 随时可以通过 `Servo_SetEnable(1)` + 让 `s_cur_en=0` 恢复对比。

顺手补了一个联锁：`E` 原来只查 `C`（电流零点）不查 `Z`（电角度）。位置环要出力矩
就得靠电角度，零点没标时"正 iq"可能出反向力矩。速度环和位置定位早就有这道，`E` 是漏的。

## 2. 测试方法

用 30040 帧（`enc_sum` int64，100 Hz）采位置，不占 ASCII 通道。

```
每个循环：
  1. 定位到 (目标 − 0.5 rad) 并驻留，确保从**同一方向**接近
  2. 定位到目标，驻留 1.2 s
  3. 采 0.35 s，取末尾 1/3 均值作为"停位"
```

- **单向重复性**：每次都从负方向接近，n=10
- **双向重复性**：正/反方向交替接近，各 n=10
- **定位偏差**：停位均值 − 目标（目标由 `P` 回显的 6 位小数给出）

坐标换算：`enc_sum` 是"相对上电点"的累积量，控制器用 `BspServo_GetThetaMulti()`
（带绝对零点），两者差一个常量。脚本先取一次基准算出偏移再统一换算。

## 3. 结果

### 3.1 行程 1.0 rad（n=10）

| 组 | n | mean (rad) | σ (µrad) | range (µrad) | ±3σ (µrad) | 相对目标 |
|---|---:|---:|---:|---:|---:|---:|
| 单向 | 10 | 2.695362 | **27** | 85 | 82 | +19.7 µrad |
| 正向接近 | 10 | 2.695383 | 33 | 108 | 100 | +41.2 µrad |
| 反向接近 | 10 | 2.695335 | 40 | 139 | 120 | −7.1 µrad |
| **双向合并** | 20 | 2.695359 | **44** | 174 | 132 | +17.0 µrad |

**双向差 = +48 µrad（0.0028°）**。

### 3.2 不同行程

| 行程 | 单向 σ | 单向 range | 双向 σ | 相对目标 |
|---|---:|---:|---:|---:|
| 0.2 rad | 22 µrad | 70 µrad | — | −50 µrad |
| 1.0 rad | 27 µrad | 85 µrad | 44 µrad | +17 µrad |
| 3.14 rad | 23 µrad | 64 µrad | 18 µrad | −85 µrad |

**重复性与行程基本无关**（18–44 µrad），说明它受限于编码器量化与摩擦微振，
而不是行程长度或规划器。

"相对目标"随行程从 −50 → +17 → −85 µrad 摆动，量级在 ±85 µrad 内，
没有明显的系统性趋势 —— 更像每次上电后基准/残余应力的随机项，而非固定偏差。

## 4. 过程中发现并修掉的关键缺陷：多圈角随机游走

第一版测出"定位偏差 −580 µrad"，换一次上电又变成 +288 µrad。查下来是
`bsp_servo.c` 里这一行：

```c
/* 旧实现 */
s_theta_multi += d;
```

`d` 是单拍角度差，带编码器 **±1 count 量化 = ±3.0 µrad**（2^21/圈）。
静止时 `d` 大部分是 0、偶尔 ±1 count —— 这是一次**随机游走**：

```
2 kHz × 5 s = 1e4 拍   →   σ ≈ 3 µrad × √1e4 ≈ 300 µrad
```

正好是观察到的量级，而且**随运行时间增长**。位置环用的是 `s_theta_multi`，
所以它的"绝对定位精度"会随时间劣化 —— 这是长时间运行的隐患，不只是测试误差。

修法：由整数计数重算，不再累加。

```c
/* 新实现：s_pos_sum 是 int64 精确累加（整数域差分 + 回绕修正） */
if (s_tmulti_first != 0U) {
    s_tmulti_first = 0U;
    s_tm_base      = theta;
    s_theta_multi  = theta;
} else {
    s_theta_multi = s_tm_base
                  + (float)((double)s_pos_sum * (6.28318530717958647692 / 2097152.0));
}
```

重算误差有界（< 1 个 float ulp ≈ 0.6 µrad @ 5 rad）且**不累积**。
`base` 取第一拍的单圈角，保持与 `s_theta` 完全同零点 —— 这样位置环才能和
30040 遥测的 `enc_sum` 对齐。

修完前后对比：

| | 相对目标偏差 |
|---|---|
| 修前 | −580 µrad / +288 µrad（两次上电不一致） |
| 修后 | +17 ~ +20 µrad（可重复） |

## 5. 测量工具本身也被修了一道

为了给"定位偏差"一个可信基准，`P` 回显的位置字段加了 `put_f6()`（6 位小数，≈1 µrad）：

- `put_f3` = 1 mrad 量化 → 基准不确定度 ±500 µrad，比被测的 30 µrad 大一个数量级
- `put_f4` = 0.1 mrad → 仍差 3 倍
- `put_f6` 用 double 乘法（float 在 95 rad 时 ulp 已经是 8，直接乘 1e6 会在第 6 位上自欺欺人）

## 6. 必须说清楚的局限

**编码器装在电机侧，减速器背隙在输出端，这里量不到。**

所以上面所有数字反映的是"**控制环把电机停准的能力**"，不等于"关节输出端停在哪儿"。
减速器的背隙、柔度、齿面接触变形都不在测量回路内。

- 关节输出侧的实际定位精度 = 电机侧精度 / 减速比 × (1/效率) + 减速器背隙 + 柔度变形
- 本机是 1:1 台架（编码器与电机同轴，未接输出端负载），所以数字偏乐观

要测输出端，需要：输出端编码器（双编码器方案）或外部测量（激光干涉仪、千分表 + 高精度转台）。

另外，"双向差 +48 µrad" 是电机侧的正反向停位差，它**不是**减速器背隙；
它反映的是电机侧传动链（联轴器、轴承）的滞环与静摩擦的方向性。

## 7. 复现命令

```bash
python pos_rep.py COM27 --delta 1.0 --n 10      # 单向 + 双向各 10 次，约 75 s
python pos_rep.py COM27 --delta 0.2 --n 6
python pos_rep.py COM27 --delta 3.14 --n 6
```

脚本会打印每次的到达点、均值、σ、极差、±3σ、相对目标偏差，以及双向差。
