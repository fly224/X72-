## 1. 摩擦前馈：为什么必须带"起动助推"

标定能测到的是**稳态** iq（3 rpm 时 0.30 A = 动摩擦），但**起动**需要 0.64 A。静摩擦约为动摩擦的 2 倍 —— 只补动摩擦的话，起动仍然靠积分慢慢爬，而爬的过程就是超调的来源。

推力上直接对比（`python Agnet/verify_speed_ff.py`，含粘滞-滑动两态摩擦模型）：

```
[+3 rpm]
  方案                        超调      稳态      iq峰值   起动延迟
  原逻辑（条件积分、无前馈）        68.0%     3.000     0.64 A    19.0 ms
  仅 back-calc（kb=0.3）          68.0%     3.000     0.64 A    19.0 ms
  摩擦前馈（无助推）               68.5%     3.000     0.65 A     6.0 ms
  摩擦前馈+助推                   21.8%     3.000     0.81 A     1.0 ms
  全套（助推+加速度前馈）          20.6%     3.000     0.93 A     1.0 ms
```

**仿真的 68.0% 与实测 68.8% 几乎重合**，说明"静摩擦 2 倍于动摩擦"这个建模是对的 —— 这也反过来解释了为什么之前降增益、加斜坡都压不下 3 rpm 的超调。

助推判据：`|w_meas| < 0.3·|w_ramp|`（明确"还没转起来"）。稳态时 w_meas ≈ w_ramp，判据自然失效，不会过补偿。

### 摩擦前馈量为什么不经过 Kt 换算

模型 `psi = 7.593 mWb`，实测 `4.455 mWb`，差 41%。如果按 `Tc/Kt` 换算，这个误差会直接进前馈。

所以标定测到的**电流**直接作为前馈幅值 —— 物理意义是"低速时需要多少安培才能克服摩擦"，与 psi 无关。`Tc(N·m)` 只作为报告值（按实测 Kt=0.0936 换算）。

### `$` 两点标定

```
$        → 3 rpm 稳定 1.6 s → 平均 200 ms → 100 rpm 稳定 1.8 s → 平均 200 ms
         → fric = iq1（A）、visc = (iq2−iq1)/(w2−w1)
```

标定期间**必须关前馈**，否则测到的是"含前馈的 iq"，会把前馈量算进摩擦，形成正反馈。失败会把原参数还原。

## 2. 加速度前馈

`iq_ff = acc_gain · dw_ref/dt`，默认 `J/Kt × 0.7 = 1.72e-3`。

打 0.7 折扣的理由：J=2.3e-4 是由"8x 增益最优"反推的，误差可能 50%。宁可让 PI 补，也不要前馈过量造成超调。

加速度项必须**低通**（一阶 alpha=0.25，≈2 ms）：斜坡走完时 `acc_ref` 从常数突降为 0，不滤的话前馈瞬间消失会让 iq 掉一个台阶，转速跟着跌落 —— 现象是"到速瞬间抖一下"。

## 3. back-calculation 抗饱和

```c
u_raw = Kp·err + i_term + ff;
u_sat = clamp(u_raw, ±iqmax);
i_term += ki·Ts·err + kb·(u_sat − u_raw);      // kb=0 时退回条件积分
```

默认 kb=0.30（对应跟踪时间常数 `Tt = Ts/kb ≈ 1.7 ms`）。

**实测工作点上看不出差别**（3/30/500 rpm 的 iq 峰值都远低于 3 A 限幅，根本不饱和）。它的价值在：
- 3000 rpm 阶跃（仿真里原来饱和 285 ms）
- 带载后 iq 逼近限幅时

保留 `kb=0` 作为回退开关（退回原来的"冻结积分"）。

## 4. 位置环速度前馈 + 多圈位置

### 4.1 固定滞后问题

`vel_profile.h` 的注释早就写明了：纯 P 位置环 + 无静差速度环，稳态关系是

```
实际转速 = v_ref，但位置存在固定滞后  e = v_ref / Kp
```

| v_ref | e (Kp=50.265) |
|---|---|
| 1 rad/s | 0.020 rad (1.1°) |
| 5 rad/s | 0.099 rad (5.7°) |
| 20 rad/s | **0.398 rad (22.8°)** |
| 50 rad/s | 0.995 rad (57.0°) |

加 `w_ff = v_ref` 后这一项被完全抵消，残余误差只剩动态部分。

### 4.2 为什么必须同时解决跨圈

模型原来的位置环是 `(pos_ref − theta_m) · par_p[0]`，`theta_m` 是**单圈 0~2π**。跨 2π 时误差会突跳 2π，所以固件不得不把 `pos_ref` 折叠回同一圈 —— 那只能保证 ±π 内正确，大范围绝对定位会被折到最近的等价点。实测（2026-11-15，3 rpm / 5.4 s）跨圈一次就 `clamp=1、f=0x01、ovc=-23.37/+22.06`，直接过流跳闸。

### 4.3 改动

模型生成代码打了两处补丁（`simulink_code_gen/three_loop_deploy.{h,c}`）：

```c
/* 头文件：ExtU 增加两个输入 */
real32_T theta_pos;    /* 多圈机械角（位置环用） */
real32_T w_ff;         /* 速度前馈 */

/* 位置环 */
hold_w = (pos_ref - theta_pos) * par_p[0] + w_ff;   // 前馈在限幅之前叠加
```

固件侧：
- `BspServo_GetThetaMulti()` 新增：与 `s_theta` 同零点、按同一个 `d`（已做 ±π 回绕修正）累加的多圈角
- `theta_pos = dir·theta_multi`、`pos_ref = dir·s_pos_ref`、`w_ff = dir·s_pos_w_ff`
- 删掉 `pos_ref` 折叠逻辑
- `VelProfile_Enable / Disable / Step` 全部改用多圈角
- `s_pos_w_ff = VelProfile_GetVref(&s_vel)`（速度轨迹模式下）

**⚠ 模型补丁是手工的，模型重新生成会覆盖。** 补丁点只有两处（结构体两个字段 + 位置环一行），重新生成后按本文档重打。

## 6. 参数持久化

`ParamBlob` 从 48 B 扩到 **56 B**：新增 `fric_a`、`fric_visc`，`PS_VERSION` 升到 **2**。

版本升级会让旧参数判为"没存过"（CRC + version 双重校验），这是有意的：字段变了就不能半套应用。烧录本来也会擦掉参数页，所以实际影响为零。

`PS_FLAG_FRIC` 只在 `fric_a > 0.01` 时才置位 —— 存一个 0 会在下次上电被当成"标定过、摩擦为零"，比不存更误导。

**恢复时不改变"是否启用"**：上电默认关，让用户显式用 `*` 打开，避免旧参数在新接线上突然生效。

## 9. 风险与回退

| 项 | 风险 | 回退 |
|---|---|---|
| 摩擦前馈 | fric 填大会低速冲一下 | `*` 关掉，或 `[0` |
| 起动助推 | boost>2 会明显冲 | `{0` 关掉助推 |
| 加速度前馈 | J 估错导致超调 | `]0` |
| back-calc | kb>1 可能振荡 | `kb=0` 需改宏（没有命令），或 `|` 收紧 iqmax |
| 多圈位置 | theta_pos 与 pos_ref 零点不一致会飞车 | 恢复折叠逻辑（`servo_isr.c` 里那段被替换的注释有原始代码） |
| 模型补丁 | 重新生成会覆盖 | 按 §4.3 重打两处 |

**最危险的是多圈位置**：如果 `theta_pos` 与 `pos_ref` 的零点错开 2π 的整数倍，位置环会看到巨大的虚假误差 → hold_w 打限幅 → iq 顶到 9 A。

上电自检建议：进位置模式前先看 `K`（虽然 K 是速度环），或者临时看 `S` 的 `clamp=` 是否在涨。若一使能就冲，立刻 `D`。

真正的护栏是：两者都从 `VelProfile_Enable(GetThetaMulti())` 这一处起步，只要不混用单圈角就不会错。
