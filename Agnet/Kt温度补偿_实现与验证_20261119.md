## 一、为什么只补三处，不补全部

`Kt` 在固件里被用作"力矩 ⇄ 电流"的换算因子。**只有用户以物理量（N·m）交互的接口才需要补偿**：

| 环节 | 位置 | 是否补偿 | 理由 |
|---|---|---|---|
| MIT：τ → iq | `servo_isr.c:1704` | **是** | 用户给 τ，50 °C 不补则只出 96.4% 力矩 |
| MIT：τ 回读 | `servo_isr.c:1714` | **是** | 只改一侧会让"设定=实际"不成立 |
| 力矩估算 `Servo_GetTorqueEst()` | `servo_isr.c:502` | **是** | 显示值，不补则高温偏高 2.4% |
| 速度/位置环 | — | 否 | 用 iq 闭环，Kt 只决定"多少 iq 出多少力矩"，**不改稳态转速**（一小时温漂实测：17 K 下误差 +0.020 rpm，R²=0.011） |
| 加速度/摩擦前馈系数 | `:794-799` | 否 | 编译期 A 单位常量，3.6% 误差由速度环 PI 吸收；动态改反而引入新整定风险 |
| 惯量辨识 `MI2_KT` | `mech_ident.c:84` | 否 | 离线辨识，每次实验温度不同本身就是变量，补偿它会污染 J 的历史可比性 |

### 实现要点

```c
/* servo_isr.c:215 起 */
#define SERVO_KT_ALPHA       (-0.001197f)   /* 1/K，实测 α_ψ */
#define SERVO_KT_T_REF       (20.0f)        /* °C */
#define SERVO_KT_COMP_MIN    (0.90f)
#define SERVO_KT_COMP_MAX    (1.10f)

static volatile float   s_kt_comp    = 1.0f;
static volatile uint8_t s_kt_comp_en = 1U;

void Servo_UpdateKtComp(float t_mot_c)      /* 1 ms 任务调用 */
{
    float k;
    if (s_kt_comp_en == 0U) { s_kt_comp = 1.0f; return; }
    if (t_mot_c != t_mot_c) { return; }     /* NaN：NTC 故障，保持上次值 */
    k = 1.0f + SERVO_KT_ALPHA * (t_mot_c - SERVO_KT_T_REF);
    if (k < SERVO_KT_COMP_MIN) { k = SERVO_KT_COMP_MIN; }
    if (k > SERVO_KT_COMP_MAX) { k = SERVO_KT_COMP_MAX; }
    s_kt_comp = k;
}
```

三处换算：

```c
/* :502  力矩估算 */
return SERVO_KT_NM_PER_A * s_kt_comp * s_cur_iq;

/* :1704  MIT τ→iq */
iq_ref = tau / (SERVO_KT_NM_PER_A * s_kt_comp);

/* :1714  MIT τ 回读（与上一行同系数，保证"设定=实际"） */
s_mit_tau_out = iq_ref * (SERVO_KT_NM_PER_A * s_kt_comp);
```

挂钩点（`Servo_SlowTask1ms`，与降额同一处、同一拍 NTC）：

```c
Servo_SetDerate(BspServo_GetDerate());
Servo_UpdateKtComp(BspServo_GetTempMotor());   /* 新增 */
Servo_MitTask1ms();
```

### 安全性设计

| 风险 | 处理 |
|---|---|
| NTC 开路/短路（驱动层返回 NaN） | `t != t` 判断，**保持上次值**，不会把 Kt 打到 0 |
| NTC 野值 | 限幅 0.90~1.10（等效 −84...+84 K） |
| 20 kHz 与 1 ms 竞争 | `volatile float`，Cortex-M4 上 32 位对齐读写原子，无需临界区 |
| 需要回退 | `Servo_SetKtCompEn(0)` 立即把系数归 1，行为与补偿前完全一致 |

## 二、诊断接口

`S` 状态行新增两个字段：

```
... idq=0.00/0.39 tau=0.035 ktc=0.974 ...
```

- `tau=` 力矩估算（N·m，3 位小数），= Kt(T)·iq
- `ktc=` 补偿系数（3 位小数），**仅在偏离 1.0 超过 0.2% 时追加**（常温 22~25 °C 就会显示，避免占满 200 字符的行宽）
- 关闭补偿时显示 `ktc=off`

用 3 位小数是必需的：3% 的补偿量在 2 位小数下会被量化淹没（0.96 vs 0.964 分不开）。

## 三、实机验证

### 3.1 为什么不能用 MIT 测

MIT 是**力矩控制**：空载稳态净力矩必然为 0（否则一直加速），所以稳态 iq 恒趋近 0，测不出 Kt。给常值 τ 又会在 `SERVO_MIT_WMAX = 30 rad/s` 前只有 60~80 ms，且必触发超速故障。

改用判据：**速度模式稳态下读 S 行的 ktc**，与 `1 + α(T−20)` 对比。

### 3.2 结果

| 工况 | Tmot (°C) | ktc 实测 | 理论 | 偏差 |
|---|---|---|---|---|
| 冷态 | 26.61 | 0.992 | 0.9921 | **0.0001** |
| 热态 | 39.62 | 0.974 | 0.9765 | 0.0022 |

13.01 K 跨度：实测变化 −0.0177，理论 −0.0156，**幅度比 1.13**。

热态 0.0022 的偏差来源（可解释，非缺陷）：
- `put_f3` 量化 0.001（±1 个 LSB）；
- NTC 采样为 10 Hz 且带噪声，`Servo_UpdateKtComp` 用的是当拍读数，与遥测快照最多差 0.1 s / 少量噪声；
- 折算成温度约 1.8 K，在 NTC 的 ±1~2 K 噪声带内。

**判据设计的一个教训**：最初想用 `τ/iq` 比值验证（理论上它恒等于 Kt·comp），但实测反而 +4.9% —— 因为 `tau` 是 3 位小数、`iq` 只有 2 位，0.49 vs 0.36 的量化误差可达 6%，把 3% 的真实变化完全淹没。**低精度字符串输出的比值不能作判据**，这一点已写进脚本注释。

## 五、局限与已知副作用

1. **基准仍是 0.0910**（对应 ψ=4.333 mWb），而本次实测 ψ20=4.390 高 1.3%。没有改基准，因为改动会波及 `mech_ident.c:MI2_KT` 与已标定的 J、前馈系数；1.3% 在 25 K 外推的不确定度内。
2. **MIT 手感会随温度轻微变化**：kp/kd 是 N·m/rad 与 N·m·s/rad，经 Kt 换算成 iq。补偿让"物理力矩准确"，但同一 kp 在不同温度下的 iq 增益变了 3.7%，**刚度/阻尼的闭环动态会略有差异**。若要用于力控，建议在冷/热两态各做一次阶跃复验。
3. **前馈系数未补**：加速度前馈 `J/Kt` 在 50 °C 偏大 3.7%，由速度环 PI 吸收，实测无影响（一小时温漂数据印证）。若将来做高速高动态轨迹，可考虑一并补偿。
4. **依赖电机 NTC**：NTC 贴在定子/散热器上，与绕组热点有 0.5~2.0 K 滞后（见 ψ 温漂报告第四节）。带载时绕组更热，补偿会**略微不足**（偏保守，不会过冲）。
5. **未做长期漂移验证**：本次验证跨 13 K、18 分钟，未验证数小时/多次热循环后的重复性。
6. **`S` 行已接近行宽上限**：实测 187 字符 / `CMD_LINE_MAX=200`。若同时触发 `dr=`（降额生效）与位置环状态字段，可能超 2~3 字符被截断。若后续还要加诊断字段，建议先把 `bias`/`ovc/raw` 这类低频字段移到独立的 `K` 命令。
