# 摩擦两点标定（`$` / action 9）：失败根因与修复

**日期** 2026-11-21 · **固件** Code=112596 · **验证** 实机通过，1000 rpm 无回退

---

## 一、失败的真正原因：采样窗口太短，不是"样本不稳"

错误码 `FC_ERR_SPREAD` 的文案是 `unstable samples (spread too high)`，容易让人以为是噪声/抖动。实际判据是三条**几何条件**（`fric_cal.c`）：

```c
dw = w2 - w1;  di = iq2 - iq1;
if ((dw < 1e-3f) || (di < 0.0f) || (di > 0.5f * iq1)) { fc_fail(FC_ERR_SPREAD); }
```

补上失败推送后拿到的第一次现场（窗口 200 ms）：

```
err=6(SPREAD)  iq1=0.0671 A @15.35 rpm   iq2=0.1468 A @99.90 rpm
di = 0.0797   0.5×iq1 = 0.0336   → 第三条命中
```

`iq1` 明显偏小。按 1000 rpm 稳态反推的黏滞（`(0.35−0.107)/104.7 = 2.32e-3 A/(rad/s)`），15 rpm 应该给出约 **0.11 A**，实测只有 0.067。

原因是**窗口只转 18°**：

- `FC_AVG_MS = 200 ms`，15 rpm → `15/60 × 0.2 = 0.05 转 = 18°` 机械角
- 15 rpm = 1.57 rad/s，落在齿槽前馈的**门控关闭区**（`CogFf_Get` 的全量区是 10–191 rad/s，即 95–1824 rpm）
- 于是齿槽扰动完全由速度环积分吸收，`iq` 的 200 ms 平均值被"停在哪个齿槽相位"直接偏置——12 槽电机的一个齿槽周期是 30°，18° 连一个都没覆盖

**验证**：只把窗口改成 1000 ms（覆盖 90°，约 3 个齿槽周期），其余不动，`iq1` 从 0.0671 变成 **0.1008**，与反推值 0.11 吻合。

---

## 二、三个修复

### 1. 窗口 200 → 1000 ms（`fric_cal.c:45`）

```c
#define FC_AVG_MS   (1000U)   /* 原 200：15 rpm 只转 18°，不足一个齿槽周期 */
```

代价：标定总时长 3.8 s → 5.5 s（两段 settle 1.6/1.8 + 两段 1.0）。

### 2. 失败也推 30092（`servo_cmd.c:2055`）

原来只有成功分支推送，失败时上位机只能等到超时——连 `iq1/iq2` 都拿不到，而 SPREAD 的判据恰恰是这两个数的关系。约定与 kind=8 一致：`ok=0` 时 `v[0] = 错误码`，后面依次 `iq1, iq2, rpm1, rpm2, visc`。

### 3. 只回写库仑项，黏滞保留原值（`fric_cal.c:266`）

`$` 成功会 `Servo_SetFeedforward(1, ff_acc, iq1, visc)`。但两点法算出的 `visc` 精度不够：`Δiq` 只有 ~0.04 A，齿槽残余就有 ±0.01 A。

实测代价很明确：

| ff_visc | 1000 rpm 稳态 | iterm 均值 |
|---|---|---|
| 2.3e-3（反推值） | 999.75 rpm | **+0.05 A** |
| 4.18e-3（两点法回写） | 999.75 rpm | **−0.145 A** |

转速靠积分兜住了，但 iq 里常驻一项负积分：动态会凹、静态多发热。所以现在只回写 `iq1`（库仑项，两点法真正测得准、且是主导项），`visc` 保持标定前的值。

`visc` 的正确来源仍是 1000 rpm 稳态反推（`30082` 的 `ff_visc` 手调）。

## 四、仍然存在的局限

**`visc` 测不准**（0.0042–0.0048 vs 反推 0.0023，差约 2 倍）。根因是两点差分对 0.04 A 量级的增量做减法，而齿槽残余与速度纹波同量级。三条出路：

1. 就用 1000 rpm 反推 + `30082` 手调（**当前做法**，够用）；
2. 改用 `)`（action 11）的 8 点摩擦曲线做最小二乘——那个已经有 `fric[8]` 数据，只是没做回归；
3. `$` 改多点（3–4 点）并做正反两次平均。

第 2 条最省事，因为数据已经采到了，只差一次回归。要做的话说一声。
