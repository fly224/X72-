## 1 会话建立

### 1.1 权限：`0` 才有权限（反直觉，最容易写错）

```c
/* app_param.c:65 */
static uint8_t has_host_auth(void) { return (s_comm_auth == 0U) ? 1U : 0U; }
```

| 事实 | 值 |
|---|---|
| `has_host_auth()` 判据 | `comm_auth == 0` 时**有**权限 |
| 上电默认 | `s_comm_auth = 0`（**默认就有权限**） |
| 发 `30068 {comm_auth=1, internal=0}` | **撤销**权限，此后所有 set 命令返回 `NO_AUTHORITY` |
| 发 `30068 {comm_auth=0, internal=0}` | 恢复权限 |
| `internal_auth != 0` | 直接 `OUT_OF_RANGE` —— 本板无内部控制器 |

**所以 `30068 {0,0}` 不是"申请权限"，而是"确保权限在"。** 上电本就有，只有在被别的主机
抢过（置 1）之后才需要发。上位机每次连接发一次 `{0,0}` 是安全的幂等操作，但要清楚它**不是**必需的授权动作。

### 1.2 模式是"登记"，不是"生效"

`30056` 只写期望模式，**不动作任何环路**。真正装配发生在 `30054` 使能（`cw bit0=1`）那一刻，
或者已经在环时切模式由 `prepare_switch()` 先 disarm 再装配。

因此：

- 发了 `30056 mode=12` 不等于进了 MIT，`30090` 的 `mode` 字段才是在环模式
- 起环后被拒时，`30090.mode` 显示的是**实际在环模式**，不是缓存值 —— 排查以它为准

### 1.3 使能的三个条件（缺一即拒）

| 条件 | 判据 | 不满足的现象 |
|---|---|---|
| 无故障 | `30090.fault == 0` | 30054 返回 `WRITE_STATE_ERROR` |
| 标定齐全 | `flags` 含 bit0(CAL) + bit1(ZERO) | 同上 |
| 不在辨识中 | `ident_busy() == 0` | 同上 |

`ident_busy()` = `Act_IsBusy() \|\| Servo_IsOpenLoop() \|\| Servo_IsVoltInject()`（`servo_cmd.c:67`）。

> 齿槽表（bit7 COG）**不是**起环条件。缺了能跑，只是低速纹波大。

## 2 状态机：三个状态与迁移

```
        ┌──────────┐  30054 cw=1 且三条件满足   ┌──────────┐
        │   IDLE   │ ──────────────────────────→ │  ARMED   │
        │ 输出封锁  │ ←────────────────────────── │ 某环在跑  │
        └──────────┘   30054 halt=1 / deadman    └──────────┘
              ↑                                        │
              │  任意故障置位（FaultSet 立即清 MOE）      │
              └────────────── FAULT ←──────────────────┘
```

| 迁移 | 触发 | 备注 |
|---|---|---|
| IDLE → ARMED | `30054 {cw=1, halt=0}` | 按 `30056` 登记的模式装配 |
| ARMED → IDLE | `30054 {cw=0, halt=1}` | 推荐显式停，不要依赖 deadman |
| ARMED → IDLE | deadman 到期（2 s） | 只置标志，封锁在主循环做 |
| 任意 → FAULT | 任一故障位置位 | **硬件立即清 MOE**，不等软件 |
| FAULT → IDLE | `30069 action=3` | 前置：PWM 必须已关（`IsPwmEnabled()==0`） |

### 2.1 切模式必须先封锁

`prepare_switch()`（`servo_cmd.c:1170`）：

- 未使能 → 直接走完整装配
- 已在目标环 → 只更新给定
- **在别的环 → 自动 `do_disable()` 再装配**

所以上位机切模式**不必**手动先停，但**必须确认切换成功**（读 `30090.mode`）。
自动封锁会丢掉原环的给定，切回去要重新给。

### 2.2 清故障的前置

`ServoCmd_ClearFault()` 第一行：

```c
if (BspServo_IsPwmEnabled() != 0U) { return 0U; }   /* X 联锁：须先 D */
```

PWM 还在输出时清故障会被**静默拒绝**（30069 的 ack 返回非 0，但故障位不变）。
正确顺序：`30054 {cw=0, halt=1}` → 确认 `flags` 的 ARMED 位已清 → 再 `action=3`。

## 3 保活与失效安全

| 通道 | 超时 | 超时行为 |
|---|---|---|
| 速度 / 力矩 / 位置给定 | **2000 ms**（`CMD_DEADMAN_MS`） | 封锁输出，模式回 IDLE |
| MIT `30065` | **20 ms** | 见下，**不是松手** |
| CAN FD `CMD_AGG` | **10 ms** | 先阻尼（MIT 下 kp=0、kd=0.5），再 50 ms 断使能 |

### 3.1 MIT 的 20 ms 语义（最反直觉）

`servo_isr.c:2632`：20 ms 无新帧 →

- `v_des = 0`、`τ_ff = 0`
- **`p_des` 固化为外推终点**（外推最多 100 ms）

于是控制律变成 `τ = kp·(p_des − p) + kd·(0 − v)`，电机被**拉回最后一帧的目标**并保持。

**要停就发 `30054 halt=1`，或持续发 `p_des = 当前角`。** 停发指令 ≠ 松手。

### 3.2 保活频率

| 模式 | 建议 |
|---|---|
| VEL / TORQUE | 100~500 Hz（2 s 窗口，10 Hz 都有 20 倍余量） |
| POS | 目标不变时**不需要**保活（位置环自己保持），但改目标要发 |
| MIT | 200~500 Hz；低于 50 Hz 会明显看到阶梯 |
| CAN FD | 1 kHz（10 ms 窗口） |

## 4 四种模式的下发序列

### 4.1 POS（位置）

```
30068 {0,0}  → 30056 mode=1 → 查 flags 含 CAL|ZERO、fault=0
→ 30019 {pos_tar_p}      ← 单位是编码器 counts（int64）
→ 30054 {cw=1}           起环
→ 需要再动就再发 30019（不必重复 30054）
→ 30054 {cw=0, halt=1}   停
```

**位置口径**：进位置模式那一拍，`p_now` 被归一化到 `[0, 2π)`，之后输入 `0` 表示"回到本圈 0 点"，
不计累计圈数。输入任意值会折到**最近的等效点**（`±2πk` 里最近的那个）。

判据：`30100` 的 `p_now / p_tgt / err` 与状态机字段。

### 4.2 VEL（速度）

```
30068 {0,0} → 30056 mode=3 → 30019 {pos=0, spd=目标}（counts/s）
→ 30054 {cw=1} → 以 ≥10 Hz 保活 30019 → 30054 {cw=0, halt=1}
```

`30019` 的两路给定是**双缓存**：`pos_tar_p` 与 `speed_tar_p_s` 都存，只装配当前模式那一路。
旁带为 0 时**保留上次有效值** —— 所以切模式不会把另一路打成 0。

### 4.3 TORQUE（力矩）

```
30068 {0,0} → 30056 mode=4 → 30025 {idq_tar_A[1] = iq}
→ 30054 {cw=1} → 保活 → 30054 {cw=0, halt=1}
```

- `30025` 的 `[0]`（id）字段固件**不解释**，要用 id 走 `30095`
- 有效力矩上限 = `cur_iqmax × Kt × kt_comp × 减速比`；`cur_iqmax` 硬上限 5 A
- **给 iq 前先确认无 0x0020**：力矩模式空载会一直加速，超速判据是 `1.5·|v_des|+30`，
  而力矩模式的 `v_des` 为 0 → 门限只有 30 rad/s（286 rpm）

### 4.4 MIT（阻抗）—— 顺序错就炸

```
30068 {0,0}
→ 30056 mode=12
→ 查 30090：fault=0、flags 含 CAL|ZERO
→ 30066 {kp=0, kd=0.05}          零刚度，此时 τ = kd·(0−v) ≈ 0
→ 30065 {p=0}                     起环；从应答里取 p_now（应答 LEN=9，不是 32）
→ 30065 {p=p_now}                 贴住当前位置
→ 30066 {kp=30, kd=0.05}          上刚度
→ 循环 30065 @200~500 Hz，p 给相对当前位置的偏移
→ 30054 {cw=0, halt=1}            停
```

**为什么必须这样**：

- `kp=30` 配 J=5.47e-5 时，**15 mrad 误差就顶满 5 A**（0.45 N·m）
- 起环帧如果盲给 `p=0` 而实际角是 3 rad，`kp·e` 会被 `EP_MAX`（1 rad）限到 −30 N·m，
  空载 3.6 ms 撞 30 rad/s → `0x0020`
- 固件从 2026-11-22 起**不再替上位机兜底**：`30066` 只改缓存，不会用旧目标重发；
  但起环后第一帧 `p` 仍然直接影响输出

**kd 的物理上限**：`kd/(2πJ) ≪ 电流环带宽`。本机 → **kd < 0.1**。kd=0.5 不是"阻尼更大"，
而是 D 项变负阻尼，会起 244 Hz 极限环顶满电流。

**目标整形**：MIT 有内置整形（15 rad/s、180 rad/s²），所以给阶跃不会炸，但**会延迟到位**
（3.09 rad 约 0.5 s）。要精确跟随轨迹就给带速度的 `p_des`，不要依赖整形去追。

## 5 标定与辨识

### 5.1 推荐顺序与理由

```
C(4) 电流零点  →  Z(5) 电角度+极对数  →  }(13) 齿槽表  →  机械四项 ($ 9 / ( 10 / ) 11 / < 12)
```

| 顺序约束 | 原因 |
|---|---|
| C 必须最先 | Z 与所有闭环都依赖电流零点；`flags.bit0=0` 时 Z 直接被拒 |
| Z 必须在齿槽/机械之前 | 齿槽表按 `theta_multi` 存，重做 Z 会让旧表因零点变化而失效 |
| 齿槽在机械四项之前 | 齿槽前馈会污染摩擦/惯量的力矩观测 |

### 5.2 通用前置

| 前置 | 判据 | 违反后果 |
|---|---|---|
| 未使能 | `flags` 的 ARMED 位 = 0 | `10069` 返回 `status=3`（需先封锁） |
| 不在辨识中 | `ident_busy() == 0` | 同上 |
| 无故障 | `fault == 0` | 同上 |
| 电机可自由转 | 物理条件 | 齿槽/机械/编码器自校准会失败或数据错 |

### 5.3 两次辨识至少隔 **0.75 s**

`Act_Acquire()` 后有 `ACT_GRACE_MS = 500 ms` 保护窗口（`actuator.c:33`）。
在这个窗口内发起下一次辨识，`Act_Acquire` 会失败，表现为 `OUT_OF_RANGE`。

**留 0.75 s 余量**（500 ms 窗口 + 命令往返 + 1 ms 任务节拍）。

### 5.4 结果读取：`30092` 事件帧

40 B，`kind` 在 `pl[0]`，`ok` 在 `pl[1]`，8 个 float 从 `pl[4]` 开始。

| kind | 对应动作 | 主要字段 |
|---|---|---|
| 1 | `+`(6) 磁链/Kt | psi_mWb, kt_mNm, Tref_C, R_mOhm, L_uH, ke, dev_pct |
| 2 | `@`(7) R/L | R_mOhm, L_uH, Z_ohm, iamp_A, ... |
| 3 | `<`(12) 惯量 | J_e4, acc1, acc2, tq1, tq2 |
| 4 | `)`(11) 摩擦曲线 | fric_a, visc, n_pts, ... |
| 5 | `}`(13) 齿槽 | pp_A, pp_fwd_A, pp_rev_A, dc_A |
| 6 | `(`(10) 扫频 | wmean_rads, wamp_rads, iamp_A |
| 7 | `^`(8) 编码器自校准 | turns, rpm_avg, rpm_min, rpm_max, ... |
| 8 | `Z`(5) 电角度 | **ratio_int(整数)**, dir, off_deg, zero_deg, n_step, n_sweep, n_fail, resid |

| 2 | CAL | 先做 C |
| 3 | FAULT | 先清故障 |

| 5 | TIMEOUT | 超时 |
| 6 | STUCK | 电机没动/卡死 |
| 7 | RATIO | 极对数不合理 |
| 8 | ENC | 编码器 |
| 9 | OTHER | |

### 5.5 各项目的额外要求

| 项目 | 额外要求 | 用时 |
|---|---|---|
| C(4) | 必须停机、PWM 关 | 200 ms |
| Z(5) | 转子可自由转动（拖拽法） | 18.6 s（含重试最多 27 s） |
| `+`(6) / `@`(7) | 需要开环注入 | 秒级 |
| `^`(8) | 开环拖动，**期间屏蔽编码器故障判据** | 数十秒 |
| `}`(13) | 10 rpm 正反各 1 圈，**行程约 2 圈** | 约 13 s |
| `(`(10) | 20~1000 Hz 扫频，**会明显振动** | 数十秒 |

**Z 的极对数只报整数**（`ratio_int`），小数残差在 `v[7]`。`v[0]` 若出现 13.92 这类值，
说明固件是 2026-11-22 之前的版本。

**`^` 期间会 `BspServo_SetEncFaultMask(1)`**，所以此时 `0x0002` 不会置位 —— 但结束后必须清 0，
否则编码器真的坏了也不会报。

## 6 参数配置

### 6.1 `30082` 是三通道，别混

`192 B` = 16 float（偏移 0~63）+ float 掩码（偏移 64）+ 16 int32（偏移 128~191）+ int 掩码（偏移 124）。

| 通道 | 值位置 | 掩码位置 | 用途 |
|---|---|---|---|
| float | `pl[i*4]` | `pl[64]`（bit i） | 增益类 |
| int | `pl[128 + i*4]` | `pl[124]`（bit i） | 开关/档位 |

**两个掩码独立**。只切一个开关时**只置 int 掩码那一位**，float 掩码给 0 —— 否则会把 16 个增益
一起写进去（大概率写坏）。

### 6.2 回读必须看真值，不能看应答

`30082` 的写入应答只有 `status + n_ok`，`n_ok` 是"成功写入的项数"，**不告诉你写进去的值是多少**。
固件对多数参数会夹到合法区间，所以实际生效值可能与你写的不一样。

**回读方式**：

| 参数 | 从哪读 |
|---|---|
| 大部分 float | 写回 `30082` 并读 16f 全表（**注意：`30000 READ_PARAM` 在本机无应答，见 §9**） |
| `cur_iqmax` | 没有遥测出口，只能看 `30082` 的 `n_ok`（`dbg_set_cur_iqmax` 内部会 `GetCurIqMax()` 比对，`n_ok=1` 即生效） |
| `spd_iqmax` | `30091` 偏移 28（**注意这是速度环的，不是 `cur_iqmax`**） |
| kp/kd | `30066` 写入应答里回读的是**门卫值**，生效值被内部夹过（kp 门卫 5000 → 内部 2000） |

### 6.3 专用配置消息优于 `30082`

| 消息 | 为什么单独开 |
|---|---|
| `30096` 陷波 | 参数会被内部限幅，必须回读实际生效值 |
| `30097` 速度轨迹 | 有"到达时间优先"的语义，不是纯数值 |
| `30098` 编码器补偿 | 16 阶谐波系数，136 B 装不进 float 槽 |

## 7 状态判读：读哪条、看哪个字段

| 想知道 | 消息 | 字段 |
|---|---|---|
| 能不能起环 | `30090` | `fault == 0` 且 `flags & 0x03 == 0x03` |
| 实际在环模式 | `30090` | `mode`（**不是** `30056` 缓存值） |
| 是否已使能 | `30090` | `flags` bit2(ARMED) |
| 输出是否真的在 | `30090` | `cw` bit0 与 `fault` 一起看 |
| 电流是否跟得上 | `30090` | `iq`（实测）vs `iq_ref`（给定） |
| 速度跟踪 | `30091` | `wref` vs `wmeas` |
| 电流环是否饱和 | `30091` | `iqc` vs `iqmax` |
| 母线/温度 | `30090` | `vbus` / `t_mot` / `t_gan` |
| 位置环是否到位 | `30100` | `p_now` / `p_tgt` / `err` / 状态机 |
| 编码器健康 | `30091` | `enc_diag`：b0..2 status、b3..5 帧错、b6..7 跳变 |
| 过流现场 | `30091` | `ovc_peak` / `ovc_raw`（**是历史值，清故障才清**） |
| 命令丢了多少 | `30090` | `drop` |

**判读的两个陷阱**：

1. **`30091` 的 `ovc_peak` 不是实时电流**，是"上次清故障以来的最大 |iu|"。看到 −54 A 不一定是刚发生的。
2. **`30090.pos` 是单圈角**（折叠到 0~2π），而 MIT/齿槽用 `theta_multi`（多圈）。两者差整数圈，
   不能直接换算成 `p_des`。

### 7.1 `30100` 位置环状态（48 B）—— 到位判据只看这里

| 偏移 | 字段 | 含义 |
|---|---|---|
| 0 | `p_now` f32 | 位置环实际角（进模式时归一到单圈，之后累积） |
| 4 | `p_tgt` f32 | 用户目标 |
| 8 | `p_tgt_c` f32 | 规划目标（含补偿） |
| 12 | `p_ref` f32 | 规划器当前参考 |
| 16 | `err` f32 | `p_ref − p_now` |
| 20 | `kp` f32 | 生效位置增益 |
| 24 | `vmax` f32 | rad/s |
| 28 | `errmax` f32 | rad（超此值落 `0x0100`） |
| 32 | `i_term` f32 | rad/s（KI=0 时恒 0） |
| 36 | `travel` f32 | 本次行程 |
| 40 | `fault_cnt` u32 | 累计跟随故障次数 |
| 44 | `st` u8 | **0 IDLE / 1 MOVE / 2 HOLD / 3 DONE / 4 ERR** |
| 45 | `settled` u8 | 1 = 到位 |
| 46 | `comp_en` u8 | 目标补偿开关 |
| 47 | `pos_mode` u8 | 1 = 当前在位置模式 |

**到位判据用 `settled == 1` 或 `st == 3`，不要用"`err` 小于某个值"** —— 规划器有自己的收敛
判定，用 `err` 阈值会在减速段误判。

不在位置模式时该帧照发，`st = 0`，其余字段保持最后值。

## 8 故障处置

`fault != 0` 时硬件立即清 MOE（不等软件），所以任何故障都表现为"输出没了"。

```
读 30090.fault → 按位分派
```

| 位 | 故障 | 先做什么 | 再做什么 |
|---|---|---|---|
| 0 | 过流 | 读 `30091.ovc_peak/raw` | raw≈0 → 电流采样链；raw 正常 → 查机械堵转/短路 |
| 1 | 编码器 | 读 `30091.enc_diag` | status≠0 → SPI/供电；帧错饱和 → 链路质量；跳变饱和 → 磁铁装配 |
| 2 | ADC 同步 | 复位后仍报 → 硬件 | 注入序列被抢占 |
| 3 | BSP 初始化 | 复位 | 外设初始化失败 |
| 4 | SPI | 复位 | MT6835 通信 |
| 5 | 超速 | 给合理的 `v_des` 或降 kp | 力矩模式最易触发（`v_des=0` 时门限只有 30 rad/s） |
| 6/7 | 母线过压/欠压 | 量 `vbus` | 回馈泵升 → 加泄放；错接电源 |
| 8 | 跟随误差 | 查是否堵转 | 位置环 `ERRMAX=6 rad`；`POS_AMAX=30` 防冲过头 |
| 9 | 缺相 | 查三相接线 | 某相实测无电流 |
| 10 | 电流采样异常 | 重做 C | 零点不在中点 / 两相差过大 |

**清故障流程**（必须按序）：

```
30054 {cw=0, halt=1}   →  确认 flags.ARMED=0  →  30069 action=3  →  读 30090 确认 fault=0
```

清完**立即复发**说明故障源还在。此时不要反复清，按上表查。
2026-11-18 与 11-22 两次 `0x0002` 都是清完立刻复发，最终靠软复位（`30069 action=2`）恢复。

## 9 误操作 → 现象对照表

| 你做的 | 看到的现象 | 真实原因 |
|---|---|---|
| 发 `30068 {1,0}` 想"申请权限" | 之后所有 set 都返回 `NO_AUTHORITY` | `1` 是**撤销**，权限值 0 才有 |
| 只发 `30056 mode=12` 就发 `30065` | 应答 `status=0`，电机完全不动 | 模式只登记；未使能时指令只缓存不装配 |
| MIT 起环直接给 `p=3.14` | 3~4 ms 内 `0x0020` | `kp·e` 满力矩，`e` 被限到 1 rad |
| MIT 停发指令以为松手 | 电机被拉回最后一帧目标 | 20 ms 后 `p_des` 固化，是**保持**不是松手 |
| 连发两条辨识 | 第二条返回 `OUT_OF_RANGE` | `ACT_GRACE_MS=500 ms` 保护窗口 |
| 使能状态下发 `action=13` | `status=3` | 辨识要求未 armed |
| PWM 还在时发 `action=3` | ack 非 0，故障位不变 | 清故障有 `IsPwmEnabled()` 联锁 |
| 写 `30082` 只置 float 掩码想改开关 | 16 个增益被一起写 | int 通道有独立掩码 `pl[124]` |
| 用 `30040.enc_sum` 换算 MIT 的 `p_des` | 差整数圈，起环就冲 | `enc_sum` 相对上电点，缺首拍基准角；用 `30065` 应答的 `p_now` |
| 用 `30090.pos` 当 MIT 目标 | 同上 | `pos` 是单圈折叠值 |
| 发 `30000` 读参数表 | 无任何应答 | 本机 `READ_PARAM` 无响应（已知问题），盲写 + 专用回读字段 |
| 力矩模式给 iq 后不管 | 加速到 286 rpm 报 `0x0020` | 力矩模式 `v_des=0`，超速门限只有 30 rad/s |
| 速度模式不保活 | 2 s 后自己停 | `CMD_DEADMAN_MS=2000` |
| 以为 `30091` 的 iqmax 是力矩上限 | 改 `30082[12]` 后它不变 | 那是 `spd_iqmax`（速度环），`cur_iqmax` 无遥测出口 |

## 10 最小可用序列（四个场景）

### 10.1 只读状态（最安全，先跑通这个）

```

```


## 附：单位换算

| 物理量 | 线上单位 | 换算 |
|---|---|---|
| 位置 | 编码器 counts（int64） | `rad = counts × 2π / 2097152`（1 count = 3.0 µrad） |
| 速度 | counts/s（float） | `rad/s = counts/s × 2π / 2097152`；`rpm = rad/s × 9.5493` |
| 电流 | A（float） | — |
| 力矩 | N·m（float，电机侧） | 输出侧 = 电机侧 × 减速比 10 |
| MIT 位置 | rad（int64 counts） | 同位置 |

`2097152 = 2²¹`，MT6835 的分辨率。
