﻿﻿# 位置控制角度归一化（进模式 0~2π，目标按当前圈折算）

**日期** 2026-11-22 08:0x · **固件** Code=107312 · **串口** COM27 @921600

---

## 0. 需求（用户原话）

> 在进入位置控制时，对当前电机角度做 0-2pi 归一化，记入当前角度，假如是 3.14rad，我要输入要回到 0rad，则回到当前 0-2pi 范围内的 0rad，意思就是不计入之前的累计圈速的角度。

**语义确定**：
- 进位置模式：`p_now` **必落 [0, 2π)**
- 下发目标：输入值按**当前圈的 0~2π** 解释 → 输入 0 就是本圈 0 点
- 行程永远 ≤ π + 输入值，**与之前转过多少圈无关**

## 1. 四处改动

### 1.1 `pos_coord_align()`：改用 `fmodf`，不再依赖 `theta_single`

```c
/* 原来 */
s = BspServo_GetThetaCached();
s_pos_base = m - s;              // 依赖 m 与 s 同拍同源

/* 现在 */
frac = fmodf(m, BSP_TWO_PI);
if (frac < 0) frac += BSP_TWO_PI;
s_pos_base = m - frac;           // 只依赖一个量，结果必然 ∈ [0, 2π)
```

**为什么改**：`m - s` 在数学上等于"圈数 × 2π"，本该等价。但 2026-11-22 实测出现过
`p_now = 25.675`（超 4 圈）——说明 `m` 与 `s` 在那一次不是同一拍/同源的量，
一相减就把圈数丢了（`base ≈ 0` → `p_pos ≈ m`）。

**这就是前一轮 0x0100 故障的根因**：`p_now` 不是 [0,2π)，用户下发 0 就要反向走 4 圈。

`fmodf` 只依赖一个量、天然同拍，还省掉了关中断读第二个量的窗口。

### 1.2 `Servo_SetPosMode()`：起环只"保持当前位置"，不再接收外部目标

```c
(void)pos_coord_align();
(void)p_target_rad;                    /* 起环不再使用外部目标 */
PosLoop_Enable(ds * pos_coord_now());  /* target = 当前位置 → HOLD */
```

同时**删掉** `p_target_rad -= (new_base - old_base)` 的平移。

**为什么删**：那个平移假设"调用方传的是旧坐标"，但 align 之后 `p_pos` 重新从单圈角起算，
旧坐标里的整圈部分全部作废。实测转 12 圈后进位置模式，目标被平移成 100.1 而实际位置
只有 25.7，差 74 rad；而删掉平移又会让另一条路径错位——**两头都不对，说明"目标坐标系"
本身没定义清楚**。

现在改成：起环只保持位置，要定位由调用方在起环**之后**调 `Servo_SetPosTarget()`，
目标语义只有一个。

### 1.3 `Servo_SetPosTarget()`：折到当前圈 + 同一目标只折算一次

```c
/* ① 去重：keepalive 10 Hz 重发同一目标时直接返回 */
if (fabsf(p_target_rad - s_pos_cmd_last) <= 1e-6f) { return; }
s_pos_cmd_last = p_target_rad;

/* ② 圈基准取"最近的 2π 倍数" */
const float turn = roundf(now / BSP_TWO_PI) * BSP_TWO_PI;

/* ③ [0,2π) 输入折算到本圈；其它值按绝对位置（保留跨圈能力） */
if ((p_target_rad >= 0.0f) && (p_target_rad < BSP_TWO_PI)) {
    tgt = turn + p_target_rad;
} else {
    tgt = p_target_rad;
}
PosLoop_SetTarget(ds * tgt);
```

**两个坑，都是实测踩出来的**：

| 坑 | 现象 | 修法 |
|---|---|---|
| `turn = now - norm_2pi(now)`，`now` 为负（过冲几个 mrad）时算出 **−2π** | 目标被推远一整圈，位置环以 v_max 一圈圈转（`wref` 长期钉在 −238.7 rpm） | 改用 `roundf(now/2π)*2π` |
| keepalive 每 100 ms 重发，每次都重算 `turn`；`now` 跨过 π 时 `roundf` 跳圈 | 下发 3.1416，电机在 3.2 附近来回乱走（实测停在 2.33） | 相同输入直接 return，**一个目标只折算一次** |

`pos_coord_align()` 里会把 `s_pos_cmd_last` 复位，保证换模式后第一次下发必定重新折算。

### 1.4 `do_pos()`：目标在 MOE 打开之后再给

```c
Servo_SetPosMode(1U, Servo_GetPosCoordNow());   /* 起环保持 */
BspServo_PwmEnable(1U);
if (BspServo_IsPwmEnabled() == 0U) { ... return; }
s_armed = 1U;
if (hold == 0U) { Servo_SetPosTarget(rad); }     /* MOE 开后再定位 */
```

**顺序不能反**：位置环在 ISR 里已经跑起来了，若在 `PwmEnable` 之前设目标，
规划位置会先跑出去而电机还没通电，规划与实际一拉开就是一次跟随误差。

### 1.5 诊断输出归一化

```c
d->p_now   = norm_2pi(pos_coord_now());
d->p_tgt   = norm_2pi(ds * PosLoop_GetTarget());
d->p_ref   = norm_2pi(ds * PosLoop_GetRef());
d->err     = ds * PosLoop_GetErr();      /* 真实差值，**不**归一化 */
```

`err` 必须保持真实值，否则 −3.14 的误差会显示成 +3.14，看起来像"越走越远"。

## 3. 一个显示上的注意点

**`-> 0` 到位后 `p_now` 可能显示 6.2813 而不是 0.0000。**

原因：定位过冲了 −1.86 mrad，位置落在 **0 的负侧**，归一到 [0,2π) 就是 `2π − 0.00186 = 6.2813`。

**这不是没到位**，环形误差只有 1.86 mrad（远小于 `POS_WIN` = 10 mrad）。
判断是否到位请看：
- `err` 字段（真实差值，−0.00186 rad）
- 或做环形差：`d = p_now − target; if (d > π) d -= 2π; if (d < −π) d += 2π`

**要不要把 2 mrad 内吸附到 0**（显示成 0.0000）？可以，但那会掩盖真实残差，
暂时保持"数学正确"的显示。

前一轮报告的 `0x0100 位置跟随误差`（下发绝对 0 冲过头 8.6 rad），**根因就是本轮的 1.1**：

# 追加：多轮复测发现的三个问题（已修，Code=107392）

用户要求「再测试几遍」。第一版（Code=107312）的 15 次定位虽然都判通过，
但改成逐拍记录后暴露出三个真问题 —— 前两个是我第一版引入的。

## A1. 起环自转约 2 秒（严重，第一版引入）

**现象**：每次切到位置模式、**还没下发任何目标**，电机就以约 235 rpm 自转，
`st=MOVE`、`err` 恒为 +0.098、`wref` 约 24 rad/s，跑满 2 s 后被 deadman 封锁才停。

逐拍记录（起点静止、只做 `set_controlword(0x0F)`）：

```
进位置 0.20s  p_now=5.9042  err=+0.0984  st=MOVE  wmeas=+235.26
进位置 0.60s  p_now=3.0870  err=+0.0991  st=MOVE  wmeas=+238.05
进位置 1.00s  p_now=0.7714  err=+0.0983  st=MOVE  wmeas=+241.19
进位置 2.20s  p_now=2.7041  err= 0.0000  st=IDLE  wmeas=+13.00   <- deadman 封锁
```

**根因**：`Servo_SetPosMode()` 里 `PosLoop_SetTarget(ds * p_target_rad)` 写在了
`if (s_pos_prev == 0U) { ... }` 块的**外面**，所以起环那一拍会执行两次：

```c
PosLoop_Enable(ds * pos_coord_now());   // ① 目标 = 归一化后的当前值（如 2.7）
PosLoop_SetTarget(ds * p_target_rad);   // ② 又改成旧坐标的连续值（如 25.7）
```

调用方传的是 `Servo_GetPosCoordNow()`（旧坐标的连续量，可能超过 4 圈），
于是 `travel = 25.7 − 2.7 ≈ 23 rad`，规划一路跑 3.7 圈。

**修法**：删掉那一行（`p_target_rad` 完全废弃，定位统一走 `Servo_SetPosTarget()`）。

## A2. 圈基准用 `roundf(now/2π)` 会多走一整圈（第一版引入）

**现象**：起点 2.71、下发 6.0，本该走约 3 rad，实测**累计弧长 11.85 rad**（近两圈）。

**根因**：`turn = roundf(now / 2π) × 2π` 只看 now、与输入值无关。
输入 6.0 且实测越过 2π 一点（6.06）时，`roundf(6.06/6.28)=1` → 目标变成 12.28。

**修法**：在「圈内偏移 = 输入值」的所有候选点里取**离当前实测最近**的一个：

```c
tgt = p_target_rad + roundf((now - p_target_rad) / 2π) * 2π;
```

这一个式子同时满足三条：
- 行程必然 ≤ π（输入 0 而实测在 6.2 时目标 = 6.283，正向走 0.08）；
- now 变化不超过 π 时 k 不变 → keepalive 重发不会跳圈；
- 不会出现 `now` 为负时算出 −2π 的问题（第一版踩过，wref 钉在 −238.7 rpm 无限绕圈）。

## A3. 长行程定位过冲成 bang-bang 极限环（既有缺陷）

**现象**：行程 ≥ 1.5 rad 时，`wref` 在 −193 / +124 / −68 / +114 rpm 之间反复换向，
`err` 摆到 ±0.6 rad，2.9 s 才衰减收敛，期间多走 10 rad。

**根因**：`POS_AMAX_DFLT = 200 rad/s²`，1.67 rad 行程规划只要 0.18 s（峰值 18 rad/s）。
而位置环是纯 P、输出限幅 ±25 rad/s，**线性区只有 v_max/Kp = 25/100 = 0.25 rad**。
电机跟不上这么快的变化 → 滞后累积到 0.5 rad → P 饱和全速追 → 冲过 → 反向饱和。

末端软着陆（`POS_SLOW_WIN`）默认是 0（关闭），所以没有兜底。

**修法**：`POS_AMAX_DFLT` 200 → **30**。1.67 rad 行程峰值 7.1 rad/s、滞后 0.07 rad，
留 3.5 倍余量；20 rad 以上行程才会跑满 v_max。

> 为什么不启用软着陆：`POS_SLOW_WIN` 窗口内 v_cmd 被压到 0.5 rad/s 以下，
> 而静摩擦死区对应约 0.15 A（≈0.26 rad/s 的等价给定），I 项也被同一个 clamp 限制，
> 会卡在离目标几 mrad 处推不动 —— 这多半就是历史上把它设成 0 的原因。

**修复前后对比（同一场景：起点 1.39，下发 6.0，行程 1.67 rad）**

| 量 | amax=200 | amax=60 | **amax=30** |
|---|---|---|---|
| err 峰值 | ±0.60 rad | ±0.45 | **< 0.007** |
| wref | −193 ~ +124 反复换向 | −85 ~ +58 | **−60 → 0 单调** |
| 到位耗时 | 2.91 s | 1.50 s | **0.60 s** |
| 累计弧长 | — | — | **= 实际行程** |

## A4. 顺带补的一处：到位后被推走、再下发同一目标会被忽略

`Servo_SetPosTarget` 为了防 keepalive 跳圈做了「输入值相同就忽略」。
副作用：定位到 0.5 后被外力推走，用户再下发 0.5 也无效。

改成：输入相同 **且** 位置环处于 DONE **且** 实测仍贴着上次目标（< 50 mrad）
才忽略；否则允许重新定位。运动中一律忽略（避免跨 π 跳圈）。

# 追加 A7：`do_disable` 漏关位置环（`Code=107392` 最终修）

## A7.1 现象

偶发「下发了目标，电机不动」：

```
goto 3.60  -> p_now=3.6005
停 keepalive 2.8 s（deadman 触发）
下发 6.20  -> p_now 仍是 3.6002、travel=0.0005、p_tgt 还是 3.60 的值
```

同样的指令在另一次测试里却正常 —— 取决于**中间有没有 deadman 触发**，所以极难复现。

## A7.2 根因链

```c
static void do_disable(const char *why)      /* servo_cmd.c */
{
    BspServo_PwmEnable(0U);
    Servo_SetEnable(0U);
    Servo_SetOpenLoop(0U, ...);
    Servo_SetSpeedMode(0U, 0.0f);     /* 速度环退了 */
    Servo_SetCurrentMode(0U, 0.0f);   /* 电流环退了 */
    /* ★ 位置环没退 —— s_pos_prev 仍是 1 */
    ...
    s_armed = 0U;
}
```

于是形成状态不一致：**`s_armed = 0` 但 `s_pos_prev = 1`**。后续：

| 步 | 发生了什么 |
|---|---|
| 1 | deadman → `do_disable` → `s_armed=0`、`s_pos_prev=1`、MOE=0 |
| 2 | 上位机发 30019(6.20) → `do_pos` 判 `s_armed==0` → 走"起环"分支 |
| 3 | `Servo_SetPosMode(1U, ...)` 内部 `if (s_pos_prev == 0U)` **不成立** → 跳过 `pos_coord_align()` 与 `PosLoop_Enable()` |
| 4 | `BspServo_PwmEnable(1)` 重开 MOE，`s_armed=1` |
| 5 | `Servo_SetPosTarget(6.20)` → 输入值与 `s_pos_cmd_last` 相同 → **去重 return** |
| 6 | 位置环目标仍是上一轮的 3.60 换算值 → 电机不动，`travel≈0` |

## A7.3 修法（两处，缺一不可）

**① `do_disable` 补关位置环**

```c
Servo_SetPosMode(0U, 0.0f);    /* 会清 s_pos_prev 并 PosLoop_Disable() */
```

**② `Servo_SetPosMode` 的 enable 分支复位去重锁存**（防御其他"目标已过期"的路径）

```c
if (enable != 0U) {
    s_pos_cmd_last = -1.0e9f;          /* 允许下一次 SetPosTarget 重新折算 */
    ...
    {
        const float p_start = pos_coord_now();
        PosLoop_Enable(ds * p_start);
        s_pos_tgt_last = p_start;      /* 与 Enable 设的目标保持同步 */
    }
```

> 为什么必须两处都改：①解决 `s_pos_prev` 残留；②保证即使 `s_pos_prev` 已被别的路径置 1，
> 下一次下发也不会被旧的"输入值"锁住。

## A7.4 复测

| 场景 | 修复前 | 修复后 |
|---|---|---|
| deadman 后下发 6.20 | `travel=0.0005`、p_now 不动 | **`travel=2.7067`、误差 +1.02 mrad** |
| 随后下发 0 | — | 弧长 0.053 rad、误差 −0.76 mrad |
| 从 6.2004 下发 0 | 反向走 6.08 rad | **弧长 0.063 rad（正向跨 0）** |
| 从 0.0008 下发 6.0 | — | `travel=0.284`（反向近路） |
| 4 轮 × 5 目标 | — | 全过，误差均值 1.08 mrad、耗时均值 0.44 s |

## A7.5 另一个副产物：`p_tgt` 恒等于输入值

折算后的目标与输入值只差 `2π` 的整数倍，归一化后又回到输入值：

| 下发 | 内部目标 | `p_tgt` 回读 |
|---|---|---|
| `0.0`（当前 6.20） | 6.2832 | `0.0000` |
| `6.20`（当前 0.09） | −0.0832 | `6.2000` |
| `3.1416` | 3.1416 | `3.1416` |

**所以 `p_tgt` 可以当作"目标是否被接受"的确认回读**，真实行程看 `travel`。

## A7.6 教训

**"部分子模块退出"是最难查的一类 bug**：`do_disable` 退了速度环、电流环、开环，
只漏了位置环，而位置环的 `s_pos_prev` 又恰好被另一个函数（`Servo_SetPosMode`）
用来决定"要不要重新对齐坐标"。

排查这类问题只能靠**入口打点**（记录函数入参和去重时的比较值），
靠读输出反推会一直猜错 —— 这次就是先猜了三种可能（`roundf` 精度、浮点比较、
`PosLoop` 内部），加诊断后一次定位。
