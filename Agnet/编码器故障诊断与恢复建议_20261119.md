# 编码器故障诊断与恢复建议

日期：2026-11-19　设备：STM32G474 X72 FOC + MT6835（21 bit，SPI）
触发事件：执行 ASCII `^`（MT6835 自校准）时被中断

---

## 一、结论

| 项 | 状态 |
|---|---|
| 编码器 SPI 通信 | **正常**（100 Hz 无丢帧，静止 ±1 count） |
| 编码器芯片状态字 | `chip_status = 0`（芯片自检通过） |
| **角度准确性** | **损坏**：电角度误差随转子位置在 −85° ~ +180° 之间变化 |
| 电机可控性 | **不可控**：1 A 力矩下转速在 +118 / −58 rpm 间跳变（失步） |
| 自动恢复 | **不可能**：`Z` 与 `^` 都要求电机能转，而电机正因角度错误转不动 |

**根因：`^` 自校准中断，MT6835 EEPROM 内的非线性补偿表被写入不完整数据。**
芯片仍在正常输出，但输出的是"按损坏补偿表修正过"的角度。

**修复必须走硬件/厂商工具，软件侧无法恢复。**

## 二、证据链

### 2.1 编码器本身是好的

| 检查 | 结果 |
|---|---|
| `30040` 帧率 | 3 s 收到 300 帧（100 Hz，无丢帧） |
| `enc_sum_p` 静止稳定性 | 24977515 → 24977514（5 s 变化 1 count） |
| 单圈机械角 | 327.674°（合法值） |
| `chip_status` | 0（无自检错） |
| 故障位 | 清后 `f=0x00`，无 SPI/编码器通信错 |

### 2.2 但电角度与机械角不一致，且随位置变化

用 `30040` 同一帧的两个字段交叉核对（`+0` 机械角、`+8` 电角度）：

| 转子位置（机械） | 14×机械角 | 实测电角度 | 偏差 |
|---|---|---|---|
| 327.68° | 267.5° | 182.4° | **−85.1°** |
| 32.29° | 92.1° | 271.7° | **+179.6°** |

**两个位置相差 264.7°** —— 若是恒定偏置，两处应相同。这直接证明误差是**位置相关**的，即补偿表失真，而非零点偏移。

### 2.3 由此导致的所有次生故障

| 现象 | 数值 | 机理 |
|---|---|---|
| 1 A 力矩转速乱跳 | +21.6 → +117.7 → **−58.2** → +10.9 rpm | 角度错 → Park 变换错 → 转矩方向随位置翻转（失步） |
| 0.4 A 完全不动 | 0 rpm | 转矩只剩 cos(85°)=8.4%，低于静摩擦 |
| `Z` 辨识失败 | `IDENT FAIL ratio_bad n=60/0` / `fault_run` | 注入 2 A 产生的 0.015 N·m < 库仑摩擦 0.029 N·m，电机不动，采不到点 |
| `Z` 反复给错零点 | 5 次均 `zero=−26°`（`^` 之前是 **−2.14°**） | Z 用失真角度对齐，结果必然偏 |
| `^` 无法重做 | `EC FAIL speed out of 400-800 turns=0` | 自校准要求 400~800 rpm，失步状态下转速上不去 |
| 极对数识别不稳 | `ratio` 在 13.77 ~ 14.14 间跳（正常应稳定 14.1） | 角度失真导致电感比估计离散 |

### 2.4 固定偏置补偿验证失败

按第一次测得的 −85.37° 加了 `+85.37°`（`servo_isr.c` 的 `s_elec_off`）后：

```
iq=1.0 A：+21.6 → +117.7 → −58.2 → +10.9 → +5.1 rpm
```

转矩出现了（能动了），但方向随位置翻转 —— 因为补偿只在某一个位置对，转到别处误差又变了。**这从反面确认了"误差随位置变化"的结论。**

## 三、根因分析

MT6835 的 `Auto Calibration`（固件 `^` 命令，`servo_cmd.c:2317`）流程：

1. 让电机以 600 rpm 匀速转 **64 圈**
2. 由芯片内部比对"理想角度 vs 实际磁场角度"，拟合非线性补偿曲线
3. 把曲线写入芯片 EEPROM
4. 固件明确提示：`!!! POWER CYCLE REQUIRED (>6s) !!!`

本次在第 3 步进行中被中断（预演阶段做了 `^` 但流程继续往下走，未断电）。EEPROM 中的补偿表处于**部分写入**状态，芯片上电后加载了这份不完整数据，于是输出角度带上了随位置变化的误差。

**关键教训**：`^` 一旦启动，必须让它完整跑完并断电重启；中途打断会损坏 EEPROM 标定数据。这条约束固件已经在回显里写明，预演时未严格执行。

## 四、恢复方案（按推荐顺序）

### 方案 A：MT6835 官方上位机工具重标定（推荐）

MagnTek 提供 MT6835 的 PC 端标定工具（SPI 转 USB 或通过 MCU 透传）。
- 需要：SPI 接线（CLK/MISO/MOSI/CS）+ 厂商软件
- 作用：重写 EEPROM 的非线性补偿表
- 完成后：先断电 >6 s，再上电，做一次 `Z`，检查 `zero` 是否回到 −2° 附近

### 方案 B：更换编码器芯片/小板

若拿不到官方工具，直接更换 MT6835（或整个编码器小板）。
更换后**必须**做一次完整的 `C → Z → ^ → 断电 >6 s` 流程。

### 方案 C：临时绕过（仅用于验证其它功能）

不推荐。若一定要让电机转起来做非精密测试，只能靠"逐位置标定误差表"临时补偿，工作量大于换芯片，且精度无保证。

## 六、长测脚本已就绪（编码器恢复后一条命令启动）

`Agnet/full_soak.py` 已完成并修过以下问题：

| 项 | 处理 |
|---|---|
| `C` 电流零点 | 默认跳过（实测 `C` 后紧跟 `Z` 会把极对数识别成 13） |
| `Z` 校验 | 必须 `ratio∈[13.5,14.5]` 且 `pn=14`，最多重试 4 次 |
| `^` 编码器校准 | 默认跳过，`--enc-cal` 才执行（帮助里已写明风险） |
| 机械辨识 | 只做惯量 + 摩擦（扫频/齿槽属分析项，会与长测抢时间） |
| `--pre-only` | 只验前置不进主测试 |
| 每组 | 停稳 → `+` 辨识 R/L/ψ → 记双温度 → 重新升速 |
| 输出 | 每组增量落盘 CSV，中断不丢数据 |

启动命令：

```bash
python full_soak.py COM27 --rpm 1000 --groups 30 --minutes 10
```

30 组 × 10 min ≈ 5.3 h，电机预计稳定在 55~58 °C（远低于 110 °C 降额线）。
