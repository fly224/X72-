# X72 固件代码结构评估与重构建议（2026-11-21）

## 一、总体判断

问题**不是"变量太多"**，而是缺三样东西：

1. **单一参数注册表** —— 同一参数有 4 条来源（编译默认 / Flash 参数页 / 30082 / ASCII 命令），
   覆盖顺序没有任何地方写清楚
2. **单一设置入口** —— 改一个字段要先读全组再写回，21 处这种反模式
3. **可观测性** —— 功能开关（如 `s_ff_en`）在遥测/回显里完全看不见

变量多只是这三个缺失的结果。

## 二、量化证据

| 指标 | 实测 | 说明 |
|---|---|---|
| `servo_cmd.c` | **3302 行** | 命令解析 + 参数 + 回显 + 辨识回调全在里面 |
| `servo_isr.c` | **2899 行** | 20 kHz 电流环 + 2 kHz 速度 + 1 kHz 位置 + 前馈 + 保护 |
| `servo_isr.c` 静态量 | **135 个**（其中 86 个 `volatile`） | 模块级状态散落，跨函数隐式耦合 |
| 宏 | isr 70 + cmd 42 | 大量编译期常量与运行时变量同名概念 |
| ASCII 单字符命令 | **55 个** | 可打印字符基本用尽 |
| 数值子命令 | **18 个**（`CMD_NUM_*`）＋ 27 个 `if (s_num_tgt==...)` 分支 | 单函数内 27 路 if-else |
| `Get-then-Set` 反模式 | **21 处** `Servo_GetFeedforward` | 改一项要读四项 |
| 时基常量 | `SERVO_OL_TS 0.00005f` 硬编码 vs `SERVO_SPD_TS = DIV*BSP_TS_CURRENT` 推导 | 同一个 20 kHz 两套写法 |

## 三、具体病灶（都来自这两天踩过的坑）

### 3.1 隐式覆盖：改了默认值却没生效

今天把 `SERVO_FF_FRIC_DFLT` 从 0.150 改成 0.107，烧录后回读仍是 **0.321**
——Flash 参数页的旧值把它盖掉了。这类问题**没有任何日志**，只能靠 30082 回读才发现。

同类：`psi` 昨天是 4.20，今天是 4.38；`z` 有时从 Flash 恢复、有时要从零标定。
**当前生效值到底来自哪一层，不可知。**

### 3.2 `Get-then-Set` 反模式

```c
Servo_GetFeedforward(&en, &a, &f, &vs);
Servo_SetFeedforward(en, v, f, vs);       // 只改 a，但四个字段都要手写一遍
```

21 处同样写法。任何人加第五个字段时，只要漏改一处就会**静默清零**。
mavlink_host.c 里 `dbg_set_ff_acc/fric/visc` 三个函数就是三份复制粘贴。

### 3.3 命令空间已耗尽

加"录波通道"时，单字符用完了，只能把通道号塞进分频值的**百位**
（`'205` = 通道 2 分频 5）。这是接口在报警：**扩展性已经为零**。

### 3.4 单位只活在注释里

- `ff_acc` 单位是 A/(rad/s²)，`]` 命令输入单位是 1e-4
- `'` 后面是分频值，百位又是通道号
- `-` 后面是电角度 deg，`+` 是磁链辨识
- 昨天给 FAIL 行加诊断时，`put_f2` 因 mdeg 超过 10000 直接打 `"nan"`

单位靠记忆、量程靠记忆，出错时现象还很误导（`nan` 看起来像数值坏，其实是超量程）。

### 3.5 没有专用诊断通道

昨晚排查 USART 时，我把 `ServoCmd_GetDiag()` 塞进 30040 的 `elec_angle` 字段。
虽然事后改回了，但这说明：**临时诊断没有落脚点**，只能借业务字段。

### 3.6 安全默认值把功能变成死代码

`s_ff_en` 无初值（=0），唯一置 1 的路径是 `$` 成功，而 `$` 必然失败
——整套速度前馈长期是死代码，而 S/K 行里**完全看不出它是关的**。
今天靠"把 ff_acc 拉到 0.5 看有没有反应"这种反向实验才确认。

### 3.7 两处 Kt

`mech_ident.c` 曾用硬编码 `MI2_KT=0.0910`，控制律用 `kt_base=0.0883`（昨天已修）。
今天 ψ 又变成 4.38（Kt=92.00）。**所有以 A 为单位的常量都隐含依赖 Kt**，
ψ 一改，这些阈值的物理含义就漂了。

### 3.8 "测量"与"应用/落盘"职责不清

- `)` 只报数，不写前馈
- `$` 才写前馈，但它一直失败
- `A` 保存的是参数页里的 `fric_a/fric_visc`（旧字段）
- 今天最终只能靠 30082 把值写进 **RAM**，掉电即失

## 四、建议（按投入产出排序，供挑选）

### A 档：低风险、当天可做

| # | 动作 | 收益 | 风险 | 工作量 |
|---|---|---|---|---|
| A1 | **参数注册表**：一张表登记 `{名字, 指针, 单位, 默认, 下限, 上限, 是否掉电, 来源优先级}`，启动时打印一屏"当前生效值与来源" | 彻底消灭 3.1 那类隐式覆盖；以后新增参数只改表 | 低（纯增量） | 2~3 h |
| A2 | **单字段 setter**：`Servo_SetFfVisc(v)` 之类，替掉 21 处 Get-then-Set | 消灭"漏写字段静默清零" | 低 | 1~2 h |
| A3 | **S 行加状态字**：一个 hex 字把 `ff_en / ff_boost_en / dead_comp_en / harmonic_en / kt_comp_en / cog_en` 装进去 | 功能开没开一眼可见，不用反向实验 | 低（S 行已满，需腾位置） | 1 h |
| A4 | **统一时基**：删掉裸 `0.00005f`，全部从 `BSP_TS_CURRENT` 推导 | 消除 3.2 类隐患 | 很低 | 0.5 h |

### B 档：值得做，需半天

| # | 动作 | 收益 | 风险 | 工作量 |
|---|---|---|---|---|
| B1 | **命令协议换代**：保留现有单字符作为别名，新增 `键=值` 文本命令（`ff.visc=0.0032`、`rec.ch=2,div=5`） | 解决 3.3 扩展性归零 | 中（要改上位机） | 半天 |
| B2 | **专用诊断槽**：30082 的 `Debug_uint32[16]` 固定划 4 个给诊断（不参与控制），或加一条 `AppDiag` 消息 | 解决 3.5 | 低 | 2 h |
| B3 | **固定单位后缀**：`_a_per_rads2`、`_mdeg`、`_rpm` 之类，参数表里加 `unit` 字段并随回显打出 | 解决 3.4 | 低（改名量大） | 3 h |
| B4 | **辨识四段化**：测量 → 建议值 → 应用 → 落盘，每段可独立调用且回显明确 | 解决 3.8；`$` 失败也不会让整条链断 | 中 | 半天 |

### C 档：结构调整，需排期

| # | 动作 | 收益 | 风险 | 工作量 |
|---|---|---|---|---|
| C1 | 把 `servo_cmd.c` 拆成 `param_registry.c` / `cmd_parser.c` / `telemetry_fmt.c` / `ident_cb.c` | 3302 行 → 4 个 800 行以内 | 中高（触碰广） | 1~2 天 |
| C2 | 把 `servo_isr.c` 里 20 kHz 路径与 1 kHz/2 kHz 路径拆文件，静态量按归属收敛 | 135 个静态量 → 分模块封装 | 高（实时路径，需逐段核对） | 2~3 天 |
| C3 | 电流环/速度环参数改为结构体 + 统一更新函数（消灭散落 `s_spd_*`、`s_cur_*`） | 便于在线辨识结果整体接管 | 中高 | 1 天 |

## 五、我的推荐顺序

如果只做三件：**A1（参数注册表）→ A3（状态字）→ A2（单字段 setter）**。
理由：这三件直接对应这两天最耗时的三类故障（隐式覆盖、功能开关不可见、漏字段清零），
而且都是增量改动，不动实时路径。

**不建议现在做 C 档**：机器刚跑通、前馈刚接入、`$` 还失败，此时大改结构会把
"哪些现象是代码引入的"和"哪些是硬件/参数问题"混在一起。等 `$` 修通、
全速段前馈标定完，再动结构。

## 六、局限

- 本文只看了 `Board/` 下的文件规模与模式，没有做逐函数复杂度分析（圈复杂度）
- 未评估 RAM/Flash 预算（当前 Code=118524、ZI=18260），拆分文件本身不增加占用，但加注册表会增加 ROM
- "工作量"是按改动面估算，未计入回归测试（每次改动都要跑 C→Z→1000rpm 全套）
