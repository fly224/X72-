## 1. 为什么不新造字段，而是用 30040

协议里本来就有电机端位置报文，字段语义正好对得上，没必要在 30025 后面硬塞：

```
30040 MotorPosSensorOutput   LEN=12  crc_extra=160   设备→主机
  +0  enc_sum_p            int64_t   累积编码器脉冲
  +8  elec_angle_now_rad   float     电角度实测
```

对比另外两个候选：

| 报文 | 为什么不用 |
|---|---|
| 30019 PosSpeedCtlInput | LEN=44，含 `pos_tar_p`/`speed_tar_p_s` 等**给定**量，方向语义是设备输入，且一次多发 32 B |
| 30038 MotorPosSensorInput | LEN=4，只有单圈 `enc_counts_now_p`，**没有多圈累积**，转几圈就看不出来 |

30040 的 `enc_sum_p` 是 int64，按 2²¹ 脉冲/圈折算可表示 ±4×10¹² 圈，工程上等于无上限。

## 2. 字段与换算

### 2.1 固件发送

```c
put_i64(&p_pos[0], enc_sum);              /* BspServo_GetPosSum() */
put_f32(&p_pos[8], POLE_PAIRS * theta_m); /* 与 30025 +20 同源 */
```

`enc_sum` 是**相对上电点**的累积脉冲，不是绝对位置。

### 2.2 上位机换算

```js
const ENC = 2097152;                        // MT6835 2^21
const sum = Number(dv.getBigInt64(0, true));
ax.turns = sum / ENC;                       // 多圈圈数（可负、带小数）
let frac = sum % ENC; if (frac < 0) frac += ENC;
ax.pos = frac / ENC * 2 * Math.PI;          // 单圈机械角 0..2π
```

负数取模必须归一化：JS 的 `-1 % 5 === -1`，不处理会让反转时角度跳到负值。

## 3. 多圈累积怎么做的

### 3.1 在原始计数域做，不在浮点角做

浮点角 `theta` 做了 `+ s_enc_zero` 与回绕，用它差分会被零点偏置和浮点舍入污染。累积必须落在原始计数上：

```c
int32_t d = (int32_t)s_enc_raw - (int32_t)s_enc_prev;
if (d >  (int32_t)(BSP_ENC_COUNTS * 0.5f)) { d -= (int32_t)BSP_ENC_COUNTS; }
if (d < -(int32_t)(BSP_ENC_COUNTS * 0.5f)) { d += (int32_t)BSP_ENC_COUNTS; }
s_pos_sum += (int64_t)d;
```

### 3.2 回绕门限的安全裕度

| 量 | 值 |
|---|---|
| 编码器分辨率 | 2²¹ = 2 097 152 脉冲/圈 |
| 半圈门限 | 1 048 576 脉冲 |
| 100 rad/s 机械转速下单拍位移 | 1669 脉冲（50 µs） |
| **裕度** | **约 628 倍** |

也就是说，即使转速比设计上限再高两个数量级，也不会把"转得快"误判成"反向回绕"。

### 3.3 int64 读撕裂保护

`s_pos_sum` 在 20 kHz ISR 里 `+=`，在 1 ms 任务里读。Cortex-M4 上 64 位存取不是原子的，读侧被 ISR 抢占时可能读到"高 32 位旧、低 32 位新"的撕裂值（跳 ±2³² 脉冲 ≈ ±2048 圈）。

`BspServo_GetPosSum()` 用 PRIMASK 做快照：

```c
uint32_t primask = __get_PRIMASK();
__disable_irq();
int64_t v = s_pos_sum;
if (primask == 0U) { __enable_irq(); }
```

调用频率只有 100 Hz，关中断窗口约 10 个周期，对 50 µs 控制周期的影响约 0.006%。若原状态本就关中断，则保持原状返回（不误开中断）。

## 4. 顺带修掉的一个既有缺陷

### 4.1 现象与机理

`BspServo_GetThetaRad()` 除了返回角度，还承担两件有状态的事：更新测速一阶低通、推进多圈累积。它内部固定用 `BSP_TS_CURRENT = 50 µs` 作分母：

```c
s_omega_mech += BSP_SPEED_LPF_ALPHA * (d / BSP_TS_CURRENT - s_omega_mech);
```

但改造前它有 **5 处调用**，其中两处是 1 ms 周期：

| 位置 | 频率 | 是否应推进测速 |
|---|---|---|
| `servo_isr.c:126`（ControlTick） | 20 kHz | ✅ 是 |
| `servo_isr.c:171`（SlowTask1ms，速度模式） | 1 kHz | ❌ 否 |
| `telemetry_tx.c:161`（组帧） | 100 Hz | ❌ 否 |
| `servo_isr.c:50/53/54`（模式切换） | 事件触发 | ❌ 否 |

机理：1 ms 任务的调用会把 `s_theta_prev` 提前刷成"当前时刻"，紧随其后的控制节拍算出的 `d` 变小，而分母仍是 50 µs，于是瞬时速度被低估；`alpha = 0.06` 的一阶低通把它摊到后续若干拍，表现为**测速系统性偏低 + 随机抖动**。这会直接进 `three_loop_deploy_U.omega_m`（速度环反馈）与 30025 的 `elec_angle_speed_rad_s`。

### 4.2 修法

拆成两个语义：

```c
float BspServo_GetThetaRad(void);      /* 有状态：每 20 kHz 控制节拍调一次，推进测速与累积 */
float BspServo_GetThetaCached(void);   /* 只读：返回上次算出的角度，不推进任何状态 */
```

- `Servo_ControlTick()` 开头无条件调一次 `GetThetaRad()`（**唯一调用点**），并把结果存进 `theta_now` 供模型与后续使用；故障时也更新，这样停机状态下也知道转子在哪。
- 其余 4 处全部改成 `GetThetaCached()`。

**未做量化实测**：要给出"偏低多少"需要对比两版固件的 `elec_angle_speed_rad_s`，而串口当前被占用。此处只陈述机理，不给数值。

## 8. 尚未完成 / 局限

1. **实物实测未取到**：`COM27` 仍被 8091 页面的 Web Serial 占用，命令行打开报 `PermissionError(13)`。上面所有位置数据都来自固件原文件的主机回放，不是实物示波器/串口截图。
2. **不是绝对多圈位置**：`s_pos_sum` 从上电时刻的原始计数开始累积，上电点即 0。要做绝对位置，需要 `BspServo_SetEncoderZero()` + `init_pos_p`（协议 30039），目前两者都未接入。
3. **零点偏置未对齐到页面**：页面用 `enc_sum_p` 算机械角，这个值**不含** `s_enc_zero`；而 30040 的 `elec_angle_now_rad` 用的是含零点的 `theta_m`。当前 `s_enc_zero == 0`（无人设置），两者一致；一旦标定零点，页面显示的机械角会与 `elecTheta/14` 相差一个偏置。届时需页面加零点参数，或用 30039 下发后同步。
4. **编码器零点/电流偏置仍未标定**：这是上一轮就列出的 P1 缺口，本次没有推进。
5. **多圈累积依赖 20 kHz 节拍持续运行**：若长时间停机后编码器被外力转动，上电点之前的变化不会被记录（这是"相对位置"的固有性质，不是 bug）。
6. **单圈角每圈回绕**：`ax.pos` 在 2π→0 处跳变，示波器上会看到锯齿；要连续波形需改用 `ax.turns * 2π`。

cd /d G:\FOC\X72\Agnet
