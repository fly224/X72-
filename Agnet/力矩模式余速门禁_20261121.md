# 力矩模式余速门禁（方案二：入口拒绝）

**日期** 2026-11-21 · **固件** Code=112540 · **验证** 7/7 + 8/8 + 17/17 + 26/26

---

## 一、要解决的问题

力矩模式的超速门限是常量 `SERVO_CUR_WMAX = 31.415927 rad/s`（=10π ≈ 300 rpm，`servo_isr.c:422`），它没有像速度环那样把"进环余速"纳入峰值保持。所以：

```
速度 1000 rpm 运行中 → 切力矩模式并给 iq
→ CtrlTorque 先 do_disable（关 MOE），再装电流环
→ 那一拍 om 还有 ~1000 rpm（104 rad/s）> 31.4
→ 8 拍（0.4 ms）后 BSP_FAULT_OVERSPEED，整机封锁
```

现象是"一切力矩模式就报故障"，而真实原因只是电机还在转。

按你选的**方案二**：不放宽门限（那条 300 rpm 是力矩模式唯一的失控保护），改成在入口拒绝。

---

## 二、实现

### 固件：`do_current()` 起环前门禁（`servo_cmd.c:514`）

```c
#define CMD_CUR_WMAX_RADS   (31.415927f)   /* 必须与 servo_isr.c 的 SERVO_CUR_WMAX 一致 */
{
    const float w_now = fabsf(BspServo_GetOmegaMech());

    if (w_now > (0.9f * CMD_CUR_WMAX_RADS)) {
        emit("[CMD] CUR refused: still spinning <X>rpm, stop first (limit 270rpm)");
        return;                            /* s_armed 保持 0，不会装环 */
    }
}
```

- 位置：`if (s_armed != 0U)` 块之后、完整装配之前 —— **已在力矩环只改给定**时不受影响。
- 阈值取 `0.9×`（270 rpm），留 10% 余量给测速噪声。
- 用 `|omega|` 而不是带符号值：只关心幅值，与坐标系无关。
- 那个宏在 `servo_isr.c` 里是私有的，所以这里复制了一份并注明"改一处必须改两处"。

### 上位机：首次装环预检（`mavlink_link.py:1067`）

固件拒绝时 `30025` 只回 `status=3`，ASCII 关掉后用户看不到原因。所以 `set_torque()` 在**首次**装环（`setpoints_valid["torque"]` 还是 False）时先读一次 30090：

```python
if precheck and first:
    st = self.ctrl_status(timeout=0.8)
    if st and abs(st["rpm"]) > 270.0:
        return {"ok": False, "error": "电机仍在 %.0f rpm，请先停稳再切力矩模式…"}
```

保活路径 `valid` 已为 True，不会多这次往返，性能零影响。

## 四、取舍与副作用

**代价**：高速滑行时**不能**用力矩模式做快速制动（给负 iq 强停），必须等转速掉到 270 rpm 以下。这是有意选的——力矩模式没有速度环，门限一放宽就没有能兜住飞车的东西了。

**如果以后确实需要"力矩制动"**，正确做法不是放宽门限，而是加一条**制动模式**：带自己的速度门限与斜坡（`iq = -min(k·ω, iq_max)`），相当于把"制动"当成独立语义，而不是借用无保护的力矩模式。约 40 行，需要单开消息。

**顺带确认的一个行为**：`halt` 之后并非自由滑行——MOE 清零后三相被短路制动，1000 rpm 在几十毫秒内就降到个位数 rpm（实测 0.25 s 时只剩 1.9 rpm）。所以"余速"窗口比想象的短，只有**运行中直接切模式**这条路径会撞到。
