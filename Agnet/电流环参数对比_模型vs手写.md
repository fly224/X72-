# 电流环参数对比：模型 vs 手写

> 2026-11-17 22:22–22:40。用实测对象（L、R）+ 离散仿真 + 实机阶跃三方对照。

---

## 1. 先看一个容易被忽略的事实：这两套是**同一个设计**

| 参数组 | Kp | Ki·Ts | Ki | **Kp/L（按各自假定的 L）** | 假定 L |
|---|---:|---:|---:|---:|---:|
| 模型 `par_c` | 0.71314 | 0.11891 | 2378.2 | **6283 rad/s** | 113.5 µH |
| 手写宏 | 0.5341 | 0.12566 | 2513.2 | **6284 rad/s** | 85 µH |

`Kp = ωc·L`，两边算出来的 ωc 都是 6283 rad/s ≈ **1000 Hz**。

**所以差别根本不是"谁整定得好"，而是"谁用的电感是真的"。**

实测电感：

| 方法 | 值 |
|---|---:|
| `@` VESC 分段辨识（1.55 A） | 80.1–80.7 µH |
| `+` ψ/R/L 联合辨识 | 89.07 µH |
| 原设计假定 | 113.5 µH |

两种独立方法都在 85 µH 附近，**113.5 µH 高 33%**。结论：**手写那组是这套 1 kHz 设计的正确实现，模型那组是没跟着实测 L 折回来的旧值。**

---

## 2. 但"正确"不等于"最优"：实机 A/B 结果反直觉

用 `U`（id 阶跃 2 A，转子不动）测，各 3 次取均值；Kp/Ki 用 `G`/`H` 档位缩放：

| 组 | Kp | Ki·Ts | tr | os | ts | 零流噪声 sd |
|---|---:|---:|---:|---:|---:|---:|
| 1.00× / 1.00×（手写现值） | 0.5341 | 0.1257 | 200 µs | 3.1% | 350 µs | 0.1286 A |
| **1.25× / 1.25×（带宽×1.25，对消保持）** | 0.6676 | 0.1571 | **150 µs** | 4.0% | **300 µs** | — |
| 1.25× / 1.00×（只加 Kp，对消破坏） | 0.6676 | 0.1257 | 167 µs | **1.6%** | 317 µs | 0.1145 A |
| 1.50× / 1.00× | 0.8012 | 0.1257 | 150 µs | 1.9% | 300 µs | — |

**Kp 提高后，tr 变快、ts 变短、过冲几乎没有变化，零电流噪声反而略降**
（原因是零电流下噪声由 874 Hz 外部扰动主导，环路增益越高压得越狠 —— 这条
在 `电流环_评估与改进清单.md` 第 9 节已经量化过：Kp 2× 时该峰完全消失）。

所以"模型那组 Kp 更大所以更差"这个直觉是**错的**。

---

## 3. 真正的约束在大电流：电感饱和后的相位裕度

L 随电流饱和（实测 87.9 → 59.0 µH，0.87 → 4.55 A）。相位裕度按 R=0.4、
延时 1.5·Ts 计算：

| Kp | L=85 µH（轻载）fc / PM | L=59 µH（4.5 A）fc / PM |
|---:|---|---|
| 0.5341（手写） | 1000 Hz / **63.0°** | 1276 Hz / **65.4°** |
| 0.6676（1.25×） | 1184 Hz / 63.5° | 1593 Hz / **60.5°** |
| 0.7131（模型） | 1256 Hz / 62.8° | 1713 Hz / **57.8°** |
| 0.8012（1.5×） | 1405 Hz / 60.6° | 1952 Hz / **51.9°** |
| 1.0000 | 1768 Hz / 52.5° | 2509 Hz / **36.5°** ← 临界 |

**模型那组的 0.713 即使在大电流饱和下也还有 57.8° 裕度，不构成稳定性风险。**
真正开始危险的是 Kp ≥ 0.8（PM 掉到 52° 以下）。

---

## 4. 模型那组真正错的地方（与 Kp 无关）

| 项 | 模型值 | 实测 | 后果 |
|---|---:|---:|---|
| `psi` | 7.59298 mWb | **4.333 mWb** | BEMF 前馈过补 **75%**，转速越高电压偏得越多 |
| `Ki/Kp`（PI 零点） | 3335 rad/s | 实测 R/L = **4706 rad/s** | 零点没对上对象极点，10 Hz 环路增益 94.6 vs 手写的 100 |
| `Ld/Lq` | 113.5 µH | 85 µH | 解耦项与 `par_c[0]` 的推导基准都偏 33% |

`psi` 这一条最要紧：它不是增益问题，而是**在 q 轴注入了一个随转速线性增大的错误电压**。
低速看不出来，3000 rpm 时 ψ·ωe 相差 75%，相当于凭空多给 9 V 量级。

---

## 5. 结论

**"哪个更好"要分两问：**

1. **作为 1 kHz 设计的两份实现，手写那组是对的**，模型那组是没更新的旧值
   （L、ψ、Ki/Kp 三项都错）。这一条没有争议。

2. **但 1 kHz 这个目标本身偏保守**。实测把它提到 1.2–1.3 kHz，tr 从 200 → 150 µs、
   ts 从 350 → 300 µs、过冲基本不动，而最恶劣工况（电感饱和 + 4.5 A）仍有
   58–60° 相位裕度。

所以正确的做法**不是**把模型的 0.713 搬过来（它的 1256 Hz 是"L 估错"的副产品，
而且 ψ/Ki 是错的），而是**显式把设计目标提到 1.2 kHz，再按实测 L、R 一起重算**：

```
Kp    = ωc·L = 2π·1200 × 85e-6 = 0.641
Ki·Ts = (R/L)·Kp·Ts = 4706 × 0.641 × 50e-6 = 0.1508
```

这样既拿到 1.2 kHz 的响应，又保住零极点对消（`Ki/Kp = 4706 = R/L`）。

## 6. 如果要改用 Kp=0.641 / Ki·Ts=0.1508

| 要改的位置 | 现值 | 新值 |
|---|---:|---:|
| `servo_isr.c` `SERVO_CUR_KP` | 0.5341 | 0.641 |
| `servo_isr.c` `SERVO_CUR_KI_TS` | 0.12566 | 0.1508 |
| `servo_isr.c` `SERVO_OL_KP`（开环辨识） | 0.5341 | 0.641 |
| `servo_cmd.c` `CMD_GAIN_BASE_KP/KITS`（G/H 基准） | 0.5341 / 0.12566 | 0.641 / 0.1508 |
| `servo_isr.c` `model_params_init()` `par_c[0]/[1]` | 0.71314 / 2378.2 | 0.641 / 3016.3 |

（`par_c[1] = Ki = 0.1508/50e-6 = 3016.3`；同时 `par_c[3][4]` 应改 85e-6、
`par_c[5]` 应改 4.333e-3 —— 这三项无论 Kp 怎么选都必须改。）

改完需要复测：2 A 阶跃、4 A 以上大电流阶跃（验证饱和下的裕度）、以及
速度环 30/100/300 rpm 纹波（电流环带宽变了，速度环等效增益会跟着变）。

## 7. 顺带修掉的一个通道死锁

本轮测试时第三次撞上"遥测照发、命令全无响应、连 `!` 都不理，只能烧录"。
排查后在 `uart_link.c` 找到一条**必然死锁**的路径：

```c
s_out 是 200 字节，UART_LINK_LINE_BUF 是 192
if ((n == 0u) || (n >= UART_LINK_LINE_BUF)) { return 0u; }   // ← 超长行直接拒发
```

`emit()` 会先把 `s_out_pending` 置 1 再调 `TrySendAscii`。一旦某一行长度落在
**192…199**，这里返回 0 → 那一行永远发不出去 → `pending` 恒为 1 → 之后每一条
回显都在 `emit()` 里被静默丢弃 → **ASCII 通道永久失联，而主循环正常**
（看门狗不会复位，`!` 也走同一条路）。

改法与配套加固：

| 位置 | 改动 |
|---|---|
| `uart_link.c` | 超长行**截断后照发**，不再返回 0 |
| `servo_cmd.c` `emit` | 覆盖未发完的行时累加 `drop` 计数 |
| `servo_cmd.c` `Task1ms` | `pending` 超过 50 ms 强制放行并累加 `rec`（兜底自愈） |
| `servo_cmd.c` `Task1ms` | 每秒检查 `USART1->CR1.RXNEIE`，掉了就重新使能 |
| `stm32g4xx_it.c` | 统计 ORE/FE/NE/PE 到 `ue` |
| `do_status` | 出过问题时在 `S` 行追加 `tx=丢弃/自愈 ue=串口错误` |

加固后跑完整测试脚本没有再卡死，`S` 读到 `tx=6/0 ue=1`
—— 确实有 6 行被覆盖（单槽设计的固有丢行），但通道再也没死。
