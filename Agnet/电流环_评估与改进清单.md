## 2. id 通道的「振荡」是测量假象（原判断已撤回）

### 2.0 ⚠ 纠正：这不是电流环的问题

初测「id 给 2 A、稳态均值只有 0.92 A、sd 1.00 A」被判定为电流环振荡。
**这个结论是错的**，原因有两个，都查清了：

1. **deadman 超时**。采集 5 s 的直方图是双峰的：

   | id 区间 | 样本数 | 含义 |
   |---|---:|---|
   | −0.5 … 0.0 | 274 | MOE 关闭后 id=0 |
   | 0.0 … 0.5 | 192 | 同上 |
   | 1.5 … 2.0 | 26 | 正常 |
   | 2.0 … 2.5 | 23 | 正常 |

   采集日志里明确打出了 `[CMD] OFF (deadman 2s)  moe=0 en=0`。
   测试脚本发完 `/2.0` 后 sleep 1.0 s，第一帧保活又在 0.8 s 后 ——
   总延迟 2.4 s > deadman 的 2.0 s，所以 MOE 被关掉，id 归零。
   只剩前 1.5 s 的 49 个样本是真实值。

2. **`S` 里的电流环内部值一直是稳的**：`idq=2.00 / 2.07 / 1.94 / 2.10 / 2.02 / 2.07`，
   以及 `theta_m` pkpk 只有 0.97°。控制本身没有任何问题。

**结论：电流环不存在 id 振荡。** 下面的 2.1–2.3 保留作为测量记录，
但结论作废；只有 2.2 的三相噪声数据仍然有效（那是直接测的）。

### 2.1 现象（原记录，前提已被 2.0 否定）

力矩模式给 `id = 2.0 A`（`/2.0`，不产生力矩、转子静止），稳态 2 s、302 帧：

| 量 | mean | sd | min | max |
|---|---:|---:|---:|---:|
| **id 实测** | **+0.92 A** | **1.00 A** | −0.17 | +2.28 |
| iq 实测 | +0.016 A | 0.049 A | −0.12 | +0.14 |

**id 的 sd 与均值同量级**，iq 却只有 0.049 —— 两者由同一组 `ialpha/ibeta` 经 Park 变换得到，
差 20 倍。`id = 0.92` 而不是 2.0 说明电流环在大范围来回摆（一度跌到 −0.17，反向）。

### 2.2 为什么是 id 而不是 iq

静止时电角度 θ 固定。若此刻 θ 接近 0，则 `cs≈1, sn≈0`：

```
id = cs·iα + sn·iβ ≈ iα ≈ iu        ← 直接吃 A 相采样噪声
iq = cs·iβ − sn·iα ≈ iβ              ← 与 iu 的噪声正交
```

静止三相实测（3 s、302 帧）：

| 相 | mean | sd | pkpk | 备注 |
|---|---:|---:|---:|---|
| iu | −0.004 | 0.048 | 0.269 | 实测 |
| iv | −0.032 | **0.092** | **0.537** | **不是实测，是 `−iu−iw` 算的**，两路独立噪声叠加 → 必然放大 √2 |
| iw | +0.035 | 0.050 | 0.295 | 实测 |

额定 5 A，噪声 sd 0.05–0.09 A（1–2%），峰峰 0.27–0.54 A（5–10%）。
20 kHz 下的瞬时尖峰更大（上一轮 `dead_probe` 测到 iu 瞬时 ±0.8 A，而稳态只有 0.08 A）。

### 2.3 后果链

采样尖峰 → `id_now` 出现假尖峰 → `ed = id_ref − id_now` 反向 → PI 输出反向 →
真实电流被拉低 → PI 再拉回 → **低阻尼振荡**。

这解释了三件事，而且是同一个根因：

1. 阶跃 `ts = 24–30 ms`（±5% 带被反复踢出，判据永远不满足）
2. 所有 Kp 档位都无效（尖峰不随增益消失，低增益时相对影响更大）
3. 上一轮"相电流波形分析"失败（同样是被尖峰污染）

**这是电流环当前的第一优先级问题，不解它，后续调参都是徒劳。**

## 3. 参数一致性问题

### 3.1 电感：设计 113.5 µH，实测 85 µH（小电流）/ 59 µH（饱和）

`Kp = ωc·L` 是按 113.5 µH 设计的，但实际电感更小：

| 条件 | Kp/L（实际闭环带宽） | R/L（极点） | 零点/极点 |
|---|---:|---:|---:|
| 设计 L=113.5 µH | 6283 rad/s = **1000 Hz** | 3524 = 561 Hz | 0.95 ✓ |
| 实测 L=85 µH | 8390 = **1335 Hz** | 4706 = 749 Hz | 0.71 |
| 饱和 L=59 µH | 12087 = **1924 Hz** | 6780 = 1079 Hz | **0.49** |

**饱和时实际带宽接近 2 kHz**，是设计值的近 2 倍，而零极点对消比掉到 0.49。
这是（配合采样尖峰）振荡风险的第二个来源。

### 3.2 磁链：`SERVO_CUR_PSI = 7.59298e-3`，实测 4.333e-3（**大 1.75 倍**）

| 转速 | 设计 ψ 的 BEMF 前馈 | 实际需要 |
|---|---:|---:|
| 1000 rpm | 11.13 V | **6.35 V** |

`dec_vq = id·ωe·Ld + ωe·ψ` 会**过补偿 4.8 V**。稳态时积分反向抵消，看不出问题；
但转速变化时前馈不准 → iq 抖动，而且白占电压余量。
（这个常量只用在 BEMF 前馈，力矩换算已改用实测值 `SERVO_KT_NM_PER_A`。）

### 3.3 零极点对消比

设计要求 `Ki/Kp = R/L`。当前 `Ki/Kp = 3335 rad/s`：

| 用哪个 L | R/L | 零点/极点 | 结论 |
|---|---:|---:|---|
| 113.5 µH（设计） | 3524 | 0.95 | 基本对消 ✓ |
| 85 µH（实测） | 4706 | 0.71 | 零点偏低 29% → 残留低频极点 → 超调 |

按实测参数重新算（目标仍 1 kHz）：

```
Kp    = 2π·1000 · 85e-6 = 0.534      （当前 0.713，高 33%）
Ki·Ts = R/L · Kp · Ts   = 0.1257     （当前 0.1189，低 5%）
```

## 5. 改进清单（按优先级）

### P0 — 电流采样质量（唯一的关键路径）

这不是改控制参数能绕过去的。三个方向，按可查证程度排序：

1. **确认 ADC 注入触发源**：G4 的电流采样应严格落在 PWM 中心（中心对齐模式下
   TIM1 计数器的峰值/谷值），通常用 `TIM1_CC4` 作为注入组的 `EXTI` 触发。
   若现在用的是"软件触发"或"定时器更新事件"，就会采到开关沿附近的振铃。
   → 需要示波器对 `TIM1_CC4` 与桥臂电流波形。
2. **检查采样电阻后的 RC**：截止频率若高于 ~50 kHz，开关噪声会直接进 ADC。
3. **确认双电阻采样的窗口**：低占空比时采样窗口会被压缩，需要检查最小脉宽。

### P1 — 参数校正（改常量即可，但需要先做 P0 才能验证收益）

| 参数 | 现值 | 建议 | 依据 |
|---|---:|---:|---|
| `SERVO_CUR_PSI` | 7.59298e-3 | **4.333e-3** | `+` 联合辨识，dev=1.85% |
| `SERVO_CUR_LD/LQ` | 113.5e-6 | **85e-6**（小电流） | `@` 在线辨识 80.1–80.7 µH @1.55 A；ψ 辨识 89.07 µH |
| `SERVO_CUR_KP` | 0.71314 | 0.534（若 L 改 85e-6） | 保持 ωc=2π·1000 |

注意：`Ld/Lq` 改小会让解耦项减弱。当前解耦用 113.5 µH 是**过补偿**，
高速大电流时会有额外扰动 —— 与 P1 一起改。

### P2 — 控制细节

1. **Ki 重算**：`Ki·Ts = R/L · Kp · Ts`，用实测 R/L 保证零极点对消。
2. **抗饱和改比例式**：`int += ki_ts·e + Kb·(u_sat − u_raw)`，Kb 取 0.3~0.5，
   与速度环用的做法一致（速度环已经这么写了）。
3. **加采样延迟补偿**（可选）：在 vd/vq 上加 `ωe·L·i` 的预测项，或直接把 PI
   改成带延迟补偿的离散形式。

### P3 — 能力补齐

1. 弱磁（负 id）支持，扩高速范围。
2. 频响测量（扫频 + 增益/相位），替代"只能看阶跃"的现状。

## 6. 结论

**骨架是好的**：稳态误差 −0.01%、电压余量 10 倍、联锁齐全、解耦/BEMF/死区补偿/谐波抑制都在。

**但被采样质量卡住了上限**：id 通道在 2 A 给定时均值只有 0.92 A、sd 1.00 A，
这不是调 PI 能解决的。在解决 P0 之前：

- 不要继续调 Kp/Ki（已验证 6 个档位全部无效）
- 不要用 id 通道做精密标定（读数不可信）
- 力矩模式的精度上限也受此限制（iq 通道恰好干净，但换一个转子位置就会轮到它）

**最省力的验证**：用示波器看 `TIM1_CC4` 与桥臂电流的对齐关系。如果触发点偏了，
改一个寄存器就可能同时解决 id 振荡、死区波形分析和力矩精度三件事。

## 7. 补充：ts 判据的真实问题，以及两处 ADC 配置实验

### 7.1 ts = 24–30 ms 不是"振荡了 30 ms"，是判据被纹波卡住

`CurStep` 的调节时间判据是"进入 ±5% 且不再离开"。对 2 A 阶跃，±5% = **±0.1 A**。

而实测电流纹波（静止时三相 pkpk 0.27–0.54 A，dq 域折算约 ±0.1–0.25 A）**本身就跨在
这个带边上**，于是判据永远不满足 —— 与增益无关，这就解释了为什么 6 个 Kp 档位
ts 全部落在 24–30 ms。

换句话说：**ts 这一栏对 2 A 阶跃没有分辨力**，应该用 ±10% 或基于纹波水平的动态阈值。
tr（150–200 µs）和 ss（−0.01%）两栏是可信的。

### 7.2 两处 ADC 配置实验：都改了，都没改善，但都保留

| 改动 | 原值 | 新值 | 依据 | 实测效果 |
|---|---|---|---|---|
| ADC 注入组采样时间 | 2.5 周期（58.8 ns） | **24.5 周期（576 ns）** | 采样保持窗口应 ≥5τ | iu sd 0.048→0.055，**无改善** |
| TIM1 CCR4（ADC 触发点） | **1**（距谷值 5.88 ns） | **150**（882 ns） | 死区是 294 ns（50 计数），原值**在死区窗口内采样** | iu sd 0.057，**无改善** |

两处都保留，理由不同：

- **采样时间**：更长的窗口对 RC 离散和温度漂移更鲁棒，代价只有 2.6 µs/50 µs（5%）。
- **CCR4**：原值 1 在原理上是错的 —— 中心对齐下 CNT=0 是谷值，CNT=1 距谷值 5.88 ns，
  而上下管死区 294 ns，这期间电流走体二极管，采样电阻上的电压不是下管电流。
  实测没变化说明死区采样不是当前噪声的主因，但这个配置本身应当修正。
  上限已校验：`VLIM_FRAC=0.5375` → 下管最短导通 1.75 µs > 882 ns。

**两个都不是根因。** 剩下的可能只有硬件层面：采样电阻后的 RC 取值、地线布局、
OPA 反馈网络。这些需要示波器看桥臂电流与 ADC 触发点的实际波形，软件侧已经到边界。

### 7.3 修正后的电流环评价

| 维度 | 结论 | 依据 |
|---|---|---|
| 稳态精度 | **优秀** | ss = −0.01%，S 里 idq 稳在 2.00 |
| 带宽 | 高于设计（实际 ~1.3–1.9 kHz vs 设计 1 kHz） | tr 150–200 µs；L 实测比设计小 25% |
| 电压余量 | 充足 | vp 1.72 V vs 限幅 16.5 V |
| 联锁/安全 | 齐全 | fault/cal/z/openloop 四道；deadman 2 s 有效（本轮亲眼见到它工作） |
| 采样噪声 | **偏大，待硬件确认** | 三相 sd 0.05–0.09 A、pkpk 0.27–0.54 A |
| 参数一致性 | **有偏差** | L 113.5 vs 85 µH；ψ 7.59 vs 4.333 mWb |

**因此改进优先级修正为**：

1. **P1 参数校正**（L、ψ）—— 现在升为最高，因为它可做、可验证，且直接影响解耦与前馈；
2. **P2 Ki 重算**（用实测 R/L 保证零极点对消）；
3. **P3 采样噪声治理** —— 需要示波器，软件侧已排查完（采样时间、触发点都试过）；
4. **P4 抗饱和改比例式**；
5. **P5 ts 判据改进**（把 ±5% 换成 ±10% 或纹波自适应阈值，否则这项指标永远不可读）。

## 9. 电流采样优化：结论是"不需要优化采样"（21:20–21:30）

### 9.1 先把噪声性质测清楚

`&` 录制 iq（20 kHz，1024 点 ×6 段），radix-2 FFT 按频段积分：

| 频段 | RMS (A) | 峰值 (A) |
|---|---:|---:|
| 0–100 Hz | 0.0009 | 0.0014 |
| **100–1000 Hz** | **0.0158** | **0.1230** |
| 1k–5k | 0.0018 | 0.0080 |
| 5k–9k | 0.0012 | 0.0029 |
| 9k–10k | 0.0010 | 0.0019 |

**99% 的能量集中在 874 Hz 的单一谱峰（0.123 A）**，5k–10k 几乎为零 ——
PWM 纹波（20 kHz）完全不在里面，白噪声也很小。

### 9.2 874 Hz 是外部扰动，不是控制振荡

用 G 档位扫 Kp（零电流、iq 给定 0）：

| Kp | 总 sd | 主峰 | 幅值 |
|---:|---:|---:|---:|
| 0.50× | 0.195 | 864 Hz | 0.159 |
| 1.00× | 0.128 | 874 Hz | 0.103 |
| **2.00×** | **0.031** | 3813 Hz | **0.0043** |

Kp 加倍后 874 Hz 峰**完全消失、sd 降 4 倍**。如果是控制振荡，提高增益只会更糟 ——
所以这是被环路增益压住的外部低频扰动（源头未定位，可能是母线/参考/地环路耦合）。

**但有载时结论相反**（id 给定 2 A）：

| Kp | id sd |
|---:|---:|
| 1.00× | **0.130** |
| 1.50× | 0.137 |
| 2.00× | 0.171 |

有载时提高 Kp 反而放大噪声。所以没有"一个 Kp 对所有工况最优"，
**1.00× 是折中点**，维持不变。

### 9.3 四个尝试，都没改善那个 0.13

| 动作 | 依据 | 结果 |
|---|---|---|
| ADC 采样时间 2.5 → 24.5 周期 | 58.8 ns 窗口太短，RC 来不及建立 | iu sd 0.048→0.055，无改善 |
| TIM1 CCR4 1 → 150 | 原值距谷值 5.88 ns，**在死区（294 ns）内采样** | 无改善 |
| `Servo_GetSample` 加 PRIMASK 临界区 | 三个 float 分时更新，读侧可能撕裂 | id sd 0.129→0.129，无改善 |
| 遥测 idq 改用 `Servo_GetIdqMeas` | 遥测自己重算 Park，用滞后一拍的角度 | id sd 0.129→0.132，无改善 |

前两个改动保留（原理上更正确），后两个也保留（无害且消除重复计算）。

### 9.4 真正被确认的事实

**20 kHz 录制（ISR 当拍值）与 100 Hz 遥测（同一变量快照）在有载时差 4 倍**：

| 工况 | 20 kHz 录制 sd | 100 Hz 遥测 sd |
|---|---:|---:|
| 零电流（iq=0） | 0.127（874 Hz 扰动） | 0.127 ✓ 一致 |
| 有载（id=2 A） | **0.033** | **0.132** ✗ 差 4 倍 |

零电流时两者一致，有载时差 4 倍。同一个 `s_cur_iq` 变量、同一个 32 位原子读，
两种采样率得到不同 sd —— **这个差异的原因尚未定位**。

可以确定的是：**控制用的电流是干净的**。
电流环在 ISR 内用当拍的局部变量 `iq_now` 做 PI，录制也取同一个值（sd 0.033），
所以采样质量对控制的影响很小。0.13 那个数只出现在观测路径上。

### 9.5 结论

**"优化电流采样"这件事本身不成立** —— 采样是干净的（ISR 内 sd 0.033，
5k–10k 频段无能量）。之前几轮把它当成"噪声大"来治，方向错了。

真正剩下的问题只有两个，都不在采样上：

1. **零电流时的 874 Hz 外部扰动**（0.12 A）。它被高增益压制，但有载时高增益会放大
   别的成分，所以不能简单提 Kp。要根治得先定位源头（母线纹波？参考噪声？地环路？），
   需要示波器测母线/VDDA 的频谱。
2. **遥测 dq 的观测偏差**（有载时 4 倍）。它不影响控制，但会误导所有基于遥测的评估。
   在定位之前，**判断电流质量请用 `&` 录制或 `S` 的稳态值，不要用 30027 的瞬时 dq**。

### 9.6 建议的下一步（如果还要继续）

- 用示波器测母线电压与 VDDA 的频谱，看 874 Hz 是否来自电源；
- 若来自母线，可以在电压前馈里加对应补偿，比提增益更有针对性；
- 若确认是随机噪声（不像），再考虑 ADC 4× 硬件过采样（无相位滞后，代价是转换时间 ×4 = 10.5 µs/50 µs）。

## 10. 三项采样链路核查（2026-11-17 21:25–21:40，网表 + 数据手册 + 实测）

### 10.1 触发源：已是 CC4 硬件触发，但**我之前对触发点的判断是错的**

配置实证（`Core/Src/adc.c` / `tim.c`）：

| 项 | 值 |
|---|---|
| TIM1 TRGO | `TIM_TRGO_OC4REF` |
| ADC1/2 注入组触发 | `ADC_EXTERNALTRIGINJEC_T1_TRGO` + `EDGE_RISING` |
| 通道模式 | CH1~3 = `PWM2` + `OCPolarity=HIGH`，`CCR=(1-d)·ARR` |
| 死区 | `DeadTime=50` → 294 ns（`CKD=DIV1`，DTG∈0xx 段） |
| 互补输出 | `CCER |= CC1NE|CC2NE|CC3NE`（`bsp_servo.c:339`）→ 死区确实作用于引脚 |
| 栅极驱动 | **FD6288Q**（Fortior，250V 三相；内置死区 100/200/300 ns，t_on 150/250，t_off 120/250） |

**不需要示波器就能确认的结论**：是硬件 CC4 触发，不是软件触发、也不是 UPDATE 事件。 ✓

**但需要纠正一处**：我上一轮把 `CCR4` 从 1 改成 150，理由是"CNT=1 距谷值 5.88 ns，
落在 294 ns 死区里"。**这个理由不成立**——死区发生器作用在 `CNT=CCR` 的开关沿上，
不在谷值。中心对齐 + PWM2 下：

- 上管导通区间以 `CNT=ARR`（峰值）为中心
- 下管导通区间以 `CNT=0`（谷值）为中心 ← 谷值是这段区间的**正中**
- 两侧开关沿都在 `CNT=CCR`，离谷值有 `CCR·5.88 ns`（0.5 占空比时 12.5 µs）

所以谷值离死区最远，是最安全的采样点。反证也支持这一点：`CCR4=1` 时期
电流环 tr=183 µs、ss=0.00%、力矩线性偏差 <0.027 A —— 若真采在死区里，不可能成立。

把 `CCR4=150`（882 ns）的真正代价算出来：低边窗口终点是 `+CCR·tcnt`，
占空比越高窗口越短。**实测占空比 1.004（2200 rpm）时，CCR4=150 已采在关断之后。**

**改法**：窗口真实中心（含驱动延时）与占空比无关：

```
起点 = -(CCR-50)·tcnt + t_on
终点 = +CCR·tcnt + t_off
中心 = (50·tcnt + t_on + t_off)/2 = (294+150+120)/2 = 282 ns  → CCR4 = 48
```

已把 `CCR4` 从 150 改成 **48**。余量对比（距关断还剩多少 ns）：

| 占空比 | CCR4=1 | CCR4=48 | CCR4=150 |
|---:|---:|---:|---:|
| 0.90 | 2614 | 2291 | 1738 |
| 0.95 | 1364 | 1041 | 488 |
| **0.97** | 864 | 541 | **−12** |
| 0.98 | 614 | 291 | −262 |

**实测效果：没有显著改善**（见 10.3）——因为噪声根本不在这一环。改动保留的理由是
高占空比下的余量（能撑到 0.98 而不是 0.957），不是"降噪"。

### 10.2 RC：截止频率 53 kHz，但方向反了——这里不该再加强滤波

网表还原（`Hardware/Netlist_PG_X72_CAN_2026-11-07.enet`）：

```
R4 (HoBB1216-3W-1mR) : U_GND — PGND，Kelvin 3/4 脚 = UI_P/UI_N   ← 低边采样
R28/R29 = 1 kΩ       : UI_P/UI_N → OPA1_N/OPA1_P
R30 = 30 kΩ          : OPA1_N → OPA1_OUT（反馈）
R31 = 30 kΩ          : HALF_VREF → OPA1_P（偏置）
C5 = 100 pF          : OPA1_N ↔ OPA1_OUT（反馈电容）
C3 = 10 pF           : OPA1_P ↔ OPA1_N（差分）
OPA1 = STM32G474 内部运放（STANDALONE，HighSpeed，`opamp.c`）
```

| 极点 | 计算 | 值 |
|---|---|---:|
| 反馈极点（主导） | 1/(2π·30k·100p) | **53.05 kHz** |
| 差分输入极点 | 1/(2π·2k·10p) | 7.96 MHz（可忽略） |
| 运放自身（GBW 13 MHz / 噪声增益 31） | — | ≈420 kHz（非瓶颈） |

增益 30（30 mV/A），20 kHz 处只衰减 **0.6 dB** —— PWM 纹波**根本没被滤掉**，
靠的是同步采样（每个周期同一相位采一点，纹波被"定格"成常量）。

**所以"RC 截止频率高于 50 kHz 会让开关噪声进 ADC"这个判断的结论要反过来**：
这里 53 kHz 已经偏低了，不是偏高。原因：低边采样的窗口在高占空比下只有 1~2 µs，
而 τ = R30·C5 = **3.0 µs**。窗口比时间常数还短 → 低边一开通，前端根本来不及建立。

| 占空比 | 窗口（谷值±） | 折合 τ | 理论建立程度 |
|---:|---:|---:|---:|
| 0.50 | 12.5 µs | 4.2τ | 98% |
| 0.80 | 5.0 µs | 1.7τ | 82% |
| 0.93 | 1.75 µs | 0.58τ | 44% |
| 0.96 | 1.0 µs | 0.33τ | 28% |

**这是一个"随占空比变化的增益误差"的隐患**：低占空比时电流读数准，高占空比时
读数系统性偏小 → 同样的 iq 给定，实际电流更大。它不影响稳定性（环路增益变低只是变慢），
但会让高速段的力矩标定失真。

**本轮无法证实也无法排除**（需要独立电流参考），所以列为待验证项：

- 用示波器同时看 OPA1_OUT（PA2）与 CH1/CH1N 栅极信号，在 2000 rpm 下测
  "低边开通 → OPA 输出稳定"的实际建立时间；
- 若确认建立不足，把 C5 从 100 pF 降到 47 pF（→113 kHz，τ=1.4 µs）或 33 pF（→161 kHz），
  代价是高次开关噪声拾取变大；
- 另一条低风险优化：`opamp.c` 的 `InternalOutput = DISABLE` 改成 `ENABLE`，
  让 ADC 从内部走线取样、不过引脚，减少 PA2 引脚/走线上的拾取。

### 10.3 采样窗口：**真正的限制在高速段，不在低占空比**

用户提的是"低占空比时采样窗口被压缩"——对低边采样来说方向相反：**占空比越高，
下管导通越短，窗口是在高占空比端被压缩的**。实测（带减速器，30.7 V 母线）：

| 指令 rpm | 母线 | dmax（限幅前） | 低边窗口 | id 均值 | id σ |
|---:|---:|---:|---:|---:|---:|
| 1500 | 30.73 | 0.832 | 4.19 µs | −0.026 | 0.092 |
| 2000 | 30.71 | 0.935 | 1.62 µs | +0.023 | 0.130 |
| **2200** | 30.71 | **1.004** | **0** | −0.012 | **0.167** |
| **2350** | 30.70 | **1.030** | **0** | +0.023 | **0.221** |

（`dmax` 由遥测的 `ua/ub/uc` 反推：`d = 0.5 + u/vbus`，取三相最大。遥测存的是限幅**前**的值，
所以 >1 就代表该相已被 `BspServo_SetDuty` 夹到 1.0。）

**关键结论：2200 rpm 以上，占空比顶到 1.0，该相下管永不导通 —— 分流器上只剩死区期间
的体二极管电流，这一相电流完全不可测。** 而 Clarke 只用 iu/iw 两相（iv 由 `−iu−iw` 推算），
丢一相就等于 dq 全错。

id 噪声随窗口塌陷单调上升（0.092 → 0.130 → 0.167 → 0.221，2.4 倍），
与"反馈周期性失效"的图像一致。**这是本轮最有价值的发现，而且之前完全没意识到。**

理论上占空比随转速（ψ=4.333 mWb，p=14）：

| rpm | BEMF | duty_max | 窗口 | 可测 |
|---:|---:|---:|---:|---|
| 2000 | 12.71 V | 0.920 | 1.99 µs | 是 |
| 2140 | 13.59 V | 0.949 | 1.27 µs | 是 |
| 2200 | 13.98 V | 0.962 | 0.96 µs | 临界 |
| 2400 | 15.25 V | 1.003 | 0 | **否** |
| 2500 | 15.88 V | 1.024 | 0 | **否** |

**两条可选路线（需决策）**：

1. **限调制比**（教科书做法）：`SERVO_CUR_VLIM_FRAC` 0.5375 → **0.45**，
   保证 dmax ≤ 0.95、窗口 ≥1.25 µs。代价：最大相电压 16.5 V → 13.8 V，
   **最高转速 2496 → 约 2140 rpm（−14%）**。
2. **维持现状，接受 2200 rpm 以上的电流反馈退化**：反正电压极限在 2496 rpm，
   只有最后 ~300 rpm 受影响；但那段 id/iq 不可信，不适合做力矩控制。

本轮**没有动** `VLIM_FRAC`（会改变已验证的最高转速，属于设计取舍）。

### 10.4 前端分辨率的真正瓶颈：增益太低，不是滤波

| 量 | 值 |
|---|---:|
| 分流器 × 增益 | 1 mΩ × 30 = **30 mV/A** |
| ADC LSB | 0.806 mV → **26.9 mA/LSB** |
| 额定 5 A | 150 mV → **186 LSB（仅 4.5% 满量程）** |
| 软件限幅 9 A | 270 mV → 335 LSB（8.2%） |
| 硬件跳闸 12 A | 360 mV → 447 LSB（10.9%） |
| 实测噪声 0.048 A RMS | **1.8 LSB** |

**186 个码字覆盖额定电流，等效分辨力不到 7.5 bit。** 噪声 1.8 LSB 已经是
12 bit ADC 的正常水平，换滤波、换触发点、加过采样都不会有实质改善——
瓶颈是模拟增益。若把 R30/R28 从 30 倍提到 100 倍（R30=100k），
5 A → 500 mV → 620 LSB，信噪比提升 3.3 倍。这是**下一版硬件**该改的地方。

| 项 | 结论 | 证据强度 |
|---|---|---|
| 注入触发源 | 已是 TIM1_CC4(TRGO=OC4REF) 硬件触发 | **强**（代码） |
| 死区不在谷值 | 死区在 CNT=CCR 开关沿；谷值是最安全点 | **强**（PWM2 + 中心对齐推演） |

| 高占空比窗口塌陷 | 2200 rpm 起 dmax≥1.0，一相电流不可测 | **强**（实测 + id σ 上升） |

| 分辨率瓶颈是增益 | 5 A 仅用 4.5% 满量程 | **强**（计算） |

## 11. 补正：母线是 32 V 台架，设计点是 48 V（2026-11-17 21:50）

### 11.1 10.3 节的"高速段窗口塌陷"要限定在 32 V 台架

用户指出：**当前台架母线 32 V，电机设计额定母线 48 V**。这改变了 10.3 节的适用边界。
占空比 = `0.5 + vmag/vbus`，同样的转速在 48 V 下占空比低得多：

| rpm | BEMF | **32 V 台架** duty / 窗口 | **48 V 设计点** duty / 窗口 |
|---:|---:|---|---|
| 2000 | 12.91 V | 0.903 / 2.42 µs | 0.769 / 5.78 µs |
| 2200 | 14.18 V | 0.943 / 1.43 µs | 0.795 / 5.12 µs |
| 2500 | 16.08 V | **1.003 / 0** | 0.835 / 4.12 µs |
| **3000（额定）** | 19.26 V | **1.102 / 0** | **0.901 / 2.47 µs** |
| 3200 | 20.53 V | 1.142 / 0 | 0.928 / 1.81 µs |
| 3400 | 21.80 V | 1.181 / 0 | 0.954 / **1.15 µs（临界）** |
| 3800 | 24.34 V | 1.261 / 0 | **1.007 / 0（不可测）** |

**结论修正：**

1. **不需要下调 `SERVO_CUR_VLIM_FRAC`。** 48 V 下窗口塌陷点在 **3800 rpm**、
   临界点在 3400 rpm，都高于额定 3000 rpm（0.901 / 2.47 µs）。10.3 节提出的
   "限调制比 0.45、牺牲 14% 最高转速"在 48 V 设计点上没有依据，**撤回**。
2. 32 V 台架上 2200 rpm 的窗口塌陷是**供电电压不足造成的台架现象**，不是设计缺陷。
3. **但有一个可用性上的收获**：32 V / 2000 rpm 的占空比 0.903 ≈ 48 V / 3000 rpm 的 0.901，
   **所以现在这台 32 V 台架在 2000~2200 rpm 就是额定工况的等价复现**。
   实测该点 id σ 从 0.092（1500 rpm）升到 0.130，说明额定点确实存在反馈质量下降。
4. 旧的 2496 rpm 封顶也是 32 V 的结果（`vmag = 0.5375×30.7 = 16.5 V`）。48 V 下
   电压极限抬到约 4000 rpm，**台架换 48 V 电源后才能真正验证 3000 rpm 额定点**。

### 11.2 `InternalOutput=ENABLE` 这条建议**撤回**，风险很高

10.2 节末尾写"另一条低风险优化：`opamp.c` 的 `InternalOutput` 改成 `ENABLE`"。**这是错的。**

HAL 头文件原文（`stm32g4xx_hal_opamp.h:70`）：

```
FunctionalState InternalOutput;   /*!< Specifies the configuration of the internal output from OPAMP to ADC.
                                       Note: When this output is enabled, regular output to I/O is disabled */
```

而网表显示反馈网络就挂在 OPA1_OUT **这个引脚**上：

```
OPA1_OUT = U4 pin 10 (PA2) = R30(30k) pin2 = C5(100pF) pin2
```

（PA1/pin9 → OPA1_P，PA3/pin11 → OPA1_N，与 `STANDALONE + IO0/IO0` 配置吻合。）

一旦置 `OPAINTOEN=1`，PA2 不再输出运放信号 → **R30/C5 构成的反相输入反馈回路断开**
→ 运放变成开环 → 输出贴轨 → 电流采样彻底失效。要上电就可能直接过流/飞车。

**保持 `DISABLE`（现状）是唯一正确的配置**：PA2 既驱动外部反馈网络，又作为
ADC1_IN3 的输入，一引脚两用。引脚走线很短、源阻抗是运放输出，拾取可以忽略。

### 11.3 修正后仍然成立的结论
