# 电流环整定与三环频率修正

> 2026-11-15 17:0x · 固件 `X72_FOC.axf` Code **76124 B** / 0 Error 0 Warning
> 实测：速度模式 **3.00 rpm（给定 3.00）**、`f=0x00`、`clamp=0`、`moe=1`
> 本轮修了 3 处错配 + 1 个坐标系 bug，其中坐标系那个会直接导致过流跳闸。

---

## 1. 结论先行

电流环本身**没有整定错**，参数是按 20 kHz 算的标准 IMC 整定（带宽 1000 Hz）。
真正的问题是**三个环的执行频率全都比设计值低了一半**，因为控制环实际跑 10 kHz
（模型 double 导致单拍 9282 cyc > 50 µs，见 `Agnet/控制节拍与预算诊断.md`）：

| 项 | 设计（20 kHz 基准） | 实际（10 kHz） | 后果 |
|---|---|---|---|
| 电流环积分步长 `dt` | 5.0E-5 | 执行 1.0E-4 | `Ki` 实际 = 1189，只有设计值 2378 的一半 |
| 速度环分频 | `/10 → 2 kHz` | `/10 → 1 kHz` | `ki_w=10.19` 的积分同样丢一半 |
| 位置环分频 | `/20 → 1 kHz` | `/20 → 500 Hz` | 响应延迟翻倍 |
| **位置环坐标系** | — | `pos_ref` 多圈 vs `theta_m` 单圈 | **跨 2π 时误差跳 2π → 过流跳闸** |

## 2. 参数是怎么流到固件里的

```
three_loop_params.m         ← 已丢失，无法重建模型
      ↓ build_three_loop_deploy.m:119  (par_c 常量)
three_loop_deploy.slx       ← 参数已固化进 Constant 块
      ↓ generate_three_loop_code.m
three_loop_deploy.c         ← 生成物，手改会被覆盖
```

`par_c = [kp ki dt Ld Lq psi max_duty overmod mag_vd_max dec imax]`

| 参数 | 值 | 说明 |
|---|---|---|
| `kp` | 0.713142 | V/A |
| `ki` | 2378.186 | V/(A·s) |
| `dt` | **5.0E-5** | 设计 20 kHz → 本轮改成 1.0E-4 |
| `Ld = Lq` | 113.5 µH | 用于解耦与前馈 |
| `psi` | 7.593 mWb | 反电动势常数 |
| `dec` | 3 | 交叉耦合 + BEMF 全解耦 |
| `imax` | 9 A | |

整定推算：`带宽 = kp / L = 0.7131 / 113.5e-6 = 6283 rad/s ≈ 1000 Hz`；
`零点 = ki / kp = 3334 rad/s`，正好抵消对象极点 `R/L`（R≈0.378 Ω）。
**这是标准的 dq PI + 极点抵消整定，本身没有问题。**

## 3. 三处错配

### 3.1 电流环 `dt`（`three_loop_deploy.c`）

```c
/* 原值 */
vd_int += (0.0 - id) * 2378.18563877 * 5.0E-5;
vq_int += err_q     * 2378.18563877 * 5.0E-5;

/* 改为 */
vd_int += (0.0 - id) * 2378.18563877 * 1.0E-4;
vq_int += err_q     * 2378.18563877 * 1.0E-4;
```

`Ki_effective = ki × dt × f_ctrl`。`dt` 写 5e-5 而实际 1e-4、`f_ctrl` 只有 10 kHz，
结果 `2378 × 5e-5 × 10000 = 1189`，积分零点从 3334 掉到 1667 rad/s —— 稳态收敛变慢、抗扰变差。

### 3.2 速度环与位置环的分频

```c
/* 位置环：设计 1 kHz = 20 kHz/20，10 kHz 下应为 /10 */
three_loop_deploy_DW.cnt_i++;
if (three_loop_deploy_DW.cnt_i >= 10.0) { ... }     /* 原 20.0 */

/* 速度环：设计 2 kHz = 20 kHz/10，10 kHz 下应为 /5 */
three_loop_deploy_DW.cnt++;
if (three_loop_deploy_DW.cnt >= 5.0) { ... }        /* 原 10.0 */
```

速度环的 `i_term` 用的是固定 `Ts_w = 0.0005`（500 µs），**只有分频回到 2 kHz 这个 `Ts_w` 才成立**。
如果只改 `dt` 不改分频，速度环会以 1 kHz 运行却按 500 µs 积分，`ki_w` 依旧只有一半。

### 3.3 位置环的坐标系 bug（最严重）

```c
/* servo_isr.c，改前 */
three_loop_deploy_U.theta_m = (real_T)theta_now;   /* 单圈 0~2π */
three_loop_deploy_U.pos_ref = (real_T)s_pos_ref;   /* 多圈累积 */
```

`BspServo_GetThetaRad()` 内部会 `if (theta >= 2π) theta -= 2π`，所以 `theta_m` 是**单圈**；
而 `VelProfile_Step()` 里的 `pos_ref += v_ref * ts` 是**多圈累积**。

theta 一旦跨过 2π，`pos_ref − theta_m` 会**突跳 2π**：

```
位置环 hold_w = (pos_ref - theta_m) * 50.265
              → 突跳到几百 rad/s → 限幅 ±120
              → 速度环 err = 120 rad/s → iq 限幅 ±9 A
              → 电流冲击 → 过流跳闸
```

**实测证据**（3 rpm / 5.4 s 窗口，跨 2π 一次）：

```
[CMD] st en=1 moe=0 ... f=0x01 clamp=1 ovc=-23.37/22.06 raw=1169/2815
平均转速 3.37 rpm    ← 转速偏低、且被过流切断
```

`VelProfile_Step()` 的 `err_max = 1.0 rad` 钳位在这里只是"副作用计数器"，
真正的根因是坐标系不一致。

**修复**：把送给模型的 `pos_ref` 折到 theta 所在的那一圈，

```c
const float ds = (float)s_dir_sign;
const float th_m = ds * theta_now;
float e = ds * (s_pos_ref - theta_now);
e -= BSP_TWO_PI * floorf((e * (1.0f / BSP_TWO_PI)) + 0.5f);   /* wrap 到 ±π */
three_loop_deploy_U.pos_ref = (real_T)(th_m + e);
```

模型算出的误差就是 `wrap_pi(真实误差)`。速度模式与位置保持的误差都远小于 π，完全正确。
代价约 15 cyc，当前 `step max = 9282 cyc / 54.6%`，可忽略。

## 5. 如何从模型侧修改（而不是改生成代码）

### 5.1 正确的三步路径

```
three_loop_params.m  →  build_three_loop_deploy.m  →  generate_three_loop_code.m
   参数唯一源              重建 .slx（写 par_c/par_w/par_p）    生成 .c
```

`generate_three_loop_code.m` 本身就会调用前两步（`:27` 调 `three_loop_params()`、
`:37` 调 `build_three_loop_deploy()`），所以**跑这一个脚本就够**。

**关键**：`build_three_loop_deploy.m:111-112` 里分频是**自动算的**：

```matlab
N_p = round(P.Ts_p / P.Ts_i);      % 1ms / 50us  = 20
N_w = round(P.Ts_w / P.Ts_i);      % 500us / 50us = 10
```

所以**只改 `Ts_i` 一处**，两个分频和延时补偿会自动跟着变：

| 量 | Ts_i = 50 µs（20 kHz） | Ts_i = 100 µs（10 kHz） |
|---|---|---|
| `par_c(3)` 即 `dt` | 5e-05 | **1e-04** |
| `N_w` 速度环分频 | 10 | **5** |
| `N_p` 位置环分频 | 20 | **10** |
| `T_angle_comp = 1.5·Ts_i` | 7.5e-05 | **1.5e-04** |
| `gain_comp = p·T_angle_comp` | 0.00105 | **0.0021** |

**最后一行是手改版漏掉的**：延时补偿不在电流环里，而在
`theta_sum = 14·theta_m + π/2 + gain_comp·omega_m` 这一项上。
`Ts_i` 翻倍后补偿必须翻倍，否则高速时 1.5 拍的角度滞后只补了一半。

### 5.2 `three_loop_params.m` 已恢复

原文件丢失（`build_three_loop_deploy.m:29` 引用它），现已按 `.slx` 里固化的值
逐项还原，19 个字段全部对齐：

| 字段 | 值 | 在 .slx 里的对应 |
|---|---|---|
| `Ts_i` | 100e-6（**本次改**） | `par_c(3)` + `FixedStep` |
| `Ts_w` | 500e-6 | `par_w(3)` |
| `Ts_p` | 1e-3 | `par_p(3)` |
| `kp_i` / `ki_i` | 0.713141532365 / 2378.18563877 | `par_c(1)` / `par_c(2)` |
| `Ld` / `Lq` | 113.5e-6 / 113.5e-6 | `par_c(4)` / `par_c(5)` |
| `psi` | 7.59297995988e-3 | `par_c(6)` |
| `max_duty` / `overmod` / `mag_vd_max` / `dec_mode` / `I_max` | 0.95 / 1 / 0.98 / 3 / 9 | `par_c(7..11)` |

（因为生成结果本身就带正确参数，补丁脚本无事可做）。

### 5.4 当前的落地方式：幂等补丁脚本

在 Temp 权限没解决前，用 `simulink_code_gen/patch_gen_code.py`：

```bash
python patch_gen_code.py --check   # 只检查
python patch_gen_code.py           # 应用（幂等）
```

它对 4 处逐一判定「已应用 / 待应用 / 异常」，异常时直接退出不改文件。
所以「重新生成 → 跑一次补丁 → 编译」是可重复流程，不会因为重复打补丁而二次出错。

### 5.5 改其他参数时动哪里

| 想改什么 | 改哪里 |

## 6. 局限与后续

1. **四处改动都是手改生成代码**（dt / N_w / N_p / gain_comp），
   `generate_three_loop_code.m` 一跑就全没。现已提供 `patch_gen_code.py`
   做幂等补丁，「生成 → 打补丁 → 编译」可重复。
   `three_loop_params.m` 已恢复，只要 Simulink 能存 .slx（见 §5.3 的 Temp 权限）
   就能走正规路径一次搞定。
2. **根本解法仍是回到 20 kHz**：single 化后单拍 1813 cyc（配置⑤实测），
   三处错配自动消失，参数无需改动，相位裕度也从 ~30° 回到 ~55°。
   见 `Agnet/控制节拍与预算诊断.md` 方案 A。
3. **位置模式跨圈移动受限**：折叠方案只保证 ±π 内正确。
   要做大范围绝对定位，必须改模型增加一个多圈角度输入 `theta_pos`。
4. **低速测速量化**：3 rpm 时每 100 µs 的编码器增量只有约 0.01 counts，
   瞬时 `omega_m` 完全被量化噪声淹没（遥测里 3~9 rpm 的跳变就是这个）。
   累积脉冲算出的平均转速是准的。要改善低速性能需换 M/T 法或加长测速窗口。
5. **电流环带宽未直接实测**：本轮只能间接验证（辨识 2 A 斜坡 60 点全稳定、
   速度阶跃中 iq 跟随良好）。要给出带宽/相位裕度的实测值，需要一个
   20 kHz 采样、触发式记录的阶跃记录器（可放入 `Board/` 作为独立诊断模块）。
