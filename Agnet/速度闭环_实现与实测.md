> 2026-11-15，X72 / STM32G474CEU6 + MT6835 + 14 对极 PMSM。
> 固件 `Code=59416 RO=3352 RW=72 ZI=9400`，0 Error 0 Warning。

| 给定 | 稳态 | 误差 | 稳态纹波(σ) | 纹波占比 | 超调 | iq 峰值 |
|---|---|---|---|---|---|---|

| 30 rpm | 29.23～29.75 | −0.8～−2.6% | 1.79～1.96 rpm | 6.2% | 30.6～31.9% | 1.22～1.69 A |
| 60 rpm | 60.377 | +0.6% | 4.13 rpm | 6.9% | 18.5% | 0.74 A |

> 采样率 100 Hz（遥测 10 ms/帧），所以"上升时间"分辨率只有 10 ms，30 rpm 的 tr 实测为 0 ms（小于一个采样点），本表不列 tr。要拿到毫秒级 tr 必须在片内以 2 kHz 记录波形，见 §7。

对照：位置环保持（`E` 后静止 2 s）mean −0.001 rpm、σ 0.027 rpm，说明 8 拍测速改动没有牺牲静止稳定性。

## 2. 为什么 F/R 不算速度闭环

固件里原本有两条"速度"相关路径，语义完全不同：

| | `F`/`R`（SERVO_MODE_VELOCITY） | `W`/`Q`（SERVO_MODE_SPEED，本次新增） |
|---|---|---|
| 控制结构 | 速度轨迹积分成 `pos_ref` → 模型位置环 P | `(w_ref − w_meas)` 直接进 PI → `iq_ref` → 电流环 |
| 速度误差参与运算 | **不参与** | 参与 |
| 稳态无静差靠什么 | 位置环 P + 速度环积分（串级） | 速度环积分 |
| 抗扰（摩擦/齿槽） | 只能靠位置落后量间接反映 | 速度误差立即反映 |
| 本质 | 位置跟踪一条匀速度斜坡 | 速度反馈闭环 |

`F`/`R` 的实测（同一套 omega 字段）：稳态 3.16 rpm、σ 0.99 rpm —— 能跑，但速度不是被"闭环"住的，而是被位置环"拖"出来的。判断依据很直接：给一个外部扰动力矩，`F` 路要等位置真的偏了才响应，`W` 路在速度一变就响应。

## 3. 实现：为什么写在 Board 层

生成代码 `three_loop_deploy.c` 的顶层输入只有 `pos_ref` / `en`，**没有 `w_ref` 端口**。速度环 `par_w` 虽然在，但它的输入 `hold_w` 只由位置环 P 产出：

```
hold_w = (pos_ref − theta_m) · kp_p        // three_loop_deploy.c:77
err    = hold_w − omega_m                  // :90
hold_iq= kp_w·err + ∫ki_w·err·Ts_w         // :99
```

要"直接把速度给定喂进速度环"，只能改模型加输入端口并重新生成代码。历史上重新生成已经覆盖过一次手工适配（`real32_T`、`par_*` 参数化、坐标系注释），代价远大于照抄 20 行算法。

所以实现在 `servo_isr.c`：

```
s_spd_en ──> Servo_SpeedLoopStep(w_ref, w_meas)  [2 kHz，10 分频]
                        │ iq_ref
                        ▼
             已有的 dq 电流环 PI（20 kHz，编码器电角度）
                        │ duty
                        ▼
                    BspServo_SetDuty
```

电流环一行没改，速度环只是接管了 `iq_ref` 的来源：

```c
if (s_spd_en != 0U) {
    iq_ref = Servo_SpeedLoopStep(dir * s_spd_ref_raw, om);
    id_ref = 0.0f;
} else {
    CurStep_Refs(&id_ref, &iq_ref);   // 阶跃整定
}
```

与 `fcn_three_speed_loop_deploy.m` 逐行对应（`cnt/n_div`、`i_term += ki·err·ts`、两次 clamp）。唯一有意偏离：模型对积分器只做简单 clamp，iq 顶到限幅后积分继续累加；这里改成"饱和且误差仍指向饱和方向就冻结积分"，代价 2 个比较，换来退饱和无超调。

### 坐标系陷阱（必须记住）

`om` 已乘 `dir_sign`（模型坐标系），速度给定也必须乘，否则 `dir=−1` 时正 iq 让 `om` 变小 → 误差变大 → 正反馈飞车。

```c
const float w_ref_model = (float)s_dir_sign * s_spd_ref_raw;  // 单位 rad/s
iq_ref = Servo_SpeedLoopStep(w_ref_model, om);
```

`Servo_SetSpeedMode()` 对外仍用**编码器坐标系**（与 `BspServo_GetOmegaMech()` 同号），所以 "+30 rpm" 永远等于"编码器正转 30 rpm"，与上位机显示一致。

## 4. 关键发现一：模型的速度环参数偏小 8 倍

模型给 `kp_w = 0.07292272`、`ki_w = 10.190689`（`ωz = ki/kp = 139.7 rad/s = 22 Hz`）。逐档实测（30 rpm，空载）：

| 档位 | kp | kiTs | 纹波(σ) | 超调 | iq 峰值 |
|---|---|---|---|---|---|
| 1x | 0.073 | 5.10e-3 | 22.5 rpm | 204% | 0.74 A |
| 2x | 0.146 | 10.19e-3 | 11.2 rpm | 108% | 0.74 A |
| 4x | 0.292 | 20.38e-3 | 5.6 rpm | 56% | 0.74 A |
| **8x** | **0.583** | **40.76e-3** | **3.2 rpm** | **25%** | **0.93 A** |
| 16x | 1.167 | 81.53e-3 | 22.1 rpm | 122% | 3.00 A（饱和） |
| 32x | 2.334 | 163.05e-3 | 25.4 rpm | 139% | 3.00 A（饱和） |

规律是"增益越低、纹波越大"，说明低增益下**积分器在慢慢摆**，不是高增益自激。16x 开始 iq 打到 3 A 限幅，环路进入饱和-退饱和循环，纹波反弹，所以 8x 是拐点前的最优。

反推惯量：`Kp ≈ J·ωc²/(Kt·|1+j·ωc/ωz|)`，8 倍意味着等效 `J ≈ 2.3e-4 kg·m²`，而模型那组参数对应 `J ≈ 2.9e-5`。模型整定时显然用了小一个数量级的惯量假设（或只按"位置环内环"场景设计，位置环 P=50.265 只需速度环慢一点即可）。

**固件默认值已改为 8x 实测值**，`L` 键仍保留扫档能力（0.125x～32x），`Y` 复位到 1x（= 实测最优）。

## 5. 关键发现二：单拍差分测速噪声不可用

第一次跑速度闭环时，`omega` 字段在 30 rpm 下标准差 18.8 rpm，但 iq 只有 0.8 A——物理上不可能。用三条独立路径交叉验证：

| 测量路径 | 30 rpm 时 σ |
|---|---|
| A 多圈计数差分（30040 enc_sum） | 3.37 rpm |
| B `omega` 字段（控制律用的量） | 18.77 rpm |
| C 对照组：`F` 模式 3 rpm 下的 `omega` | 1.64 rpm（与位置差分 0.99 一致） |

C 组说明**测速链路本身没坏**：位置环下 omega 是对的。差别在于速度环把噪声放大进了环路。

但 B 组的 18.8 rpm 仍然偏大。根因是单拍差分：50 µs 内编码器量化 ±1 count（2²¹ 脉冲/圈）就折算 ±5.7 rpm，再叠加"某拍读到上一拍旧值"的隔拍效应。

改成 8 拍累计差分（`bsp_servo.h`）：

```c
s_spd_acc += d;                                  // 每拍累加角度增量
if (++s_spd_cnt >= 8) {                          // 400 us
    w_raw = s_spd_acc / (50us * 8);
    s_omega_mech += 0.21f * (w_raw - s_omega_mech);   // 等效 95 Hz 低通
}
```

- 量化噪声：±1 count / 400 µs = ±0.71 rpm
- 隔拍只影响 1/8，不会出现"0 与 2x 交替"
- `alpha = 1−exp(−2π·95·400µs) = 0.212`，截止频率与原来一致
- 代价：多 200 µs 平均延迟，在 8 Hz 位置环处相位滞后 0.6°

位置保持回归：σ 0.027 rpm（改动前未单独记录，但 8 Hz 振荡问题未复现）。

## 6. 命令与用法

```
C  电流零点标定（200 ms，须静止）
Z  电角度/极对数/方向辨识（VESC 三段式，约 9 s）
I  查看上次辨识结果
E  / D   使能 / 封锁
M / N    电流闭环 ±1 A（力矩模式）
T / U / V  电流阶跃 iq / id / 两轴
W / Q    速度闭环 正转 / 反转（转速由 O 选定）
O        循环转速档位 3 / 10 / 30 / 60 / 100 rpm（环内按 O 直接换给定）
L        速度环增益档位 0.125x … 32x
Y        速度环增益 + 转速档位复位（每次测试前先发）
K        速度环详情：wref / wmeas / iqc / iterm / nex / kp / kiTs
F / R    速度轨迹 ±3 rpm（位置环方案，对照用）
P        位置保持
S        状态回读（含 spd= 标志）
X        清故障（需 MOE=0）
```

典型上机序列：

```
C  Z            # 标定 + 辨识（每次上电一次）
S               # 确认 cal=1 z=1 f=0x00
Y               # 速度环复位到实测最优
W               # 进环正转 30 rpm
K               # 看 wmeas 是否跟上 wref、nex 是否在涨
O               # 换 60 rpm
D               # 封锁
```

安全联锁（都实测踩过）：
- 未做 `C` → 拒绝进环（零漂会被 PI 当真实电流积分）
- 未做 `Z` → 拒绝进环（零点错时"正 iq"可能产生反向力矩，速度环会推成飞车）
- 超速保护：`|om| > 1.5·|w_ref| + 10 rad/s` → `f=0x20` 并封 MOE。空载 3 A 约 956 rad/s²，10 ms 就能撞线，编码器断线时这是唯一能兜住的东西
- deadman 2 s：到点自动 `D`

## 7. 局限与后续

| 项 | 现状 | 影响 / 下一步 |
|---|---|---|
| 速度环带宽 | 约 3 Hz（等效 J≈2.3e-4） | 属于低速环。再快需要同时提 Kp 和 iq 限幅，且受测速噪声限制 |
| 上升时间 | 只有 100 Hz 遥测，分辨率 10 ms | 要毫秒级 tr 需在 2 kHz 速度环里片内记录 400 ms 波形（参照 `cur_step.c`） |
| 3 rpm 超调 68.8% | 低速段库仑摩擦 + 静摩擦起跳 | 需要速度前馈或摩擦补偿；`deadband_comp` 默认关闭，未标定真实 `comp_du` |
| 负载测试 | 全部为**空载** | 带载后 iq 需求上升，8x 增益是否仍最优需重扫；Kt=0.159 N·m/A，3 A 对应 0.48 N·m |
| 过温保护 | 无（只上报温度） | 长时堵转/带载需要加 derating |
| 掉电保存 | `cal`/`z`/`dir`/增益档位均在 RAM | 每次上电要重做 C+Z（约 9.3 s） |
| 参数化转速 | 固定 5 档表（O 键） | 单字符命令层不做数字解析（二进制流里的 0x30~0x39 会误触发） |

## 9. 高速段实测：3000 rpm 到不了，边界由电压决定（2026-11-16）

### 9.1 实测

| 给定 | 实际稳态 | iq 给定 | iq 实测 | vq | \|v\| | 圆限幅 0.5375·vbus |
|---|---|---|---|---|---|---|
| 3000 rpm | **2496 rpm** | 3.000 A（顶限幅） | 0.470 A | +16.482 V | **16.50 V** | 16.50 V |

`|v|` 精确等于圆限幅，说明不是力矩不够，是**电压打满**：速度环还在要求 3 A，电流环只挤出 0.47 A。

### 9.2 第一个坑：自己的限幅静默截断

第一次发 3000 rpm，转速稳在 **955 rpm**、iq 只有 0.4 A。看着像电压受限（955 rpm 恰好是 `0.5375×30.75/0.1063` 的一半），实际是：

```
K: wref=954.93rpm        <- 100 rad/s 的换算值
```

`SERVO_SPD_WREF_MAX` 当时写的是 100 rad/s，3000 rpm 在进速度环前就被夹掉了。**静默截断比报错难查得多**——现象与"电压受限"几乎无法区分。已改为 400 rad/s（3820 rpm），让"到不了"由电压和超速保护明确暴露。

### 9.3 第二个发现：模型 psi 偏大 41%

用 30025 的 uabc + iabc 按固件同一电角度做 Park 反算（θ = 14θm + π/2 + 1.05e-3·ωm）：

```
wm = 2496 rpm (261.4 rad/s)   we = 3659.5 rad/s
vd = -0.237 V   vq = +16.482 V   |v| = 16.50 V
id = +0.072 A   iq = +0.470 A
```

`psi = (vq − R·iq)/we`：

| R | psi | 与模型 7.5930 mWb |
|---|---|---|
| 0.3785 Ω（模型 R_eff） | 4.4554 mWb | **−41%** |
| 0.4200 Ω（万用表实测绕组） | 4.4501 mWb | −41% |

两种 R 只差 0.1%，说明结果对 R 不敏感，不是电阻估错。

连带影响：`Kt = 1.5·p·psi` 实际 ≈ **0.0936 N·m/A**，而模型按 7.593 mWb 算的是 0.15945（偏大 41%）。所以"iq 1 A 约 0.16 N·m"这类换算是错的，实际只有 0.094 N·m/A。

**但这不影响转速上限**：电压饱和时 vq 全部用于抵消 BEMF，`ωm_max = 0.5375·vbus/(p·psi实测)`。用实测 psi 算 30.7 V 的上限是 2526 rpm，实测 2496 rpm，误差 1.2% —— 相互印证。

### 9.4 到 3000 rpm 需要多少母线

```
vbus_min = p·psi·ωm / 0.5375 = 14 × 4.455e-3 × 314.16 / 0.5375 = 36.5 V
```

| 母线 | 理论上限 |
|---|---|
| 30.7 V（当前） | 2526 rpm |
| **36.5 V** | **3000 rpm** |
| 48 V | 3950 rpm |

结论：这台电机的反电势常数与 30 V 母线不匹配，**3000 rpm 必须 ≥37 V**；48 V 系统有 32% 余量。若要留在 30 V 系统，只能靠弱磁（id < 0）提速，代价是电流增大、效率下降。

### 9.5 顺带修复：Keil 工程丢失 4 个源文件

`X72_FOC.uvprojx` 在 11-15 23:16 被改写后，`Application/User/Servo` 组里的 `servo_cmd.c`、`motor_ident.c`、`cur_step.c`、`deadband_comp.c` 四个条目消失，但对应的 `.o` 还是 23:11 的旧产物，所以平时 `-r` 全量重建照样能链接通过（用的是旧 .o），直到这次改 `servo_cmd.c` 才暴露成 8 个 `L6218E Undefined symbol`。
