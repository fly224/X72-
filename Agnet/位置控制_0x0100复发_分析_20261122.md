## 2. 一个必须先说清的数学矛盾

`0x0100` 的判据是 **`|e| = |规划 − 实测| > 6.0 rad` 持续 100 ms**（`POS_ERRMAX_DFLT=6.0`）。

而这次行程只有 **2.142 rad**。即使电机**完全不动**，`e` 的最大值也只有 2.142 —— **够不到 6**。

所以「报 0x0100」一定还满足下面之一：

| 可能 | 说明 |
|---|---|
| **A. 规划目标不是 6.2832，而是更远处** | 例如 `s_p_tgt_c` 仍是上一轮的旧目标（+2π 的整数倍），而 `p_ref` 一路朝它跑 |
| **B. 实测位置跳了 2π 的整数倍** | `s_pos_base` 被重新对齐（重新起环）而 `p_ref` 没同步 |
| **C. `p_meas` 反向跑了 4 rad 以上** | 符号/坐标错乱 |

这三种都需要 `30100` 的逐拍数据才能定案 —— 见 §5 的诊断脚本。

> **实测补充（`Code=107464`、Kp=28、同样行程）**：`|err|` 峰值只有 **1.9 mrad**，
> 0.32 s 到位、环形误差 +0.01 mrad、无故障（数据见 §7）。
> 所以「行程 2.14 就报 0x0100」在本固件上**不可能由正常定位产生**，
> 只能是上面 A/B/C 之一的异常路径。其中 A（目标被改成远处）正是 §3 那条已修的 bug 会造成的。

## 3. 已修：清故障后重发**同一个目标**会被静默吞掉（确定的 bug）

### 3.1 机制（代码可证）

`ServoCmd_ClearFault()`（`action=3`）会调 `PosLoop_ClearFault()`：

```c
if (s_st == POS_ST_ERR) {
    s_hold_req = 1U;      /* Step 里 s_p_tgt = p_meas：停在当前位置 */
    s_restart  = 1U;
    s_st       = POS_ST_HOLD;
}
```

位置环被重置成「停在当前位置」，**但 `Servo_SetPosTarget` 的去重锁存 `s_pos_cmd_last` 没有复位**：

```c
if (fabsf(p_target_rad - s_pos_cmd_last) <= 1e-6f) {
    if (PosLoop_GetState() != POS_ST_DONE) { return; }   /* HOLD 态 → 直接返回 */
    ...
}
```

于是「清故障 → 再输入 0.0000」这条最常见的操作：

| 步 | 结果 |
|---|---|
| 1. 上次已下发 0.0000，`s_pos_cmd_last = 0.0` | — |
| 2. 报 0x0100，清故障，位置环停在当前位置（HOLD） | 目标变成 `p_meas` |
| 3. 上位机再发 0.0000 | 输入值相同 → 命中 `s_pos_cmd_last` → **`st != DONE` → return** |
| 4. 目标**没有被设回 6.2832** | 位置环停在原地，或继续按旧目标跑 |

**这正好解释日志里「定位成功（上位机以为发下去了）→ 随后又报 0x0100」。**

### 3.2 修法

新增 `Servo_ResetPosCmdLatch()`，在清故障时一并复位：

```c
void Servo_ResetPosCmdLatch(void)
{
    s_pos_cmd_last = -1.0e9f;              /* 允许下一次重新折算 */
    s_pos_tgt_last = pos_coord_now();      /* 与 Enable 设的目标同步 */
}
```

```c
/* ServoCmd_ClearFault() 里 */
PosLoop_ClearFault();
Servo_ResetPosCmdLatch();      /* ← 新增 */
```

**没有改成「按折算结果去重」的原因**：那样在 `now` 跨过 π 时目标会翻一整圈，
keepalive 每 100 ms 重发就会跳圈（上一轮实测过：wref 钉在 −238.7 rpm 无限绕）。
按输入值去重是防跳圈的唯一可靠判据，只能在「清故障」这种目标确实失效的时机复位它。

## 4. 顺带发现：`POS_KI_DFLT = 0`，位置环是**纯 P**

`pos_loop.h`：`#define POS_KI_DFLT (0.0f) /* 0 = 关闭（默认） */`

代码里虽有 I 项实现（含抗饱和回灌），但 **Ki=0 时积分恒为 0**。所以位置环实际是纯 P：

```
静摩擦死区 ≈ iq_fric / (Kp_spd × Kp_pos) = 0.15 / (0.583 × Kp)
```

| Kp | 死区 | 到位窗口 10 mrad |
|---|---|---|
| **28（当前）** | **9.2 mrad** | **刚好卡在窗口边缘** |
| 100（默认） | 2.6 mrad | 稳在窗口内 |

**Kp=28 时末端会停在 9.2 mrad，与 10 mrad 的到位窗口几乎相等**，于是状态在
`MOVE`/`DONE` 之间反复跳；跟随误差虽然不大（0.29 rad 量级），但末端刚度很差，
负载稍大就可能磨不到位。

> 建议：**Kp 回 100**（`POS_KP_DFLT`，注释里写明「实测最优」）。
> 若确实需要更软的环，请同时把 `POS_KI` 打开（现在默认 0），否则纯 P 的死区会一直是 Kp 的倒数级。

## 7. 实测（`Code=107464`，端口恢复后）

**场景一：完全复现你的操作 —— Kp 设成 28，输入 0.0000**

```
参数: pos_kp=28.0  cur_iqmax=5.00  spd_iqmax=3.00
起环: p_now=5.8468  p_tgt=5.8466  p_ref=5.8466  err=-0.00025  st=DONE

下发 0.0000：
  t=0.00  p_now=5.8540  p_tgt=0.0000  p_ref=5.8529  err=-0.0010  MOVE
  t=0.08  p_now=6.0005  p_tgt=0.0000  p_ref=5.9996  err=-0.0005  MOVE  wref=+28.8
  t=0.20  p_now=0.0012  p_tgt=0.0000  p_ref=6.2824  err=-0.0019  MOVE
  t=0.32  p_now=0.0000  p_tgt=0.0000  p_ref=0.0000  err=-0.0000  DONE

未报故障，环形误差 +0.01 mrad，|err| 峰值 0.0019 rad
```

**场景二：连续改目标 7 次（在环只发 30019）**

| 次 | 目标 | 实到 | 环形误差 |
|---|---|---|---|
| 1 | 0.0000 | 0.0005 | +0.48 mrad |
| 2 | 3.1416 | 3.1422 | +0.55 |
| 3 | 0.5000 | 0.5005 | +0.46 |
| 4 | 6.0000 | 6.0010 | +0.95 |
| 5 | 0.0000 | 0.0001 | +0.14 |
| 6 | 2.0000 | 1.9993 | −0.66 |
| 7 | 0.0000 | 0.0011 | +1.06 |

**场景三：清故障 → 重起环 → 重发同一目标（本轮修复的路径）**

```
先定位到 5.0000        -> 实到 5.0005  (+0.54 mrad)
halt + action(3)       -> status=0  fault=0x0000
重起环                 -> p_now=5.0618  p_tgt=5.0615  st=DONE
清故障后发 0           -> 实到 0.0004  (+0.43 mrad)
再发一次 0（同一值）    -> 实到 0.0003  (+0.33 mrad)   ← 修复前会被去重吞掉
```

**总判定：7 + 3 次全部 DONE，无一次 0x0100。**

### 7.1 由此可以下的结论

| 结论 | 依据 |
|---|---|
| **Kp=28 本身可用** | 三种场景误差都 ≤1.1 mrad，远好于纯 P 的理论死区 9.2 mrad |
| **正常定位不会报 0x0100** | 行程 2.14 时 `\|err\|` 峰值 1.9 mrad，离 6 rad 差 3000 倍 |
| **你的那次故障来自目标异常（A/B/C），最可能是 §3 那条已修的路径** | 清故障后重发同一值被吞 → 位置环按旧目标跑 → `e` 累积 |
| 但**未直接复现**到你那一帧的 0x0100 | 修复后该路径已不通，无法人为制造 |

### 7.2 一个必须提醒的点：`pos_kp` **不落盘**

`30082` 的运行时参数（含 `pos_kp`）都只在 RAM 里，**上电复位后 Kp 回到默认 100**。

- 现在板子跑的是我实测用的 **Kp=28**（RAM 里），重新上电会变回 **100**
- 若你要固定用 28，得：① 每次连接后下发一次；或 ② 改 `pos_loop.h` 的 `POS_KP_DFLT`
- 建议直接用 100（默认值、注释里写「实测最优」），28 没有必要——两者实测精度都在 1 mrad 级
