| 选位置模式 | **30056** | `mode = 1` | 2 B：`status` + `mode` |

| 读绝对位置（编码器计数） | 30040 | `enc_sum_p` @0（int64） | 主动上报 |
| 读单圈角 / 模式 / 故障 | **30090** | `pos@16`、`mode@2`、`fault@36` | 主动上报 |

```
使能：30068(权限) → 30056(1) → 30054(cw=0x0F)  → 坐标在此刻 = 编码器单圈角（3.14 就是 3.14，不归零）
坐标：切模式后**先读 30100 的 p_now**，再用它算目标（顺序反了可能偏整圈）
移动：30019(pos_tar_p) → 规划器 → P 环 → 速度环 → 电流环
保活：30019 每 ≤2 s 重发同一目标（deadman=2 s），且 keepalive 必须用 mode=1
判到位：30100 的 settled==1（或 st==DONE）
```

**一句话**：位置环是**级联外环**，只输出速度给定；它只有 Kp 一个可调增益，其余限幅是编译常量。

> **坐标只用 30100 的 `p_now`**。它每次进位置模式时对齐到单圈角（0~2π），之后连续。不要用 `30090.pos + 30040.enc_sum×k` 拼——那条路既差 `s_enc_zero`，又会在 0 附近随单圈回绕跳变。

## 1. 控制逻辑

### 1.1 级联结构

```
pos_tar_p ──→ 规划器（梯形：vmax=25 rad/s, amax=200 rad/s²）
                 │
                 ├─ p_ref（规划位置）──┐
                 └─ v_ff （规划速度）──┤
                                       ↓
                    v_cmd = v_ff + Kp·(p_ref − p_meas)     Kp=100 1/s
                                       ↓
                         速度环（PI + 前馈 + 调度）        2 kHz
                                       ↓
                                   iq → 电流环              20 kHz
```

**为什么不直接出 iq**：那样位置环要自己兜摩擦、齿槽、重力、母线波动，等于重写一个速度环。级联后速度环的 PI 已经把这些吃掉，位置环只剩“比例 + 前馈”，稳定边界清楚，**而且没有稳态误差**——速度环 PI 无静差，只要 `e≠0` 就产生速度，积分会把摩擦顶过去。

### 1.2 规划器

- **梯形**，固定参数：`vmax = 25 rad/s`（≈239 rpm）、`amax = 200 rad/s²`、`jmax = 2000 rad/s³`（梯形下不使用）。
- 规划器有两个作用：① 阶跃不再是阶跃，齿轮间隙和齿槽不会被一次撞出来；② 匀速段直接给 `v_ff`，跟踪误差从 `v/Kp` 降到接近 0。
- **规划起点用“命令生效那一拍的实测位置与实测速度”**（`profile_start(p_meas, v_meas)`），不是命令里的位置。

### 1.3 P 环（+ 可选 I）

```
v_cmd = v_ff + Kp·e + i_term        e = p_ref − p_meas
```

- **Kp 默认 100 1/s**，范围 1~200。定值依据（`pos_loop.h` 顶部，90° 摆动 n=30 实测）：

| Kp | σ（A/B 两次） | range | 双向差 | 备注 |
|---|---|---|---|---|
| 25 | 19.2" / 18.1" | 105" / 103" | −3.7" | 2026-11-17 的值 |
| 40 | 7.7" / 5.8" | 32" / 20" | −0.1" | |
| 60 | 6.1" / 6.7" | 23" / 32" | +1.8" | |
| **100** | **4.5" / 4.3"** | 20" / 18" | +0.8" | **当前值**，裕度 50% |
| 120 | 4.3" / 3.5" | 16" / 16" | +0.2" | σ 最优，裕度仅 25% |
| 150 | 3.6" / 293.6" | 16" / 1278" | −18.9" | **失稳（极限环）** |

  失稳边界在 120~150 之间。取 100 而不是 120：只差 0.2"，却把裕度从 25% 拉到 50%。

- **积分默认关闭**（`Ki=0`）。实测（n=100）：σ 无改善，双向差从 −3.7" 恶化到 +37"，因为速度环内部已有积分在兜摩擦，两层积分对同一扰动竞争，变成方向相关的静态偏置。

### 1.4 目标补偿（**默认值已归零**，接口保留）

历史上行程 ≥1 圈时实际停止位置稳定少走 **4125"（0.01998 rad）**，补偿量就是按这个标定的。

**2026-11-21 更正：那 4125" 不是齿槽势阱，而是 Ki=0 时的抗饱和回灌 bug。**

`PosLoop_Step` 原本把回灌放在与 `s_ki` 无关的分支，`Ki=0` 时只要输出饱和，`s_i_term` 就被推到 −2.0 rad/s 且积不回来，于是速度给定里长期挂着伪偏置，稳态位置偏差 = 2.0/Kp = 0.020 rad（Kp=100）。该 bug 已于 2026-11-18 修复，修复后 20 圈重测均值为 **+3.7" / +9.8"**，固定偏差消失。

所以：

| | 含义 |
|---|---|
| 旧 `POS_COMP_DFLT = 0.01998` | 补的是一个**已经不存在**的偏差 |
| 现在 `POS_COMP_DFLT = 0` | 误开不再是“补少走”，而是**每次都多走 0.02 rad（1.15°）** |

历史实测（bug 修复前，20 圈 n=20）：补偿关 σ=28.5"、补偿开 σ=245.2"（恶化 8.6 倍）。这条结论仍然成立——补偿本身就是有害的。

接口保留：`30082 int 6/7/8`（`comp_mrad` / `comp_min_mrad` / `comp_en`），默认 `0 / 5000 / 0`，仅供实验。

**工程建议**：要绝对精度用外部闭环（用 30100 的 `p_now` 算偏差，修正下一条指令），不要开这个补偿。

### 1.5 到位判定与状态机

```
IDLE ──使能──→ HOLD（目标=当前位置）
                  │ 30019 新目标
                  ↓
                MOVE ──位置窗口持续 100 ms──→ DONE
                  │                            │ 被外力推走
                  │ e > 6 rad 持续 100 ms       ↓
                  └──────────────────────→ ERR（跟随误差故障，封锁输出）
```

到位判据（2026-11-21 修订）：规划器 `DONE` + `|e| < 10 mrad`，**连续维持 100 ms**。

| 参数 | 旧值 | 现值 | 为什么改 |
|---|---|---|---|
| 位置窗口 | 5 mrad | **10 mrad** | 静摩擦死区要求速度给定 0.26 rad/s，对应稳态误差 2.6 mrad；实测 `\|e\|` 在 0.7~4.8 mrad 抖动，5 mrad 窗口经常被打断 |
| 速度窗口 | 0.5 rad/s | **不再参与判据** | 静止测速噪声尖峰达 20 rad/s，实测 20 拍里 19 拍超 0.5 → **位置停稳了也判不成立**，`st` 永远停 MOVE |
| 持续时间 | 10 ms | **100 ms** | 原 10 ms 被噪声反复清零；防"路过目标误判"改用时间窗而不是瞬时速度 |

> 这一条是 30100 上线后才暴露的：以前没有 `settled` 出口，谁都看不到"到位标志其实从不置位"。实测定稿后 4 次定位（+3.0 / +3.0 acc=20 / −3.0 acc=20 / +0.2）全部 `DONE`，**DONE 丢失 0 次**。

**ERR 的恢复**：`30069 action=3`（清故障）会同时清 `POS_ST_ERR`；只清故障位而不清状态的话，下一拍又立刻置位，现象是“清了马上回来”。

### 1.6 跟随误差保护

- 判据用 **`p_ref − p_meas`**（规划与实际），不是 `目标 − 实际`——后者刚起步就很大，会把正常定位误判成故障。
- 阈值 **6 rad**、持续 **100 ms**，触发 `BSP_FAULT_FOLLOW`（bit8）。
- 6 rad 必须远大于 `vmax/Kp = 25/100 = 0.25 rad`；纯 P 环起动瞬间误差实测 **4~5 rad**（电机要先攒够速度给定才能克服静摩擦）。**原来设 1.5 rad，20 圈定位时被瞬态冲破，直接锁死**——现象是“电机纹丝不动、`e≈0`、状态停在 DONE”，极难反推。

### 1.7 起环与切环

- **使能不跑旧目标**：`30054` 使能时位置环以**当前实测位置**为目标（`PosLoop_Enable(p_now)`），不会朝上次的目标冲。
- **已在位置环**：`30019` 只改目标，不重开 MOE（避免一次通断冲击）。
- **从速度/力矩切过来**：`prepare_switch` 先 `do_disable`，再按 POS 重新装配；位置环仍从当前位起步，不会因余速受罚（与力矩模式的余速门禁不同）。
- **每次起环都重置坐标基准**：`Servo_SetPosMode(1, …)` 里先 `pos_coord_align()` 把坐标对齐到单圈角，再把传入的目标按 `(new_base − old_base)` 平移到新坐标。所以调用方传的目标必须与本函数同一坐标系 —— `do_enable` / `do_pos` 的 hold 分支用 `Servo_GetPosCoordNow()`，**不能**用 `BspServo_GetThetaMulti()`（差一个 `s_pos_base`，实测会让第二次起环的目标偏 −2π）。
- **位置环使能时必须显式关速度环**：ISR 的给定分支里 `s_spd_en` 优先于 `s_pos_en`，两个都开会得到“位置环使能了但完全不生效”，而且速度环积分还带着旧给定。

## 2. 坐标系与单位

| 量 | 单位 | 换算 |
|---|---|---|
| `pos_tar_p` | 编码器计数（int64） | `counts = rad × 2²¹/(2π) = rad × 333887.4` |
| `speed_tar_p_s` | 计数/s | `counts/s = rad/s × 333887.4`（= rpm × 34952.53） |
| `acc_tar_p_ss` | 计数/s² | 同上比例 |
| 30040 `enc_sum_p` | 计数（int64） | `rad = counts × 2π/2²¹` |
| 30090 `pos` | rad（单圈 0~2π） | — |

### 2.1 位置坐标：进模式时就是编码器单圈角（**不是归零**）

位置环的坐标 = `theta_multi − s_pos_base`，其中 `theta_multi` 是上电以来累积的多圈角。`s_pos_base` 是**可重置的偏置**，在**每次进入位置模式**时重新计算：

```c
/* servo_isr.c  pos_coord_align() */
s_pos_base = theta_multi − theta_single;    // theta_single = 编码器单圈角，0~2π
```

于是进入那一拍：

```
p_pos = theta_multi − (theta_multi − theta_single) = theta_single ∈ [0, 2π)
```

> **★ 这里是"保留数值"，不是"当零点"。**
>
> 进入位置模式时，如果编码器单圈角是 **3.14 rad**，那么 `p_now` 就是 **3.14**，不是 0。
> 实测：进入时 `p_now = 2.8571`，同时 `30090.pos = 2.8572` —— 两者相等，且都不是 0。
>
> 所谓"重置"只重置**圈数部分**（把上电以来的累积圈数清零），单圈角的数值原样保留。
> 对比三种可能的语义：
>
> | 语义 | 进入时 p_now（假设单圈角 3.14） | 是否本实现 |
> |---|---|---|
> | 把当前位置当 0（归零） | 0.00 | ❌ 不是 |
> | **保留单圈角** | **3.14** | ✅ **是** |
> | 保留上电以来的累积多圈角 | 可能 80+ | ❌ 不是（这就是原来跳变/难用的原因） |

之后 `p_pos` 随 `theta_multi` 连续变化，跨 0/2π 不跳。

> 为什么不能直接把反馈换成单圈角：`theta` 在 2π→0 回绕，位置环看到 6.28→0 会认为"还差 6.28 rad"，直接满速反转一整圈，比原问题更糟。用"偏置"而不是"换量"，才能既保留单圈数值又保持连续。

实测（Code=117724）：

| 场景 | p_now | 说明 |
|---|---|---|
| 第 0 次进位置模式 | **2.8571** | = 30090.pos (2.8572) |
| 走 +0.4 | 3.2559 | 连续 |
| 速度模式转 1.6 s 后切回 | **5.2318** | 重新对齐到单圈角 |
| 再切一次 | **1.5533** | 又对齐 |
| 从 1.85 走到 8.43（跨 2π） | 5.8412 → 6.3419 | **单步 0.5 rad，无跳变** |

**关键性质**：

| 项 | 说明 |
|---|---|
| **上电时** | 参数页加载完就对齐一次，所以**从第一帧起** `p_now` 就 = `30090.pos`（差 <0.1 mrad） |
| 进入位置模式时 | `p_now` = 当前单圈角，∈ [0, 2π)；因为上电已对齐，通常不再产生跳变（实测 +0.55 mrad） |
| 之后 | 连续，**可以超过 2π**（跨圈定位需要），此时 `p_now − 30090.pos = 2π × n` |
| 齿槽前馈 | 用裸 `theta_multi`，**不受影响**，`}` 不用重做 |
| MIT / 力矩 / 速度模式 | 不受影响（各自用自己的坐标） |
| 30090 `pos` | 不变（仍是含零点的单圈角） |
| 示教点 | **单圈内稳定**（`p_now` 就是编码器角，跨切换、跨上电都一样）；**跨圈会偏整圈**，需要上位机自己补圈数 |

因此：

- ✅ 上位机流程：**切模式 → 读 30100 `p_now` → 再算目标**。
- ✅ 跨圈运动直接给 >2π 的目标，例如 `p_now + 2π + 0.3`，不要给 `0.3`（后者会被理解成反向转一圈）。
- ❌ 不要用 `BspServo_GetThetaMulti()` 的等价物（30040 计数推算）当位置环坐标——它与 `p_now` 差 `s_pos_base`。
- ❌ 不要用 `30090.pos + 30040×k` 拼坐标：既差零点，又会因单圈回绕在 0 附近跳。

#### 实现要点（代码审查发现的三处）

| 坑 | 后果 | 修法 |
|---|---|---|
| **对齐时两次读角可能跨拍** | 若 ISR 插在 `GetThetaMulti()` 与 `GetThetaCached()` 之间，且那拍正好跨 2π，算出的 `s_pos_base` 差**整整 2π**，一使能就反向冲一圈 | 关中断读（窗口约 20 周期 / 0.12 µs），`__get_PRIMASK` + `__set_PRIMASK` 恢复 |
| **`s_pos_base` 跨上下文** | 1 ms 任务写、20 kHz ISR 读；不加 `volatile` 可能被提升到循环外，表现为"切了模式坐标没变" | 声明 `static volatile float s_pos_base` |
| **`p_target` 的参照系不统一** | 原来 `do_enable` 传裸 `GetThetaMulti()`，而函数内部按"本坐标系绝对位置"平移，第二次起环偏 **−2π** | 所有调用方统一用 `Servo_GetPosCoordNow()`；`p_target` 的约定写死为"本坐标系绝对位置" |

**上电也对齐一次**（`Servo_Init` 里参数加载之后）。否则上电读到的是裸 `theta_multi`，与单圈角差 `-s_enc_zero`（实测 0.1231 对 5.4755，差 5.35 rad），看起来像"上电角度不对、进了位置模式才跳回来"。

加了对齐之后：

```
上电（未进位置模式）: p_now=0.2764  30090.pos=0.2764  差 0.00000
进位置模式:           p_now=0.2769  30090.pos=0.2775  差 -0.64 mrad
进模式前后 p_now 变化：+0.55 mrad      ← 几乎不动，不再有"跳一下"
```

### 2.2 用 30100 一次读全（推荐，2026-11-21 起）

`30100 AppPosStatus` 的 `p_now` 就是位置环内部用的坐标，**与下发目标同一坐标系**。上位机从此不必再拼 30090 + 30040：

```python
ps = lk.pos_status()          # 100 Hz 遥测，无需请求
p0 = ps["p_now"]              # 位置环坐标（进入时 = 单圈角）
lk.set_pos_speed(pos_rad=p0 + 0.5)     # 目标与反馈同一坐标系
```

实测验证（Code=117724）：用 `p_now` 下发 +3.0 / −3.0 / +0.2 rad，定位误差 **−0.85 / −5.83 / −3.96 mrad**，全部 `DONE`；跨 2π 走 6.58 rad，最终误差 **+0.27 mrad**，过程中无跳变。

> `p_now` 与 `30090.pos` 的关系**取决于进了几次位置模式**：
> - 刚进位置模式那一刻：两者相等（差一个 `s_pos_base` 刚好抵消）
> - 之后转过整圈：`p_now − 30090.pos = 2π × n`，实测跨一圈后差 **6.2829 rad**
>
> 所以 `p_now` 是"单圈角 + 本次进入后的累计圈数"，既不会在 0 附近跳，也不会跑成 100 多 rad。

**跨上电怎么办**：`p_now` 每次上电从"上电姿态的单圈角"开始，多圈部分不保持。要跨上电示教，由上位机维护（首次读到的 `p_now` + 自己累计的圈数），或每次用限位/挡块回零。见 §7 第 7 条与 §8 缺口 #8。

## 3. 指令集

### 3.1 30068 权限 / 30056 模式 / 30054 控制字

| msgid | 载荷 | 说明 |
|---|---|---|
| 30068 | `comm_auth(1) + ctrl_auth(1)` | 都填 0 = 上位机持有权限；不做这一步所有写操作回 `status=4` |
| 30056 | `mode(1)` | **1 = 位置**、3 = 速度、4 = 力矩、12 = MIT |
| 30054 | `cw(u16) + halt(u8)` | `cw bit0=1` 使能；`halt≠0` 无条件封锁并清 `cw` |

应答：30056 回 `[status, mode]`；30054 回 `[status, cw 低字节]`。

30056 **只登记模式，不动作环**；真正装配由随后的 30019 或 30054 完成。

### 3.2 30019 PosSpeedCtlInput（位置给定）

载荷 44 B：

| 偏移 | 字段 | 类型 | 位置模式下的作用 |
|---|---|---|---|
| **0** | **`pos_tar_p`** | int64 | **目标位置（计数）** |
| 8 | `pos_now_p` | int64 | 不用（设备侧填） |
| 16 | `position_offset_p` | int64 | **固件忽略**（未解析） |
| 24 | `iq_max_A` | f32 | 不用 |
| 28 | `speed_tar_p_s` | f32 | 位置模式**不参与规划**，只缓存给后续切速度用 |
| 32 | `acc_tar_p_ss` | f32 | 只写速度环斜坡（`AppParam_SetSpeedAccel`），**位置规划不用**；0 = 不改 |
| 36/40 | `speed_now_rad_s` / `speed_offset_p_s` | f32 | 不用 |

应答 5 B：`status` + 目标回读（f32，rad）。

关键行为：

- **目标完全没变（≤1e-6 rad）直接忽略**，不重规划。这是为 deadman 保活设计的——每 1.35 s 重发同一目标绝不能触发 `profile_start`，否则规划器跟着测速噪声走，实测 20 圈会漂 −9705"。
- 目标变化 >0.01 rad 才清积分。
- 位置范围 **±1256 rad（±200 圈）**，超了回 `OUT_OF_RANGE`。


**Kp 下限不再是 1**（2026-11-21 修）。纯 P 环的匀速段跟随误差 = `vmax/Kp`，若 `Kp < vmax/errmax` 则一进匀速就越限、100 ms 后落 FOLLOW 故障。现在下限取

```

```

写 1 或 5 都会被抬到 **8.333**（实测回读确认）。改 `vmax` / `errmax` 之后也会重新夹一次，防止“先设 Kp 再改 errmax”绕过下限。

## 5. 下发序列

### 5.1 冷启动定位（推荐写法，实测通过）

> **顺序不能反**：先进位置模式（此时 `p_now` 才变成当前单圈角），**再读 `p_now`**，最后下发目标。切换前读到的是上一次的圈数基准，用它算目标可能偏 2π 的整数倍。

```python
lk.set_permission(0, 0)                 # 30068
if lk.ctrl_status()["fault"]:           # 30090
    lk.action(3); time.sleep(0.6)
lk.set_controlword(0x06, halt=1)        # 先彻底封锁，清干净上一轮状态
time.sleep(0.4)

lk.set_mode(1)                          # 30056，位置模式
time.sleep(0.3)
lk.set_controlword(0x0F, 0)             # 30054，使能 → 坐标在此刻对齐到单圈角
time.sleep(0.6)

p0 = lk.pos_status()["p_now"]           # ★ 必须在这之后读：才是本次基准
lk.set_pos_speed(pos_rad=p0 + 1.0)      # 30019，走 +1 rad
time.sleep(0.1)                         # 先给一次，保活才有有效给定
lk.set_keepalive(True, 1, 10.0)         # ★ mode=1（位置！）10 Hz 重发，deadman 2 s

# 判到位：直接读 settled，不要再自己算
t0 = time.time()
while time.time() - t0 < 3.0:
    ps = lk.pos_status()
    if ps and ps["settled"]:
        break
    time.sleep(0.01)
print(ps["st_name"], ps["p_now"], ps["err"])
```

> **`set_keepalive` 的第二个参数是模式**，位置模式必须传 **1**。传 3（速度）等于没保活——实测 2.2 s 后被 deadman 封锁，`st` 从 MOVE 掉回 IDLE，定位差 41 mrad，很容易误判成“位置环有 bug”。

> **跨圈目标要给展开值**：从 `p_now = 5.9` 走到"0.3"应该下发 `p_now + 0.68`（≈6.58），不能下发 `0.3`——后者会被理解成反向走 5.6 rad。实测走 6.58 rad（跨 2π）定位误差 +0.27 mrad。

### 5.2 运行中改目标

只发 **30019**。不要重发 30054：已在位置环时重发控制字没有任何好处，`halt` 写错还会直接封锁。

### 5.3 保持当前位置

```python
lk.set_pos_speed(pos_rad=<当前 p_now>)   # 目标=当前位，规划器立即进 HOLD
```

没有专门的“保持”消息；`30019` 给当前位置即可。

### 5.4 切回速度

```python

```

`30056` 只登记，下一帧 30019 会按 VEL 装配并自动先封锁位置环。

## 7. 规则与坑

1. **deadman 2 s**：30019 必须周期重发（保活 5 Hz 足够）。停了就封锁，现象是“走到一半自己停”。
   > 保活**必须用位置模式**：`set_keepalive(True, 1, hz)`。用 `mode=3`（速度）保活等于没保——实测 2.2 s 后被封锁，`st` 从 MOVE 掉回 IDLE，定位差 41 mrad。
2. **重发同一目标不会重规划**（≤1e-6 rad 忽略）。所以保活是安全的；但也意味着**想重新走同一段必须先把目标改成别的值**。
3. **改目标会让规划从“当前实测位置”重新起步**，不是从上一次规划的位置继续——中途改目标会有一次减速再加速。
4. **使能不跑旧目标**：`30054` 使能锁当前位；要动必须发 30019。
5. **位置与速度共用 30019**：同一帧里两个字段都写，固件只装配当前模式那一路，另一路缓存。切模式后可直接用缓存值。
6. **`acc_tar_p_ss` 不影响位置规划，但会改内环斜坡**（2026-11-21 修）。位置环给的是速度给定，仍要过速度环斜坡；原实现让 `a_max = s_spd_acc`，所以速度模式里把 acc 调小会让位置定位跟不上规划（峰误差 0.2~0.27 rad，虽不落故障但动态变差）。现在位置模式下 `a_max = max(s_spd_acc, 200)`，默认 acc=400 时行为完全不变。
7. **`p_now` 的基准在"每次进位置模式"和"每次上电"时都会重建，但都是"等于单圈角"而非归零**（2026-11-21 起）。
   - **上电**：参数页加载完立即对齐一次，所以**第一帧 `p_now` 就等于 `30090.pos`**（实测差 0.00000）。
   - **进位置模式**：`p_now` 变成**当时的编码器单圈角**（0~2π），**数值原样保留、不是归零**。
     - 单圈内的示教点因此**照旧有效**（`p_now` 与编码器角一一对应，跨切换、跨上电都稳定）。
     - 跨圈的示教点会偏 **2π 的整数倍**，要由上位机自己记圈数。
     - 上电已对齐，所以进模式通常不再有跳变（实测 +0.55 mrad）。
   - 之后的运动连续，可以超过 2π；此时 `p_now − 30090.pos = 2π × n`。
   - 30090 的 `pos` 含 `s_enc_zero`，重做 Z 会变；`p_now` 的单位基准是编码器 raw 0 点，重做 Z **不影响**它。
   - 需要跨上电的绝对位置，只能由上位机自己记（上电基准 + 累计圈数），或用外部基准（限位/挡块）回零。
8. **`pos_kp` 超过 120 有失稳风险**（120~150 之间起极限环），改之前先备份。
9. **判到位读 30100 的 `settled`**，不要用 `|v_meas|` 自己判——静止测速噪声尖峰能到 20 rad/s。

### 9.1 2026-11-21 修订后的验收（固件 Code=117644）

用 30100 的 `p_now` 作坐标、`settled` 判到位，acc 默认 400：

| 动作 | 到位耗时 | 峰值跟随误差 | 定位误差 | 结果 |
|---|---|---|---|---|
| +3.0 rad | 0.363 s | 0.0053 rad | −0.85 mrad | DONE |
| +3.0 rad，acc=20 | 0.480 s | 0.2011 rad | −1.41 mrad | DONE |
| −3.0 rad，acc=20 | 0.495 s | 0.2701 rad | −5.83 mrad | DONE |
| +0.2 rad，acc=20 | 0.211 s | 0.0117 rad | −3.96 mrad | DONE |

- `settled` **DONE 丢失 0 次**（每段 2.5 s 内只置位一次，不掉）。
- `acc=20` 是模拟“速度模式里把加速度调小后切位置模式”的遗留场景：修复前内环被卡在 20 rad/s²，峰误差更大；现在峰值 0.20~0.27 rad，远小于 6 rad 的故障门限。
- 定位误差在 1~6 mrad，主要是静摩擦死区对应的稳态误差（`I_fric/Kp_spd/Kp_pos ≈ 2.6 mrad`）加测速噪声。

| 第 2 次 | **1.5533** | 1.5530 | +0.75 mrad | 1.9496 | 是 |

**第二轮（Code=117748，加入 volatile + 关中断读后，五次切换）**：

| 轮次 | `p_now` | 30090 `pos` | 差 | `\|err\|` | 0~2π |
|---|---|---|---|---|---|
| 0 | 3.1546 | 3.1549 | −0.23 mrad | 1.8 mrad | 是 |
| 1 | 1.2891 | 1.2891 | −0.04 mrad | 3.5 mrad | 是 |
| 2 | 5.7318 | 5.7313 | +0.50 mrad | 3.2 mrad | 是 |

| 4 | 2.0894 | 2.0893 | +0.05 mrad | 3.3 mrad | 是 |

`p_now` 与 `30090.pos` 的差从 0.4 mrad 降到 **0.5 mrad 以内**（同拍读生效），5 轮全部落在 0~2π 且起环无冲击。

**第三轮（Code=117812，加上电即对齐后，三次切换）**：

| 轮次 | `p_now` | 30090 `pos` | 差 | `\|err\|` |
|---|---|---|---|---|
| 0 | 0.7672 | 0.7674 | −0.26 mrad | 0.2 mrad |

```
第一轮：1.85 → 8.43（走 6.58 rad）

```
