结论先行：

| 项 | 结果 |
|---|---|
| 判据 | 三相电流 RMS 关系：`rms(iu+iw)/max(rms iu, rms iw)` + 单相 RMS 比 |
| 阈值来源 | 今年两次真实 V 相断路的实测（0.091 / 0.963），不是拍的 |
| 位置 | 20 kHz 节拍内（10 kHz 抽取，200 ms 一窗），170 MHz 的 0.25% |
| 误报防护 | 200 ms 窗口 + 400 ms 消抖；纯 DC / 角度没扫开 → 明确判"不可判"而不是猜 |
| 接口 | 30082 槽 14 `ph_diag`（只读）、槽 15 `ph_trip`（是否升级为故障，默认 0） |

| 固件 | `Code=109652`（+904 B），0 Error 0 Warning |

## 一、为什么两相采样"物理上"看不出缺相

本板只采 U、W 两相，V 相是 KCL 重构出来的：

```c
s_iv = -(iu + iw);          /* servo_isr.c */
```

一旦真的有一相没有电流，**重构出来的 iv 也跟着是 0** —— 从电流之和上完全
看不出来。今年两次 V 相断路的现场表现都是"Z 辨识 STUCK / ratio_bad，查半天",
第一次甚至误判成机械抱死、编码器打滑。

所以判据不能建在 KCL 上，只能建在**三相电流的统计关系**上。

## 二、判据

健康三相电流互差 120°，`iu+iw = -iv`。一个完整电周期内：

```
rms(iu) ≈ rms(iv) ≈ rms(iw)
```

于是定义（全部只用 iu、iw 两路 + 指令电角度）：

| 量 | 定义 | 健康 | 缺相 |
|---|---|---|---|
| `ratio_v` | `rms(iu+iw) / max(rms_iu, rms_iw)` | ≈1 | V 缺 → ≈0 |
| `balance` | `min(rms_iu, rms_iw) / max(…)` | ≈1 | U 或 W 缺 → ≈0 |

判据顺序（先单相后 V 相，避免串判）：

```
若 max(rms) < 0.15 A            → 不可判（无激励）
否则若 扫角 < 1.5 rad           → 不可判（角度没扫开）
否则若 balance < 0.20           → 判 U / W 缺流（看哪一路小）
否则若 ratio_v < 0.30           → 判 V 缺流
否则                            → 正常
```

**阈值不是拍脑袋**，是两次真实故障的实测值：

| 工况 | ratio_v | corr(iu,iw) |
|---|---|---|
| 健康（2026-11-20 修复后） | 0.963 | −0.521 |
| V 相断路（2026-11-20） | 0.091 | −0.997 |
| V 相断路（2026-11-21 09:59） | 0.091 | −0.997 |

取 0.30 作门限：距故障值 3.3 倍、距健康值 3.2 倍，两边都留足余量。

## 三、两个关键设计决定（都是踩过才知道的）

### 3.1 扫角门必须用**指令**角，不能用实测角

静止矢量恰好落在某相过零点时（例如 θ 让 iv=0），`iu+iw` 确实恒为 0 ——
这在物理上与"V 相断路"**不可区分**。这是两相采样的固有限制，不是判据缺陷。
所以加一道门：窗口内**指令电角度**至少扫过 1.5 rad（86°），才认为
`rms(iu+iw)` 的统计量有意义。

为什么必须是指令角：V 相断路时转子几乎不动（实测每步只走 2.663°，期望 8.571°）。
用实测角算扫角，窗口永远扫不开 → 判"不可判" → **恰好把最该看护的工况排除掉**。
开环时用虚拟角 `s_ol_theta`，闭环时用实测多圈角 × 极对数（单圈角越过 2π 会跳变）。

### 3.2 激励门槛 0.35 A 太严，实测降到 0.15 A

第一版按"相电流峰值 ≈ iq"取 0.35 A。实测 100 rpm 空载 iq=0.27 A，相电流
RMS 只有 **0.19 A** → 一直判"不可判"，检测器等于不存在（`verify_phase_mon`
第一轮就是这么失败的：固件 code=0 但离线 code=4）。

降到 0.15 A 之后正常工作。**为什么不怕噪声误报**：iu、iw 的噪声不相关，
`rms(iu+iw) ≈ √2·rms(iu)`，比值反而 ≈1.4 > 0.30，不会误判成缺相；
单相比值在纯噪声下 ≈1，也不会误判成 U/W 缺。

## 四、实现

```c
/* servo_isr.c —— 20 kHz 节拍里，ReadInjected 之后 */
Servo_PhaseMonTick(iu, iw, th_cmd);      /* 内部 10 kHz 抽取 */

/* 窗口 200 ms = 2000 点；累积量只有 3 个平方和 + 1 个扫角 */
s_pm_iu2 += iu*iu;  s_pm_iw2 += iw*iw;  s_pm_is2 += (iu+iw)^2;
s_pm_sweep += |Δθ_cmd|;                  /* 单步 >90° 视为跳变，忽略 */
```

开销：4 次乘加 + 1 次 sqrt（每 200 ms）≈ 0.4 Mcyc/s，**不占 1 ms 任务**。
窗口结算后做消抖：连续 2 窗（400 ms）认定，连续 3 窗（600 ms）正常才清除。

`1 ms` 任务只做一件事：`ph_trip=1` 且判出缺相且 MOE 已开 → 置
`BSP_FAULT_PHASE_LOSS (1U<<9)`。

**默认 trip=0（只诊断不跳闸）**：缺相跳闸会直接断输出，关节负载侧会掉下来，
这个决定必须由使用者显式打开。判据本身照常工作、随时可读。

## 五、接口

| 通道 | 内容 |
|---|---|
| 30082 槽 14 `ph_diag`（只读） | b0=消抖后结论(0正常/1 U/2 V/3 W)；b1=本窗口原始结论(4=不可判)；b2=`ratio_v×100`；b3=`balance×100` |
| 30082 槽 15 `ph_trip`（可写） | 1 = 判出缺相后置故障，默认 0 |
| `mavlink_link.phase_mon()` | 解码成 `{code, name, raw, raw_name, ratio_v, balance, trip}` |
| `mavlink_link.set_phase_trip(0/1)` | 写槽 15 |

## 六、验证（`verify_phase_mon.py`，10/10）

思路：缺相是偶发硬件故障，不可能为了验证去拔线。但判据是纯代数，可以拿
**真实稳态波形**做代换：V 缺时物理上 `iu ≡ -iw`，直接把 iw 换成 -iu；U 缺
`iu ≡ 0`；W 缺 `iw ≡ 0`。这样三条分支都在真实波形上跑过。

实测（100 rpm 稳态，78 个 30025 帧，扫角 110.4 rad）：

```
离线：ratio_v=1.304 balance=0.952 → code=0（正常）
固件：ratio_v=1.21  balance=0.99  → code=0（正常）      ← 两条独立实现对账

代换（同一段真实波形）：
  U 缺（iu≡0）     ratio_v=1.000 balance=0.000 → code=1  ✓
  W 缺（iw≡0）     ratio_v=1.000 balance=0.000 → code=3  ✓
  V 缺（iw≡-iu）   ratio_v=0.000 balance=1.000 → code=2  ✓
三条分支互不串（{1,2,3}）
```

另外验证过的：
- 空闲（MOE=0）：直接判"不可判"，不误报；窗口在 MOE 关闭时清零，不带脏数据；
- `ph_trip` 写 1 读回 1、写 0 读回 0；
- 全程跑完 `ident_elec` + `ident_mech`（Z 步进、1000 rpm 旋转、齿槽 1 rpm 正反、
  惯量 1/2 A 阶跃）**没有出现一次误报**。

**没验证到的**：真实缺相的正例（现在硬件是好的）。等下次真断，或者做 HIL 注入。

## 七、排查顺序（以后再遇到"Z STUCK"）

1. 读 `phase_mon()` → `code` 直接说是哪一相
2. `ratio_v` ≈ 0 → V 相；`balance` ≈ 0 → 看 `rms` 哪一路小（U 或 W）
3. 若 `raw=4`（不可判）→ 先确认有电流（`iq`）且在转（角度在动），否则本来就不该判

## 九、遗留隐患（建议下一步处理）

**参数保存是"擦整页 → 再编程"，擦写之间只要复位就整页归零。**
09:43 那次 `ps:empty magic / ver=0xFFFF` 最可能就是烧录复位恰好落在保存窗口里：
页面已擦、还没写 magic，于是整页 0xFF，且"参数看起来全丢"。

建议改成**双页乒乓**（0x0807F000 / 0x0807E800 交替写，写完更新一个页序号），
擦写中断只会丢掉最新一次，上一份仍完整。改动约 60 行，比"每次烧录重跑 C/Z"
便宜得多。
