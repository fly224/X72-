# 单精度（single / float）化说明

> 2026-11-15 18:40 · 目标：把 STM32G474 部署代码从 `double` 改成 `single`，
> 让 M4F 硬件 FPU 直接执行，满足 20 kHz（50 µs）实机预算。权威说明以本文 + `README.md` 为准。

---

## 1. 结论先行

**生成代码已全面单精度化并通过 host 验证**：`three_loop_deploy.h` 里 `ExtU/ExtY/DW` 全部为
`real32_T`，`three_loop_deploy.c` 使用 `sinf / cosf / sqrtf`（不再调用双精度软件库），
静态 RAM 从 **392 B 降到 232 B（−41%）**。host SIL 3000 拍最大误差 **1.79e-7**（float 精度量级），
参数接口自检 **14/14 PASS**，20 kHz 的三环节拍与 PID 默认值全部不变。

⚠ **实机仍需 DWT 复测**：文档配置⑤的 1813 cyc 是单精度版的实测参考值，
但本次只做了 host x64 编译，没有 ARM 目标编译与实机周期测量；烧录前请用 `DWT->CYCCNT`
确认 `step()` 单拍 < 50 µs（8500 cyc @170 MHz）。

## 3. 类型与内存对照（nm 实测）

| 符号 | double 版 | single 版 | 说明 |
|---|---|---|---|
| `three_loop_deploy_U` | 0xe0 = 224 B | **0x80 = 128 B** | 接口 28 个 float |
| `three_loop_deploy_Y` | 0x48 = 72 B | **0x28 = 40 B** | 输出 9 个 float |
| `three_loop_deploy_DW` | 0x60 = 96 B | **0x40 = 64 B** | 状态 12 个 float |
| **合计静态 RAM** | **392 B** | **232 B** | −160 B / −41% |
| `THREE_LOOP_TUNING_DEFAULT` | 0xc0 = 192 B | **0x60 = 96 B** | 常量区同步减半 |
| `three_loop_deploy_step` (host x64 -O2) | 0x930 = 2352 B | **0x8e0 = 2272 B** | 代码略小；ARM 尺寸需目标编译确认 |

生成代码关键行（`three_loop_deploy.c`）：
```c
err = sinf(rtb_theta_sum);
rtb_theta_sum = cosf(rtb_theta_sum);
i_beta = sqrtf(i_beta);
```
`model_io_check.txt` 新增两项：
`[PASS] 接口为单精度 real32_T（非 double）`、`[PASS] 生成代码使用 sinf/cosf/sqrtf（M4F 硬件 FPU）`。

## 4. 验证结果

| 项目 | 结果 |
|---|---|
| 代码生成 | 退出 0，`is_single=1`、`single_math=1`，11/11 输入 + 5/5 输出 |
| host 编译 | MinGW GCC `-std=c99 -O2 -Wall` ×2，0 error / 0 warning |
| SIL 数值一致性 | 3000 拍 `max|Δduty| = 1.79e-7` → PASS（float 精度量级）；tick 3000/300/150（20:2:1） |
| 参数接口自检 | **14/14 PASS**（默认值、定点 ID、只读、使能拒写、越界、跨 2π wrap、固定项保护） |
| 节拍核验 | `patch_gen_code.py --check` 4/4「模型侧已修正」；`step() @ 50us (20kHz)`、/10、/20、gain_comp=0.00105 |
| 闭环 MIL | 五场景重跑结果与 20 kHz double 版一致（A: 0.0012° / 79.2 ms / iq 7.168 A / \|v\| 8.76 V） |

### 踩过的四个坑（逐条定位）

1. **`mk_in` 参数顺序**：先 `set_param(p,'Name',...)` 重命名再设 `OutDataTypeStr` → 旧路径 `In1` 已失效。
   改为「先设类型、后重命名」。
2. **π/2 量化诊断**：`Constant` 值写 double 的 1.57079632679，设为 single 后报精度损失警告。
   改为 `sprintf('%.17g', single(pi/2))` = 1.5707963705062866，可直接精确表示。
3. **SIL 外部输入类型**：根 Inport 变 single 后，矩阵型 `ExternalInput`（double）无法加载。
   改用 `Simulink.SimulationData.Dataset` + `timeseries(single(data), t)` 按端口名绑定。
4. **参数接口内存布局 bug（最关键）**：`ThreeLoop_Tuning_T` 字段从 8 字节 double 变 4 字节 float 后，
   `field_get/field_set` 仍按 `double*` 访问 → 读到相邻两个 float 拼成的垃圾值，
   表现为 `Validate=2`（越界）、`ParamGet` 返回 `INT32_MIN`、`ParamSet` 不生效（4 项自检 FAIL）。
   改为 `real32_T*` 后全部恢复。这类「结构体变窄但指针没跟着变」是 C 侧 single 化最易漏的点。

## 5. 边界与局限（务必阅读）

1. **闭环 MIL 仿真仍用 double 控制器**：`sim_check` 的 plant/激励是 SPS 电气域 double，
   直接换 single chart 会触发 EMChart 输出类型推断失败（已实测报错并恢复）。
   当前分工是：**部署代码 single（host SIL 1.79e-7 保证等价）**，**闭环 MIL 用 double 控制器**
   以便与 10 kHz / 20 kHz 历史结果同口径对比。float 精度对闭环指标的影响在 1e-7 量级，可忽略。
   若需要 single MIL，需在 Controller 输入前加 11 个 `Data Type Conversion`（double→single）
   并在 duty 输出后加 single→double，列为可选项。
2. **实机周期数未测**：1813 cyc 是文档配置⑤的历史实测，不是本轮测量。烧录前用
   `DWT->CYCCNT` 复测 `step()` 单拍周期，确认 < 50 µs；若仍超限，需进一步优化
   （减少运行时分支、查表 sin/cos、关闭 `dec` 判断等）。
3. **未做 ARM 目标编译**：本机无 `arm-none-eabi-gcc`，只做 host x64 语法/数值验证。
4. 单精度下参数定点换算（×1e3 / ×1e6）与范围检查仍用 double 计算后转 float，
   避免整数/浮点累加误差；`ParamGet` 回读的 raw 值与 double 版一致（已验证 713 / 1426 / 1050）。
5. 未建模死区、管压降、ADC/编码器量化、弱磁；位置 wrap 仍限 ±π。
